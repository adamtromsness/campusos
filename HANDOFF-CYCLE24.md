## What this cycle adds on top of Cycle 23

**Greenfield — clean `pfl_*` namespace.** Cycle 24 ships the entire M26 Portfolio module from scratch.

- **5 new tenant base tables** across 2 migrations (081 + 082). Tenant base table count after Cycle 23 was 320 → **325** after Cycle 24.
- **1 new backend module** (PortfolioModule) with 3 services + 1 controller + 21 endpoints under `ach-001:read/write/admin` + `ach-002:read/write/admin`.
- **1 new Kafka emit topic**: `pfl.achievement.awarded` (fires when a teacher awards a student a custom or auto-generated achievement; cross-module consumers can listen for badge fan-out, parent notification, or external sharing).
- **5 new web routes**: `/portfolio` (persona-aware landing), `/portfolio/edit` (student builder), `/portfolio/achievements` (gallery with award + share modals), `/children/:id/portfolio` (parent view), `/portfolio-share/:token` (PUBLIC unauthenticated viewer with 410 Gone on expiry).
- **No new permission codes**: ACH-001 + ACH-002 were already in the catalogue from earlier waves. Catalogue stays at **454**.

**Three structural keystones for the cycle:**

1. **STUDENT-OWNED portfolio surface (KEYSTONE).** Cycle 24 is the first surface where a STUDENT actor holds `:write` on their own data and CAN edit, curate, and share it on their own authority. Prior student-input surfaces — wellbeing check-ins (Cycle 11.1, COU-004:read), reading logs / reviews (Cycle 12, LIB-003:write), club registration / service hours (Cycle 17, CLB-001..004) — wrote into staff-administered systems where staff hold the moderator role. Portfolio inverts the model: the student is owner; teachers and parents are read-only viewers gated by the student-controlled visibility setting.

2. **4-tier visibility lattice.** `pfl_portfolios.visibility` is a 4-value CHECK (PRIVATE / TEACHER / PARENT / PUBLIC). The visibility model is monotonic — increasing visibility unlocks the strictly-larger reader set:
   - `PRIVATE` — only the owning student. Teachers, parents, admins all 404 (don't-leak-existence). Admin override is allowed (a school admin can read every portfolio for ops purposes).
   - `TEACHER` — student + assigned teachers + admin.
   - `PARENT` — TEACHER + linked guardians via `sis_student_guardians` joined on `actor.personId`.
   - `PUBLIC` — every authenticated user in the tenant.

3. **Polymorphic item sourcing with cross-module resolution.** `pfl_portfolio_items.source_ref_id` is a DISPLAY-ONLY polymorphic UUID per ADR-001/020 — no DB FK. Application-layer resolution at read time joins `cls_submissions` (Cycle 2) for `SUBMISSION` items, `cls_grades` (Cycle 2) for `GRADE` items, and `pfl_achievements` for `ACHIEVEMENT` items. The Step 4 `PortfolioItemService.list` enriches every row with the resolved source title before returning the DTO. `pfl_achievements.source_module` + `pfl_achievements.source_ref_id` is the second polymorphic surface — achievements aggregate from every prior cycle. Cycle 12's `lib_programme_completions.achievement_id` is the canonical example: when the seed (or future Cycle 12 worker) creates a `pfl_achievements` row for a programme completion, it stamps `source_module='library'` + `source_ref_id=lib_programme_completions.id` and back-fills `lib_programme_completions.achievement_id` so the integration is bidirectional.

**Existing-system touchpoints:**

- `cls_submissions(id)` — soft ref on `pfl_portfolio_items.source_ref_id` when `item_type='SUBMISSION'`. Resolution joins `cls_assignments` for the title.
- `cls_grades(id)` — soft ref on `pfl_portfolio_items.source_ref_id` when `item_type='GRADE'`.
- `pfl_achievements(id)` — soft ref on `pfl_portfolio_items.source_ref_id` when `item_type='ACHIEVEMENT'`.
- `lib_programme_completions.achievement_id` (Cycle 12) — soft ref to `pfl_achievements(id)`. The Cycle 12 column has been waiting for the Cycle 24 target table; the seed plants the `source_module='library'` shape so the bidirectional integration is demonstrable.
- `ext_service_progress(id)` (Cycle 17) — soft ref on `pfl_achievements.source_ref_id` for COMMUNITY achievements (Maya's "Community Service Star" achievement points at her seeded ext_service_progress row).
- `ath_all_time_records(id)` (Cycle 13) — soft ref reserved on `pfl_achievements.source_ref_id` for SPORTING achievements (deferred to Phase 2 — manual creation only this cycle).
- `hr_employees(id)` — DB-enforced FK on `pfl_achievements.awarded_by` with `ON DELETE SET NULL` so the achievement survives a teacher leaving the school.
- `platform.platform_users(id)` — soft ref on `pfl_portfolio_shares.created_by` and `pfl_achievement_shares.shared_by`.

What does not change: every existing module continues to function. Cycle 24 is purely additive on a clean `pfl_*` namespace.
