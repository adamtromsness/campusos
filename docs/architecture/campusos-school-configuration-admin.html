School Configuration
Admin

Three organizational structures with full CRUD, hierarchy visualization, and cross-structure assignment views. The admin surfaces that make a school operational before the first bell rings. No new schema — UI layer on existing tables from Cycles 0, 1, 4, 5, 21.
May 2026 · 7 Steps · 0 new tables · ~12 new pages · Admin-gated

The Three Structures

Design Principle

Each structure is a self-contained hierarchy that the admin builds independently. Then the admin connects them through assignments. The UI reflects this: three separate tree views (Facility, Academic, Position), plus an Assignments view that shows how they link. Every node in every tree is clickable for detail, editable in-place, and deletable with dependency warnings.

Structure 1 — Facility: Campus → Building → Floor/Wing → Room. Tables: fac_buildings (building_id, name, code, year_built, total_floors), fac_spaces (building_id FK, name, floor, space_type, sch_room_id cross-link). The school itself is the implicit campus. Buildings contain floors (the floor column on fac_spaces). Rooms are spaces with type=CLASSROOM.

Structure 2 — Academic / Operational: District → School → Grade Bands → Classes. Tables: organisations (district/MAT), schools (school unit, subdomain, timezone), sis_academic_years + sis_terms (time structure), sis_classes (grade_level, subject, teacher). Grade bands are derived from the grade_level values on classes and students — the admin configures which grade levels belong to which division.

Structure 3 — Position: Organisation → Department → Position → Person. Tables: hr_positions (title, department, reports_to), hr_employees (person fills position). The org chart is built from the reports_to self-referential FK on positions.

Step-by-Step Build Plan

01Configuration Hub Landing Page

The entry point for all school configuration. Admin-gated. Provides navigation to the three structures + assignments + a setup completeness indicator.

Page: /admin/configuration
  1. Three structure cards: "Facility Structure" (building icon, count of buildings + rooms), "Academic Structure" (graduation cap icon, count of grade levels + classes), "Position Structure" (org chart icon, count of positions + staff). Each card links to its manager page.
  2. Assignments card: "Connections" (link icon) — shows how the three structures connect. Links to the assignments view.
  3. Setup completeness indicator: Checklist-style progress: "Buildings defined" (check/x), "Rooms created" (check/x), "Academic year configured" (check/x), "Classes created" (check/x), "Staff positions defined" (check/x), "Staff assigned to positions" (check/x), "Classes assigned to rooms" (check/x). Green when complete, amber when partial, gray when not started. This is computed on render from existing data — no new tracking table.
  4. Quick actions: "Add Building", "Add Class", "Add Position" — shortcuts that jump into the relevant structure's create form.
Produces → /admin/configuration hub page with structure cards + setup completeness.
02Facility Structure Manager

Interactive tree view of the entire physical plant: buildings, floors/wings within buildings, and rooms/spaces within floors. Full CRUD at every level.

Page: /admin/configuration/facilities
  1. Tree view (left panel): Collapsible tree rooted at the school name. Level 1: buildings (expandable). Level 2: floors/wings (grouped from fac_spaces.floor values within each building). Level 3: rooms/spaces (individual fac_spaces rows). Each node shows: name, type pill (CLASSROOM emerald / GYM purple / CAFETERIA amber / OFFICE blue / STORAGE gray), active/inactive status. Click a node to select it and load detail in the right panel.
  2. Detail panel (right): When a building is selected: name, code, year built, total floors, active toggle, total room count, room breakdown by type (pie chart or bar). Edit button opens inline form. Delete button with dependency check ("This building has 12 rooms — remove all rooms first or archive the building").
  3. When a room/space is selected: name, floor, space_type dropdown, area (sqft), sch_room cross-link status ("Linked to Scheduling" green pill or "Not linked" gray pill — shows the sch_rooms.id it maps to), active toggle. For CLASSROOM type: shows which classes are scheduled here (from sch_timetable_slots). Edit inline. Delete with dependency warning.
  4. Add actions: "Add Building" button (top of tree) opens create form: name, code, year built, floors. "Add Room" button (on building node) opens create form: name, floor (dropdown from building floors or free-text for new floor), space_type dropdown, area. On create: emits fac.space.created which auto-creates the sch_rooms draft entry.
  5. Bulk import: "Import Rooms" button with CSV template: building_name, room_name, floor, space_type, area_sqft. Validates building exists, creates rooms in batch.
Produces → /admin/configuration/facilities with interactive tree + detail panel + CRUD + bulk import.
03Academic Structure Manager

Hierarchical view of the academic organization: district (if applicable), school, academic years with terms, grade levels grouped by division/band, and classes within each grade level.

Page: /admin/configuration/academic
  1. Tree view (left panel): Level 0 (if district): organisation name. Level 1: school name + academic year selector (dropdown, current year default). Level 2: grade bands/divisions — admin-configurable groupings (e.g., "Lower School PK–2", "Middle School 3–5", "Upper School 6–8"). These are stored as a JSONB config on platform_tenant_configs with key grade_band_definitions. Level 3: individual grade levels within each band. Level 4: classes within each grade level. Each class node shows: name, subject, teacher name, student count, room assignment.
  2. Detail panel (right): When academic year selected: year name, start/end dates, terms list with date ranges, status (ACTIVE/FUTURE/ARCHIVED). Add/edit terms inline.
  3. When a grade band selected: band name, grade levels included (drag-reorder or multi-select), division head (staff member), total students in band, total classes.
  4. When a class selected: class name, subject, grade level, assigned teacher(s), student count with "View Roster" link, assigned room with "Change Room" dropdown (pulls from sch_rooms), schedule summary (from sch_timetable_slots). Edit inline. "Add Students" button links to the SIS student assignment flow.
  5. Add actions: "Add Academic Year" (name, dates). "Configure Grade Bands" (opens modal: define band names + assign grade levels to bands). "Add Class" (name, subject, grade level, teacher dropdown, room dropdown).
  6. Grade band configuration modal: List of grade levels (PK, K, 1–12). Drag each into a named band. Save writes to platform_tenant_configs. This is the only new configuration surface — everything else uses existing tables.
Produces → /admin/configuration/academic with year/term/grade/class tree + grade band configuration.
04Position Structure Manager

Organizational chart view of the position hierarchy with department grouping, reports-to chains, and person-to-position assignment.

Page: /admin/configuration/positions
  1. Org chart view (primary): Visual organizational chart rendering the reports-to hierarchy. Root: school head (Principal/Head of School). Each node: position title, department pill, person name (or "Vacant" in amber), person avatar. Lines connect each position to its reports_to parent. Zoom + pan for large orgs. Click a node to select and load detail.
  2. List view (toggle): Table view with columns: position title, department, reports to, filled by, status (Filled emerald / Vacant amber). Sortable + filterable by department.
  3. Detail panel: When a position selected: title, department, reports to (dropdown of other positions), description, currently filled by (employee name + link to HR profile), assignment history (who held this position previously). Edit inline. "Assign Person" button opens employee selector.
  4. Add actions: "Add Position" (title, department from predefined list or free-text, reports_to dropdown, description). "Add Department" (name, code). Positions auto-appear in the org chart on create.
  5. Drag-reassign: Drag a position node in the org chart to a new parent to change the reports_to relationship. Confirmation modal: "Move [Art Teacher] to report to [Department Head - Arts]?"
  6. Vacancy dashboard: Summary card at top: total positions, filled, vacant. List of vacant positions with "Assign" buttons. Links to the Cycle 4.1 HR recruitment pipeline when built.
Produces → /admin/configuration/positions with org chart + list view + CRUD + drag-reassign.
05Assignments & Connections View

The view that shows how the three structures connect: which buildings serve which school units, which positions are assigned where, which people fill which positions, and which classes meet in which rooms.

Page: /admin/configuration/connections
  1. Four assignment sections rendered as interactive tables with inline editing:
  2. School ↔ Facility: Table showing each building and which school unit it serves. Most single-campus schools have one row. Multi-campus: multiple rows. Add/remove building-to-school linkages. Derived from fac_buildings.school_id.
  3. Position ↔ School: Table showing positions grouped by school unit. Each row: position title, department, school, filled-by. Filter by department. Derived from hr_positions.school_id.
  4. Person ↔ Position: Table showing all staff with their position(s). Columns: person name, position(s), department, start date. "Assign" button for unassigned staff. "Change Position" for reassignment. Derived from hr_employees.position_id.
  5. Class ↔ Room: Table showing class-to-room assignments from the schedule. Columns: class name, grade, teacher, room, building, schedule (days/times). "Change Room" dropdown. "Unassigned" rows highlighted in amber for classes without a room. Derived from sch_timetable_slots.room_id.
  6. Sankey diagram (visual): A single visual showing the flow: Buildings → Rooms → Classes → Teachers → Departments. Hovering over any node highlights its connections across all three structures. This is the "big picture" view that shows the admin how everything connects.
Produces → /admin/configuration/connections with 4 assignment tables + Sankey diagram.
06Setup Wizard (First-Time Onboarding)

A guided step-by-step flow for first-time school setup. Walks the admin through creating all three structures in dependency order, then connecting them. Resumable — the admin can leave and come back.

Page: /admin/setup-wizard
  1. Step 1 — School Identity: School name, address, timezone, phone, website, logo upload. Writes to schools. Pre-filled from tenant provisioning if available.
  2. Step 2 — Academic Calendar: Academic year name + start/end dates. Add terms (Fall, Spring or Term 1/2/3). Define grade levels offered (checkboxes PK through 12). Configure grade bands (drag grades into named divisions). Writes to sis_academic_years + sis_terms + platform_tenant_configs.grade_band_definitions.
  3. Step 3 — Buildings & Rooms: Add building(s) with name + floors. Per building: add rooms (name, floor, type). Bulk CSV import available. Writes to fac_buildings + fac_spaces. Auto-creates sch_rooms via fac.space.created.
  4. Step 4 — Departments & Positions: Define departments (Administration, English, Math, Science, etc.). Per department: add positions (Principal, Department Head, Teacher, Aide, etc.) with reports-to chain. Writes to hr_positions.
  5. Step 5 — Staff Import: CSV upload: first_name, last_name, email, position_title, department. Creates iam_person + platform_users + hr_employees + position assignment. Sends welcome email via IdP. Bulk operation.
  6. Step 6 — Student Import: CSV upload: first_name, last_name, grade_level, guardian_name, guardian_email. Creates iam_person + platform_students + sis_students + sis_guardians + sis_student_guardians. Creates parent accounts. Bulk operation.
  7. Step 7 — Classes & Assignments: Create classes (name, subject, grade_level, teacher, room). Or CSV: class_name, subject, grade_level, teacher_email, room_name. Assigns students to classes. Writes to sis_classes + sis_enrolments.
  8. Step 8 — Review & Launch: Summary page showing everything created: X buildings, Y rooms, Z staff, W students, N classes. Completeness check (any missing assignments highlighted). "Complete Setup" button marks the school as fully configured. Confetti animation.
  9. Resumability: Each step saves progress. The wizard shows completed steps with green checkmarks. The admin can jump to any completed step to edit. Incomplete steps show the "Continue" prompt. Progress stored in platform_tenant_configs with key setup_wizard_progress.
Produces → /admin/setup-wizard with 8-step guided onboarding, CSV imports, resumable progress.
07API Endpoints for Structure Views

New API endpoints that return the hierarchical data in the format the tree views and org chart need. These are read-only aggregate endpoints — individual CRUD uses the existing module APIs.

New Endpoints
  1. GET /admin/configuration/facility-tree — Returns the full facility hierarchy: buildings with nested floors with nested spaces, including sch_room cross-links and scheduled class counts per room. Single query with joins.
  2. GET /admin/configuration/academic-tree — Returns the full academic hierarchy: academic year with terms, grade bands (from tenant config), grade levels with nested classes, including teacher names, student counts, and room assignments per class.
  3. GET /admin/configuration/position-tree — Returns the position hierarchy as a tree rooted at the top position (reports_to IS NULL). Each node includes: position, department, filling employee (or null for vacant). Recursive CTE query for arbitrary depth.
  4. GET /admin/configuration/connections-summary — Returns the cross-structure assignment summary: building-school links, position-school links, person-position links (with vacancies), class-room links (with unassigned classes).
  5. GET /admin/configuration/setup-status — Returns the setup completeness checklist: boolean per step (buildings_defined, rooms_created, academic_year_configured, classes_created, positions_defined, staff_assigned, classes_assigned_rooms).
  6. POST /admin/configuration/import/staff — Bulk CSV import: validates, creates iam_person + platform_users + hr_employees + position assignments in one transaction.
  7. POST /admin/configuration/import/students — Bulk CSV import: validates, creates iam_person + platform_students + sis_students + guardians in one transaction.
  8. POST /admin/configuration/import/rooms — Bulk CSV import: validates building exists, creates fac_spaces in batch.
  9. PATCH /admin/configuration/grade-bands — Saves the grade band definitions to platform_tenant_configs.
Produces → 9 new endpoints (5 reads + 3 imports + 1 config). All admin-gated. No new tables.
