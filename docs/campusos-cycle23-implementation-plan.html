Plan Overview

Cycle 23 builds the M25 Curriculum module — all 11 ERD tables plus the 2 platform-schema seed tables (cur_standards_frameworks_platform + cur_standards_platform). This is the first Academic Advanced module and the first cycle that reads back into Cycle 2's classroom data at the planning layer: cur_unit_lessons links curriculum units to cls_lessons so teachers can see which lessons deliver which standards, and the nightly cur_delivery_gaps materialisation compares planned coverage against actual lesson delivery to surface gaps.

The module has a unique platform/tenant split: national standards frameworks (Common Core State Standards, Next Generation Science Standards, etc.) are seeded into cur_standards_frameworks_platform + cur_standards_platform in the platform schema so a CCSS update requires one migration, not one per tenant. Schools adopt frameworks via cur_school_framework_adoptions and can also create custom bespoke frameworks in their tenant schema. This dual-resolution pattern (platform OR tenant) is resolved at the application layer per the soft integrity pattern.

Vertical Slice Deliverable

Admin seeds the platform with "Common Core ELA" framework + 50 standards → school adopts CCSS ELA for the 2026-2027 year → Department Head creates a "Grade 5 ELA" curriculum map → adds 6 units in scope-and-sequence order ("Narrative Writing" 4 weeks, "Persuasive Essays" 3 weeks, etc.) → aligns 8 CCSS standards to "Narrative Writing" unit (CCSS.ELA-LITERACY.W.5.3a through W.5.3e) → links 3 existing cls_lessons from Cycle 2 to the "Narrative Writing" unit → attaches a teacher-only resource PDF "Narrative Writing Rubric" → also creates a custom school framework "Lincoln Academy Writing Standards" with 5 school-specific standards → the nightly delivery gap worker materialises: "Narrative Writing" shows 3 lessons planned, 2 delivered, gap_type=PARTIAL for 2 standards not yet assessed → Cycle 12's lib_reading_lists.curriculum_unit_id soft FK now resolves to the "Narrative Writing" unit, linking the library reading list to the curriculum.

In scope (all 11 tenant tables + 2 platform seeds): cur_school_framework_adoptions, cur_standards_frameworks, cur_standards, cur_curriculum_maps, cur_units, cur_unit_standards, cur_unit_lessons, cur_delivery_gaps, cur_resource_links. Platform: cur_standards_frameworks_platform, cur_standards_platform (seeded with CCSS ELA + CCSS Math + NGSS). Function TCH-008 (Curriculum Management).

Step-by-Step Build Plan

01Framework + Standards Schema
Schema

Platform-seeded national frameworks with GIN-indexed standards, school adoption records linking platform frameworks to academic years, and school-created custom frameworks with custom standards.

Tables (5 — 2 platform + 3 tenant)
  1. cur_standards_frameworks_platform (PLATFORM schema) — name TEXT NOT NULL UNIQUE, body TEXT (governing body, e.g., "National Governors Association"), region TEXT, version TEXT. Updated by platform migrations only. Schools adopt via cur_school_framework_adoptions.
  2. cur_standards_platform (PLATFORM schema) — framework_id UUID FK NOT NULL, code TEXT NOT NULL, description TEXT NOT NULL, grade_band TEXT, domain TEXT, cluster TEXT. UNIQUE(framework_id, code). GIN INDEX on to_tsvector(code || ' ' || description) for keyword search. Updated by platform migrations only.
  3. cur_school_framework_adoptions (TENANT) — school_id UUID, platform_framework_id UUID (soft to cur_standards_frameworks_platform), academic_year_id UUID FK. UNIQUE(school_id, platform_framework_id, academic_year_id). Indicates which national frameworks the school follows in a given year.
  4. cur_standards_frameworks (TENANT) — School-created custom frameworks only. school_id UUID NOT NULL (enforced — platform frameworks never in this table), name TEXT NOT NULL, version TEXT, description TEXT. UNIQUE(school_id, name, version).
  5. cur_standards (TENANT) — School-created custom standards only. framework_id UUID FK(cur_standards_frameworks) NOT NULL, code TEXT NOT NULL, description TEXT NOT NULL, grade_band TEXT, domain TEXT. UNIQUE(framework_id, code).
Produces → 2 platform + 3 tenant tables. Platform migration: platform_015_cur_standards.sql. Tenant migration: 073_cur_frameworks.sql.
02Curriculum Maps + Units + Alignment Schema
Schema

Curriculum maps per subject per grade per year, ordered units with scope-and-sequence, unit-to-standard alignment (resolves from both platform and tenant standards), unit-to-lesson linking back into Cycle 2, nightly materialised delivery gaps, and teaching resource links.

Tables (6 tenant)
  1. cur_curriculum_maps — school_id UUID, framework_id UUID (resolved by application from either tenant cur_standards_frameworks or platform cur_standards_frameworks_platform via cur_school_framework_adoptions), academic_year_id UUID FK, subject TEXT NOT NULL, grade_level TEXT NOT NULL, created_by UUID FK, status TEXT NOT NULL DEFAULT 'DRAFT' 3-value CHECK (DRAFT, PUBLISHED, ARCHIVED). INDEX(school_id, academic_year_id, subject).
  2. cur_units — curriculum_map_id UUID FK NOT NULL, title TEXT NOT NULL, description TEXT, sequence_order INT NOT NULL, estimated_weeks INT, start_date DATE, end_date DATE, essential_questions TEXT[]. INDEX(curriculum_map_id, sequence_order).
  3. cur_unit_standards — unit_id UUID FK NOT NULL, standard_id UUID NOT NULL (SOFT INTEGRITY → cur_standards.id OR cur_standards_platform.id — application-layer resolution). UNIQUE(unit_id, standard_id). The dual-resolution is the keystone: one unit can align to both a CCSS standard and a school-custom standard.
  4. cur_unit_lessons — unit_id UUID FK NOT NULL, cls_lesson_id UUID NOT NULL (SOFT INTEGRITY → cls_lessons.id from Cycle 2 — registered in platform_reference_health per ADR-028). UNIQUE(unit_id, cls_lesson_id). This is the cross-cycle read-back keystone: curriculum planning links to classroom delivery.
  5. cur_delivery_gaps — MATERIALISED NIGHTLY (ADR-018). unit_id UUID FK NOT NULL, standard_id UUID NOT NULL, gap_type TEXT NOT NULL 3-value CHECK (NOT_STARTED, PARTIAL, COMPLETE), lessons_planned INT, lessons_delivered INT, last_assessed_at TIMESTAMPTZ. UNIQUE(unit_id, standard_id). Never computed on demand — the Step 6 worker reads from cls_lessons + cls_assignments delivery records and materialises the gap state nightly.
  6. cur_resource_links — unit_id UUID FK NOT NULL, resource_type TEXT NOT NULL 4-value CHECK (FILE, URL, VIDEO, TEXTBOOK), url TEXT, title TEXT NOT NULL, s3_key TEXT nullable (for uploaded files), is_teacher_only BOOLEAN DEFAULT false (when true: students + parents cannot see this resource). INDEX(unit_id, resource_type).
Produces → 6 tenant tables. Migration: 074_cur_maps_units.sql. Total Cycle 23 tables: 11 (9 tenant + 2 platform).
03Seed Data
Seed
What Gets Seeded
  1. 3 platform frameworks + ~150 standards: "Common Core State Standards — ELA" (~50 standards with code/description/grade_band/domain), "Common Core State Standards — Math" (~50), "Next Generation Science Standards" (~50). GIN index immediately searchable.
  2. 1 school framework adoption: Lincoln Academy adopts CCSS ELA for 2025-2026.
  3. 1 custom framework + 5 custom standards: "Lincoln Academy Writing Standards" with 5 school-specific writing standards.
  4. 1 curriculum map + 4 units: "Grade 5 ELA 2025-2026" (PUBLISHED). Units: "Narrative Writing" (seq 1, 4 weeks), "Persuasive Essays" (seq 2, 3 weeks), "Research Reports" (seq 3, 5 weeks), "Poetry & Creative Writing" (seq 4, 3 weeks).
  5. 8 unit-standard alignments: "Narrative Writing" aligned to CCSS.ELA-LITERACY.W.5.3a through W.5.3e (5 standards) + 3 Lincoln Academy custom standards.

  9. Permissions: TCH-008:read to Teacher, Parent (view curriculum maps + standards). TCH-008:write to Teacher (create/edit maps, units, alignments, resources). TCH-008:admin to Admin (configure frameworks, adopt standards, manage department-level approval). Admin gets all via everyFunction.

06Delivery Gaps + Resources NestJS Module
Code
Services & Endpoints
  1. DeliveryGapService — NIGHTLY MATERIALISATION WORKER (ADR-018). Internal worker triggered on schedule (or manually via admin endpoint): for each active curriculum map, walks each unit's standards, counts planned lessons (from cur_unit_lessons) and delivered lessons (from cls_lessons WHERE status='COMPLETED'), computes gap_type per (unit, standard), and UPSERTs cur_delivery_gaps. Emits cur.delivery_gap.detected when a new NOT_STARTED or PARTIAL gap is materialised for a PUBLISHED map. GET /curriculum/delivery-gaps (gap dashboard: filters map, unit, gap_type; sorts by severity), GET /curriculum/units/:id/gaps (per-unit gap detail). POST /curriculum/delivery-gaps/refresh (admin: manual re-materialisation).
  2. ResourceLinkService — GET /curriculum/units/:id/resources (filters is_teacher_only for non-staff readers), POST /curriculum/units/:id/resources, PATCH /curriculum/resources/:id, DELETE /curriculum/resources/:id.
Produces → 2 services, ~8 endpoints, 1 Kafka emit (cur.delivery_gap.detected). Total Cycle 23 endpoints: ~32.

09Cross-Cycle Integration Verification
Code

  1. cur_unit_lessons → cls_lessons (Cycle 2): UnitService.addLesson validates the cls_lesson_id exists in the calling tenant via a SELECT against cls_lessons. The unit detail page renders the lesson title + delivery status from Cycle 2's classroom data.
