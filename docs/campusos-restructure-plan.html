CampusOS|Design Hub|RESTRUCTURE PLAN

Codebase Restructure Plan

Consolidate 80+ flat cycle-by-cycle folders into 38 canonical ERD modules. Clean up documentation. Prepare for module-by-module test strategy. One Claude Code cycle, executed in 4 phases.

Risk mitigation: This restructure touches every import path in 695+ files. Execute on a clean main with no parallel branches. Run pnpm build + pnpm test after each phase. If any phase breaks the build, fix before proceeding. Git commit after each phase so rollback is granular.

What Changes

  1. Source code — apps/api/src/ folders consolidated from ~80 flat directories into 38 canonical module directories under apps/api/src/modules/, plus a shared/ directory for cross-cutting infrastructure.
  2. Documentation — docs/ reorganised from flat dump into structured subdirectories: architecture, plans, reviews, policies, operations.
  3. Tests — existing mock specs move with their services. Integration test harness directory stays at apps/api/test/integration/. Future integration tests mirror the module structure.

What Does NOT Change

  1. Database — no schema changes, no migrations, no table renames.
  2. Prisma — packages/database/ stays exactly as-is.
  3. Web app — apps/web/ stays as-is (frontend restructure is a separate project).
  4. Packages — packages/ stay as-is.
  5. Module functionality — no logic changes. Pure file moves + import rewrites.

Phase 3: Import Path Rewrite

After moving files, every import statement that references the old path must be updated. This is the most mechanical and highest-risk phase.

  1. Use TypeScript path aliases in tsconfig.json to simplify future imports:
// tsconfig.json paths
{
  "compilerOptions": {
    "paths": {
      "@modules/*": ["apps/api/src/modules/*"],
      "@shared/*": ["apps/api/src/shared/*"]
    }
  }
}
  1. Update all relative imports to use the new paths. Claude Code can do this mechanically with a find-and-replace script.
  2. Update app.module.ts to import all module classes from their new locations.
  3. Update vitest.config.ts and vitest.integration.config.ts to resolve the path aliases.
  4. Run pnpm build + pnpm test to verify.

Phase 4: Verification
