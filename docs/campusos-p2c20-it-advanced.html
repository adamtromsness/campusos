Plan Overview

Phase 2 Cycle 20 builds the deferred tables from Cycle 22's M62 IT Infrastructure module — 10 new tables. Cycle 22 built the core IT surface (device fleet, MDM sync, assignments, damage reports, repair tracking, software licensing, credential vault). This cycle adds the operational depth: remote MDM actions, inventory audits, usage analytics, licence renewals, VOIP, documentation, and monitoring.

Security — Remote Actions Are IMMUTABLE

tech_remote_actions is IMMUTABLE — no UPDATE, no DELETE at the service layer. Every remote MDM command (LOCK, WIPE, RESTART, LOCATE, UNENROLL) is an auditable, permanent record with mandatory justification (minimum 20 characters). A WIPE action auto-sets tech_assets.status=AVAILABLE on completion (device reset). MDM provider integration is stubbed this cycle — the command is recorded and status is manually updated. Live MDM integration (Jamf/Intune API) is a future enhancement.

Vertical Slice Deliverable

IT admin discovers a lost student iPad → issues LOCK remote action with justification "Student reported iPad lost at bus stop, locking to prevent unauthorized access" → tech_remote_actions IMMUTABLE row created (PENDING) → MDM sends lock command (stubbed) → status → COMPLETED → parent finds iPad next day → IT admin issues DISABLE_LOST_MODE → separately, IT admin schedules annual device audit for Building A → starts audit: system lists 45 expected devices in Building A → auditor scans each device barcode → found/not-found per asset → 42 found, 2 missing, 1 unrecorded device discovered → completes audit → discrepancy report generated → meanwhile, Photoshop licence approaching 80% seat usage → alert fires → IT admin renews licence → tech_licence_renewals row created, expiry_date extended, cost recorded → IT admin documents the school's network topology in tech_config_documentation with a Visio diagram upload → configures uptime monitoring for 3 critical systems (SIS API, payment gateway, email) with 5-minute intervals → MonitoringWorker checks every 5 min → SIS API returns 200 → HEALTHY → payment gateway timeout → DEGRADED → alert fires after 2 consecutive failures.

What's In / What's Deferred

Step-by-Step Build Plan

01Schema — Remote Actions + Licence Renewals + Usage + Inventory (5 tables)
Schema
  1. tech_remote_actions — IMMUTABLE. asset_id UUID FK(tech_assets) NOT NULL, action_type TEXT NOT NULL 7-value CHECK (LOCK, WIPE, RESTART, LOCATE, UNENROLL, ENABLE_LOST_MODE, DISABLE_LOST_MODE), initiated_by UUID FK NOT NULL, initiated_at TIMESTAMPTZ NOT NULL, justification TEXT NOT NULL CHECK(length(trim(justification)) ≥ 20), mdm_command_ref TEXT, status TEXT NOT NULL DEFAULT 'PENDING' 4-value CHECK (PENDING, SENT, COMPLETED, FAILED), completed_at TIMESTAMPTZ, failure_reason TEXT. NO UPDATE, NO DELETE. INDEX(asset_id, initiated_at DESC). On WIPE + COMPLETED: tech_assets.status = AVAILABLE.
  2. tech_licence_renewals — licence_id UUID FK(tech_software_licences) NOT NULL, previous_expiry_date DATE NOT NULL, new_expiry_date DATE NOT NULL, renewal_cost NUMERIC(10,2), renewed_by UUID FK NOT NULL, renewed_at TIMESTAMPTZ NOT NULL, notes TEXT. INDEX(licence_id, renewed_at DESC). On INSERT: tech_software_licences.expiry_date updated to new_expiry_date.
  3. tech_device_usage_summaries — asset_id UUID FK(tech_assets) NOT NULL, summary_date DATE NOT NULL, screen_time_minutes INT, apps_used TEXT[], flagged_activity BOOLEAN DEFAULT false, summary_source TEXT. UNIQUE(asset_id, summary_date). Populated from MDM provider data (manual this cycle).
  4. tech_inventory_audits — school_id UUID NOT NULL, audit_name TEXT NOT NULL, conducted_by UUID FK NOT NULL, audit_date DATE NOT NULL, total_assets_expected INT NOT NULL, total_assets_found INT NOT NULL, total_assets_missing INT NOT NULL, total_assets_unrecorded INT NOT NULL, audit_notes TEXT, status TEXT NOT NULL DEFAULT 'IN_PROGRESS' 2-value CHECK (IN_PROGRESS, COMPLETED), completed_at TIMESTAMPTZ. INDEX(school_id, audit_date DESC).
  5. tech_inventory_audit_items — audit_id UUID FK NOT NULL, asset_id UUID FK (null for unrecorded assets), asset_tag TEXT NOT NULL, found BOOLEAN NOT NULL, condition_observed TEXT 4-value CHECK (EXCELLENT, GOOD, FAIR, DAMAGED) nullable, location_observed TEXT, discrepancy_notes TEXT. UNIQUE(audit_id, asset_tag). INDEX(audit_id, found).
Produces → 5 tables. Migration: 140_tech_remote_actions_audit.sql.
02Schema — VOIP + Documentation + Monitoring + Infrastructure (5 tables)
Schema
  1. tech_phone_extensions — school_id UUID NOT NULL, extension_number TEXT NOT NULL, assigned_to UUID FK (soft to hr_employees), location TEXT, department TEXT, extension_type TEXT NOT NULL 5-value CHECK (DESK, CLASSROOM, OFFICE, COMMON_AREA, FAX), is_active BOOLEAN DEFAULT true. UNIQUE(school_id, extension_number). INDEX(school_id, assigned_to).
  2. tech_config_documentation — school_id UUID NOT NULL, title TEXT NOT NULL, category TEXT NOT NULL 7-value CHECK (NETWORK_TOPOLOGY, SERVER_CONFIG, WIFI, VOIP, FIREWALL, BACKUP, OTHER), content_markdown TEXT NOT NULL, version INT NOT NULL DEFAULT 1, diagram_s3_key TEXT, last_updated_by UUID FK NOT NULL, last_updated_at TIMESTAMPTZ NOT NULL. UNIQUE(school_id, title). Versioned: updates increment version, previous versions accessible.
  3. tech_monitoring_checks — school_id UUID NOT NULL, system_name TEXT NOT NULL, check_url TEXT, check_type TEXT NOT NULL 4-value CHECK (HTTP, PING, TCP, MANUAL), interval_minutes INT NOT NULL DEFAULT 5, expected_status_code INT DEFAULT 200, timeout_seconds INT DEFAULT 10, consecutive_failures_to_alert INT DEFAULT 2, is_active BOOLEAN DEFAULT true. UNIQUE(school_id, system_name).
  4. tech_monitoring_alerts — check_id UUID FK NOT NULL, alert_type TEXT NOT NULL 3-value CHECK (DOWN, DEGRADED, RECOVERED), detected_at TIMESTAMPTZ NOT NULL, resolved_at TIMESTAMPTZ, response_time_ms INT, status_code INT, error_message TEXT, acknowledged_by UUID FK, acknowledged_at TIMESTAMPTZ. INDEX(check_id, detected_at DESC). Partial INDEX WHERE resolved_at IS NULL for active alerts.
  5. tech_infrastructure_items — school_id UUID NOT NULL, item_name TEXT NOT NULL, item_type TEXT NOT NULL 9-value CHECK (SWITCH, ACCESS_POINT, SERVER, ROUTER, FIREWALL, PRINTER, NAS, UPS, OTHER), location TEXT NOT NULL, ip_address TEXT, mac_address TEXT, make TEXT, model TEXT, serial_number TEXT, purchase_date DATE, warranty_expiry DATE, status TEXT NOT NULL DEFAULT 'ACTIVE' 3-value CHECK (ACTIVE, MAINTENANCE, DECOMMISSIONED), last_checked_at TIMESTAMPTZ. UNIQUE(school_id, serial_number) WHERE serial_number IS NOT NULL.
Produces → 5 tables. Migration: 141_tech_voip_monitoring.sql. Total P2-20 tables: 10.

04Remote Actions + Inventory Audit NestJS Module
Code
  1. RemoteActionService — POST /it/devices/:assetId/remote-action (IMMUTABLE: creates tech_remote_actions with mandatory justification ≥20 chars; validates action_type against device type; emits tech.remote_action.issued), GET /it/devices/:assetId/remote-actions (action history), PATCH /it/remote-actions/:id/status (MDM callback updates status; on WIPE+COMPLETED: auto-sets tech_assets.status=AVAILABLE). NO update or delete on the remote action row itself.
  2. InventoryAuditService — POST /it/inventory-audits (start audit: computes total_assets_expected from tech_assets for the building), POST /it/inventory-audits/:id/scan (record per-asset: asset_tag + found + condition; if asset_tag not in system: asset_id=null, counted as unrecorded), POST /it/inventory-audits/:id/complete (finalize: computes found/missing/unrecorded counts), GET /it/inventory-audits, GET /it/inventory-audits/:id/report (discrepancy report: missing assets + unrecorded assets + condition changes).
  3. LicenceRenewalService — POST /it/licences/:id/renew (creates renewal record + updates licence expiry_date), GET /it/licences/:id/renewals (renewal history + cost chart).
  4. DeviceUsageService — POST /it/devices/:assetId/usage (record daily summary), GET /it/devices/:assetId/usage (usage trends), GET /it/device-usage/flagged (devices with flagged_activity=true).
Produces → 4 services, ~16 endpoints, 1 Kafka emit.
05VOIP + Documentation + Monitoring + Infrastructure NestJS Module
Code
  1. PhoneExtensionService — CRUD for extensions. GET /it/phone-extensions (directory searchable by name/department/extension), POST /it/phone-extensions/:id/assign, POST /it/phone-extensions/:id/unassign.
  2. ConfigDocumentationService — CRUD with versioning. GET /it/documentation (by category), POST /it/documentation (creates v1), PATCH /it/documentation/:id (increments version), GET /it/documentation/:id/history (version history). Diagram upload to S3.
  3. MonitoringService — CRUD for checks. GET /it/monitoring (all checks with latest status), POST /it/monitoring/:checkId/result (record check result; if DOWN and consecutive failures ≥ threshold → create tech_monitoring_alerts; if RECOVERED → resolve active alert), GET /it/monitoring/alerts (active alerts), PATCH /it/monitoring-alerts/:id/acknowledge. Emits tech.monitoring.alert for IT admin notification.
  4. InfrastructureService — CRUD for infrastructure items. GET /it/infrastructure (with status filter), GET /it/infrastructure/warranty-expiring (30-day lookahead).
Produces → 4 services, ~18 endpoints, 1 Kafka emit. Total P2-20 endpoints: ~34.

07Vertical Slice Integration Test
Test
  1. Remote action IMMUTABLE: Issue LOCK with justification. Verify row created. Attempt UPDATE → rejected. Attempt DELETE → rejected. Verify justification <20 chars → 400.
  2. WIPE auto-reset: Issue WIPE. Update status to COMPLETED. Verify tech_assets.status = AVAILABLE. Verify previous assignment ended.
  3. Inventory audit lifecycle: Start audit (45 expected). Scan 42 (found). Scan 1 unknown tag (unrecorded). Complete. Verify totals: 42 found, 2 missing, 1 unrecorded. Verify discrepancy report lists missing asset_tags.
  4. Licence renewal: Licence expires 2026-12-31. Renew to 2027-12-31 at $500. Verify tech_software_licences.expiry_date updated. Verify renewal history shows previous + new dates.
  5. Monitoring alert: Configure check (HTTP, 5 min, 2 consecutive failures). Record 2 consecutive failures. Verify alert created (DOWN). Record success. Verify alert resolved (RECOVERED). Verify tech.monitoring.alert fires on DOWN.
  6. Config documentation versioning: Create doc v1. Update → v2. Verify version incremented. Verify v1 accessible via history.
  7. Visibility: IT admin can issue remote actions + configure monitoring. IT staff can conduct audits + manage extensions. Teachers cannot access IT module. All IT staff can view documentation.
Produces → Verified IT advanced: remote actions (IMMUTABLE) → WIPE auto-reset → inventory audit → licence renewal → monitoring alerts → documentation versioning.
