P2-29: Commerce .1 Bundle

Deferred tables from three commerce modules: Procurement (M86) with vendor catalogues, contract lifecycle management, and spending analytics; School Store (M67) with inventory adjustments, promotions, loyalty points, gift cards, wishlists, and price scheduling; and Finance Extensions (M83/M84) with departmental budget management, budget transfers, and enhanced journal entry batches. Full GL accounting (period close, AP three-way matching, grants) remains in Phase 3 Theme B. Pre-split into 2 sub-cycles.
May 2026 · 2 Sub-Cycles · ERD v11 · M86.1 + M67.1 + M83/84.1 (19 tables) · PRC-001..004 + STR-001..002 + FIN-001..003 · Phase 2 Cycle 29
Phase 2 vs Phase 3 Finance Boundary

Phase 2 builds the operational finance layer: departmental budgets, budget transfers between departments, and enhanced journal entry batches for admin-initiated corrections. Phase 3 Theme B builds the full accounting layer: chart of accounts management, period close with trial balance, AP three-way matching, grant accounting, and financial statement generation. This boundary is set by ADR-058 + ADR-061: full accounting requires the GL backbone to be battle-tested with real production data before layering complex accounting workflows on top.

Sub-Cycle Structure

P2-29a — Procurement Advanced + Finance Extensions (9 tables)

Vendor catalogues with pre-approved items at pre-negotiated prices, catalogue-based requisitions that auto-populate pricing, contract lifecycle management (draft → active → expiring → renewed/terminated) with renewal alerting, procurement spending analytics by vendor/category/department, departmental budget management with allocation tracking, inter-department budget transfers with approval, and enhanced journal entry batches for manual GL corrections.

P2-29b — Store Advanced (10 tables)

Store inventory adjustments with reason tracking and audit trail, product promotions with date-range scheduling and discount types (percentage, flat, BOGO), loyalty points with configurable earn rates and redemption, gift card issuance with balance management and top-up, product wishlists with back-in-stock notification, price scheduling for seasonal pricing, store categories with hierarchy, store analytics dashboard, and enhanced order fulfilment workflow.

P2-29a: Procurement + Finance (M86.1 + M83/84.1)

01Schema (9 tables)
Schema
  1. prc_vendor_catalogues — vendor_id UUID FK(fin_suppliers) NOT NULL, school_id UUID NOT NULL, catalogue_name TEXT NOT NULL, effective_from DATE NOT NULL, effective_to DATE, is_active BOOLEAN DEFAULT true. UNIQUE(vendor_id, school_id, catalogue_name). Pre-approved item lists at pre-negotiated prices.
  2. prc_catalogue_items — catalogue_id UUID FK NOT NULL, item_code TEXT NOT NULL, description TEXT NOT NULL, unit TEXT, negotiated_price NUMERIC(10,2) NOT NULL, category TEXT, min_order_qty INT DEFAULT 1, lead_time_days INT. UNIQUE(catalogue_id, item_code). Requisitions from catalogue auto-populate pricing.
  3. prc_contracts — school_id UUID NOT NULL, vendor_id UUID FK(fin_suppliers) NOT NULL, contract_number TEXT NOT NULL, title TEXT NOT NULL, start_date DATE NOT NULL, end_date DATE NOT NULL, total_value NUMERIC(12,2), spent_to_date NUMERIC(12,2) DEFAULT 0, status TEXT NOT NULL DEFAULT 'DRAFT' 5-value CHECK (DRAFT, ACTIVE, EXPIRING, RENEWED, TERMINATED), document_s3_key TEXT, renewal_reminder_days INT DEFAULT 90, created_by UUID FK NOT NULL. UNIQUE(school_id, contract_number). INDEX(school_id, status, end_date). ContractExpiryWorker: nightly checks end_date - renewal_reminder_days → ACTIVE → EXPIRING + notifies procurement lead.
  4. prc_contract_amendments — contract_id UUID FK NOT NULL, amendment_number INT NOT NULL, description TEXT NOT NULL, value_change NUMERIC(12,2), new_end_date DATE, document_s3_key TEXT, approved_by UUID FK, effective_date DATE NOT NULL. UNIQUE(contract_id, amendment_number). On value_change: updates prc_contracts.total_value.
  5. prc_spending_analytics — school_id UUID NOT NULL, period DATE NOT NULL (monthly), vendor_id UUID FK, category TEXT, department TEXT, total_spend NUMERIC(12,2), po_count INT, avg_lead_time_days NUMERIC(5,1). UNIQUE(school_id, period, vendor_id, category, department). Materialised monthly by ProcurementAnalyticsWorker from prc_purchase_orders + prc_receiving_records.
  6. fin_departmental_budgets — school_id UUID NOT NULL, academic_year_id UUID FK NOT NULL, department TEXT NOT NULL, budget_category TEXT NOT NULL 6-value CHECK (PERSONNEL, SUPPLIES, EQUIPMENT, CONTRACTED_SERVICES, TRAVEL, OTHER), allocated_amount NUMERIC(12,2) NOT NULL, committed_amount NUMERIC(12,2) DEFAULT 0 (from prc_budget_commitments), spent_amount NUMERIC(12,2) DEFAULT 0, available_amount NUMERIC(12,2) (computed: allocated - committed - spent), approved_by UUID FK. UNIQUE(school_id, academic_year_id, department, budget_category). On prc.po.issued: committed_amount incremented. On pay.payment.received for vendor: committed released, spent incremented.
  7. fin_budget_transfers — school_id UUID NOT NULL, from_budget_id UUID FK(fin_departmental_budgets) NOT NULL, to_budget_id UUID FK(fin_departmental_budgets) NOT NULL, amount NUMERIC(12,2) NOT NULL CHECK(>0), reason TEXT NOT NULL, requested_by UUID FK NOT NULL, approved_by UUID FK, status TEXT NOT NULL DEFAULT 'PENDING' 3-value CHECK (PENDING, APPROVED, REJECTED), transferred_at TIMESTAMPTZ. CHECK(from_budget_id != to_budget_id). On APPROVED: from_budget.allocated decremented, to_budget.allocated incremented atomically.
  8. fin_journal_entry_batches — school_id UUID NOT NULL, batch_name TEXT NOT NULL, description TEXT, entry_count INT NOT NULL DEFAULT 0, total_debits NUMERIC(14,2) NOT NULL DEFAULT 0, total_credits NUMERIC(14,2) NOT NULL DEFAULT 0, is_balanced BOOLEAN (computed: total_debits = total_credits), status TEXT NOT NULL DEFAULT 'DRAFT' 3-value CHECK (DRAFT, POSTED, VOIDED), posted_by UUID FK, posted_at TIMESTAMPTZ. INDEX(school_id, status). On POST: validates is_balanced=true (rejects if not), creates fin_gl_entries for each line item.
  9. fin_journal_entry_lines — batch_id UUID FK NOT NULL, account_id UUID FK(fin_chart_of_accounts) NOT NULL, debit NUMERIC(14,2) DEFAULT 0, credit NUMERIC(14,2) DEFAULT 0, description TEXT. CHECK(debit ≥ 0 AND credit ≥ 0). CHECK(debit = 0 OR credit = 0) — a line is either debit or credit, never both. INDEX(batch_id).
Produces → 9 tables. Migration: 162_prc_catalogues_fin_budgets.sql.

P2-29b: Store Advanced (M67.1)

03Schema (10 tables)
Schema
  1. str_inventory_adjustments — product_id UUID FK(str_products) NOT NULL, adjustment_type TEXT NOT NULL 5-value CHECK (RECOUNT, DAMAGE, THEFT, RETURN_TO_STOCK, WRITE_OFF), quantity_delta INT NOT NULL, reason TEXT NOT NULL, adjusted_by UUID FK NOT NULL. INDEX(product_id, created_at DESC). On INSERT: updates str_products.stock_quantity += quantity_delta. Audit trail for all inventory changes outside of normal sales.
  2. str_promotions — store_id UUID FK(str_stores) NOT NULL, name TEXT NOT NULL, discount_type TEXT NOT NULL 4-value CHECK (PERCENTAGE, FLAT_AMOUNT, BOGO, FREE_SHIPPING), discount_value NUMERIC(10,2) NOT NULL, min_order_amount NUMERIC(10,2), promo_code TEXT, starts_at TIMESTAMPTZ NOT NULL, ends_at TIMESTAMPTZ NOT NULL, max_uses INT, current_uses INT DEFAULT 0, is_active BOOLEAN DEFAULT true. UNIQUE(store_id, promo_code) WHERE promo_code IS NOT NULL. INDEX(store_id, starts_at, ends_at).
  3. str_promotion_products — promotion_id UUID FK NOT NULL, product_id UUID FK(str_products) NOT NULL. UNIQUE(promotion_id, product_id). Junction: which products a promotion applies to (empty = all products).
  4. str_loyalty_config — store_id UUID FK(str_stores) NOT NULL UNIQUE, points_per_dollar INT NOT NULL DEFAULT 1, redemption_rate_cents INT NOT NULL DEFAULT 1 (1 point = 1 cent discount), min_redemption_points INT DEFAULT 100, is_enabled BOOLEAN DEFAULT false. School configures loyalty programme parameters.
  5. str_loyalty_transactions — store_id UUID FK NOT NULL, customer_id UUID FK NOT NULL, transaction_type TEXT NOT NULL 3-value CHECK (EARNED, REDEEMED, ADJUSTMENT), points INT NOT NULL, order_id UUID FK, description TEXT. INDEX(customer_id, created_at DESC). Customer balance = SUM(points) WHERE transaction_type IN (EARNED, ADJUSTMENT) - SUM(points) WHERE transaction_type = REDEEMED.
  6. str_gift_cards — store_id UUID FK(str_stores) NOT NULL, card_code TEXT NOT NULL UNIQUE, initial_balance_cents INT NOT NULL, current_balance_cents INT NOT NULL, purchased_by UUID FK, recipient_email TEXT, status TEXT NOT NULL DEFAULT 'ACTIVE' 3-value CHECK (ACTIVE, DEPLETED, CANCELLED), expires_at DATE. INDEX(card_code). On current_balance_cents = 0: status → DEPLETED.
  7. str_gift_card_transactions — card_id UUID FK NOT NULL, transaction_type TEXT NOT NULL 3-value CHECK (PURCHASE, REDEMPTION, TOP_UP), amount_cents INT NOT NULL, order_id UUID FK, performed_by UUID FK. INDEX(card_id, created_at DESC). On REDEMPTION: atomic decrement current_balance_cents; reject if insufficient.
  8. str_wishlists — customer_id UUID FK NOT NULL, product_id UUID FK(str_products) NOT NULL, notify_on_restock BOOLEAN DEFAULT true. UNIQUE(customer_id, product_id). RestockNotificationWorker: when str_products.stock_quantity goes from 0 to >0, notifies all wishlist entries with notify_on_restock=true.
  9. str_price_schedules — product_id UUID FK(str_products) NOT NULL, scheduled_price NUMERIC(10,2) NOT NULL, effective_from TIMESTAMPTZ NOT NULL, effective_to TIMESTAMPTZ, reason TEXT. INDEX(product_id, effective_from). PriceScheduleWorker: applies scheduled prices at effective_from. Reverts at effective_to if set.
  10. str_category_hierarchy — store_id UUID FK(str_stores) NOT NULL, name TEXT NOT NULL, parent_category_id UUID FK(str_category_hierarchy) nullable (null = top-level), sort_order INT NOT NULL, is_active BOOLEAN DEFAULT true. UNIQUE(store_id, name, parent_category_id). Self-referential hierarchy for product categories. ALTER str_products ADD category_id UUID FK(str_category_hierarchy).
Produces → 10 tables + ALTER str_products ADD category_id. Migration: 163_str_promotions_loyalty.sql. Total P2-29 tables: 19.
04Seed + Services + UI + Tests (P2-29b)
SeedCodeUITest

Services (~24 endpoints): InventoryAdjustmentService (adjust with reason + audit trail), PromotionService (CRUD + promo code validation + max_uses enforcement), LoyaltyService (configure + earn on purchase + redeem at checkout + balance query), GiftCardService (issue + redeem + top-up + balance check + expiry), WishlistService (add/remove + restock notification), PriceScheduleService (CRUD + PriceScheduleWorker), CategoryHierarchyService (CRUD with self-referential tree).
