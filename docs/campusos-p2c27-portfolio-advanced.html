P2-27: Portfolio Advanced

Portfolio sections with drag-reorder organisation, student reflections with prompted self-assessment, teacher and counsellor endorsements with skill tagging, post-secondary readiness pathways with milestone checklists and completion tracking, college application tracking with deadline management, career readiness self-assessments, portfolio templates for grade-level scaffolding, and student resume builder with PDF export. The student’s lifelong record of growth.
May 2026 · 8 Steps · ERD v11 · M26 Portfolio .1 (8 tables) · ACH-002 + ACH-003 · Phase 2 Cycle 27

Plan Overview

Phase 2 Cycle 27 builds the deferred tables from Cycle 24’s M26 Portfolio module — 8 new tables. Cycle 24 built the core portfolio surface (portfolios, portfolio items, portfolio shares, achievements, achievement shares). This cycle adds the structure and depth that makes a portfolio more than a collection of files: organised sections, reflective writing, endorsements from trusted adults, post-secondary readiness tracking, and a resume builder that synthesises the portfolio into a shareable document.

The post-secondary readiness system (ACH-003) is the highest-value addition. Schools define readiness pathways (College Prep, Career & Technical, Arts Conservatory) with milestone checklists. Students track progress against their chosen pathway. Counsellors see at a glance which students are on-track vs at-risk for their post-secondary goals. College application tracking integrates with P2-13’s transcript generation for a complete admissions workflow.

Vertical Slice Deliverable

Student Maya organises her portfolio into 4 sections (Academic Work, Art Portfolio, Community Service, Athletic Highlights) with drag-reorder → adds a reflection to her best English essay: “This essay taught me to structure arguments with evidence. I revised 3 times before I was satisfied.” (prompted: What did you learn? What would you do differently?) → English teacher Mrs Rivera endorses Maya’s portfolio with skills: [Critical Thinking, Written Communication, Perseverance] and comment: “Maya demonstrates exceptional analytical writing” → counsellor assigns Maya to “College Prep” readiness pathway → pathway has 12 milestones: SAT taken (COMPLETED), 3 AP courses (IN_PROGRESS, 2 of 3 done), community service 40hrs (COMPLETED via P2-13 service learning), college essay drafted (NOT_STARTED), 3 teacher recommendations (IN_PROGRESS, 1 of 3), transcript requested (COMPLETED via P2-13), FAFSA filed (NOT_STARTED) → Maya adds 3 target colleges to her application tracker: Stanford (RESEARCHING, deadline Jan 2), MIT (APPLYING, essay submitted), State U (ACCEPTED) → Maya builds resume from portfolio: pulls academic highlights, achievements, service hours, athletic highlight clips, endorsement quotes → exports as PDF for college applications → counsellor views readiness dashboard: Maya 8/12 milestones complete (67%), on-track.

What’s In / What’s Deferred

In scope (8 tables): pfl_portfolio_sections, pfl_reflections, pfl_endorsements, pfl_readiness_pathways, pfl_student_pathway_assignments, pfl_pathway_milestones, pfl_college_applications, pfl_resume_profiles. Functions ACH-002 (Student Portfolio extended) + ACH-003 (Post-Secondary Readiness).

Deferred: AI-generated portfolio summary narrative. Common App / UCAS integration for college applications. Career aptitude assessment integration. Employer portal for career-track students. Portfolio analytics (which items get the most views from share links). Portfolio comparison across academic years. Video portfolio items with transcription. LinkedIn profile sync for graduating students.

Step-by-Step Build Plan

01Sections + Reflections + Endorsements Schema (3 tables)
Schema
  1. pfl_portfolio_sections — portfolio_id UUID FK NOT NULL, title TEXT NOT NULL, description TEXT, sort_order INT NOT NULL, cover_image_s3_key TEXT. UNIQUE(portfolio_id, sort_order). INDEX(portfolio_id). Portfolio items (pfl_portfolio_items) gain a section_id FK (nullable — unsectioned items remain valid). ALTER pfl_portfolio_items ADD section_id UUID FK(pfl_portfolio_sections) nullable.
  2. pfl_reflections — portfolio_item_id UUID FK(pfl_portfolio_items) NOT NULL, student_id UUID FK NOT NULL, prompt TEXT (optional guided prompt: “What did you learn?”, “What would you do differently?”, “How does this connect to your goals?”), reflection_text TEXT NOT NULL, written_at TIMESTAMPTZ NOT NULL. UNIQUE(portfolio_item_id, student_id). Student-owned — only the student can write or edit their own reflections.
  3. pfl_endorsements — portfolio_id UUID FK NOT NULL, endorsed_by UUID FK NOT NULL (teacher or counsellor), endorser_role TEXT NOT NULL 3-value CHECK (TEACHER, COUNSELLOR, MENTOR), skills TEXT[] NOT NULL (tagged skills: Critical Thinking, Communication, Leadership, etc.), comment TEXT NOT NULL, is_visible_on_share BOOLEAN DEFAULT true (student controls whether endorsement appears on shared portfolio), endorsed_at TIMESTAMPTZ NOT NULL. UNIQUE(portfolio_id, endorsed_by). INDEX(portfolio_id). Students cannot endorse themselves or other students.
Produces → 3 tables + ALTER pfl_portfolio_items ADD section_id. Migration: 156_pfl_sections_reflections.sql.
02Post-Secondary Readiness Schema (3 tables)
Schema
  1. pfl_readiness_pathways — school_id UUID NOT NULL, name TEXT NOT NULL, description TEXT, pathway_type TEXT NOT NULL 5-value CHECK (COLLEGE_PREP, CAREER_TECHNICAL, ARTS_CONSERVATORY, MILITARY, GENERAL), is_active BOOLEAN DEFAULT true. UNIQUE(school_id, name). School defines which post-secondary pathways are offered.
  2. pfl_pathway_milestones — pathway_id UUID FK NOT NULL, milestone_name TEXT NOT NULL, description TEXT, category TEXT NOT NULL 6-value CHECK (ACADEMIC, TESTING, SERVICE, APPLICATION, FINANCIAL_AID, OTHER), sort_order INT NOT NULL, is_required BOOLEAN DEFAULT true, auto_check_source TEXT (when set: milestone auto-completes from another module — e.g., “graduation_audit:SERVICE_HOURS” auto-checks when P2-13 service learning requirement is met; “transcript:GENERATED” auto-checks when P2-13 transcript is created). UNIQUE(pathway_id, milestone_name). INDEX(pathway_id, sort_order).
  3. pfl_student_pathway_assignments — student_id UUID FK NOT NULL, pathway_id UUID FK NOT NULL, assigned_by UUID FK NOT NULL (counsellor), assigned_at TIMESTAMPTZ NOT NULL, milestone_statuses JSONB NOT NULL DEFAULT '[]' (array of {milestone_id, status: NOT_STARTED|IN_PROGRESS|COMPLETED, completed_at, notes, progress_detail} — one entry per milestone), overall_progress NUMERIC(5,2) (computed: completed_required / total_required × 100), status TEXT NOT NULL DEFAULT 'ACTIVE' 3-value CHECK (ACTIVE, COMPLETED, WITHDRAWN). UNIQUE(student_id, pathway_id). INDEX(student_id). On milestone_statuses change: recompute overall_progress. Emits pfl.pathway.milestone_completed when a milestone transitions to COMPLETED.
Produces → 3 tables. Migration: 157_pfl_readiness_pathways.sql.
03College Applications + Resume Schema (2 tables)
Schema
  1. pfl_college_applications — student_id UUID FK NOT NULL, college_name TEXT NOT NULL, application_type TEXT NOT NULL 4-value CHECK (EARLY_DECISION, EARLY_ACTION, REGULAR, ROLLING), deadline DATE, status TEXT NOT NULL DEFAULT 'RESEARCHING' 7-value CHECK (RESEARCHING, PREPARING, SUBMITTED, INTERVIEW_SCHEDULED, ACCEPTED, REJECTED, WAITLISTED), essay_s3_key TEXT, recommendation_count INT DEFAULT 0, transcript_sent BOOLEAN DEFAULT false, financial_aid_applied BOOLEAN DEFAULT false, notes TEXT, decision_date DATE. INDEX(student_id, deadline). INDEX(student_id, status). Student-owned with counsellor read access.
  2. pfl_resume_profiles — student_id UUID FK NOT NULL UNIQUE, objective_statement TEXT, skills TEXT[] (aggregated from endorsement skills + self-reported), work_experience JSONB (array of {employer, role, start_date, end_date, description}), extracurriculars JSONB (auto-populated from ext_activity_enrollments if available; manually editable), awards JSONB (auto-populated from pfl_achievements; manually editable), service_hours_total NUMERIC(5,1) (auto-populated from P2-13 sis_service_learning_hours), references JSONB (array of {name, title, relationship, email}), pdf_s3_key TEXT, last_generated_at TIMESTAMPTZ. Student-owned. Resume PDF generated on demand from profile + portfolio data.
Produces → 2 tables. Migration: 158_pfl_college_resume.sql. Total P2-27 tables: 8.

05Portfolio Organisation + Endorsements NestJS Module
Code
  1. PortfolioSectionService — CRUD with drag-reorder. POST /portfolios/:id/sections, PATCH /portfolios/sections/:id (reorder), PATCH /portfolios/items/:itemId (assign item to section via section_id). GET /portfolios/:id (returns sections with items nested, unsectioned items separate).
  2. ReflectionService — POST /portfolios/items/:itemId/reflections (student writes; optional prompt), GET /portfolios/items/:itemId/reflections, PATCH /portfolios/reflections/:id (student edits own only). Reflection prompts configurable via platform_tenant_configs key portfolio_reflection_prompts.
  3. EndorsementService — POST /portfolios/:id/endorsements (teacher/counsellor endorses with skills + comment; students cannot endorse), GET /portfolios/:id/endorsements, PATCH /portfolios/endorsements/:id/visibility (student toggles is_visible_on_share).
Produces → 3 services, ~12 endpoints.
06Readiness + College + Resume NestJS Module
Code
  1. ReadinessPathwayService — CRUD for pathways + milestones. POST /portfolios/pathways/:pathwayId/assign/:studentId (counsellor assigns; initialises milestone_statuses JSONB from pathway milestones). PATCH /portfolios/pathway-assignments/:id/milestones (update individual milestone status in JSONB; recompute overall_progress; emit pfl.pathway.milestone_completed on COMPLETED). GET /portfolios/readiness/:studentId (student’s pathway with milestone checklist). GET /portfolios/readiness/dashboard (counsellor: all students with progress, sortable by at-risk). MilestoneAutoCheckWorker: subscribes to cross-module events (sis.service_learning.approved, sis.transcript.generated) and auto-completes matching milestones.
  2. CollegeApplicationService — CRUD. GET /portfolios/college-applications/:studentId, POST /portfolios/college-applications (student creates), PATCH /portfolios/college-applications/:id (status transitions + essay upload). GET /portfolios/college-applications/deadlines (upcoming deadlines across all students — counsellor view).
  3. ResumeService — GET /portfolios/resume/:studentId, PATCH /portfolios/resume (student updates objective, skills, work experience, references), POST /portfolios/resume/generate-pdf (assembles from resume profile + portfolio data + achievements + service hours + endorsement quotes → generates PDF → stores s3_key). Auto-populate: skills from pfl_endorsements.skills UNION, service_hours from sis_service_learning_hours SUM, awards from pfl_achievements, extracurriculars from ext_activity_enrollments.
Produces → 3 services + 1 worker, ~14 endpoints, 1 Kafka emit. Total P2-27 endpoints: ~26.
07Portfolio Advanced UI
UI
  1. Portfolio Organiser (extends existing portfolio view) — student: drag-create sections, drag items into sections, reorder. Section cover images. Unsectioned items area.
  2. Reflection Writer (inline on portfolio item) — prompted questions with text area. Edit toggle. Teacher sees reflections when viewing student portfolio.
  3. Endorsements (sidebar on portfolio) — teacher/counsellor: endorse button with skill tag selector + comment. Student: toggle visibility per endorsement for shared view. Endorsement cards with skill badges.
  4. Readiness Tracker /portfolios/readiness — student: pathway with milestone checklist (green complete, amber in-progress, gray not started). Progress bar. Counsellor: school-wide dashboard with student list sorted by progress. At-risk students highlighted (<50% with approaching deadlines).
  5. College Application Tracker /portfolios/college — student: college cards with status pills + deadlines. Add college form. Essay upload. Counsellor: all students’ applications with deadline calendar.
  6. Resume Builder /portfolios/resume — student: form with auto-populated fields (skills, awards, service hours, extracurriculars from other modules). Edit any field. Add work experience + references manually. “Generate PDF” button. Preview + download.
Produces → Portfolio organiser, reflections, endorsements, readiness tracker, college applications, resume builder.
08Vertical Slice Integration Test
Test
  1. Sections: Create 3 sections. Assign 2 items to section 1. Reorder sections. Verify sort_order updated. Verify GET returns items nested under sections.
  2. Reflections: Student writes reflection with prompt. Verify UNIQUE(portfolio_item_id, student_id). Another student cannot write on Maya’s item. Student edits own reflection → success. Teacher cannot edit student reflection.
  3. Endorsements: Teacher endorses with 3 skills. Verify UNIQUE(portfolio_id, endorsed_by). Student attempts to endorse → 403. Student toggles visibility off. Verify endorsement hidden on shared portfolio view but visible to student.
  4. Readiness pathway: Counsellor assigns student to pathway. Verify milestone_statuses initialised from milestones. Complete 3 milestones. Verify overall_progress recomputed. Verify pfl.pathway.milestone_completed fires. Auto-check: emit sis.service_learning.approved → verify matching milestone auto-completes.
  5. College applications: Student creates 3 applications. Verify deadline index. Transition RESEARCHING → SUBMITTED → ACCEPTED. Counsellor views all students’ deadlines. Student cannot see other students’ applications.
  6. Resume: Student updates profile. Generate PDF. Verify skills auto-populated from endorsements. Verify service hours from P2-13. Verify awards from pfl_achievements. Verify PDF s3_key stored.
  7. Visibility: Student owns portfolio sections, reflections, college apps, resume. Teacher can endorse + view. Counsellor can assign pathways + view all. Parent sees shared portfolio (with endorsed visibility). Other students cannot access.
Produces → Verified: sections → reflections → endorsements → readiness pathways → college applications → resume builder.
