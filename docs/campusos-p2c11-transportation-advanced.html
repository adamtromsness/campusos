P2-11: Transportation
Advanced

Deep fleet maintenance with repair tracking, parts inventory, and component lifecycle management, fuel logging with efficiency computation, driver hours regulatory compliance with configurable weekly limits, route generation pipeline with constraint profiles and candidate review workflow, GPS vehicle position telemetry for live tracking, and the materialised fleet status dashboard. Sub-Cycle Structure

22 tables is the third-largest cycle in Phase 2. Split into 3 independently shippable sub-cycles: fleet maintenance (the garage), route optimisation (the planning office), and live operations (the dispatch centre). Peer review after all 3 complete.

P2-11a — Fleet Maintenance + Fuel + Driver Hours (8 tables)

Vehicle repairs with vendor tracking + warranty claims, parts inventory with reorder alerting, vehicle component lifecycle (tyres, brakes, batteries) with expected-life tracking, fuel logging with efficiency computation, driver hours regulatory compliance with configurable weekly limits and approaching-limit alerts. No external service dependencies.

P2-11b — Route Generation Pipeline (7 tables)

School-level constraint profiles (max ride time, max stops, walkable radius, arrival buffer), generation requests with full/term/date-range scoping, candidate routes with constraint violation reporting, candidate stops with student assignments, TC review workflow (approve/reject/modify → activate as live trn_routes), ad-hoc trip requests, and contracted route tracking. Requires Scheduling Solver extracted service (stub if not deployed).

P2-11c — GPS Telemetry + Fleet Dashboard (7 tables)

Real-time vehicle position telemetry (TimescaleDB hypertable or RANGE partitioned by timestamp), geofence definitions for schools + stops + zones with enter/exit event logging, ETA computation from position + route, parent live-tracking view, transport dispatch event log, and the materialised rpt_fleet_status dashboard. Requires Transport Dispatch extracted service (stub if not deployed).

P2-11a: Fleet Maintenance + Fuel + Driver Hours

01Schema (8 tables)
Schema
  1. trn_vehicle_repairs — vehicle_id UUID FK(trn_vehicles) NOT NULL, repair_date DATE NOT NULL, mileage_at_repair INT NOT NULL, problem_description TEXT NOT NULL, work_performed TEXT NOT NULL, parts_used JSONB, labour_hours NUMERIC(5,2), total_cost NUMERIC(10,2) NOT NULL, performed_by_type TEXT NOT NULL 2-value CHECK (INTERNAL, EXTERNAL_VENDOR), vendor_account_id UUID (soft to platform_vendor_accounts), warranty_claim BOOLEAN DEFAULT false, invoice_s3_key TEXT. INDEX(vehicle_id, repair_date DESC).
  2. trn_parts_inventory — school_id UUID NOT NULL, part_name TEXT NOT NULL, part_number TEXT, quantity_on_hand INT DEFAULT 0, min_stock_level INT DEFAULT 0, unit_cost NUMERIC(8,2), supplier TEXT, last_restocked_at DATE. INDEX(school_id, quantity_on_hand) WHERE quantity_on_hand ≤ min_stock_level. Emits trn.parts.low when below min_stock_level.
  3. trn_vehicle_components — vehicle_id UUID FK NOT NULL, component_type TEXT NOT NULL 9-value CHECK (TYRE, BRAKE, BATTERY, BELT, HOSE, ALTERNATOR, STARTER, TRANSMISSION, OTHER), installed_date DATE NOT NULL, installed_mileage INT NOT NULL, expected_life_miles INT, expected_life_months INT, warranty_provider TEXT, warranty_expiry_date DATE, status TEXT NOT NULL DEFAULT 'ACTIVE' 3-value CHECK (ACTIVE, REPLACED, FAILED). INDEX(vehicle_id, status) WHERE status='ACTIVE'. Alert: when current_mileage - installed_mileage approaches expected_life_miles.
  4. trn_vehicle_fuel_logs — vehicle_id UUID FK NOT NULL, logged_by UUID FK NOT NULL, log_date DATE NOT NULL, odometer_reading NUMERIC(9,1) NOT NULL, fuel_quantity NUMERIC(7,2) NOT NULL, fuel_cost NUMERIC(8,2), fuel_type TEXT NOT NULL 5-value CHECK (DIESEL, PETROL, ELECTRIC, HYBRID, LPG), refuel_location TEXT. INDEX(vehicle_id, log_date DESC). Fuel efficiency computed: (current_odometer - previous_odometer) / fuel_quantity.
  5. trn_driver_hours_logs — driver_id UUID FK(hr_employees) NOT NULL, run_id UUID FK(trn_route_run_logs) nullable, log_date DATE NOT NULL, duty_start_at TIMESTAMPTZ NOT NULL, duty_end_at TIMESTAMPTZ, driving_minutes INT, break_minutes INT NOT NULL DEFAULT 0, cumulative_weekly_minutes INT (computed on duty_end_at). INDEX(driver_id, log_date DESC). Alert: when cumulative_weekly_minutes approaches jurisdiction-specific limit (configurable).
  6. trn_driver_hours_limits — school_id UUID NOT NULL UNIQUE, weekly_driving_limit_minutes INT NOT NULL DEFAULT 2880 (48 hours default — EU Working Time Directive), daily_driving_limit_minutes INT NOT NULL DEFAULT 600 (10 hours), mandatory_break_after_minutes INT NOT NULL DEFAULT 270 (4.5 hours → 45 min break), jurisdiction TEXT NOT NULL DEFAULT 'US_FEDERAL'. Configurable per school based on local regulations.
  7. trn_repair_categories — school_id UUID, name TEXT NOT NULL, is_safety_critical BOOLEAN DEFAULT false (safety-critical repairs block vehicle dispatch until resolved). UNIQUE(school_id, name).
  8. trn_vehicle_lifecycle — vehicle_id UUID FK NOT NULL UNIQUE, purchase_date DATE, purchase_price NUMERIC(10,2), expected_life_years INT, expected_life_miles INT, depreciation_method TEXT DEFAULT 'STRAIGHT_LINE' 2-value CHECK (STRAIGHT_LINE, DECLINING_BALANCE), current_book_value NUMERIC(10,2), disposal_date DATE, disposal_value NUMERIC(10,2), disposal_method TEXT 4-value CHECK (SOLD, SCRAPPED, TRADED_IN, DONATED) nullable. Fleet replacement planning data.
Produces → 8 tables. Migration: 123_trn_fleet_maintenance.sql.

P2-11b: Route Generation Pipeline

03Schema (7 tables)
Schema
  1. trn_route_constraints — school_id UUID FK NOT NULL, constraint_name TEXT NOT NULL, max_ride_time_minutes INT NOT NULL DEFAULT 45, max_route_mileage NUMERIC(7,2), max_students_per_vehicle INT, required_arrival_buffer_minutes INT NOT NULL DEFAULT 10, max_stops_per_route INT, walkable_radius_metres INT NOT NULL DEFAULT 400, is_active BOOLEAN DEFAULT true. UNIQUE(school_id, constraint_name).
  2. trn_generation_requests — school_id UUID NOT NULL, requested_by UUID FK NOT NULL, request_type TEXT NOT NULL 4-value CHECK (FULL_YEAR, TERM, DATE_RANGE, SINGLE_DATE), academic_year_id UUID FK, term_id UUID FK, date_from DATE, date_to DATE, constraint_id UUID FK(trn_route_constraints) NOT NULL, directions TEXT NOT NULL DEFAULT 'BOTH' 3-value CHECK (AM_ONLY, PM_ONLY, BOTH), status TEXT NOT NULL DEFAULT 'QUEUED' 5-value CHECK (QUEUED, RUNNING, COMPLETED, FAILED, CANCELLED), optimiser_run_id TEXT, routes_generated INT, students_covered INT, students_uncovered INT, error_message TEXT, queued_at TIMESTAMPTZ NOT NULL, started_at TIMESTAMPTZ, completed_at TIMESTAMPTZ. INDEX(school_id, status). Emits trn.generation.completed.
  3. trn_generation_candidates — request_id UUID FK NOT NULL, candidate_name TEXT NOT NULL, direction TEXT NOT NULL 2-value CHECK (AM, PM), vehicle_type_required TEXT NOT NULL 3-value CHECK (BUS, MINIBUS, VAN), total_students INT NOT NULL, total_stops INT NOT NULL, estimated_route_mileage NUMERIC(7,2) NOT NULL, estimated_duration_minutes INT NOT NULL, max_student_ride_time_minutes INT NOT NULL, all_constraints_satisfied BOOLEAN NOT NULL, constraint_violations JSONB, review_status TEXT NOT NULL DEFAULT 'PENDING' 4-value CHECK (PENDING, APPROVED, REJECTED, MODIFIED), reviewed_by UUID FK, reviewed_at TIMESTAMPTZ, approved_route_id UUID FK(trn_routes). INDEX(request_id, review_status).
  4. trn_generation_candidate_stops — candidate_id UUID FK NOT NULL, stop_name TEXT NOT NULL, latitude NUMERIC(9,6) NOT NULL, longitude NUMERIC(9,6) NOT NULL, sequence_order INT NOT NULL, scheduled_time TIME, student_ids UUID[] NOT NULL, student_count INT NOT NULL. INDEX(candidate_id, sequence_order).
  5. trn_adhoc_trip_requests — school_id UUID NOT NULL, requested_by UUID FK NOT NULL, trip_purpose TEXT NOT NULL 5-value CHECK (FIELD_TRIP, ATHLETIC_EVENT, SPECIAL_EVENT, MEDICAL_TRANSPORT, OTHER), trip_date DATE NOT NULL, departure_time TIME, return_time TIME, pickup_location TEXT NOT NULL, destination TEXT NOT NULL, estimated_passengers INT NOT NULL, special_requirements TEXT, linked_event_id UUID (soft to evt_events or ath_games), assigned_vehicle_id UUID FK(trn_vehicles), assigned_driver_id UUID FK(hr_employees), status TEXT NOT NULL DEFAULT 'REQUESTED' 5-value CHECK (REQUESTED, APPROVED, SCHEDULED, COMPLETED, CANCELLED), linked_approval_id UUID FK(wsk_approval_requests). INDEX(school_id, trip_date, status).
  6. trn_contracted_routes — route_id UUID FK(trn_routes) NOT NULL UNIQUE, contractor_id UUID (soft to platform_vendor_accounts), contract_reference TEXT, contract_start_date DATE NOT NULL, contract_end_date DATE NOT NULL, daily_rate NUMERIC(8,2), payment_frequency TEXT DEFAULT 'MONTHLY' 3-value CHECK (WEEKLY, MONTHLY, TERM), performance_rating NUMERIC(2,1). For routes operated by third-party bus companies.
  7. trn_route_change_requests — school_id UUID NOT NULL, student_id UUID FK NOT NULL, submitted_by UUID FK NOT NULL, change_date DATE NOT NULL, change_type TEXT NOT NULL 3-value CHECK (DIFFERENT_STOP, NO_BUS, DIFFERENT_ROUTE), requested_stop_id UUID FK, requested_route_id UUID FK, reason TEXT, status TEXT NOT NULL DEFAULT 'PENDING' 3-value CHECK (PENDING, APPROVED, REJECTED), reviewed_by UUID FK, reviewed_at TIMESTAMPTZ. INDEX(school_id, status) WHERE status='PENDING'. On APPROVED: creates one-day override in trn_student_assignments.

P2-11c: GPS Telemetry + Fleet Dashboard

External Service Dependencies

P2-11c requires the Transport Dispatch extracted service for GPS position ingestion and ETA computation. If not deployed, the schema + service layer can still be built with manual position entry and stubbed ETA computation. The vehicle_positions table is designed for high-frequency writes (every 10-30 seconds per vehicle) — use TimescaleDB hypertable or RANGE partition by timestamp.

05Schema (7 tables)
Schema
  1. trn_vehicle_positions — vehicle_id UUID NOT NULL, latitude NUMERIC(9,6) NOT NULL, longitude NUMERIC(9,6) NOT NULL, speed_kmh NUMERIC(5,1), heading NUMERIC(5,1), recorded_at TIMESTAMPTZ NOT NULL, source TEXT DEFAULT 'GPS' 3-value CHECK (GPS, MANUAL, SIMULATED). RANGE partition by recorded_at DAILY. 7-day hot retention, 90-day cold. High-frequency insert — no UPDATE, no DELETE. INDEX(vehicle_id, recorded_at DESC). This is the highest-volume table in the entire ERD.
  2. trn_geofences — school_id UUID NOT NULL, name TEXT NOT NULL, geofence_type TEXT NOT NULL 4-value CHECK (SCHOOL, STOP, SPEED_ZONE, RESTRICTED_AREA), boundary JSONB NOT NULL (GeoJSON polygon or circle: {type: "circle", center: {lat, lng}, radius_metres} or {type: "polygon", coordinates: [[lat,lng],...]}), speed_limit_kmh INT, is_active BOOLEAN DEFAULT true. UNIQUE(school_id, name).
  3. trn_geofence_events — geofence_id UUID FK NOT NULL, vehicle_id UUID NOT NULL, event_type TEXT NOT NULL 2-value CHECK (ENTER, EXIT), recorded_at TIMESTAMPTZ NOT NULL, speed_at_event NUMERIC(5,1). RANGE partition by recorded_at DAILY. Emits trn.geofence.entered + trn.geofence.exited (parent notification when bus enters school zone).
  4. trn_vehicle_eta — vehicle_id UUID NOT NULL, stop_id UUID FK(trn_stops) NOT NULL, eta TIMESTAMPTZ NOT NULL, computed_at TIMESTAMPTZ NOT NULL, confidence TEXT DEFAULT 'HIGH' 3-value CHECK (HIGH, MEDIUM, LOW). UNIQUE(vehicle_id, stop_id). Upserted every position update. Parent-facing: "Your child's bus is 8 minutes away."
  5. trn_dispatch_events — school_id UUID NOT NULL, vehicle_id UUID, route_id UUID FK, driver_id UUID FK, event_type TEXT NOT NULL 8-value CHECK (ROUTE_STARTED, ROUTE_COMPLETED, DELAY_REPORTED, BREAKDOWN_REPORTED, STUDENT_NO_SHOW, EMERGENCY_STOP, DETOUR, DRIVER_SWAP), event_data JSONB, recorded_at TIMESTAMPTZ NOT NULL, recorded_by UUID FK. INDEX(school_id, recorded_at DESC). Real-time dispatch operations log.
  6. trn_parent_tracking_tokens — student_id UUID FK NOT NULL, route_id UUID FK NOT NULL, token TEXT NOT NULL UNIQUE, expires_at TIMESTAMPTZ NOT NULL, is_active BOOLEAN DEFAULT true. INDEX(token) WHERE is_active=true. Parents access live tracking via a unique token link — no authentication required, but token-scoped to show only their child's bus position.
  7. rpt_fleet_status — vehicle_id UUID FK NOT NULL UNIQUE, school_id UUID NOT NULL, vehicle_registration TEXT NOT NULL, vehicle_status TEXT NOT NULL, days_until_insurance_expiry INT, days_until_registration_expiry INT, days_until_mot_expiry INT, days_until_licence_expiry INT, maintenance_overdue BOOLEAN NOT NULL DEFAULT false, last_incident_date DATE, total_incidents_this_year INT NOT NULL DEFAULT 0, current_route_assignment TEXT, last_position_at TIMESTAMPTZ, fuel_efficiency_last_month NUMERIC(5,2). Materialised nightly by FleetStatusWorker. INDEX(school_id, maintenance_overdue).
Produces → 7 tables. Migration: 125_trn_gps_fleet.sql. Total P2-11 tables: 22.
06Seed + Services + UI + Tests (P2-11c)
SeedCodeUITest
Seed
  1. 50 vehicle positions across 3 vehicles (simulated GPS trail). 3 geofences (1 SCHOOL, 1 STOP, 1 SPEED_ZONE). 5 geofence events. 3 ETA records. 8 dispatch events (ROUTE_STARTED, DELAY_REPORTED, ROUTE_COMPLETED, etc.). 2 parent tracking tokens. 3 fleet status rows (1 maintenance_overdue, 1 insurance expiring in 10 days).
Services (~18 endpoints)
  1. VehiclePositionService — POST /transport/vehicles/:id/position (ingest from GPS device or Transport Dispatch service; high-frequency), GET /transport/vehicles/:id/position/latest, GET /transport/vehicles/:id/position/history (date range).
  2. GeofenceService — CRUD for geofences. GET /transport/geofences. GeofenceWorker: on each position update, checks all active geofences; on boundary cross → creates trn_geofence_events + emits Kafka events.
  3. ETAService — GET /transport/routes/:id/eta (all stop ETAs for a route), GET /transport/stops/:id/eta (single stop ETA). Computed from latest vehicle position + route geometry + historical speed.
  4. DispatchService — POST /transport/dispatch/events (driver/dispatcher logs event), GET /transport/dispatch/events (today's dispatch log).
  5. ParentTrackingService — GET /transport/tracking/:token (parent: bus position + ETA for their child's stop — unauthenticated, token-scoped). POST /transport/tracking/tokens (system generates on route assignment).
  6. FleetStatusWorker — Nightly: materialises rpt_fleet_status from trn_vehicles + trn_vehicle_documents + trn_vehicle_maintenance + trn_vehicle_fuel_logs + trn_vehicle_positions. GET /transport/fleet/status (TC dashboard).
UI
  1. Live Tracking Map /transport/tracking — TC: all vehicles on map with real-time positions. Click vehicle → route overlay + stop ETAs + dispatch events. Geofence visualization.
  2. Parent Tracking View /transport/tracking/:token — parent: single bus on map with ETA countdown to their child's stop. No authentication required.
  3. Fleet Status Dashboard /transport/fleet — TC: vehicle grid with status pills (active/maintenance/expired docs). Maintenance overdue, insurance expiring, fuel efficiency trends. One-stop fleet health view.
  4. Dispatch Console /transport/dispatch — TC: today's routes with status (started/delayed/completed). Event log feed. Breakdown/emergency response actions.
Produces → P2-11c: 7 tables, ~18 endpoints, 2 workers, 2 Kafka emits. Create all peer review docs after this sub-cycle. Total P2-11 endpoints: ~62.
