Sub-Cycle Structure

15 tables split into 2 independently shippable sub-cycles. P2-10a covers recipes + full inventory management (the kitchen ops backbone). P2-10b covers pre-orders + production records + staff meals + the health-to-food allergen consumer (the service delivery layer). Peer review happens after both are complete.

P2-10a — Recipes + Inventory (8 tables)

Recipe definitions linked to menu items with ingredient-level allergen auto-computation and cost-per-serving calculation, multi-group inventory pools (Main Kitchen, Breakfast, Concessions), inventory items with reorder thresholds, current stock levels, immutable stock movement transactions (RANGE partitioned monthly), and inter-group transfer requests with approval workflow.

P2-10b — Pre-Orders + Production + Staff + Allergen Consumer (7 tables)

Student meal pre-ordering with time-windowed selection and allergen cross-check, pre-order production planning reports (JSONB item totals + dietary breakdown), USDA production records for federal compliance documentation, staff meal accounts with payroll deduction, and the AllergenAlertConsumer that wires hlth.allergy_alert.changed into fds_student_allergen_alerts live (replacing the seed-only sync from Cycle 20).

P2-10a: Recipes + Inventory

01Schema (8 tables)
Schema
  1. fds_recipes — school_id UUID NOT NULL, name TEXT NOT NULL, category TEXT NOT NULL 9-value CHECK (ENTREE, SIDE, VEGETABLE, FRUIT, GRAIN, DAIRY, BEVERAGE, SNACK, DESSERT), serving_yield INT NOT NULL, prep_time_minutes INT, cook_time_minutes INT, instructions TEXT, allergens TEXT[] (auto-computed: UNION of all ingredient allergens), cost_per_serving NUMERIC(6,2) (auto-computed: SUM ingredient costs / serving_yield), menu_item_id UUID FK(fds_menu_items) nullable, is_active BOOLEAN DEFAULT true. INDEX(school_id, category).
  2. fds_recipe_ingredients — recipe_id UUID FK NOT NULL, inventory_item_id UUID FK(fds_inventory_items) nullable (linked when ingredient maps to a tracked inventory item), ingredient_name TEXT NOT NULL, quantity NUMERIC(8,3) NOT NULL, unit TEXT NOT NULL, allergens TEXT[] DEFAULT '{}', unit_cost NUMERIC(6,3), notes TEXT. UNIQUE(recipe_id, ingredient_name). On INSERT/UPDATE: recompute parent recipe.allergens + recipe.cost_per_serving.
  3. fds_inventory_groups — school_id UUID NOT NULL, name TEXT NOT NULL, group_type TEXT NOT NULL 6-value CHECK (LUNCH, BREAKFAST, SNACK, CONCESSIONS, CATERING, OTHER), location TEXT, is_active BOOLEAN DEFAULT true, managed_by UUID FK(hr_employees). UNIQUE(school_id, name).
  4. fds_inventory_items — school_id UUID NOT NULL, name TEXT NOT NULL, unit TEXT NOT NULL, category TEXT NOT NULL 9-value CHECK (PROTEIN, DAIRY, GRAIN, VEGETABLE, FRUIT, CONDIMENT, BEVERAGE, PACKAGING, OTHER), allergen_codes TEXT[] DEFAULT '{}', reorder_threshold NUMERIC(8,2), preferred_vendor_id UUID (soft to fin_suppliers), unit_cost NUMERIC(8,4). UNIQUE(school_id, name).
  5. fds_inventory_levels — group_id UUID FK NOT NULL, item_id UUID FK NOT NULL, quantity_on_hand NUMERIC(10,3) NOT NULL DEFAULT 0 CHECK(≥0), last_counted_at TIMESTAMPTZ. UNIQUE(group_id, item_id). INDEX(group_id, quantity_on_hand) WHERE quantity_on_hand=0. When quantity_on_hand ≤ reorder_threshold: emit fds.inventory.low.
  6. fds_inventory_transactions — IMMUTABLE. school_id UUID NOT NULL, group_id UUID FK NOT NULL, item_id UUID FK NOT NULL, transaction_type TEXT NOT NULL 7-value CHECK (RECEIPT, USAGE, WASTE, ADJUSTMENT, TRANSFER_IN, TRANSFER_OUT, STOCKTAKE), quantity_delta NUMERIC(10,3) NOT NULL (positive for IN, negative for OUT), performed_by UUID FK NOT NULL, transaction_at TIMESTAMPTZ NOT NULL, transfer_reference_id UUID (links paired TRANSFER_OUT + TRANSFER_IN), related_session_id UUID FK(fds_meal_service_sessions), notes TEXT. NO UPDATE, NO DELETE. RANGE partition by transaction_at MONTHLY, 3-year retention. INDEX(group_id, item_id, transaction_at DESC).
  7. fds_inventory_transfer_requests — school_id UUID NOT NULL, from_group_id UUID FK NOT NULL, to_group_id UUID FK NOT NULL, item_id UUID FK NOT NULL, quantity NUMERIC(10,3) NOT NULL, reason TEXT, status TEXT NOT NULL DEFAULT 'PENDING' 5-value CHECK (PENDING, APPROVED, COMPLETED, REJECTED, CANCELLED), requested_by UUID FK NOT NULL, reviewed_by UUID FK, reviewed_at TIMESTAMPTZ, completed_at TIMESTAMPTZ, transfer_reference_id UUID (set on COMPLETED). INDEX(school_id, status) WHERE status IN ('PENDING','APPROVED'). On COMPLETED: creates paired TRANSFER_OUT + TRANSFER_IN fds_inventory_transactions rows with shared transfer_reference_id.
  8. fds_staff_meal_accounts — employee_id UUID FK(hr_employees) NOT NULL UNIQUE, school_id UUID, balance NUMERIC(8,2) DEFAULT 0, deduction_method TEXT NOT NULL DEFAULT 'PAYROLL' 3-value CHECK (PAYROLL, PREPAID, COMPLIMENTARY), daily_limit NUMERIC(6,2). Staff meal charges deducted via payroll integration (P2-4) or prepaid balance.
Produces → 8 tables. Migration: 121_fds_recipes_inventory.sql.

SeedCodeUITest
Seed

Auto-computed allergens + cost_per_serving. 2 inventory groups (Main Kitchen LUNCH, Breakfast Programme BREAKFAST). 10 inventory items across categories. 10 inventory levels. 15 inventory transactions (mix of RECEIPT, USAGE, WASTE, 1 paired TRANSFER). 1 transfer request (COMPLETED). 2 staff meal accounts (1 PAYROLL, 1 COMPLIMENTARY).

On ingredient change: recompute allergens (UNION of all ingredient allergens) + cost_per_serving (SUM unit_cost × quantity / serving_yield). GET /food-service/recipes/:id/scaling (given target servings, compute ingredient quantities).
  2. InventoryService — GET /food-service/inventory/groups, POST /food-service/inventory/groups. GET /food-service/inventory/items, POST /food-service/inventory/items. GET /food-service/inventory/levels/:groupId (current stock). POST /food-service/inventory/receive (RECEIPT transaction + level increment). POST /food-service/inventory/usage (USAGE transaction + level decrement). POST /food-service/inventory/waste (WASTE + decrement). POST /food-service/inventory/stocktake (STOCKTAKE adjustment to actual count). All create IMMUTABLE fds_inventory_transactions rows. Emits fds.inventory.low when level hits reorder_threshold.
  3. TransferService — POST /food-service/inventory/transfers (request), PATCH /food-service/inventory/transfers/:id (approve/reject), POST /food-service/inventory/transfers/:id/complete (creates paired TRANSFER_OUT + TRANSFER_IN transactions with shared reference). GET /food-service/inventory/transfers.
  4. StaffMealService — GET /food-service/staff-meals/:employeeId, POST /food-service/staff-meals (create account), POST /food-service/staff-meals/:id/charge (POS charges staff meal). GET /food-service/staff-meals/payroll-deductions (monthly summary for payroll integration).
UI
  1. Recipe Manager /food-service/recipes — recipe list with category filter. Per-recipe: ingredients editor (add/remove/edit quantities), auto-computed allergen tags, cost breakdown, scaling calculator.
  2. Inventory Dashboard /food-service/inventory — group selector. Per-group: item list with current levels, colour-coded (green=good, amber=low, rose=out). Receive/usage/waste/stocktake forms. Transfer request form + approval queue.
  3. Staff Meals /food-service/staff-meals — account list. Charge form. Monthly deduction report for payroll.
Produces → P2-10a: 8 tables, ~22 endpoints. Independently shippable.

P2-10b: Pre-Orders + Production + Allergen Consumer

03Schema (7 tables)
Schema
  1. fds_preorder_windows — school_id UUID, opens_at TIMESTAMPTZ, closes_at TIMESTAMPTZ, service_date DATE, meal_type TEXT NOT NULL 4-value CHECK (BREAKFAST, LUNCH, DINNER, SNACK). UNIQUE(school_id, service_date, meal_type). Defines when students/parents can pre-order for a given service date.
  2. fds_meal_preorders — student_id UUID FK NOT NULL, preorder_window_id UUID FK NOT NULL, ordered_by UUID FK NOT NULL (student or parent), status TEXT NOT NULL DEFAULT 'PENDING' 3-value CHECK (PENDING, CONFIRMED, CANCELLED), allergen_check_passed BOOLEAN NOT NULL DEFAULT true (false if any selected item conflicts with fds_student_allergen_alerts — order blocked until conflict resolved). UNIQUE(student_id, preorder_window_id).
  3. fds_meal_preorder_items — preorder_id UUID FK NOT NULL, menu_item_id UUID FK(fds_menu_items) NOT NULL, quantity INT DEFAULT 1. UNIQUE(preorder_id, menu_item_id).
  4. fds_preorder_production_reports — school_id UUID, service_date DATE, meal_type TEXT NOT NULL, generated_at TIMESTAMPTZ, report_data JSONB NOT NULL (item totals per menu item, dietary restriction breakdown, estimated ingredient usage from recipes, staffing estimate). UNIQUE(school_id, service_date, meal_type). Generated from aggregating confirmed pre-orders.
  5. fds_production_records — school_id UUID NOT NULL, meal_service_date DATE NOT NULL, meal_type TEXT NOT NULL, menu_item_id UUID FK(fds_menu_items) NOT NULL, recipe_id UUID FK(fds_recipes), quantity_prepared INT NOT NULL, quantity_served INT NOT NULL, quantity_leftover INT DEFAULT 0, quantity_wasted INT DEFAULT 0, meets_meal_pattern BOOLEAN NOT NULL. UNIQUE(school_id, meal_service_date, meal_type, menu_item_id). USDA compliance: documents what was prepared vs served vs wasted.
  6. fds_usda_reimbursement_claims — school_id UUID, academic_year_id UUID FK, month_year DATE, free_meals_count INT, reduced_meals_count INT, paid_meals_count INT, reimbursement_amount NUMERIC(10,2), status TEXT NOT NULL DEFAULT 'DRAFT' 4-value CHECK (DRAFT, SUBMITTED, APPROVED, REJECTED), submitted_at TIMESTAMPTZ. Monthly federal reimbursement claims for NSLP/SBP.
  7. fds_eligibility_applications — school_id UUID NOT NULL, student_id UUID FK NOT NULL, academic_year_id UUID FK, submitted_by UUID FK NOT NULL (guardian), household_size INT NOT NULL, household_income NUMERIC(10,2), income_frequency TEXT NOT NULL 4-value CHECK (WEEKLY, BIWEEKLY, MONTHLY, ANNUAL), snap_benefits BOOLEAN DEFAULT false, tanf_benefits BOOLEAN DEFAULT false, foster_child BOOLEAN DEFAULT false, migrant_worker BOOLEAN DEFAULT false, homeless_status BOOLEAN DEFAULT false, status TEXT NOT NULL DEFAULT 'SUBMITTED' 4-value CHECK (SUBMITTED, APPROVED, DENIED, EXPIRED), determined_category TEXT 4-value CHECK (FREE, REDUCED, PAID, DENIED) nullable, effective_from DATE, effective_to DATE, reviewed_by UUID FK, reviewed_at TIMESTAMPTZ. INDEX(school_id, academic_year_id, status).
Produces → 7 tables. Migration: 122_fds_preorders_production.sql. Total P2-10 tables: 15.
04Seed + Services + UI + Tests + Allergen Consumer (P2-10b)
SeedCodeUITest
Seed
  1. 2 preorder windows (tomorrow LUNCH open, next week BREAKFAST opens in 3 days). 5 preorders (3 CONFIRMED, 1 PENDING, 1 CANCELLED) with 12 preorder items. 1 production report (JSONB with item totals). 3 production records (today's lunch service). 1 USDA reimbursement claim (DRAFT). 2 eligibility applications (1 APPROVED FREE, 1 SUBMITTED).
Services (~18 endpoints)
  1. PreorderService — GET /food-service/preorders/windows (open windows for student/parent), POST /food-service/preorders (student/parent selects items within window; ALLERGEN CROSS-CHECK: cross-reference selected menu_item allergen_codes against fds_student_allergen_alerts — CRITICAL severity blocks, WARNING alerts; allergen_check_passed set accordingly), PATCH /food-service/preorders/:id (cancel), POST /food-service/preorders/windows (admin creates), POST /food-service/preorders/production-report (generate: aggregates confirmed preorders into item totals + dietary breakdown + ingredient usage from recipes).
  2. ProductionRecordService — POST /food-service/production-records (FSM records what was prepared/served/wasted per item; links to recipe if available), GET /food-service/production-records (date range filter for USDA reporting).
  3. USDAClaimService — POST /food-service/usda-claims (generate monthly claim from fds_meal_transactions aggregated by eligibility category), GET /food-service/usda-claims, PATCH /food-service/usda-claims/:id (submit).
  4. EligibilityService — POST /food-service/eligibility (parent submits), GET /food-service/eligibility (admin: all; parent: own), PATCH /food-service/eligibility/:id (admin reviews: APPROVED with category + effective dates → updates fds_student_dietary_profiles.free_meal_eligible).
  5. AllergenAlertConsumer — KAFKA CONSUMER KEYSTONE. Subscribes to dev.hlth.allergy_alert.changed. On event: upserts fds_student_allergen_alerts (the POS read model from Cycle 20) with current allergen data from the health module. This replaces the seed-only sync from Cycle 20 with live event-driven sync. Emits fds.allergen_alert.synced.
UI
  1. Pre-Order Portal /food-service/preorders — student/parent: browse today's menu for open preorder windows. Select items. Allergen warning if conflict detected. Confirm order.
  2. Production Planning /food-service/production — FSM: generate production report from preorders. View item totals + dietary breakdown. Record actual production (prepared/served/leftover/wasted). USDA compliance indicator.
  3. USDA Claims /food-service/usda — admin: monthly claim generator. Free/reduced/paid meal counts. Reimbursement calculation. Submit workflow.
  4. Eligibility Manager /food-service/eligibility — parent: application form (household income, benefits). Admin: review queue. Approval with category assignment.
Produces → P2-10b: 7 tables, ~18 endpoints, 1 new Kafka consumer (AllergenAlertConsumer). Create all peer review docs after this sub-cycle. Total P2-10 endpoints: ~40.
