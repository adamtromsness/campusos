Cycle 25: Publications

Recurring publication series with numbered editions, collaborative content authoring with multi-section publications and contributor attribution, role-based approval workflow (ADR-035: staff publish directly, students require approval), targeted distribution lists with rule-based audience resolution, series subscriptions with opt-out, and delivery tracking. The school newsletter as a first-class platform object. Closes Wave 5.
May 2026 · 10 Steps · ERD v11 · M42 Publications (15 tables — 11 core in scope, 4 deferred) · ADR-035 · Closes Wave 5

Plan Overview

Cycle 25 builds the M42 Publications module — 11 of the 15 ERD tables. This is the final Academic Advanced module, closing Wave 5. Publications turns the school newsletter, principal's bulletin, student magazine, and athletic programme into structured, version-tracked, collaboratively-authored platform objects with targeted distribution — replacing the patchwork of Mailchimp, Google Docs, and BCC'd email blasts that schools use today.

The module spans 3 domains: (1) series + editions + publications with multi-section content structure and collaborator roles, (2) sections with contributor attribution and the section-level content model, and (3) distribution lists with rule-based audience targeting, per-recipient delivery tracking, and series subscriptions with opt-out. Per ADR-035, staff-authored publications publish directly; student-authored contributions require approval via the Cycle 7 wsk_approval_requests integration.

Vertical Slice Deliverable

Admin creates "The Weekly Eagle" newsletter series (NEWSLETTER, WEEKLY) → editor creates Edition #12 "Spring 2026" with cover image + editorial note → adds 4 sections: "Principal's Message" (Rivera), "Sports Roundup" (Coach Martinez), "Student Spotlight" (Maya's submission — requires approval per ADR-035), "Upcoming Events" (admin) → Rivera contributes to the "Principal's Message" section as EDITOR → Maya submits "Student Spotlight" content as CONTRIBUTOR → admin approves Maya's section via wsk_approval_requests → edition status: DRAFT → IN_REVIEW → APPROVED → PUBLISHED → distribution list targets ALL_PARENTS + ALL_STAFF via rules → audience resolved to ~200 recipients → pub.publication.published fires → Cycle 14 Communications fans out delivery → delivery tracking shows 180 delivered, 150 opened → David Chen (parent) receives the newsletter, reads it, clicks "Unsubscribe from The Weekly Eagle" → subscription status flips to UNSUBSCRIBED → next edition skips David.

Step-by-Step Build Plan

01Series + Editions + Publications Schema
Schema

Recurring publication series (the brand), numbered editions (specific issues), individual publications (content documents that may be standalone or belong to an edition), and collaborator roles.

Tables (4)
  1. pub_series — school_id UUID, title TEXT NOT NULL, description TEXT, publication_type TEXT NOT NULL 6-value CHECK (NEWSLETTER, BULLETIN, ANNOUNCEMENT, MAGAZINE, PROGRAM, REPORT), frequency TEXT NOT NULL 7-value CHECK (DAILY, WEEKLY, FORTNIGHTLY, MONTHLY, TERMLY, ANNUAL, IRREGULAR), series_logo_s3_key TEXT, is_active BOOLEAN DEFAULT true, created_by UUID FK. UNIQUE(school_id, title). A series is the container; editions are instances.
  2. pub_edition — series_id UUID FK NOT NULL, edition_number INT NOT NULL (auto-incremented per series), edition_label TEXT (e.g., "Vol. 3 Issue 12"), theme TEXT, cover_image_s3_key TEXT, editorial_note TEXT, status TEXT NOT NULL DEFAULT 'DRAFT' 5-value CHECK (DRAFT, IN_REVIEW, APPROVED, PUBLISHED, ARCHIVED), scheduled_publish_at TIMESTAMPTZ, published_at TIMESTAMPTZ, editor_id UUID FK, approval_request_id UUID nullable (soft to wsk_approval_requests per ADR-035). UNIQUE(series_id, edition_number).
  3. pub_publications — school_id UUID, title TEXT NOT NULL, publication_type TEXT NOT NULL same 6-value CHECK, series_id UUID FK nullable (NULL for standalone), edition_id UUID FK nullable, created_by UUID FK, status TEXT NOT NULL DEFAULT 'DRAFT' 5-value CHECK (DRAFT, IN_REVIEW, APPROVED, PUBLISHED, ARCHIVED), scheduled_publish_at TIMESTAMPTZ, published_at TIMESTAMPTZ, approval_request_id UUID nullable (soft to wsk_approval_requests). CHECK(edition_id IS NULL OR series_id IS NOT NULL). INDEX(school_id, status, published_at DESC).
  4. pub_publication_collaborators — publication_id UUID FK NOT NULL, user_id UUID FK NOT NULL (soft to platform_users), role TEXT NOT NULL 4-value CHECK (EDITOR, CONTRIBUTOR, REVIEWER, VIEWER), invited_by UUID FK, invited_at TIMESTAMPTZ, accepted_at TIMESTAMPTZ. UNIQUE(publication_id, user_id).
Produces → 4 new tables. Migration: 077_pub_series_publications.sql.
02Sections + Contributors + Comments Schema
Schema

Content sections within a publication (each section is a named content block with an owner), contributor attribution per section, and threaded editorial comments for collaborative review.

Tables (3)
  1. pub_sections — publication_id UUID FK NOT NULL, title TEXT NOT NULL, body TEXT, section_type TEXT NOT NULL DEFAULT 'ARTICLE' 5-value CHECK (ARTICLE, ANNOUNCEMENT, PHOTO_GALLERY, CALENDAR, CUSTOM), owner_id UUID FK NOT NULL (the person responsible for this section's content), sort_order INT NOT NULL, is_approved BOOLEAN DEFAULT false (per ADR-035: student-owned sections require admin approval). INDEX(publication_id, sort_order).
  2. pub_section_contributors — section_id UUID FK NOT NULL, contributor_id UUID FK NOT NULL (soft to platform_users), contribution_note TEXT, contributed_at TIMESTAMPTZ. UNIQUE(section_id, contributor_id). Attribution tracking beyond the section owner.
  3. pub_section_comments — section_id UUID FK NOT NULL, author_id UUID FK NOT NULL, body TEXT NOT NULL, is_resolved BOOLEAN DEFAULT false, resolved_by UUID nullable, resolved_at TIMESTAMPTZ, parent_comment_id UUID FK nullable (threaded replies). INDEX(section_id, is_resolved, created_at ASC).
Produces → 3 new tables. Migration: 078_pub_sections.sql.
03Distribution + Subscriptions Schema
Schema

Distribution lists with rule-based audience targeting, per-recipient delivery tracking with open/bounce status, and series-level subscriptions with opt-out.

Tables (4)
  1. pub_distribution_lists — publication_id UUID FK NOT NULL, list_name TEXT NOT NULL, is_active BOOLEAN DEFAULT true. A publication can have multiple lists combined at send time.
  2. pub_distribution_rules — distribution_list_id UUID FK NOT NULL, rule_type TEXT NOT NULL 4-value CHECK (ROLE, GRADE, CLASS, GROUP_MEMBERSHIP), rule_value TEXT NOT NULL (e.g., "PARENT", "5", class UUID, group UUID). Multiple rules per list are OR'd — matching any rule includes the recipient.
  3. pub_distribution_recipients — Pre-computed delivery rows (same pattern as msg_announcement_audiences). publication_id UUID FK NOT NULL, recipient_id UUID NOT NULL (soft to platform_users), delivery_status TEXT NOT NULL DEFAULT 'PENDING' 4-value CHECK (PENDING, DELIVERED, OPENED, BOUNCED), delivered_at TIMESTAMPTZ, opened_at TIMESTAMPTZ. UNIQUE(publication_id, recipient_id). INDEX(publication_id, delivery_status).
  4. pub_series_subscriptions — series_id UUID FK NOT NULL, subscriber_id UUID NOT NULL (soft to platform_users), status TEXT NOT NULL DEFAULT 'SUBSCRIBED' 2-value CHECK (SUBSCRIBED, UNSUBSCRIBED), subscribed_at TIMESTAMPTZ, unsubscribed_at TIMESTAMPTZ. UNIQUE(series_id, subscriber_id). Unsubscribed recipients are excluded from distribution even when rules match.
Produces → 4 new tables. Migration: 079_pub_distribution.sql. Total Cycle 25 tables: 11.
