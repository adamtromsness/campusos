P2-15: Analytics
Read Models

18 domain-specific materialised read models covering every module built in Phases 1 and 2, wired to live Kafka consumers replacing the nightly batch materialisation from Cycle 29. Each read model has a documented source topic, owning worker, rebuild procedure, and single-writer guarantee. All queries route to the read replica — zero impact on the primary database. Pre-split into 2 sub-cycles.
May 2026 · 2 Sub-Cycles · ERD v11 · M110 Analytics .1 (18 tables) · RPT-001..003 · Phase 2 Cycle 15

Design Principles

Read Model Ownership Rules (Architecture Review §19)

Single-writer: Each rpt_* table is written by exactly one worker. No table has two writers. Consumer-owned: The analytics module owns all rpt_* tables. Source modules never write to or read from rpt_* tables (CI enforced). Idempotent: Every worker uses INSERT ON CONFLICT DO UPDATE on the table's UNIQUE constraint. Replaying the same event produces the same result. Replica-routed: All rpt_* reads go to the read replica, never the primary. Rebuildable: Any rpt_* table can be fully rebuilt by resetting the Kafka consumer group offset and replaying events from the beginning. No rpt_* table stores data that can't be reconstructed from events.

Sub-Cycle Structure

P2-15a — Operations Read Models (9 tables + 9 Kafka consumers)

Read models for operational modules: procurement, store, food service (meal counts + NSLP), transportation (ridership), facilities (condition + KPI), IT fleet, library circulation, communications metrics.

P2-15b — Engagement + Performance Read Models (9 tables + 9 Kafka consumers)

Read models for engagement and performance modules: enrolment funnel, athletics season, officials marketplace, game results, groups engagement, publications distribution, extracurricular services, wellbeing trends, event revenue. Plus: live Kafka consumer wiring to replace nightly batch for all 18 read models.
