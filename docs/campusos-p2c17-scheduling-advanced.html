P2-17: Scheduling Advanced

Rotation calendars with A/B week and multi-day cycle support, automated constraint-solver schedule generation with hard/soft constraint separation and candidate review workflow (ADR-053 + ADR-060), student subject choice collection for demand-driven scheduling, exam scheduling with room-level seating and accommodation enforcement, co-teaching arrangements with five teaching models, pull-out intervention scheduling with attendance pre-marking, cross-school staff assignments with person-level double-booking prevention, and complex cover arrangements with class splits and supervised self-study. The most algorithmically complex module in CampusOS. Closes Wave C.
May 2026 · 2 Sub-Cycles · ERD v11 · M22 Scheduling .1 (20 tables) · ADR-053 + ADR-060 · SCH-001..005 · Phase 2 Cycle 17 · Closes Wave C

Sub-Cycle Structure

20 tables split into 2 independently shippable sub-cycles along the ADR-053 expansion boundaries. P2-17a is the schedule generation engine (how the master timetable is created). P2-17b is the daily operations layer (how the schedule handles exams, co-teaching, pull-outs, visiting staff, and complex cover on any given day). Peer review after both complete.

P2-17a — Rotation Calendars + Schedule Generation + Subject Choices (10 tables)

Rotation cycle definitions with A/B week and 6-day rotation, rotation calendar mapping dates to rotation days, constraint profiles (hard: teacher/room double-booking, student concurrency, room capacity, cross-school max periods; soft: consecutive period avoidance, teacher preferences, student free period minimisation), student subject choices for demand input, scheduling requests with solver algorithm selection (CP-SAT ≤300 sections, heuristic >300), candidate solutions with constraint violation reporting, candidate slots with clash detection, promotion lifecycle (DRAFT → REVIEWED → APPROVED → ACTIVE), and room change requests.

P2-17b — Exams + Co-Teaching + Pull-Out + Cross-School + Complex Cover (10 tables)

Exam session scheduling with room assignment junction table, student seating with accommodation enforcement from sis_student_active_accommodations, invigilator assignment, co-teaching arrangements with five models (team, one-teach-one-support, station rotation, parallel, alternative), pull-out interventions with attendance pre-marking as PULL_OUT, cross-school staff assignments with person-level EXCLUSION constraint for double-booking prevention, complex cover arrangements with per-class disposition (substitute, merge, split, self-study), and split-class student assignment junction table.

P2-17a: Rotation + Schedule Generation

01Schema (10 tables)
Schema
  1. sch_rotation_cycles — school_id UUID NOT NULL, name TEXT NOT NULL, cycle_length INT NOT NULL (2 = A/B week, 6 = 6-day rotation, etc.), academic_year_id UUID FK, is_active BOOLEAN DEFAULT true. UNIQUE(school_id, name).
  2. sch_rotation_calendar — rotation_cycle_id UUID FK NOT NULL, calendar_date DATE NOT NULL, rotation_day INT NOT NULL (1..cycle_length), is_school_day BOOLEAN DEFAULT true. UNIQUE(rotation_cycle_id, calendar_date). Admin maintains; adjusted for closures.
  3. sch_scheduling_constraints — school_id UUID NOT NULL, academic_year_id UUID FK, name TEXT NOT NULL, hard_constraints JSONB NOT NULL (H1: teacher no double-book, H2: room no double-book, H3: student no concurrency, H4: class ≤ room capacity, H5: cross-school max periods), soft_constraints JSONB NOT NULL (S1..S5 with weights), is_active BOOLEAN DEFAULT true. UNIQUE(school_id, academic_year_id, name).
  4. sch_student_subject_choices — student_id UUID FK NOT NULL, academic_year_id UUID FK NOT NULL, course_id UUID FK(sis_courses) NOT NULL, preference_rank INT, is_required BOOLEAN DEFAULT false, submitted_at TIMESTAMPTZ. UNIQUE(student_id, academic_year_id, course_id). Demand input for the solver.
  5. sch_scheduling_requests — school_id UUID NOT NULL, academic_year_id UUID FK, constraint_id UUID FK NOT NULL, section_count_at_submission INT NOT NULL, solver_algorithm TEXT NOT NULL 2-value CHECK (CP_SAT, HEURISTIC) (CP_SAT ≤300, HEURISTIC >300 per ADR-060), status TEXT NOT NULL DEFAULT 'QUEUED' 5-value CHECK (QUEUED, RUNNING, COMPLETED, FAILED, CANCELLED), requested_by UUID FK NOT NULL, candidates_generated INT, queued_at TIMESTAMPTZ, started_at TIMESTAMPTZ, completed_at TIMESTAMPTZ, error_message TEXT. INDEX(school_id, status). Emits sch.generation.completed.
  6. sch_scheduling_candidates — request_id UUID FK NOT NULL, candidate_name TEXT, solver_seed TEXT (for heuristic reproducibility), total_slots INT, total_clashes INT, all_constraints_satisfied BOOLEAN, constraint_violations JSONB, soft_constraint_score NUMERIC(8,2), review_status TEXT NOT NULL DEFAULT 'PENDING' 4-value CHECK (PENDING, APPROVED, REJECTED, MODIFIED). INDEX(request_id, review_status).
  7. sch_scheduling_candidate_slots — candidate_id UUID FK NOT NULL, class_id UUID FK, teacher_id UUID FK, room_id UUID FK, period_id UUID FK, day_of_week SMALLINT, rotation_day SMALLINT, has_clash BOOLEAN DEFAULT false, clash_description TEXT. INDEX(candidate_id). On APPROVED: promoted to sch_timetable_slots.
  8. sch_room_change_requests — school_id UUID NOT NULL, timetable_slot_id UUID FK NOT NULL, requested_by UUID FK NOT NULL, current_room_id UUID FK, requested_room_id UUID FK NOT NULL, reason TEXT, status TEXT NOT NULL DEFAULT 'PENDING' 3-value CHECK (PENDING, APPROVED, REJECTED), reviewed_by UUID FK. INDEX(school_id, status).
  9. sch_scheduling_activation_log — candidate_id UUID FK NOT NULL, slots_promoted INT, slots_skipped INT, activated_by UUID FK NOT NULL, activated_at TIMESTAMPTZ NOT NULL. INDEX(candidate_id). Audit trail for promotion.
  10. sch_subject_choice_windows — school_id UUID NOT NULL, academic_year_id UUID FK, opens_at TIMESTAMPTZ NOT NULL, closes_at TIMESTAMPTZ NOT NULL, target_grade_levels TEXT[], is_active BOOLEAN DEFAULT true. UNIQUE(school_id, academic_year_id). Controls when students can submit subject choices.
Produces → 10 tables + ALTER sch_periods ADD rotation_day SMALLINT. Migration: 134_sch_rotation_generation.sql.
02Seed + Services + UI + Tests (P2-17a)
SeedCodeUITest
Seed
  1. 1 rotation cycle (A/B week, length=2). 20 rotation calendar entries (10 school days mapped to day 1 or 2). 1 constraint profile with 5 hard + 5 soft constraints. 15 student subject choices across 5 students. 1 completed scheduling request (CP_SAT, 2 candidates). 2 candidates (1 APPROVED with 30 slots promoted, 1 REJECTED). 30 candidate slots (2 with has_clash=true). 1 activation log. 1 room change request (APPROVED). 1 subject choice window (open).
Services (~24 endpoints)
  1. RotationService — CRUD for rotation cycles + calendar. GET /scheduling/rotation/:date (what rotation day is today?). POST /scheduling/rotation/generate (auto-generate calendar for academic year from cycle definition + school closure dates).
  2. SubjectChoiceService — POST /scheduling/subject-choices (student submits during open window), GET /scheduling/subject-choices (admin: all; student: own), GET /scheduling/subject-choices/demand (demand matrix: course × student count). GET/POST /scheduling/subject-choice-windows.
  3. ScheduleGenerationService — POST /scheduling/generate (queue request; SchedulingWorker assembles input payload from student choices + classes + teachers + rooms + periods + constraints → calls Scheduling Solver external service → writes candidates + slots; stub solver if not deployed), GET /scheduling/requests/:id (with candidates inlined), POST /scheduling/candidates/:id/approve (SchedulingActivationWorker promotes slots to sch_timetable_slots; writes activation log; emits sch.timetable.updated), POST /scheduling/candidates/:id/reject.
  4. RoomChangeService — POST /scheduling/room-changes, GET /scheduling/room-changes, PATCH /scheduling/room-changes/:id (approve: updates sch_timetable_slots.room_id).
UI
  1. Rotation Calendar /scheduling/rotation — admin: visual calendar with rotation day colour-coding. Edit rotation day per date. Auto-generate from cycle.
  2. Subject Choice Portal /scheduling/subject-choices — student: choose subjects with preference ranking during open window. Admin: demand summary matrix.
  3. Schedule Generation Dashboard /scheduling/generate — admin: configure constraints → generate → review candidates side-by-side with clash highlighting → approve/reject → activate. Promotion progress tracker.
Produces → P2-17a: 10 tables, ~24 endpoints, 2 workers. Independently shippable.

P2-17b: Exams + Co-Teaching + Pull-Out + Cross-School + Cover

03Schema (10 tables)
Schema
  1. sch_exam_sessions — school_id UUID NOT NULL, exam_name TEXT NOT NULL, subject_id UUID FK(sis_courses), exam_date DATE NOT NULL, start_time TIME NOT NULL, end_time TIME NOT NULL, duration_minutes INT NOT NULL, extra_time_minutes INT DEFAULT 0 (global extra time for this exam). INDEX(school_id, exam_date).
  2. sch_exam_session_rooms — session_id UUID FK NOT NULL, room_id UUID FK(sch_rooms) NOT NULL, capacity INT NOT NULL, is_main_room BOOLEAN DEFAULT true. UNIQUE(session_id, room_id). Junction table replacing former room_ids array. Room conflict detection via tstzrange overlap check against sch_timetable_slots.
  3. sch_exam_seatings — session_id UUID FK NOT NULL, student_id UUID FK NOT NULL, room_id UUID FK NOT NULL, seat_number TEXT, extra_time_minutes INT DEFAULT 0 (per-student from sis_student_active_accommodations), separate_room BOOLEAN DEFAULT false, reader_required BOOLEAN DEFAULT false, scribe_required BOOLEAN DEFAULT false. UNIQUE(session_id, student_id). Accommodation fields drawn from sis_student_active_accommodations on seat assignment.
  4. sch_exam_invigilator_assignments — session_id UUID FK NOT NULL, room_id UUID FK NOT NULL, invigilator_id UUID FK(hr_employees) NOT NULL, is_lead BOOLEAN DEFAULT false. UNIQUE(session_id, room_id, invigilator_id).
  5. sch_coteaching_arrangements — timetable_slot_id UUID FK NOT NULL, primary_teacher_id UUID FK NOT NULL, secondary_teacher_id UUID FK NOT NULL, teaching_model TEXT NOT NULL 5-value CHECK (TEAM_TEACHING, ONE_TEACH_ONE_SUPPORT, STATION_ROTATION, PARALLEL_TEACHING, ALTERNATIVE_TEACHING), effective_from DATE, effective_to DATE. UNIQUE(timetable_slot_id, secondary_teacher_id). Secondary teacher's double-booking EXCLUSION relaxed for co-teaching slots.
  6. sch_pull_out_interventions — school_id UUID NOT NULL, student_id UUID FK NOT NULL, regular_slot_id UUID FK(sch_timetable_slots) NOT NULL, intervention_name TEXT NOT NULL, intervention_provider UUID FK(hr_employees), intervention_location TEXT, start_date DATE NOT NULL, end_date DATE, frequency TEXT NOT NULL 4-value CHECK (WEEKLY, FORTNIGHTLY, DAILY, CUSTOM), days_of_week SMALLINT[]. INDEX(student_id, start_date). Attendance pre-marked as PULL_OUT for the regular slot.
  7. sch_cross_school_staff_assignments — home_school_id UUID NOT NULL, visiting_school_id UUID NOT NULL, person_id UUID FK(iam_person) NOT NULL, home_employee_id UUID FK(hr_employees) NOT NULL, role_at_visiting_school TEXT NOT NULL, effective_from DATE NOT NULL, effective_to DATE, max_periods_per_week INT, approved_by UUID FK. UNIQUE(visiting_school_id, person_id, effective_from). Teacher EXCLUSION CONSTRAINT uses person_id to prevent same human double-booked across schools.
  8. sch_cover_arrangements — school_id UUID NOT NULL, absent_teacher_id UUID FK NOT NULL, cover_date DATE NOT NULL, cover_type TEXT NOT NULL 5-value CHECK (SUBSTITUTE_REPLACEMENT, INTERNAL_COVER, CLASS_MERGE, CLASS_SPLIT, SELF_STUDY), sub_assignment_id UUID (soft to sub_assignments from P2-9), covering_teacher_id UUID FK, status TEXT NOT NULL DEFAULT 'PLANNED' 3-value CHECK (PLANNED, ACTIVE, COMPLETED), notes TEXT. INDEX(school_id, cover_date, status).
  9. sch_cover_arrangement_classes — arrangement_id UUID FK NOT NULL, affected_class_id UUID FK(sis_classes) NOT NULL, affected_slot_id UUID FK(sch_timetable_slots) NOT NULL, disposition TEXT NOT NULL 5-value CHECK (COVERED_BY_SUB, MERGED_INTO, SPLIT_TO, SELF_STUDY, CANCELLED), destination_room_id UUID FK, supervising_teacher_id UUID FK. INDEX(arrangement_id).
  10. sch_cover_split_students — arrangement_class_id UUID FK(sch_cover_arrangement_classes) NOT NULL, student_id UUID FK(sis_students) NOT NULL, destination_class_label TEXT. UNIQUE(arrangement_class_id, student_id). Junction table for SPLIT_CLASS — which students go to which split group.
Produces → 10 tables. Migration: 135_sch_exams_coteach_cover.sql. Total P2-17 tables: 20.
04Seed + Services + UI + Tests (P2-17b)
SeedCodeUITest
Seed
  1. 2 exam sessions (Math Final, English Final). 3 exam rooms (1 main + 1 accommodation). 8 exam seatings (2 with extra_time, 1 separate_room). 3 invigilator assignments. 2 co-teaching arrangements (TEAM_TEACHING, STATION_ROTATION). 2 pull-out interventions (Reading Recovery WEEKLY, Speech Therapy FORTNIGHTLY). 1 cross-school staff assignment (visiting music teacher). 2 cover arrangements (1 SUBSTITUTE_REPLACEMENT linked to P2-9, 1 CLASS_SPLIT). 3 cover arrangement classes. 5 cover split students.
Services (~22 endpoints)
  1. ExamSchedulingService — POST /scheduling/exams (create session), POST /scheduling/exams/:id/rooms (assign rooms with capacity), POST /scheduling/exams/:id/seat (assign students to rooms + seats; auto-populate accommodation fields from sis_student_active_accommodations), POST /scheduling/exams/:id/invigilators. GET /scheduling/exams/:id/conflicts (room overlap check against timetable). GET /scheduling/exams (calendar view).
  2. CoTeachingService — POST /scheduling/co-teaching (create arrangement with teaching model), GET /scheduling/co-teaching, PATCH /scheduling/co-teaching/:id. On create: relaxes secondary teacher's double-booking check for that slot.
  3. PullOutService — POST /scheduling/pull-outs (creates intervention; triggers attendance pre-marking as PULL_OUT for regular slot on intervention days), GET /scheduling/pull-outs (student's pull-out schedule), PATCH /scheduling/pull-outs/:id (end/modify).
  4. CrossSchoolStaffService — POST /scheduling/cross-school-staff (assign visiting teacher), GET /scheduling/cross-school-staff. Person-level EXCLUSION constraint prevents double-booking across schools.
  5. CoverArrangementService — POST /scheduling/cover (create arrangement with per-class dispositions), GET /scheduling/cover/:date (today's cover board), POST /scheduling/cover/:id/classes (add affected class with disposition), POST /scheduling/cover-splits/:id/students (assign split students).
UI
  1. Exam Scheduler /scheduling/exams — admin: exam calendar. Create session → assign rooms (drag from room list) → seat students (auto-seat with accommodation sort) → assign invigilators. Conflict detector.
  2. Co-Teaching Manager /scheduling/co-teaching — timetable overlay showing co-taught lessons. Create/edit with model selector.
  3. Pull-Out Schedule /scheduling/pull-outs — SENCO: student pull-out list with regular lesson impact. Teacher: which students leave which lessons.
  4. Cover Board /scheduling/cover — admin: daily cover board. Absent teachers → affected classes → disposition per class. Split student assignment. Links to P2-9 substitute assignments.
Produces → P2-17b: 10 tables, ~22 endpoints. Create all peer review docs. Total P2-17: 20 tables, ~46 endpoints.
