Student Life

Club and activity management with membership rosters, field trips with digital parent consent collection, student government elections with structurally anonymous voting, and community service hour logging with supervisor approval. The third student-input surface (students register for clubs, vote in elections, and log service hours).
May 2026 · 10 Steps · ERD v11 · M64 Clubs & Student Life (22 tables — 16 core in scope, 6 deferred) · CLB-001 through CLB-004

Plan Overview

Cycle 17 builds the M64 Clubs & Student Life module — 16 of the 22 ERD tables. This is a clean greenfield with a new table prefix (ext_). The module is distinctive because it introduces structurally anonymous voting — the ext_votes table has NO voter_id column, and ext_election_voter_check records WHO voted without linking to HOW they voted. This is the strongest privacy guarantee in the platform, enforced at the schema level.

The module spans 4 domains: (1) activity types + clubs/activities with membership rosters and schedules, (2) field trips with digital parent consent collection and chaperone assignments, (3) student government elections with candidate registration + anonymous ballot, and (4) community service programmes with student hour logging and supervisor approval. Students are active participants: they register for clubs, vote in elections, and log service hours — making this the third student-input surface after wellbeing check-ins (Cycle 11.1) and library reading logs/reviews (Cycle 12).

Privacy — Structurally Anonymous Voting

The election voting system enforces ballot secrecy at the schema level, not the application level. ext_votes contains election_id + position + candidate_id + voted_at but NO voter identity column. The separate ext_election_voter_check table records (election_id, student_id) as a primary key to prevent double-voting, but this table has NO reference to any vote row. There is no JOIN path from a vote to a voter — the anonymity is structural and cannot be reversed even by a database administrator.

Step-by-Step Build Plan

01 Activities + Membership Schema
Schema

Club and activity definitions, membership rosters with role tracking, and recurring schedule entries.

Tables (4)
  1. ext_activity_types — school_id UUID, name TEXT NOT NULL, category TEXT NOT NULL 6-value CHECK (SPORT, ARTS, ACADEMIC, LEADERSHIP, COMMUNITY, OTHER). UNIQUE(school_id, name).
  2. ext_activities — school_id UUID, activity_type_id UUID FK, name TEXT NOT NULL, description TEXT, academic_year_id UUID FK, advisor_id UUID FK(hr_employees), max_participants INT nullable (null = unlimited), status TEXT NOT NULL DEFAULT 'ACTIVE' 3-value CHECK (ACTIVE, INACTIVE, COMPLETED), meeting_location TEXT, group_id UUID nullable (soft to grp_groups for future M103 integration). INDEX(school_id, academic_year_id, status).
  3. ext_activity_members — activity_id UUID FK NOT NULL, student_id UUID FK(sis_students) NOT NULL, role TEXT NOT NULL DEFAULT 'MEMBER' 4-value CHECK (MEMBER, OFFICER, PRESIDENT, SECRETARY), joined_at DATE NOT NULL, left_at DATE nullable, is_active BOOLEAN DEFAULT true. UNIQUE(activity_id, student_id). INDEX(student_id, is_active) for "my clubs" view.
  4. ext_activity_schedules — activity_id UUID FK NOT NULL, day_of_week SMALLINT NOT NULL CHECK(0–6), start_time TIME NOT NULL, end_time TIME NOT NULL, location TEXT, is_active BOOLEAN DEFAULT true. INDEX(activity_id, is_active).
Produces → 4 new tables. Migration: 056_ext_activities.sql.
02 Field Trips + Consent Schema
Schema

Field trip planning with participant tracking, digital parent consent collection with signature timestamps, and chaperone assignments with background-check status.

Tables (4)
  1. ext_field_trips — school_id UUID, title TEXT NOT NULL, description TEXT, destination TEXT NOT NULL, trip_date DATE NOT NULL, departure_time TIME, return_time TIME, grade_levels TEXT[], max_participants INT, cost_per_student NUMERIC(6,2) nullable, transport_request_id UUID nullable (soft to trn_ for future M61 integration), organiser_id UUID FK(hr_employees) NOT NULL, status TEXT NOT NULL DEFAULT 'PLANNING' 5-value CHECK (PLANNING, APPROVED, CONFIRMED, COMPLETED, CANCELLED), consent_deadline DATE. INDEX(school_id, trip_date DESC).
  2. ext_field_trip_participants — field_trip_id UUID FK NOT NULL, student_id UUID FK(sis_students) NOT NULL, attendance_status TEXT DEFAULT 'REGISTERED' 4-value CHECK (REGISTERED, ATTENDED, ABSENT, WITHDRAWN). UNIQUE(field_trip_id, student_id).
  3. ext_field_trip_consent_records — PARENT CONSENT KEYSTONE. field_trip_id UUID FK NOT NULL, student_id UUID FK(sis_students) NOT NULL, guardian_person_id UUID NOT NULL (soft to iam_person), consent_given BOOLEAN NOT NULL, signed_at TIMESTAMPTZ NOT NULL, ip_address TEXT, emergency_contact_override TEXT nullable, medical_notes_override TEXT nullable, notes TEXT. UNIQUE(field_trip_id, student_id, guardian_person_id). Emits ext.consent.received on sign.
  4. ext_field_trip_chaperones — field_trip_id UUID FK NOT NULL, person_id UUID NOT NULL (soft to iam_person — covers staff and parent volunteers), role TEXT NOT NULL DEFAULT 'CHAPERONE' 3-value CHECK (LEAD, CHAPERONE, DRIVER), background_check_status TEXT DEFAULT 'NOT_REQUIRED' 4-value CHECK (NOT_REQUIRED, PENDING, CLEARED, FAILED), confirmed BOOLEAN DEFAULT false. UNIQUE(field_trip_id, person_id).
Produces → 4 new tables. Migration: 057_ext_field_trips.sql.
03 Elections + Service Schema
Schema

Student government elections with structurally anonymous voting, and community service programmes with student hour logging and supervisor approval.

Tables (8)
  1. ext_elections — school_id UUID, title TEXT NOT NULL, description TEXT, voting_start TIMESTAMPTZ NOT NULL, voting_end TIMESTAMPTZ NOT NULL, eligible_voters_filter JSONB NOT NULL (structured: grade levels, year groups, or custom student list), status TEXT NOT NULL DEFAULT 'DRAFT' 4-value CHECK (DRAFT, OPEN, CLOSED, RESULTS_PUBLISHED), created_by UUID FK NOT NULL. INDEX(school_id, status).
  2. ext_candidates — election_id UUID FK NOT NULL, student_id UUID FK(sis_students) NOT NULL, position TEXT NOT NULL, statement TEXT, photo_s3_key TEXT, is_approved BOOLEAN DEFAULT true, registered_at TIMESTAMPTZ. UNIQUE(election_id, student_id, position).
  3. ext_votes — ANONYMITY KEYSTONE. election_id UUID FK NOT NULL, position TEXT NOT NULL, candidate_id UUID FK(ext_candidates) NOT NULL, voted_at TIMESTAMPTZ NOT NULL. NO voter_id column. The vote cannot be traced to a voter at the schema level.
  4. ext_election_voter_check — Anti-double-vote ledger. election_id UUID FK NOT NULL, student_id UUID FK(sis_students) NOT NULL. PRIMARY KEY(election_id, student_id). Records WHO voted but has NO reference to any ext_votes row. There is no JOIN path from vote to voter.
  5. ext_service_programmes — school_id UUID, name TEXT NOT NULL, academic_year_id UUID FK, target_hours NUMERIC(6,1) NOT NULL, start_date DATE, end_date DATE, is_active BOOLEAN DEFAULT true, eligible_grade_levels TEXT[]. UNIQUE(school_id, name, academic_year_id).
  6. ext_service_hours — STUDENT-INPUT. student_id UUID FK(sis_students) NOT NULL, programme_id UUID FK nullable, organisation TEXT NOT NULL, description TEXT NOT NULL, service_date DATE NOT NULL, hours NUMERIC(4,1) NOT NULL CHECK(> 0), supervisor_name TEXT, supervisor_contact TEXT, evidence_s3_key TEXT nullable. INDEX(student_id, service_date DESC).
  7. ext_service_hour_approvals — service_hour_id UUID FK UNIQUE NOT NULL, approved_by UUID FK(hr_employees) NOT NULL, status TEXT NOT NULL DEFAULT 'PENDING' 3-value CHECK (PENDING, APPROVED, REJECTED), notes TEXT, reviewed_at TIMESTAMPTZ. The advisor approves student-submitted hours.
  8. ext_service_progress — Per-(programme, student) running total. programme_id UUID FK NOT NULL, student_id UUID FK(sis_students) NOT NULL, approved_hours NUMERIC(6,1) DEFAULT 0, pending_hours NUMERIC(6,1) DEFAULT 0, is_complete BOOLEAN DEFAULT false. UNIQUE(programme_id, student_id). Updated on every approval.
Produces → 8 new tables. Migration: 058_ext_elections_service.sql. Total Cycle 17 tables: 16.

09 Clubs UI — Elections + Service + Student Portal
UI
Pages
  1. Election Ballot /clubs/elections/:id/vote — ANONYMOUS VOTING UI. Candidates grouped by position with statements + photos. One selection per position. Submit button with "Your vote is anonymous and cannot be changed" confirmation. Post-submit: "Thank you for voting" with no indication of who was selected. The UI never stores or displays the voter's choice after submission.
  2. Election Results /clubs/elections/:id — before RESULTS_PUBLISHED: candidate list only, no counts. After: vote counts per candidate per position with winner indicator. Admin: Open/Close/Publish buttons.
  3. Service Hour Logger /clubs/service-hours — STUDENT-INPUT. Log form: organisation, description, date, hours, supervisor, optional evidence upload. My hours list with status pills (PENDING amber / APPROVED emerald / REJECTED rose). Teacher view: approval queue with Approve/Reject per row.
  4. Service Progress /clubs/service-progress — student sees progress bars per programme (approved_hours / target_hours). Leaderboard per programme.
  5. Student Clubs Portal /clubs/my — student landing: my activities + upcoming schedules, my field trips + consent status, active elections (vote button when OPEN), service progress summary.
Produces → Anonymous ballot page, election results, service hour logger (student input), service progress, student clubs portal.
