Plan Overview

Cycle 30 builds the DPO Compliance Suite — all 12 dpo_ tables per ADR-052. This is the regulatory compliance backbone that makes CampusOS pilot-ready for schools operating under GDPR, UK GDPR, FERPA, and COPPA simultaneously. Unlike every prior module which serves operational school workflows, this module serves the Data Protection Officer (DPO) — a role that often spans multiple schools within a district or trust.

The DPO role is scoped at ORGANISATION level in IAM — a single DPO can query dpo_* tables across all schools in their org. The module touches every prior cycle: the ROPA catalogs what data each module processes, the DPIA assesses risk for high-risk activities (AI inference, biometric attendance, health records), the breach log covers any module's data, and the erasure request workflow must traverse every module's tables to find and pseudonymise a data subject's PII. The dpo_pseudonymisation_log records every field-level pseudonymisation operation — currently scoped to audit_log.metadata JSONB (the highest-risk free-form field), with GL/ledger entries retained on legal obligation grounds.

Regulatory — 72-Hour Breach Notification Clock

dpo_data_breach_records.discovery_date starts the GDPR 72-hour supervisory authority notification window. On INSERT, the Cycle 7 Task Worker creates an URGENT escalating task. If supervisory_authority_notified_at remains null after 70 hours, a PAGE-level alert fires to the DPO and platform SRE. This is the highest-urgency automated escalation in CampusOS — a missed 72-hour window is a regulatory violation.

Vertical Slice Deliverable

DPO creates the ROPA: registers 5 processing activities ("Student academic record management" LEGAL_OBLIGATION, "AI lesson summarisation" LEGITIMATE_INTERESTS + high_risk=true, "Health record management" LEGAL_OBLIGATION, "Staff payroll" CONTRACT, "Biometric attendance" CONSENT) → documents retention policies per category (academic records 7 years FERPA, health records 25 years, CCTV 30 days) → "AI lesson summarisation" has high_risk=true but no linked DPIA → compliance dashboard flags the gap → DPO creates a DPIA (risks identified, mitigation measures, residual risk=MEDIUM, DPO opinion recorded) → registers 4 third-party processors (AWS CLOUD_INFRASTRUCTURE, Stripe PAYMENT_PROCESSOR, OpenAI AI_PROVIDER, Google IDENTITY_PROVIDER) → Stripe DPA signed and uploaded; OpenAI DPA missing → compliance dashboard flags the DPA gap → publishes Privacy Notice v2.1 → records parent consent for "AI lesson summarisation" processing → data breach discovered: laptop with student records stolen → breach logged, 72-hour clock starts, URGENT task created → DPO notifies supervisory authority within 72 hours → David Chen submits a Subject Access Request (SAR) for Maya's data → 30-day clock starts → DPO compiles cross-module data export → separately, a parent submits an erasure request for a withdrawn student → DPO reviews: academic records denied (FERPA 7-year hold), audit_log.metadata pseudonymised with opaque token → pseudonymisation_log records the operation → Maya turns 18 → DataSubjectTransferWorker flips data_subject_is_self=true → Maya (not David) is now the data subject for all future SARs.

Step-by-Step Build Plan

01ROPA + Retention + DPIA Schema
Schema

GDPR Article 30 Register of Processing Activities, data retention policy documentation with review schedules, and Article 35 Data Protection Impact Assessments linked to high-risk processing activities.

Tables (3)
  1. dpo_processing_activities — school_id UUID, activity_name TEXT NOT NULL, purpose TEXT NOT NULL, legal_basis TEXT NOT NULL 6-value CHECK (LEGAL_OBLIGATION, PUBLIC_TASK, LEGITIMATE_INTERESTS, VITAL_INTERESTS, CONTRACT, CONSENT), data_categories TEXT[] NOT NULL, data_subjects TEXT[] NOT NULL, retention_policy_id UUID FK nullable, transfers_outside_uk_eea BOOLEAN DEFAULT false, transfer_safeguards TEXT, automated_decision_making BOOLEAN DEFAULT false, profiling BOOLEAN DEFAULT false, high_risk_processing BOOLEAN DEFAULT false, dpia_id UUID FK nullable, is_active BOOLEAN DEFAULT true, last_reviewed_at DATE, reviewed_by UUID FK. INDEX(school_id, is_active). INDEX(school_id, high_risk_processing) WHERE high_risk=true. GAP RULE: high_risk=true AND dpia_id IS NULL = compliance gap.
  2. dpo_retention_policies — school_id UUID, data_category TEXT NOT NULL, retention_period TEXT NOT NULL, legal_basis_for_retention TEXT NOT NULL, review_frequency TEXT NOT NULL DEFAULT 'ANNUAL' 3-value CHECK (ANNUAL, BIENNIAL, ON_CHANGE), last_reviewed_at DATE, next_review_date DATE NOT NULL, reviewed_by UUID FK, links_to_archive_tier TEXT. UNIQUE(school_id, data_category).
  3. dpo_dpias — school_id UUID, processing_activity_id UUID FK, dpia_title TEXT NOT NULL, trigger_reason TEXT NOT NULL, status TEXT NOT NULL DEFAULT 'SCOPING' 5-value CHECK (SCOPING, IN_PROGRESS, COMPLETED, APPROVED, REJECTED), description_of_processing TEXT NOT NULL, necessity_proportionality_assessment TEXT, risks_identified JSONB, residual_risk_level TEXT 3-value CHECK (LOW, MEDIUM, HIGH), dpo_opinion TEXT, supervisory_authority_consultation_required BOOLEAN DEFAULT false, completed_at DATE, completed_by UUID FK, approved_by UUID FK, document_s3_key TEXT. INDEX(school_id, status).
Produces → 3 tables. Migration: 092_dpo_ropa.sql.
02Processors + DPAs + Breach Records Schema
Schema

GDPR Article 28 third-party processor register, Data Processing Agreements with document storage and review tracking, and data breach records with the 72-hour supervisory authority notification countdown.

Tables (3)
  1. dpo_third_party_processors — school_id UUID, processor_name TEXT NOT NULL, processor_type TEXT NOT NULL 9-value CHECK (CLOUD_INFRASTRUCTURE, PAYMENT_PROCESSOR, AI_PROVIDER, MDM_PROVIDER, VIDEO_CONFERENCING, EMAIL_PROVIDER, IDENTITY_PROVIDER, ANALYTICS, OTHER), registered_country TEXT NOT NULL, data_categories_processed TEXT[] NOT NULL, dpa_in_place BOOLEAN NOT NULL DEFAULT false, dpa_id UUID FK nullable, adequacy_decision_applicable BOOLEAN DEFAULT false, transfer_mechanism TEXT 4-value CHECK (ADEQUACY_DECISION, SCCs, BCRs, DEROGATION), last_reviewed_at DATE, next_review_date DATE NOT NULL. UNIQUE(school_id, processor_name). INDEX(school_id, dpa_in_place) WHERE dpa_in_place=false. GAP RULE: dpa_in_place=false = compliance gap.
  2. dpo_data_processing_agreements — school_id UUID, processor_id UUID FK NOT NULL, agreement_reference TEXT NOT NULL, effective_from DATE NOT NULL, effective_to DATE, document_s3_key TEXT NOT NULL, sub_processors_disclosed BOOLEAN DEFAULT false, sub_processor_list_s3_key TEXT, review_date DATE NOT NULL, signed_by UUID FK NOT NULL, status TEXT NOT NULL DEFAULT 'ACTIVE' 4-value CHECK (DRAFT, ACTIVE, EXPIRED, TERMINATED). INDEX(processor_id, status).
  3. dpo_data_breach_records — 72-HOUR COUNTDOWN KEYSTONE. school_id UUID, breach_title TEXT NOT NULL, breach_type TEXT NOT NULL 8-value CHECK (UNAUTHORISED_ACCESS, ACCIDENTAL_DISCLOSURE, RANSOMWARE, THEFT, LOSS_OF_DEVICE, SYSTEM_MISCONFIGURATION, THIRD_PARTY_BREACH, OTHER), discovery_date TIMESTAMPTZ NOT NULL, breach_start_date DATE, personal_data_categories_involved TEXT[] NOT NULL, estimated_affected_individuals INT, risk_level TEXT NOT NULL 4-value CHECK (LOW, MEDIUM, HIGH, VERY_HIGH), risk_to_individuals TEXT NOT NULL 4-value CHECK (UNLIKELY, POSSIBLE, LIKELY, VERY_LIKELY), supervisory_authority_notification_required BOOLEAN NOT NULL, supervisory_authority_notified_at TIMESTAMPTZ, supervisory_authority_reference TEXT, data_subjects_notification_required BOOLEAN DEFAULT false, data_subjects_notified_at TIMESTAMPTZ, breach_cause TEXT NOT NULL, remediation_actions TEXT NOT NULL, is_resolved BOOLEAN DEFAULT false, resolved_at TIMESTAMPTZ, reported_by UUID FK NOT NULL, status TEXT NOT NULL DEFAULT 'UNDER_INVESTIGATION' 4-value CHECK (UNDER_INVESTIGATION, NOTIFIED, CONTAINED, RESOLVED). INDEX(school_id, status). On INSERT: Task Worker creates URGENT task; if supervisory_authority_notification_required=true, 72-hour countdown task. Emits dpo.breach.discovered.
Produces → 3 tables. Migration: 093_dpo_processors_breach.sql.
03SARs + Erasure + Consent + Privacy + Pseudonymisation Schema
Schema

Data subject access requests with 30/45-day deadline enforcement, erasure requests with legal hold checks and denial basis documentation, processing consent records, privacy notice version control, immutable pseudonymisation audit log, and DPO compliance dashboard configuration.

Tables (6)
  1. dpo_subject_access_requests — school_id UUID, data_subject_id UUID FK(iam_person) NOT NULL, requested_by UUID FK NOT NULL, request_type TEXT NOT NULL 4-value CHECK (ACCESS, RECTIFICATION, PORTABILITY, RESTRICTION), deadline_date DATE NOT NULL (30 days GDPR default; 45 days FERPA), status TEXT NOT NULL DEFAULT 'RECEIVED' 6-value CHECK (RECEIVED, IN_PROGRESS, EXTENSION_REQUESTED, COMPLETED, DENIED, OVERDUE), response_s3_key TEXT, completed_at TIMESTAMPTZ, denial_reason TEXT. INDEX(school_id, status). INDEX(deadline_date) WHERE status NOT IN ('COMPLETED','DENIED').
  2. dpo_erasure_requests — school_id UUID, data_subject_id UUID FK(iam_person) NOT NULL, requested_by UUID FK NOT NULL, status TEXT NOT NULL DEFAULT 'RECEIVED' 5-value CHECK (RECEIVED, REVIEWING, PARTIALLY_COMPLETED, COMPLETED, DENIED), denial_basis TEXT (e.g., "FERPA 7-year retention obligation", "Active safeguarding case"), categories_erased TEXT[], categories_retained TEXT[], categories_pseudonymised TEXT[], completed_at TIMESTAMPTZ. INDEX(school_id, status).
  3. dpo_processing_consent_records — school_id UUID, data_subject_id UUID FK(iam_person) NOT NULL, processing_activity_id UUID FK NOT NULL, consented BOOLEAN NOT NULL, consent_given_at TIMESTAMPTZ, consent_withdrawn_at TIMESTAMPTZ, consent_method TEXT NOT NULL 3-value CHECK (DIGITAL, PAPER, VERBAL), evidence_s3_key TEXT. INDEX(data_subject_id, consented). INDEX(school_id, processing_activity_id, consented).
  4. dpo_privacy_notices — school_id UUID, notice_version TEXT NOT NULL, effective_from DATE NOT NULL, content_summary TEXT NOT NULL, document_s3_key TEXT NOT NULL, published_by UUID FK NOT NULL, published_at TIMESTAMPTZ, superseded_at TIMESTAMPTZ. UNIQUE(school_id, notice_version). INDEX(school_id, effective_from DESC).
  5. dpo_pseudonymisation_log — IMMUTABLE. school_id UUID, erasure_request_id UUID FK NOT NULL, data_subject_id UUID FK(iam_person) NOT NULL, target_table TEXT NOT NULL, target_field TEXT NOT NULL, rows_pseudonymised INT NOT NULL, pseudonymisation_token TEXT NOT NULL, pseudonymised_at TIMESTAMPTZ NOT NULL, pseudonymised_by UUID FK NOT NULL. NO UPDATE, NO DELETE. INDEX(erasure_request_id). INDEX(data_subject_id).
  6. dpo_compliance_dashboard_config — school_id UUID UNIQUE, sar_default_deadline_days INT DEFAULT 30, breach_escalation_hours INT DEFAULT 70, dpia_review_reminder_days INT DEFAULT 30, retention_review_reminder_days INT DEFAULT 60, dpa_review_reminder_days INT DEFAULT 90.
Produces → 6 tables. Migration: 094_dpo_sars_erasure.sql. Total Cycle 30 tables: 12.
