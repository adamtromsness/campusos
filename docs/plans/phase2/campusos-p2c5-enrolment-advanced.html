P2-5: Enrolment Advanced

Campus tour scheduling with public slot booking and guest tracking, formal student withdrawal workflow with multi-department exit task checklist, mid-year admission requests with capacity checking, and returning student re-enrolment confirmations with automatic withdrawal initiation on non-continuation. The admissions office's complete lifecycle — from first tour visit to final withdrawal. Opens Wave B.
May 2026 · 8 Steps · ERD v11 · M81 Enrolment .1 (7 tables) · STU-003 + STU-004 · Phase 2 Cycle 5 · Opens Wave B

Plan Overview

Phase 2 Cycle 5 builds the deferred tables from Cycle 16's M81 Enrolment module — 7 new tables across 3 domains: campus tours (3 tables), student withdrawal (2 tables), and re-enrolment + mid-year admission (2 tables). Cycle 16 built the admissions pipeline (applications, waitlists, offers, onboarding). This cycle adds the bookends: what happens before a family applies (tour) and what happens when a student leaves (withdrawal) or continues (re-enrolment).

The tour system is the first public-facing booking surface beyond the enrolment application portal. Prospective families browse available tour slots and book without needing a CampusOS account — an iam_person is created at booking per ADR-055, and if the family later submits an application, the tour booking links to the application via linked_application_id. The withdrawal system orchestrates exit tasks across 6 departments (library books returned, device returned, locker cleared, fees resolved, records prepared, bus cancelled) with per-task status tracking.

Vertical Slice Deliverable

Admin creates 4 tour slots for Open Day Saturday (group tour, max 10 families each) + 6 individual family tour slots across the next 2 weeks → publishes slots → prospective parent Sarah books the Saturday group tour with 2 guests (herself + prospective student age 10) → confirmation email sent → slot current_bookings increments to 1/10 → Sarah attends, completes tour, later submits a full enrolment application (linked_application_id populated) → separately, the Chen family notifies the school that Maya will not return next year → re-enrolment confirmation submitted: confirmed_continuing=false, reason="relocating" → EnrollmentWorker auto-initiates enr_withdrawal_requests → 7 exit tasks auto-created: library books (PENDING), device return (PENDING), locker cleared (PENDING), fees resolved (PENDING), records package (PENDING), bus cancelled (PENDING), lunch account closed (PENDING) → librarian marks books returned (COMPLETED), IT marks device returned (COMPLETED), facilities marks locker cleared (COMPLETED), finance marks fees resolved with $50 credit refunded (COMPLETED), registrar prepares records package (COMPLETED), transport cancels assignment (COMPLETED), food service closes lunch account (COMPLETED) → all tasks COMPLETED → withdrawal status → COMPLETED → sis_students.enrollment_status = WITHDRAWN → meanwhile, a family relocating mid-year submits a mid-year admission request for Grade 4 → EO checks capacity (enr_capacity_summary shows 2 places remaining) → offer made → family accepts → linked to full application pipeline from Cycle 16.

What's In / What's Deferred

In scope (7 tables): enr_tour_slots, enr_tour_bookings, enr_tour_booking_guests, enr_withdrawal_requests, enr_withdrawal_exit_tasks, enr_reenrollment_confirmations, enr_mid_year_admission_requests. Functions STU-003 (Enrolment & Admissions) + STU-004 (Withdrawal & Transfer).

Deferred: Virtual tour integration (meeting_url field ready; video integration deferred). Tour feedback surveys. Automated records transfer to receiving school (manual preparation this cycle). Withdrawal appeal process. Re-enrolment deposit collection. Mid-year admissions assessment scheduling.

Step-by-Step Build Plan

01Tours Schema (3 tables)
Schema
  1. enr_tour_slots — school_id UUID NOT NULL, tour_date DATE NOT NULL, start_time TIME NOT NULL, end_time TIME NOT NULL, max_bookings INT NOT NULL DEFAULT 1 (1=individual; >1=group), current_bookings INT NOT NULL DEFAULT 0, tour_type TEXT NOT NULL DEFAULT 'INDIVIDUAL_FAMILY_TOUR' 4-value CHECK (GENERAL_OPEN_DAY, INDIVIDUAL_FAMILY_TOUR, VIRTUAL_TOUR, SPECIALIST_TOUR), led_by UUID FK(hr_employees) nullable, meeting_point TEXT, notes TEXT, is_published BOOLEAN DEFAULT false, is_cancelled BOOLEAN DEFAULT false. UNIQUE(school_id, tour_date, start_time). INDEX(school_id, tour_date, is_published) WHERE is_published=true AND is_cancelled=false.
  2. enr_tour_bookings — slot_id UUID FK NOT NULL, booked_by UUID FK(iam_person) NOT NULL, family_name TEXT NOT NULL, contact_email TEXT NOT NULL, contact_phone TEXT, status TEXT NOT NULL DEFAULT 'CONFIRMED' 4-value CHECK (CONFIRMED, CANCELLED, NO_SHOW, COMPLETED), booked_at TIMESTAMPTZ NOT NULL, cancelled_at TIMESTAMPTZ, cancellation_reason TEXT, linked_application_id UUID FK(enr_applications) nullable, notes TEXT. UNIQUE(slot_id, booked_by). INDEX(booked_by, booked_at DESC). On INSERT: slot.current_bookings++. On current_bookings=max_bookings: slot marked full.
  3. enr_tour_booking_guests — booking_id UUID FK NOT NULL, guest_type TEXT NOT NULL 3-value CHECK (ADULT, CHILD, PROSPECTIVE_STUDENT), first_name TEXT NOT NULL, last_name TEXT NOT NULL, age INT nullable, notes TEXT. INDEX(booking_id).
Produces → 3 tables. Migration: 106_enr_tours.sql.
02Withdrawal + Re-enrolment + Mid-Year Schema (4 tables)
Schema
  1. enr_withdrawal_requests — school_id UUID NOT NULL, student_id UUID FK(sis_students) NOT NULL, initiated_by TEXT NOT NULL 2-value CHECK (FAMILY, SCHOOL), requested_by UUID FK NOT NULL, withdrawal_reason_category TEXT NOT NULL 10-value CHECK (FAMILY_RELOCATION, TRANSFER_TO_OTHER_SCHOOL, HOME_EDUCATION, EXCLUSION, MEDICAL, FEE_DEFAULT, SAFEGUARDING, GRADUATION, DECEASED, OTHER), withdrawal_reason_detail TEXT, last_attendance_date DATE NOT NULL, requested_at TIMESTAMPTZ NOT NULL, destination_school_name TEXT, destination_school_country TEXT, records_release_consented BOOLEAN DEFAULT false, records_sent_at DATE, status TEXT NOT NULL DEFAULT 'REQUESTED' 4-value CHECK (REQUESTED, IN_PROGRESS, COMPLETED, CANCELLED), completed_at TIMESTAMPTZ, completed_by UUID FK, re_enrollment_hold_placed BOOLEAN DEFAULT false, re_enrollment_hold_reason TEXT. INDEX(school_id, status). On COMPLETED: sis_students.enrollment_status=WITHDRAWN, sis_family_school_links.is_active=false, emits enr.student.withdrawn.
  2. enr_withdrawal_exit_tasks — withdrawal_id UUID FK NOT NULL, task_name TEXT NOT NULL, task_category TEXT NOT NULL 6-value CHECK (ADMINISTRATIVE, FINANCE, IT, FACILITIES, TRANSPORT, RECORDS), status TEXT NOT NULL DEFAULT 'PENDING' 4-value CHECK (PENDING, COMPLETED, WAIVED, NOT_APPLICABLE), completed_by UUID FK, completed_at TIMESTAMPTZ, notes TEXT. INDEX(withdrawal_id, status) WHERE status='PENDING'.
  3. enr_reenrollment_confirmations — school_id UUID NOT NULL, student_id UUID FK(sis_students) NOT NULL, academic_year_id UUID FK NOT NULL, submitted_by UUID FK NOT NULL (guardian), confirmed_continuing BOOLEAN NOT NULL, withdrawal_reason TEXT (required when false), submitted_at TIMESTAMPTZ NOT NULL, processed_by UUID FK, processed_at TIMESTAMPTZ. UNIQUE(student_id, academic_year_id). INDEX(school_id, academic_year_id, confirmed_continuing). On confirmed_continuing=false: auto-initiates enr_withdrawal_requests.
  4. enr_mid_year_admission_requests — school_id UUID NOT NULL, requested_by UUID FK NOT NULL, student_first_name TEXT NOT NULL, student_last_name TEXT NOT NULL, student_date_of_birth DATE NOT NULL, applying_for_grade_level TEXT NOT NULL, requested_start_date DATE NOT NULL, admission_reason TEXT NOT NULL 6-value CHECK (FAMILY_RELOCATION, TRANSFER_FROM_OTHER_SCHOOL, RETURNING_FROM_ABROAD, HOME_EDUCATION_ENDING, LOOKED_AFTER_CHILD, OTHER), previous_school_name TEXT, previous_school_country TEXT, records_requested BOOLEAN DEFAULT false, status TEXT NOT NULL DEFAULT 'RECEIVED' 6-value CHECK (RECEIVED, CAPACITY_CHECKED, OFFER_MADE, ENROLLED, DECLINED, WITHDRAWN), capacity_available BOOLEAN, linked_application_id UUID FK(enr_applications) nullable, notes TEXT. INDEX(school_id, status, requested_start_date).
Produces → 4 tables. Migration: 107_enr_withdrawal_reenrol.sql. Total P2-5 tables: 7.
03Seed Data
Seed
  1. Tours: 3 published slots (1 group Open Day max 10, 2 individual tours). 2 bookings (1 COMPLETED with linked application, 1 CONFIRMED upcoming). 3 guests across the bookings.
  2. Withdrawal: 1 COMPLETED withdrawal (Maya Chen transfer — all 7 exit tasks COMPLETED). 1 IN_PROGRESS withdrawal (3 tasks PENDING, 4 COMPLETED).
  3. Re-enrolment: 5 confirmations for next year: 4 confirmed_continuing=true, 1 confirmed_continuing=false (auto-initiated withdrawal).
  4. Mid-year: 1 ENROLLED mid-year admission (linked to Cycle 16 application). 1 RECEIVED request (capacity not yet checked).
  5. Permissions: STU-003 extended: tour slot management (admin), tour booking (public/parent). STU-004: withdrawal initiation (parent, admin), exit task completion (per-department staff), re-enrolment (parent), mid-year admission (parent, EO).
Produces → Tour, withdrawal, re-enrolment, mid-year demo data. STU-003..004 permissions extended.
04Tours NestJS Module
Code
  1. TourSlotService — GET /enrolment/tours (public: published, non-cancelled, with availability count), POST /enrolment/tours (admin creates slots), PATCH /enrolment/tours/:id (publish/cancel), GET /enrolment/tours/admin (all slots with booking details).
  2. TourBookingService — POST /enrolment/tours/:slotId/book (public: creates iam_person if needed per ADR-055, creates booking + guests, increments current_bookings, sends confirmation email; rejects if slot full), GET /enrolment/tour-bookings (admin: all bookings), PATCH /enrolment/tour-bookings/:id (cancel/no-show/complete), POST /enrolment/tour-bookings/:id/link-application (EO links a booking to a later application).
Produces → 2 services, ~8 endpoints. Emits enr.tour.booked.
05Withdrawal + Re-enrolment + Mid-Year NestJS Module
Code
  1. WithdrawalService — POST /enrolment/withdrawals (initiate: auto-creates 7 exit tasks per department template), GET /enrolment/withdrawals, GET /enrolment/withdrawals/:id (with exit tasks inlined), PATCH /enrolment/withdrawals/:id/complete (all tasks must be COMPLETED or WAIVED; sets sis_students.enrollment_status=WITHDRAWN; emits enr.student.withdrawn).
  2. ExitTaskService — PATCH /enrolment/exit-tasks/:id (department staff marks COMPLETED/WAIVED with notes), GET /enrolment/exit-tasks/my-department (staff: pending tasks for my department).
  3. ReenrolmentService — POST /enrolment/reenrolment (parent submits for next year), GET /enrolment/reenrolment (admin: all confirmations for a year), GET /enrolment/reenrolment/summary (continuing vs departing counts per grade). On confirmed_continuing=false: auto-calls WithdrawalService.
  4. MidYearAdmissionService — POST /enrolment/mid-year (parent/EO submits), GET /enrolment/mid-year, PATCH /enrolment/mid-year/:id (EO: check capacity, make offer, link to Cycle 16 application pipeline).
Produces → 4 services, ~14 endpoints, 2 Kafka emits. Total P2-5 endpoints: ~22.
06Enrolment Advanced UI
UI
  1. Tour Manager /enrolment/tours — admin: slot calendar with availability counts. Create slot form (date, time, type, max bookings, leader, meeting point). Publish toggle. Per-slot: booking list with guest details.
  2. Public Tour Booking /enrolment/tours/public — prospective families: available slots calendar. Book button with name, email, phone, guest details form. Confirmation page.
  3. Withdrawal Manager /enrolment/withdrawals — admin: withdrawal list with status. Per-withdrawal: exit task checklist with department assignments. Task completion by department staff. "Complete Withdrawal" button (requires all tasks done).
  4. Re-enrolment Dashboard /enrolment/reenrolment — admin: response summary per grade (continuing vs departing). Outstanding responses highlighted. Parent: "Confirm your child's place for next year" form.
  5. Mid-Year Admissions /enrolment/mid-year — admin: request queue with capacity check. Link to full application pipeline. Parent: request form.
Produces → Tour manager + public booking, withdrawal manager, re-enrolment dashboard, mid-year admissions.
07Vertical Slice Integration Test
Test
  1. Tour lifecycle: Admin creates group slot (max 10). Publishes. Prospective parent books with 2 guests. Verify current_bookings=1. Book 9 more. Verify slot full. 11th attempt → 409 Conflict. Cancel a booking. Verify current_bookings decrements. Complete tour. Link to application.
  2. Withdrawal lifecycle: Parent initiates withdrawal (FAMILY_RELOCATION). Verify 7 exit tasks auto-created (1 per department template). Librarian marks books returned. IT marks device returned. Attempt "Complete Withdrawal" with 5 tasks still PENDING → 400. Complete remaining tasks. Complete withdrawal. Verify sis_students.enrollment_status=WITHDRAWN. Verify enr.student.withdrawn fires.
  3. Re-enrolment + auto-withdrawal: Parent submits confirmed_continuing=false with reason. Verify enr_withdrawal_requests auto-initiated. Verify exit tasks created. Parent submits confirmed_continuing=true. Verify no withdrawal created.
  4. Mid-year admission: Parent submits request for Grade 4. EO checks capacity (enr_capacity_summary shows places). EO links to Cycle 16 application pipeline. Application → offer → enrolment.
  5. Re-enrolment hold: Admin places re_enrollment_hold on a withdrawn student. Verify future re-enrolment blocked for that student.
  6. Visibility: Public can browse published tour slots + book. Parent can submit re-enrolment + withdrawal. Department staff can complete their own department's exit tasks only. Admin manages all.
Produces → Verified enrolment advanced: tour booking → withdrawal + exit tasks → re-enrolment → mid-year admission.
08Exit Task Template Configuration
Code
