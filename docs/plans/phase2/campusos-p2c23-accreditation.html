P2-23: Accreditation

Platform-seeded accreditation frameworks (AdvancED, IB, CIS, NEASC, WASC) with school adoption, standard-by-standard evidence collection with multi-type artifacts (documents, URLs, metrics, observations, surveys), self-study ratings with rationale, improvement action plans with responsible party assignment and overdue detection, site visit preparation tracking with readiness scoring, and a readiness dashboard that shows the school's accreditation posture at a glance. No split needed.
May 2026 · 8 Steps · ERD v11 · M85 Accreditation (6 tenant + 2 platform = 8 tables) · TCH-008 extended · Phase 2 Cycle 23

Plan Overview

Phase 2 Cycle 23 builds the entire M85 Accreditation module — 6 tenant tables + 2 platform tables. This is a tenant + platform hybrid module: platform-standard frameworks (AdvancED, IB, CIS, etc.) and their standards live in the platform schema, seeded once and shared across all schools. Each school adopts one or more frameworks, then collects evidence against the standards, rates itself in a self-study, creates improvement action plans, and prepares for site visits.

The evidence system uses SOFT INTEGRITY for standard_id — evidence can link to either a platform standard (acc_standards_platform) or a school-created custom standard (within acc_frameworks). The service layer resolves the reference at query time. This avoids a hard FK that would span schemas.

Vertical Slice Deliverable

Platform admin seeds AdvancED framework with 7 domains and 30 standards (platform schema, shared across all schools) → Lincoln Academy adopts AdvancED (acc_school_framework_adoptions created) → accreditation coordinator begins self-study: rates Standard 1.1 "Purpose and Direction" as ACCOMPLISHED with rationale "Clear mission statement reviewed annually" → uploads 3 evidence items: school mission document (DOCUMENT), strategic plan URL (URL), parent survey results (SURVEY) → rates Standard 2.3 "Learning Environment" as DEVELOPING with rationale "Classroom observation data shows inconsistent implementation" → creates action plan: goal "Implement consistent classroom management framework", responsible: VP Academic, target date 6 months, actions: [{description: "Select framework", due: "2 weeks"}, {description: "Staff training", due: "2 months"}, {description: "Classroom observation cycle", due: "4 months"}] → ActionPlanOverdueWorker detects action past target → status OVERDUE, coordinator notified → site visit scheduled: visit_date June 15, accreditor_org "AdvancED Southern Region", lead contact "Dr. Smith" → status PREPARING → readiness_score computed: 24/30 standards rated, 18 with evidence, 3 action plans COMPLETE → readiness_score = 75 → coordinator pushes to close gaps → all 30 rated + evidenced → readiness_score = 95 → status READY → site visit occurs → status VISIT_COMPLETE.

What's In / What's Deferred

In scope (8 tables): Platform: acc_frameworks_platform, acc_standards_platform. Tenant: acc_school_framework_adoptions, acc_frameworks (custom), acc_evidence_items, acc_self_study_ratings, acc_action_plans, acc_site_visit_prep. Function TCH-008 extended.

Deferred: Site visit team member management (visiting evaluators). Site visit schedule/agenda builder. Evidence auto-linking from other modules (e.g., auto-attach attendance data as evidence for a relevant standard). Multi-cycle comparison (how ratings changed between accreditation cycles). External accreditor portal (read-only view for visiting team). Peer school benchmarking.

Step-by-Step Build Plan

01Platform Schema — Frameworks + Standards (2 tables)
Schema

PLATFORM SCHEMA — seeded once, shared across all schools.

  1. acc_frameworks_platform — name TEXT NOT NULL UNIQUE, abbreviation TEXT NOT NULL UNIQUE, organisation TEXT NOT NULL, description TEXT, version TEXT, is_active BOOLEAN DEFAULT true. Seeded: AdvancED/Cognia, IB (PYP/MYP/DP), CIS, NEASC, WASC, SACS, MSA.
  2. acc_standards_platform — framework_id UUID FK NOT NULL, standard_code TEXT NOT NULL, domain TEXT NOT NULL, standard_text TEXT NOT NULL, guidance_notes TEXT, sort_order INT NOT NULL. UNIQUE(framework_id, standard_code). INDEX(framework_id, domain, sort_order). AdvancED: 7 domains × ~5 standards = ~35 rows. IB: varies by programme.
Produces → 2 platform tables. Migration: 149_platform_acc_frameworks.sql (platform schema).
02Tenant Schema — Adoptions + Custom Frameworks + Evidence + Self-Study + Action Plans + Site Visit (6 tables)
Schema
  1. acc_school_framework_adoptions — school_id UUID NOT NULL, platform_framework_id UUID FK(acc_frameworks_platform) NOT NULL, adopted_at DATE NOT NULL, is_active BOOLEAN DEFAULT true. UNIQUE(school_id, platform_framework_id). A school can adopt multiple frameworks (e.g., AdvancED + IB).
  2. acc_frameworks — school_id UUID NOT NULL, name TEXT NOT NULL, description TEXT, is_active BOOLEAN DEFAULT true. UNIQUE(school_id, name). School-created custom frameworks only. CHECK(school_id IS NOT NULL) — platform frameworks live in acc_frameworks_platform, never here.
  3. acc_evidence_items — standard_id UUID NOT NULL (SOFT INTEGRITY — resolves to acc_standards_platform OR custom standard within acc_frameworks), school_id UUID NOT NULL, evidence_type TEXT NOT NULL 5-value CHECK (DOCUMENT, URL, METRIC, OBSERVATION, SURVEY), title TEXT NOT NULL, description TEXT, s3_key TEXT, url TEXT, metric_value TEXT, status TEXT NOT NULL DEFAULT 'DRAFT' 4-value CHECK (DRAFT, SUBMITTED, APPROVED, REJECTED), submitted_by UUID FK NOT NULL, submitted_at TIMESTAMPTZ, reviewed_by UUID FK, reviewed_at TIMESTAMPTZ, reviewer_notes TEXT. INDEX(standard_id, school_id, status). INDEX(school_id, status).
  4. acc_self_study_ratings — standard_id UUID NOT NULL (SOFT INTEGRITY), school_id UUID NOT NULL, cycle_id TEXT NOT NULL (e.g., "2025-2026"), rating TEXT NOT NULL 4-value CHECK (EXEMPLARY, ACCOMPLISHED, DEVELOPING, NOT_MET), rationale TEXT NOT NULL, rated_by UUID FK NOT NULL, rated_at TIMESTAMPTZ NOT NULL. UNIQUE(standard_id, school_id, cycle_id). INDEX(school_id, cycle_id, rating).
  5. acc_action_plans — standard_id UUID NOT NULL (SOFT INTEGRITY), school_id UUID NOT NULL, goal TEXT NOT NULL, actions JSONB NOT NULL (array of {description, due_date, status: PENDING|COMPLETED|OVERDUE}), responsible_party UUID FK(hr_employees) NOT NULL, target_date DATE NOT NULL, status TEXT NOT NULL DEFAULT 'PLANNED' 4-value CHECK (PLANNED, IN_PROGRESS, COMPLETE, OVERDUE). INDEX(school_id, status). ActionPlanOverdueWorker: nightly checks target_date → flips IN_PROGRESS to OVERDUE + notifies responsible party. Emits acc.action_plan.overdue.
  6. acc_site_visit_prep — school_id UUID NOT NULL, visit_date DATE NOT NULL, accreditor_org TEXT NOT NULL, lead_contact_name TEXT, lead_contact_email TEXT, status TEXT NOT NULL DEFAULT 'PREPARING' 3-value CHECK (PREPARING, READY, VISIT_COMPLETE), readiness_score NUMERIC(3,0) (0-100, computed: % of standards with both a rating AND at least one APPROVED evidence item), notes TEXT, created_by UUID FK NOT NULL. INDEX(school_id, visit_date).
Produces → 6 tenant tables. Migration: 150_acc_evidence_selfstudy.sql. Total P2-23 tables: 8.

  2.   3. Permissions: TCH-008 extended: accreditation read (all staff), accreditation write (accreditation coordinator + admin), evidence submission (all staff), evidence approval (coordinator + admin), action plan management (coordinator + admin).
Produces → Platform frameworks seeded. Tenant accreditation demo data.
04Accreditation NestJS Module
Code
  1. FrameworkService — GET /accreditation/frameworks (platform frameworks available for adoption), POST /accreditation/adoptions (school adopts framework), GET /accreditation/adoptions (school's adopted frameworks with standards). POST /accreditation/custom-frameworks (school creates custom), GET /accreditation/standards/:frameworkId (all standards for a framework, platform or custom).
  2. EvidenceService — POST /accreditation/evidence (staff submits evidence linked to a standard; S3 upload for DOCUMENT), GET /accreditation/evidence/:standardId (all evidence for a standard), PATCH /accreditation/evidence/:id (coordinator reviews: SUBMITTED → APPROVED/REJECTED). GET /accreditation/evidence/by-status (coordinator: pending review queue).
  3. SelfStudyService — POST /accreditation/self-study-ratings (coordinator rates standard with rationale), GET /accreditation/self-study/:cycle (all ratings for a cycle, grouped by domain), GET /accreditation/self-study/:cycle/summary (rating distribution: how many EXEMPLARY/ACCOMPLISHED/DEVELOPING/NOT_MET).
  4. ActionPlanService — CRUD. PATCH /accreditation/action-plans/:id/actions (update individual action status within the JSONB array). ActionPlanOverdueWorker: nightly → flips IN_PROGRESS to OVERDUE when target_date past; emits acc.action_plan.overdue.
  5. SiteVisitService — CRUD. GET /accreditation/site-visit/:id/readiness (computes readiness_score: % of adopted standards with rating + APPROVED evidence; updates acc_site_visit_prep.readiness_score). PATCH /accreditation/site-visit/:id (status transitions: PREPARING → READY → VISIT_COMPLETE).
Produces → 5 services + 1 worker, ~22 endpoints, 1 Kafka emit.
05Accreditation UI
UI
  1. Accreditation Dashboard /accreditation — coordinator: adopted frameworks with progress. Per-framework: domain breakdown with rating pills (green EXEMPLARY → red NOT_MET). Evidence count per standard. Action plan status. Readiness score gauge for upcoming site visit.
  2. Standards Explorer /accreditation/standards — standard list grouped by domain. Per-standard: current rating + rationale + evidence list + action plan (if any). Quick-rate form. Evidence upload form.
  3. Evidence Manager /accreditation/evidence — coordinator: pending review queue (SUBMITTED items). Approve/reject with notes. Staff: upload evidence form (type selector, S3 upload, link to standard).
  4. Self-Study Report /accreditation/self-study — coordinator: full self-study view for a cycle. Rating distribution chart. Export as PDF for submission to accrediting body.
  5. Action Plans /accreditation/action-plans — Kanban board by status (PLANNED → IN_PROGRESS → COMPLETE). Overdue highlighted. Per-plan: actions checklist with due dates.
  6. Site Visit Prep /accreditation/site-visit — visit details + readiness score. Checklist of gaps (standards without rating or evidence). Status progression.
Produces → Dashboard, standards explorer, evidence manager, self-study report, action plans, site visit prep.
06Vertical Slice Integration Test
Test
  1. Framework adoption: School adopts AdvancED. Verify 30 standards accessible via adoption. Adopt IB. Verify both frameworks' standards returned. Attempt duplicate adoption → 409.
  2. Evidence lifecycle: Staff submits DOCUMENT evidence for Standard 1.1. Status=DRAFT. Submit → SUBMITTED. Coordinator approves → APPROVED. Upload to S3. Verify s3_key populated. Submit URL evidence. Verify url populated.
  3. Self-study rating: Coordinator rates Standard 1.1 as ACCOMPLISHED with rationale. Verify UNIQUE(standard_id, school_id, cycle_id). Attempt duplicate → 409. Rate all 30 standards. Verify summary distribution correct.
  4. Action plan + overdue: Create action plan for Standard 2.3 (DEVELOPING), target_date = yesterday. Run ActionPlanOverdueWorker. Verify status → OVERDUE. Verify acc.action_plan.overdue fires. Complete all actions in JSONB → status → COMPLETE.
  5. Readiness score: 30 standards adopted. 24 rated + evidenced. Verify readiness_score = 80. Rate + evidence remaining 6. Verify readiness_score = 100.
  6. SOFT INTEGRITY: Evidence links to platform standard_id. Verify resolves correctly. Evidence links to custom standard. Verify resolves correctly. Evidence links to non-existent standard_id → 404.
  7. Visibility: All staff can view standards + submit evidence. Only coordinator + admin can rate, approve evidence, manage action plans. Students/parents cannot access accreditation module.
Produces → Verified accreditation: adopt → evidence → self-study → action plans → readiness → site visit.
07Readiness Score Computation
Code
  1. Readiness score formula: (standards_with_rating_AND_approved_evidence / total_adopted_standards) × 100. A standard is "ready" when it has at least one self-study rating for the current cycle AND at least one APPROVED evidence item. The score updates on every evidence approval + every self-study rating submission. Cached on acc_site_visit_prep.readiness_score for dashboard rendering.
Produces → Readiness score auto-computation.
08Platform Framework Seeder
Seed
  1. Idempotent platform seeder for accreditation frameworks. On platform boot: upserts acc_frameworks_platform + acc_standards_platform with the 3 initial frameworks (AdvancED, IB MYP, CIS). Future frameworks added by extending the seed file — no schema changes needed. Schools see new frameworks automatically on next adoption page load.
Produces → Idempotent platform framework seeder.
