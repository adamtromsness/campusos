Plan Overview

Phase 2 Cycle 2 builds the M91 Incident & Emergency module — all 11 ERD tables. This is the safety backbone: when a lockdown is declared, this module orchestrates the response. It extends Cycle 14's emergency alert system (which handles the notification fan-out) with the operational response layer: who declared it, what procedures to follow, where is everyone, who has been accounted for, and when was each student reunified with their parent.

The module has two modes: (1) emergency declarations (lockdown, fire evacuation, shelter-in-place, etc.) with the full accountability + reunification lifecycle, and (2) non-discipline incident logging (student injury, medical episode, property damage, environmental) for day-to-day safety documentation that doesn't rise to emergency level.

Safety — Declaration Outbox Pattern

inc_declaration_outbox is created atomically in the same transaction as inc_incidents. Each nullable TIMESTAMPTZ column represents one fan-out step: tasks_created_at, muster_taken_at, alert_sent_at. The outbox worker queries for NULL columns and executes the corresponding step. This means: if the server crashes mid-declaration, on restart the worker picks up from the last completed step. No fan-out step is ever skipped. Adding a new step is a single column addition — zero impact on existing code. Alert: any step NULL >5 minutes after declaration triggers a PAGE.

Vertical Slice Deliverable

Admin configures emergency procedures: LOCKDOWN (8-step procedure with time targets, primary contact = Principal Rivera, assembly point = gymnasium), FIRE_EVACUATION (6 steps, assembly = front parking lot), MEDICAL_EMERGENCY (5 steps) → admin schedules a fire drill for next Friday → real emergency: Principal Rivera declares a LOCKDOWN incident → inc_declaration_outbox created atomically → outbox worker step 1: creates URGENT wsk_tasks for all assigned responders (tasks_created_at stamped) → step 2: triggers vis_emergency_muster snapshot from P2-1's visitor data + student/staff muster from SIS rosters (muster_taken_at stamped) → step 3: fires Cycle 14 emergency alert to all staff + parents (alert_sent_at stamped) → emergency procedures surfaced to responders on their devices → immutable timeline entries logged: "10:32 LOCKDOWN declared", "10:33 Police notified", "10:35 Building A cleared" → accountability records: 250 students + 35 staff + 3 visitors tracked → accountability summary materialises in real-time: 245 accounted, 5 unknown, 0 missing → Rivera resolves incident at 10:55 → reunification begins: parents arrive, reception verifies identity, student released to parent (inc_reunification_records), released_by staff member logged → a parent correction: wrong student released (inc_reunification_corrections logged) → after-action: incident report auto-generated from the immutable timeline → separately, a teacher reports a student playground injury as a non-discipline incident: student name, location, description, linked to Cycle 8 service ticket for nurse follow-up.

Step-by-Step Build Plan

01Incident Types + Incidents + Procedures + Outbox Schema
Schema
Tables (4)
  1. inc_incident_types — school_id UUID, code TEXT NOT NULL, name TEXT NOT NULL, severity TEXT NOT NULL 4-value CHECK (LOW, MEDIUM, HIGH, CRITICAL), requires_lockdown BOOLEAN DEFAULT false, notification_template TEXT. UNIQUE(COALESCE(school_id, '00000000-0000-0000-0000-000000000000'), code).
  2. inc_incidents — school_id UUID NOT NULL, incident_type_id UUID FK, declared_by UUID FK NOT NULL, declared_at TIMESTAMPTZ NOT NULL, title TEXT, description TEXT, status TEXT NOT NULL DEFAULT 'ACTIVE' 3-value CHECK (ACTIVE, RESOLVED, CANCELLED), resolved_at TIMESTAMPTZ, resolution_notes TEXT. INDEX(school_id, status) WHERE status='ACTIVE'.
  3. inc_emergency_procedures — school_id UUID NOT NULL, procedure_type TEXT NOT NULL 9-value CHECK (FIRE_EVACUATION, LOCKDOWN, SHELTER_IN_PLACE, MEDICAL_EMERGENCY, BOMB_THREAT, HAZMAT, MISSING_STUDENT, SAFEGUARDING_CRISIS, GENERAL), title TEXT NOT NULL, procedure_steps JSONB NOT NULL (ordered array of {step_number, action, responsible_role, time_target_seconds}), primary_contact_id UUID FK NOT NULL, secondary_contact_id UUID FK, external_contacts JSONB, assembly_points JSONB, last_reviewed_at DATE NOT NULL, reviewed_by UUID FK NOT NULL, next_review_date DATE NOT NULL, is_active BOOLEAN DEFAULT true, procedure_document_s3_key TEXT. UNIQUE(school_id, procedure_type). Surfaced during active incidents.
  4. inc_declaration_outbox — ATOMIC ORCHESTRATION. incident_id UUID FK UNIQUE. Created in same transaction as inc_incidents. tasks_created_at TIMESTAMPTZ nullable, muster_taken_at TIMESTAMPTZ nullable, alert_sent_at TIMESTAMPTZ nullable. Outbox worker queries WHERE column IS NULL. Each step stamps its column. Any step NULL >5 min after declaration = PAGE alert.
Produces → 4 tables. Migration: 098_inc_incidents.sql.
02Timeline + Accountability + Reunification Schema
Schema
Tables (5)
  1. inc_incident_timeline — IMMUTABLE. incident_id UUID FK NOT NULL, recorded_by UUID FK NOT NULL, event_type TEXT NOT NULL, description TEXT NOT NULL, metadata JSONB, recorded_at TIMESTAMPTZ NOT NULL. 05Emergency Declaration NestJS Module
Code
Services & Endpoints
  1. IncidentService — POST /incidents/declare (ATOMIC DECLARATION: inside one tx: creates inc_incidents + inc_declaration_outbox; emits inc.emergency.declared), GET /incidents (active + resolved with filters), GET /incidents/:id (with timeline + accountability + reunification inlined), PATCH /incidents/:id/resolve (ACTIVE → RESOLVED with resolution notes).
  2. DeclarationOutboxWorker — Polls inc_declaration_outbox WHERE tasks_created_at IS NULL (or other NULL columns). Per step: tasks_created_at → creates URGENT wsk_tasks for procedure contacts. muster_taken_at → triggers vis_emergency_muster snapshot (P2-1) + creates inc_accountability_records for all students (from sis_enrolments) + staff (from hr_employees) + currently signed-in visitors. alert_sent_at → emits to Cycle 14 emergency alert. 5-minute PAGE alert if any step remains NULL.
  3. ProcedureService — GET /incidents/procedures, GET /incidents/procedures/:type (returns the active procedure for a type — surfaced during active incidents), POST /incidents/procedures, PATCH /incidents/procedures/:id.
Produces → IncidentModule with 3 services, ~8 endpoints, 1 Kafka emit (inc.emergency.declared), 1 outbox worker.

10Vertical Slice Integration Test
Test
Test Script
  1. Emergency declaration + outbox: Admin declares LOCKDOWN. Verify inc_incidents + inc_declaration_outbox created in one tx. Verify inc.emergency.declared fires. Verify outbox worker stamps tasks_created_at, muster_taken_at, alert_sent_at in sequence.
  2. Outbox crash recovery: Simulate crash after tasks_created_at stamped but before muster_taken_at. Restart worker. Verify it picks up from muster step (not re-creates tasks).
  3. 5-minute PAGE alert: Declare incident. Block outbox worker. Verify PAGE fires after 5 minutes for un-stamped steps.
  4. Accountability lifecycle: Declaration auto-creates accountability records for 10 students + 5 staff + 2 visitors (from P2-1 on-site list). Verify all start as UNKNOWN. Mark 8 students ACCOUNTED_FOR via bulk. Verify summary materialises: 8 accounted, 2 unknown students, etc.
  5. Timeline immutability: Add 3 timeline entries. Attempt UPDATE → rejected (no endpoint). Attempt DELETE → rejected. Verify entries persist with timestamps.
  6. Reunification + correction: Release student to signed-in visitor (from P2-1). Verify reunification record + accountability updated to ACCOUNTED_FOR. Submit correction with reason. Verify inc_reunification_corrections audit row created.
  7. Incident resolution: Resolve the LOCKDOWN. Verify status=RESOLVED + resolved_at stamped. Verify after-action report auto-generates from timeline.
  8. Drill scheduling + completion: Schedule fire drill. Complete with 95% participation. Verify no "overdue" alert. Wait 91 days (simulate). Verify overdue alert fires.
  9. Non-discipline incident: Teacher reports playground injury (STUDENT_INJURY, MEDIUM). Verify inc.incident.reported fires. Link follow-up ticket. Close incident.
  10. Visibility: Teacher can report non-discipline incidents + view own. Cannot declare emergencies. Admin can declare + manage accountability + reunify. Staff can update accountability during emergency. Parent sees emergency alerts (via Cycle 14) but cannot access the incident module.
