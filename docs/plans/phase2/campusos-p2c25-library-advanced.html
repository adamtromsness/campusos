Plan Overview

Phase 2 Cycle 25 builds the deferred tables from Cycle 12's M24 Library module — 6 new tables. Cycle 12 built the core library surface (catalogue, items, patrons, checkouts, holds, fines, reading programmes, study rooms, maker space). This cycle adds the advanced features librarians need for a complete media centre: AI-driven recommendations, curated reading lists that link to curriculum units, class set bulk checkouts for novels studied in English class, interlibrary loan tracking for district partnerships, and bulk import tools for librarians onboarding existing catalogues.

The recommendation engine (lib_recommendations) uses 5 scoring strategies: collaborative filtering (students who read X also read Y), reading level match (Lexile/AR level alignment), subject match (from catalogue subject tags), new arrivals (recently catalogued items in the student's interest areas), and staff picks (librarian-curated selections). The LibraryRecommendationWorker regenerates recommendations weekly for all active patrons. When the AI Inference Service (P3-A1) is deployed, it enhances collaborative filtering with embedding-based similarity; until then, the collaborative filtering uses simple co-checkout frequency counts.

Vertical Slice Deliverable

Librarian creates reading list "Grade 5 Historical Fiction" (list_type=CURRICULUM_UNIT, linked to Cycle 23 cur_units US History unit) with 8 books: 3 REQUIRED, 4 RECOMMENDED, 1 EXTENSION → publishes list → students + parents see it in the library portal → teacher requests class set of "Number the Stars" for 25 students → librarian processes: lib_class_set_checkouts created (copy_count=25), 25 individual lib_checkouts auto-created linking specific barcodes → teacher returns 23 copies after 3 weeks (returned_count=23, status=PARTIALLY_RETURNED) → 2 copies still out → overdue notifications → separately, student Maya searches for her next book → lib_recommendations shows 5 books: "Island of the Blue Dolphins" (COLLABORATIVE_FILTERING, score 0.92 — students who read "Number the Stars" also read this), "Esperanza Rising" (READING_LEVEL_MATCH, Lexile 750), "New Moon" (NEW_ARRIVAL), "Code Talker" (SUBJECT_MATCH, historical fiction), "The Giver" (STAFF_PICK) → Maya checks out "Island of the Blue Dolphins" and writes a review (4 stars, "I loved the survival parts") → librarian approves review → visible on catalogue page → meanwhile, a student requests "The Outsiders" which is not in the catalogue → librarian submits interlibrary loan request to Eastside Elementary (BORROWED, status=REQUESTED) → book arrives (IN_TRANSIT → ACTIVE) → due in 4 weeks.

What's In / What's Deferred

In scope (6 tables): lib_reading_lists, lib_reading_list_items, lib_class_set_checkouts, lib_interlibrary_loans, lib_recommendations, lib_catalogue_import_jobs. Functions LIB-002 (Circulation extended) + LIB-003 (Reading Programmes extended).

Deferred: AI embedding-based recommendation enhancement (requires P3-A1 AI Inference Service). MARC record Z39.50/SRU live lookup (manual import this cycle). WorldCat API integration for catalogue enrichment. Automated Lexile/AR level assignment from AI text analysis. Reading list sharing across schools in a district. Interlibrary loan request approval workflow between schools. Class set reservation calendar. Digital resource lending (ebooks/audiobooks).

Step-by-Step Build Plan

01Reading Lists + Class Sets Schema (3 tables)
Schema
  1. lib_reading_lists — school_id UUID NOT NULL, name TEXT NOT NULL, description TEXT, list_type TEXT NOT NULL 5-value CHECK (CLASS, YEAR_GROUP, CURRICULUM_UNIT, GENERAL, NEW_ARRIVALS), created_by UUID FK NOT NULL, target_class_id UUID (SOFT INTEGRITY → sis_classes), target_grade_level TEXT, curriculum_unit_id UUID (SOFT INTEGRITY → cur_units), academic_year_id UUID FK, is_published BOOLEAN DEFAULT false, published_at TIMESTAMPTZ. UNIQUE(school_id, name, academic_year_id). INDEX(school_id, list_type, is_published).
  2. lib_reading_list_items — reading_list_id UUID FK NOT NULL, catalogue_item_id UUID FK(lib_catalogue_items) NOT NULL, item_type TEXT NOT NULL DEFAULT 'RECOMMENDED' 4-value CHECK (REQUIRED, RECOMMENDED, EXTENSION, REFERENCE), sort_order INT NOT NULL, added_by UUID FK NOT NULL, notes TEXT. UNIQUE(reading_list_id, catalogue_item_id). INDEX(reading_list_id, sort_order).
  3. lib_class_set_checkouts — school_id UUID NOT NULL, catalogue_item_id UUID FK(lib_catalogue_items) NOT NULL, teacher_patron_id UUID FK(iam_person) NOT NULL, class_id UUID (SOFT INTEGRITY → sis_classes), copy_count INT NOT NULL, checkout_date DATE NOT NULL, due_date DATE NOT NULL, returned_count INT NOT NULL DEFAULT 0, status TEXT NOT NULL DEFAULT 'ACTIVE' 4-value CHECK (ACTIVE, PARTIALLY_RETURNED, RETURNED, OVERDUE), notes TEXT. INDEX(school_id, status). INDEX(teacher_patron_id, checkout_date DESC). On INSERT: creates copy_count individual lib_checkouts rows linking specific barcodes via class_set_checkout_id. On returned_count = copy_count: status → RETURNED. On due_date passed + returned_count < copy_count: status → OVERDUE.
Produces → 3 tables + ALTER lib_checkouts ADD class_set_checkout_id UUID FK. Migration: 153_lib_reading_lists_classsets.sql.
02Recommendations + ILL + Import Schema (3 tables)
Schema
  1. lib_recommendations — student_id UUID FK(sis_students) NOT NULL, recommended_item_id UUID FK(lib_items) NOT NULL, reason_type TEXT NOT NULL 5-value CHECK (COLLABORATIVE_FILTERING, READING_LEVEL_MATCH, SUBJECT_MATCH, NEW_ARRIVAL, STAFF_PICK), score NUMERIC(5,3), generated_at TIMESTAMPTZ NOT NULL. INDEX(student_id, score DESC). Regenerated weekly by LibraryRecommendationWorker — full replace, not upsert (DROP + INSERT for each student's recommendations). Maximum 20 recommendations per student.
  2. lib_interlibrary_loans — school_id UUID NOT NULL, loan_direction TEXT NOT NULL 2-value CHECK (BORROWED, LENT), partner_institution TEXT NOT NULL, catalogue_item_id UUID FK(lib_catalogue_items) nullable (for LENT: references our catalogue; for BORROWED: may not exist in our catalogue), title TEXT NOT NULL, isbn TEXT, request_date DATE NOT NULL, received_date DATE, sent_date DATE, due_date DATE, returned_date DATE, status TEXT NOT NULL DEFAULT 'REQUESTED' 6-value CHECK (REQUESTED, IN_TRANSIT, ACTIVE, RETURNED, OVERDUE, LOST). INDEX(school_id, status). INDEX(school_id, loan_direction, status).
  3. lib_catalogue_import_jobs — school_id UUID NOT NULL, import_type TEXT NOT NULL 4-value CHECK (ISBN_BATCH, MARC_IMPORT, CSV_UPLOAD, WORLDCAT_SYNC), source_file_s3_key TEXT, total_records INT, records_imported INT NOT NULL DEFAULT 0, records_skipped INT NOT NULL DEFAULT 0 (duplicates by ISBN), records_failed INT NOT NULL DEFAULT 0, status TEXT NOT NULL DEFAULT 'QUEUED' 5-value CHECK (QUEUED, PARSING, IMPORTING, COMPLETED, FAILED), initiated_by UUID FK NOT NULL, error_log_s3_key TEXT, started_at TIMESTAMPTZ, completed_at TIMESTAMPTZ. INDEX(school_id, status). CatalogueImportWorker processes asynchronously.
Produces → 3 tables. Migration: 154_lib_recommendations_ill.sql. Total P2-25 tables: 6.

04Reading Lists + Class Sets NestJS Module
Code
  1. ReadingListService — CRUD. GET /library/reading-lists (published lists, filterable by type + grade + curriculum unit), POST /library/reading-lists (librarian/teacher creates), POST /library/reading-lists/:id/items (add item with type + sort order), PATCH /library/reading-lists/:id/publish (sets is_published=true, published_at). GET /library/reading-lists/:id (with items + catalogue details inlined).
  2. ClassSetService — POST /library/class-sets (creates checkout + auto-creates copy_count individual lib_checkouts linked via class_set_checkout_id; validates copy_count ≤ available copies of that catalogue item), GET /library/class-sets (active class sets), POST /library/class-sets/:id/return (return N copies; increments returned_count; if all returned → RETURNED). ClassSetOverdueWorker: nightly checks due_date with returned_count < copy_count → OVERDUE + notifies teacher.
Produces → 2 services + 1 worker, ~10 endpoints.
05Recommendations + ILL + Import NestJS Module
Code
  1. RecommendationService — GET /library/recommendations/:studentId (up to 20, sorted by score DESC), POST /library/recommendations/:recommendationId/dismiss (student dismisses — excluded from future runs). LibraryRecommendationWorker: weekly, for each active student patron: (1) COLLABORATIVE_FILTERING: find students with ≥3 shared checkouts, recommend their other checkouts not yet read by this student, scored by co-checkout frequency. (2) READING_LEVEL_MATCH: match catalogue items within ±50 Lexile of student's reading level. (3) SUBJECT_MATCH: match catalogue subject tags to student's checkout history tags. (4) NEW_ARRIVAL: items catalogued in last 30 days matching student's subject preferences. (5) STAFF_PICK: librarian-flagged items from lib_reading_lists WHERE list_type='GENERAL'. Top 20 by score inserted per student.
  2. InterlibraryLoanService — CRUD. POST /library/ill (librarian creates BORROWED or LENT request), GET /library/ill (all loans with status filter), PATCH /library/ill/:id (status transitions: REQUESTED → IN_TRANSIT → ACTIVE → RETURNED; ACTIVE past due_date → OVERDUE). GET /library/ill/overdue.
  3. CatalogueImportService — POST /library/imports (upload CSV/MARC file or submit ISBN list; creates job QUEUED), GET /library/imports/:id (job status + counts). CatalogueImportWorker: parses file → for each record: ISBN lookup against existing catalogue (skip if duplicate), create lib_catalogue_items + lib_items, increment counters. On failure: log to error CSV, increment records_failed. On complete: generate error_log_s3_key if any failures. Emits lib.import.completed.
Produces → 3 services + 2 workers, ~12 endpoints, 1 Kafka emit. Total P2-25 endpoints: ~22.

08Recommendation Engine Configuration
Code
  1. Recommendation weights stored in platform_tenant_configs with key library_recommendation_weights (JSONB: {collaborative_filtering: 30, reading_level_match: 25, subject_match: 20, new_arrival: 15, staff_pick: 10}). Librarian configures via GET/PATCH /library/recommendation-config. Schools that prioritise reading level alignment can increase that weight. The worker normalises scores within each strategy, then applies weights to produce the final ranked list.
Produces → Configurable recommendation weights via tenant config.
