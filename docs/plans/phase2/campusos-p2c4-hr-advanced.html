P2-4: HR Advanced

The full HR lifecycle: payroll processing with pay periods, salary scales, deductions, and GL journal integration, recruitment pipeline from job posting through interview panels to offer acceptance, training programme management with certification tracking and renewal alerting, performance appraisals with lesson observations and goal tracking, expense claims with receipt management, employee documents, and return-to-work plans. The largest single cycle in the roadmap. Closes Wave A.
May 2026 · 12 Steps · ERD v11 · M80 HR .1 + M87 Appraisals (30 tables) · HR-002 through HR-006 · Phase 2 Cycle 4 · Closes Wave A

Plan Overview

Phase 2 Cycle 4 completes the M80 HR module and builds the entire M87 HR Appraisals module — 30 new tables across 4 domains: Payroll (10), Recruitment (8), Training & Certifications (5), and Appraisals & Performance (7). This is the largest single cycle in the roadmap and closes Wave A (Pilot Critical). Cycle 4 built the HR core (positions, employees, leave types, leave balances, leave requests) — this cycle adds everything else a school HR department needs to operate.

The payroll domain integrates with Cycle 26's GL via hr.payroll.processed Kafka emit — the GLConsumer auto-posts salary journal entries (DEBIT Salaries Expense + CREDIT Cash) just as it does for payment events. The recruitment domain introduces the first external-facing job board surface. The appraisals domain includes lesson observations — a classroom visit by a senior teacher or principal with structured feedback, which is a mandatory part of teacher evaluation in most school systems.

Cycle Size — 30 Tables

This is the largest single cycle. If Claude Code hits context limits, split into 3 sub-cycles: P2-4a Payroll (Steps 1–4, 10 tables), P2-4b Recruitment (Steps 5–7, 8 tables), P2-4c Appraisals + Training (Steps 8–10, 12 tables). Each sub-cycle is independently shippable. Commit after each sub-cycle.

Vertical Slice Deliverable

Payroll: Admin configures salary scale (Grade 1: $35K–$45K, Grade 2: $45K–$60K) → assigns Rivera to Grade 2 Step 3 ($52K) → opens bi-weekly pay period → PayrollProcessingWorker computes: gross $2,000, federal tax deduction $400, state tax $120, health insurance $200, retirement $100 → net $1,180 → payroll record created → hr.payroll.processed fires → GLConsumer posts: DEBIT Salaries $2,000 + CREDIT Cash $1,180 + CREDIT Tax Payable $520 + CREDIT Benefits Payable $300 → payslip generated. Recruitment: Admin posts "5th Grade Teacher" (LIVE, deadline in 30 days) → 3 applications received → screening panel reviews → 2 advance to interview → interview panel (Principal + Dept Head) → evaluations submitted → offer extended to top candidate ($48K, start Aug 1) → candidate accepts → auto-creates hr_employees record. Training: Admin assigns "Safeguarding Level 2" training to all staff (required, annual renewal) → Rivera completes → certification recorded with expiry in 12 months → 30-day renewal alert scheduled. Appraisals: Admin creates appraisal cycle 2025-2026 → Principal Rivera appraises Teacher Hayes: 3 goals set, 1 lesson observation conducted (GOOD), overall rating GOOD → Hayes signs off via wsk_approval_requests.

Appraisals: hr_appraisal_frameworks, hr_appraisal_cycles, hr_appraisals, hr_appraisal_goals, hr_lesson_observations, hr_appraisal_comments, hr_expense_claims.

Return-to-work phased plans (hr_return_to_work_plans deferred). Applicant tracking system (ATS) integration. Background check API integration for recruitment. 360-degree feedback. Competency framework mapping. Expense claim receipt OCR.

Step-by-Step Build Plan

01Payroll Schema (10 tables)
Schema
Tables
  1. hr_pay_grades — school_id UUID, grade_name TEXT NOT NULL, min_salary NUMERIC(10,2), max_salary NUMERIC(10,2). UNIQUE(school_id, grade_name).
  2. hr_salary_scales — pay_grade_id UUID FK, step INT NOT NULL, annual_salary NUMERIC(10,2) NOT NULL. UNIQUE(pay_grade_id, step). Step-based salary progression within a grade.
  3. hr_pay_periods — school_id UUID, start_date DATE, end_date DATE, pay_date DATE, status TEXT 4-value CHECK (OPEN, PROCESSING, PAID, CLOSED). UNIQUE(school_id, start_date).
  4. hr_payroll_records — employee_id UUID FK, pay_period_id UUID FK, gross_pay NUMERIC(10,2), total_deductions NUMERIC(10,2), net_pay NUMERIC(10,2), status TEXT 3-value CHECK (DRAFT, APPROVED, PAID). UNIQUE(employee_id, pay_period_id).
  5. hr_payroll_deductions — payroll_record_id UUID FK, deduction_type TEXT 7-value CHECK (FEDERAL_TAX, STATE_TAX, SOCIAL_SECURITY, MEDICARE, HEALTH_INSURANCE, RETIREMENT, OTHER), amount NUMERIC(10,2). INDEX(payroll_record_id).
  6. hr_payroll_adjustments — employee_id UUID FK, adjustment_type TEXT 7-value CHECK (RETROACTIVE_PAY, BONUS, BACK_PAY, OVERPAYMENT_RECOVERY, SIGNING_BONUS, SEVERANCE, OTHER), amount NUMERIC(10,2), effective_pay_period_id UUID FK, reason TEXT NOT NULL, approved_by UUID FK. INDEX(employee_id, effective_pay_period_id).
  7. hr_salary_review_requests — requested_by UUID FK, employee_id UUID FK, review_type TEXT 5-value CHECK (ANNUAL_INCREMENT, PROMOTION, MARKET_ADJUSTMENT, PERFORMANCE_BONUS, RETENTION), current_salary NUMERIC(10,2), recommended_salary NUMERIC(10,2), justification TEXT NOT NULL, linked_approval_id UUID FK(wsk_approval_requests), status TEXT 6-value CHECK (DRAFT, SUBMITTED, UNDER_REVIEW, APPROVED, REJECTED, WITHDRAWN). INDEX(school_id, status).
  8. hr_employee_tax_info — employee_id UUID FK UNIQUE, filing_status TEXT, federal_allowances INT, state_allowances INT, additional_withholding NUMERIC(10,2). Encrypted at rest (PII).
  9. hr_employee_benefits — employee_id UUID FK, benefit_type TEXT 5-value CHECK (HEALTH, DENTAL, VISION, LIFE, RETIREMENT), plan_name TEXT, employee_contribution NUMERIC(10,2), employer_contribution NUMERIC(10,2), effective_from DATE, effective_to DATE. INDEX(employee_id, benefit_type).
  10. hr_employee_documents — employee_id UUID FK, document_type TEXT 8-value CHECK (CONTRACT, OFFER_LETTER, ID_COPY, QUALIFICATION, BACKGROUND_CHECK, TAX_FORM, CERTIFICATION, OTHER), title TEXT NOT NULL, s3_key TEXT NOT NULL, uploaded_by UUID FK, uploaded_at TIMESTAMPTZ. INDEX(employee_id, document_type).
Produces → 10 tables. Migration: 102_hr_payroll.sql.
02Payroll NestJS Module
Code
  1. PayGradeService — CRUD for pay grades + salary scales. GET /hr/pay-grades, POST /hr/pay-grades, GET /hr/pay-grades/:id/scales.
  2. PayrollService — POST /hr/pay-periods (open period), POST /hr/pay-periods/:id/process (PAYROLL PROCESSING: for each active employee: compute gross from salary scale, apply deductions from hr_employee_tax_info + hr_employee_benefits + adjustments, compute net, create hr_payroll_records + hr_payroll_deductions rows), POST /hr/pay-periods/:id/approve, POST /hr/pay-periods/:id/mark-paid (emits hr.payroll.processed for GL journal posting). GET /hr/payroll/:employeeId/payslips (employee views own).
  3. SalaryReviewService — POST /hr/salary-reviews (DH submits via wsk_approval_requests), GET /hr/salary-reviews, PATCH /hr/salary-reviews/:id.
  4. ExpenseClaimService — POST /hr/expense-claims, GET /hr/expense-claims, PATCH /hr/expense-claims/:id (approve/reject).
Produces → 4 services, ~18 endpoints, 1 Kafka emit (hr.payroll.processed).
03Payroll UI
UI
  1. Payroll Dashboard /hr/payroll — pay period timeline with status pills. Open/process/approve/mark-paid workflow buttons. Per-period: employee count, total gross, total deductions, total net.
  2. Payslip Viewer /hr/payroll/payslips — employee: own payslips with gross/deductions/net breakdown. Admin: any employee's history.
  3. Salary Scale Manager /hr/pay-grades — grade + step matrix editor. Assign employees to grades.
  4. Salary Review Queue /hr/salary-reviews — pending reviews from department heads. Approve/reject with notes.
Produces → Payroll dashboard, payslip viewer, salary scales, review queue.
04Recruitment Schema (8 tables)
Schema
  1. hr_job_postings — school_id UUID, position_title TEXT, department TEXT, description TEXT, qualifications_required TEXT, salary_range_low/high NUMERIC(10,2), employment_type TEXT 4-value CHECK (FULL_TIME, PART_TIME, TEMPORARY, LONG_TERM_SUBSTITUTE), application_deadline DATE, status TEXT 6-value CHECK (DRAFT, PENDING_APPROVAL, APPROVED, LIVE, CLOSED, CANCELLED). INDEX(status) WHERE status='LIVE'.
  2. hr_applications — posting_id UUID FK, person_id UUID FK(iam_person), status TEXT 10-value CHECK (SUBMITTED, UNDER_REVIEW, SCREENING, INTERVIEW_SCHEDULED, INTERVIEW_COMPLETED, OFFER_EXTENDED, OFFER_ACCEPTED, OFFER_DECLINED, NOT_SELECTED, WITHDRAWN), cover_letter_s3_key TEXT, resume_s3_key TEXT. INDEX(posting_id, status).
  3. hr_interview_panels — posting_id UUID FK, panel_name TEXT.
  4. hr_interview_panel_members — panel_id UUID FK, panelist_person_id UUID FK(iam_person). UNIQUE(panel_id, panelist_person_id).
  5. hr_interviews — application_id UUID FK, panel_id UUID FK, scheduled_at TIMESTAMPTZ, location TEXT, status TEXT 4-value CHECK (SCHEDULED, COMPLETED, NO_SHOW, CANCELLED).
  6. hr_interview_evaluations — interview_id UUID FK, evaluator_id UUID FK, rating TEXT 5-value CHECK (STRONG_HIRE, HIRE, NEUTRAL, NO_HIRE, STRONG_NO_HIRE), strengths TEXT, concerns TEXT, notes TEXT. UNIQUE(interview_id, evaluator_id).
  7. hr_offers — application_id UUID FK UNIQUE, position_title TEXT, salary NUMERIC(10,2), start_date DATE, contract_type TEXT 4-value CHECK (ANNUAL, MULTI_YEAR, AT_WILL, TEMPORARY), conditions JSONB, acceptance_deadline DATE, status TEXT 5-value CHECK (PENDING, ACCEPTED, DECLINED, EXPIRED, WITHDRAWN).
  8. hr_job_alerts — person_id UUID FK(iam_person), subject_area TEXT, grade_level TEXT, employment_type TEXT, is_active BOOLEAN.
Produces → 8 tables. Migration: 103_hr_recruitment.sql.
05Recruitment NestJS Module
Code
  1. JobPostingService — CRUD + status workflow (DRAFT → LIVE → CLOSED). GET /hr/jobs (public: LIVE postings), POST /hr/jobs, PATCH /hr/jobs/:id. Emits hr.job.posted on LIVE for job alert matching.
  2. ApplicationService — POST /hr/jobs/:id/apply (external applicant: creates iam_person if new + application), GET /hr/applications (admin: pipeline view), PATCH /hr/applications/:id (advance status). GET /hr/jobs/:id/applications (all apps for a posting).
  3. InterviewService — POST /hr/interviews (schedule with panel), POST /hr/interviews/:id/evaluate (panelist submits), GET /hr/interviews/:id/evaluations.
  4. OfferService — POST /hr/applications/:id/offer (extend), PATCH /hr/offers/:id (accept/decline). On ACCEPTED: auto-creates hr_employees record + position assignment. Emits hr.offer.accepted.
Produces → 4 services, ~16 endpoints, 2 Kafka emits.

07Training & Certifications Schema (5 tables)
Schema

  2. hr_training_events — programme_id UUID FK, title TEXT, scheduled_at TIMESTAMPTZ, duration_minutes INT, location TEXT, facilitator TEXT, max_participants INT, status TEXT 3-value CHECK (SCHEDULED, COMPLETED, CANCELLED).
  3. hr_training_completions — event_id UUID FK, employee_id UUID FK, completed_at TIMESTAMPTZ, score NUMERIC(5,2), passed BOOLEAN. UNIQUE(event_id, employee_id).
  4. hr_certification_types — school_id UUID, name TEXT NOT NULL, issuing_body TEXT, validity_months INT, is_required BOOLEAN. UNIQUE(school_id, name).
  5. hr_employee_certifications — employee_id UUID FK, certification_type_id UUID FK, issued_date DATE, expiry_date DATE, certificate_s3_key TEXT, status TEXT 3-value CHECK (CURRENT, EXPIRING_SOON, EXPIRED). INDEX(employee_id, expiry_date). Alert: 30 days before expiry.
Produces → 5 tables. Migration: 104_hr_training.sql.
08Appraisals Schema (7 tables)
Schema
  1. hr_appraisal_frameworks — school_id UUID, name TEXT, criteria JSONB (competency areas with weightings). UNIQUE(school_id, name).
  2. hr_appraisal_cycles — school_id UUID, academic_year_id UUID, cycle_type TEXT 3-value CHECK (ANNUAL, MID_YEAR, PROBATIONARY), framework_id UUID FK, status TEXT 3-value CHECK (OPEN, CLOSED, ARCHIVED). UNIQUE(school_id, academic_year_id, cycle_type).
  3. hr_appraisals — cycle_id UUID FK, employee_id UUID FK, appraiser_id UUID FK, overall_rating TEXT 4-value CHECK (OUTSTANDING, GOOD, REQUIRES_IMPROVEMENT, INADEQUATE), status TEXT 3-value CHECK (DRAFT, IN_REVIEW, SIGNED_OFF), linked_approval_id UUID FK(wsk_approval_requests). UNIQUE(cycle_id, employee_id).
  4. hr_appraisal_goals — appraisal_id UUID FK, goal_text TEXT NOT NULL, target_date DATE, progress TEXT 4-value CHECK (NOT_STARTED, IN_PROGRESS, ACHIEVED, NOT_ACHIEVED).
  5. hr_lesson_observations — appraisal_id UUID FK, observer_id UUID FK, observed_employee_id UUID FK, observation_date DATE, observed_class_label TEXT (denormalised snapshot), observed_class_id UUID (soft to sis_classes), duration_minutes INT, overall_grade TEXT 4-value CHECK (OUTSTANDING, GOOD, REQUIRES_IMPROVEMENT, INADEQUATE), notes TEXT. Requires lesson_observation:write permission.
  6. hr_appraisal_comments — appraisal_id UUID FK, author_id UUID FK, comment_text TEXT, is_visible_to_employee BOOLEAN DEFAULT false. INDEX(appraisal_id, created_at).
  7. hr_expense_claims — employee_id UUID FK, claim_title TEXT, total_amount NUMERIC(10,2), receipt_s3_keys TEXT[], status TEXT 4-value CHECK (SUBMITTED, APPROVED, REJECTED, PAID), approved_by UUID FK, linked_approval_id UUID FK(wsk_approval_requests).

12Vertical Slice Integration Test
Test
  1. Payroll lifecycle: Configure pay grade. Assign employee. Open period. Process payroll (verify gross - deductions = net). Apply adjustment. Approve. Mark paid. Verify hr.payroll.processed fires. Verify employee sees own payslip.
  2. Recruitment pipeline: Post job (LIVE). Submit application. Screen. Schedule interview with panel. Submit evaluations. Extend offer. Accept. Verify hr_employees auto-created. Verify hr.offer.accepted fires.
  3. Training + certification: Create mandatory programme. Schedule event. Record completion. Create certification with 12-month expiry. Verify EXPIRING_SOON at 30 days. Verify hr.certification.expiring fires.
  4. Appraisal lifecycle: Open cycle. Create appraisal. Set 3 goals. Conduct lesson observation. Submit rating. Sign off via wsk_approval_requests. Verify locked after sign-off.
  5. Salary review: DH submits review for employee. Routes via wsk_approval_requests. Admin approves. Verify salary updated.
  6. GL integration: Verify hr.payroll.processed payload matches GLConsumer contract (employee_id, gross, deductions breakdown, net, journal entries mapping).
  7. Visibility: Employee sees own payslips, training, certifications, appraisal. Cannot see other employees. Admin manages all. Principal can appraise teachers. DH can submit salary reviews for reports.
