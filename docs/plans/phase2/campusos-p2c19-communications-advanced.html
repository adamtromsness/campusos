Sub-Cycle Structure

P2-19a — Translation + Templates + Broadcast Analytics (6 tables)

On-demand message translation via AI Inference service with user language preferences and auto-translate toggle, reusable message templates with named variable slots and per-template permission scoping, broadcast segment definitions for targeted delivery, and broadcast-level analytics with delivery/open/click tracking per segment.

P2-19b — Moderation + Push Campaigns + Appeals (7 tables)

Three-tier moderation policies (platform non-negotiable + district + building) with keyword matching and AI sensitivity scoring, moderation action log with review workflow, user appeal process, push notification campaigns with audience targeting and scheduled delivery, per-campaign engagement analytics, and AI moderation result caching.

P2-19a: Translation + Templates + Broadcast Analytics

01Schema (6 tables)
Schema
  1. msg_user_language_preferences — user_id UUID FK(platform_users) NOT NULL UNIQUE, preferred_language TEXT NOT NULL DEFAULT 'en', auto_translate_incoming BOOLEAN DEFAULT false, auto_translate_outgoing BOOLEAN DEFAULT false. When auto_translate_incoming=true: all incoming messages auto-translated to preferred_language via AI.
  2. msg_translations — message_id UUID FK(msg_messages) NOT NULL, target_language TEXT NOT NULL, translated_text TEXT NOT NULL, model_version TEXT, confidence NUMERIC(3,2), translated_at TIMESTAMPTZ NOT NULL, requested_by UUID FK. UNIQUE(message_id, target_language). Cached — same message translated to same language returns cached result. AI Inference service required (stub if not deployed).
  3. msg_templates — school_id UUID NOT NULL, name TEXT NOT NULL, category TEXT NOT NULL 6-value CHECK (ANNOUNCEMENT, REMINDER, EMERGENCY, WELCOME, FOLLOW_UP, CUSTOM), subject_template TEXT, body_template TEXT NOT NULL, variables JSONB NOT NULL DEFAULT '[]' (array of {name, description, required, default_value} — e.g., [{name:"student_name", required:true}, {name:"event_date", required:true, default_value:"TBD"}]), allowed_roles TEXT[] (which roles can use this template), is_active BOOLEAN DEFAULT true, created_by UUID FK NOT NULL. UNIQUE(school_id, name).
  4. msg_broadcast_segments — school_id UUID NOT NULL, name TEXT NOT NULL, segment_type TEXT NOT NULL 6-value CHECK (ALL_PARENTS, ALL_STAFF, GRADE_LEVEL, CLASS, TRANSPORT_ROUTE, CUSTOM), filter_criteria JSONB NOT NULL (e.g., {grade_level: "5"} or {route_ids: [...]} or {custom_user_ids: [...]}), estimated_recipients INT, is_active BOOLEAN DEFAULT true. UNIQUE(school_id, name). Segments resolve to a set of platform_users at send time.
  5. msg_broadcast_analytics — broadcast_id UUID FK(msg_broadcasts) NOT NULL, segment_id UUID FK(msg_broadcast_segments), total_recipients INT NOT NULL, delivered INT DEFAULT 0, opened INT DEFAULT 0, clicked INT DEFAULT 0, bounced INT DEFAULT 0, unsubscribed INT DEFAULT 0, delivery_rate NUMERIC(5,4), open_rate NUMERIC(5,4), last_updated_at TIMESTAMPTZ. UNIQUE(broadcast_id, segment_id). Updated by BroadcastAnalyticsWorker consuming delivery webhooks.
  6. msg_template_usage_log — template_id UUID FK NOT NULL, used_by UUID FK NOT NULL, used_at TIMESTAMPTZ NOT NULL, broadcast_id UUID FK, thread_id UUID FK. INDEX(template_id, used_at DESC). Analytics: which templates are used most, by whom.
Produces → 6 tables. Migration: 138_msg_translation_templates.sql.
02Seed + Services + UI + Tests (P2-19a)
SeedCodeUITest
Seed
  1. 3 language preferences (1 Spanish auto-translate, 1 Mandarin manual, 1 English default). 4 translations (2 English→Spanish, 2 English→Mandarin). 3 templates ("Snow Day Announcement" with {school_name, closure_date, reopen_date}, "Field Trip Reminder" with {student_name, trip_destination, trip_date}, "Welcome New Family" with {family_name, orientation_date}). 3 broadcast segments (ALL_PARENTS, GRADE_LEVEL "5", TRANSPORT_ROUTE). 2 broadcast analytics rows with delivery stats. 4 template usage log entries.
Services (~18 endpoints)
  1. TranslationService — POST /communications/translate (translate message to target language via AI; caches result), GET /communications/translations/:messageId (all cached translations for a message). GET/PATCH /communications/language-preferences (user sets preferred language + auto-translate toggle). TranslationWorker: when auto_translate_incoming=true, consumes msg.message.posted → auto-translates to recipient's preferred_language → stores in msg_translations.
  2. TemplateService — CRUD for templates. GET /communications/templates (filtered by user's role via allowed_roles), POST /communications/templates/:id/render (accepts variable values → returns interpolated subject + body), POST /communications/templates/:id/use (logs usage). GET /communications/templates/:id/analytics (usage count + last used).
  3. BroadcastSegmentService — CRUD for segments. POST /communications/segments/:id/resolve (computes recipient list from filter_criteria). GET /communications/segments/:id/preview (estimated recipients).
  4. BroadcastAnalyticsService — GET /communications/broadcasts/:id/analytics (per-segment delivery/open/click rates). BroadcastAnalyticsWorker: consumes delivery webhook events → upserts msg_broadcast_analytics.
UI
  1. Translation Settings (user preferences) — language selector + auto-translate toggles. Translated message shown inline with "View Original" toggle.
  2. Template Library /communications/templates — admin: create/edit templates with variable editor. Staff: browse + use templates when composing messages/broadcasts.
  3. Broadcast Composer (extends existing broadcast UI) — segment selector with recipient preview. Template quick-fill. Post-send analytics dashboard with delivery funnel (sent → delivered → opened → clicked).
Produces → P2-19a: 6 tables, ~18 endpoints, 2 workers. Independently shippable.

P2-19b: Moderation + Push Campaigns + Appeals

03Schema (7 tables)
Schema
  1. msg_moderation_rules — school_id UUID (null = platform-level), scope TEXT NOT NULL 3-value CHECK (PLATFORM, DISTRICT, BUILDING), scope_id UUID, keywords TEXT[] NOT NULL, keyword_action TEXT NOT NULL 3-value CHECK (BLOCK, FLAG_FOR_REVIEW, ESCALATE_TO_COUNSELLOR), ai_sensitivity_threshold NUMERIC(3,2) (0.0–1.0; messages scoring above this are flagged), escalation_rules JSONB, is_active BOOLEAN DEFAULT true. Three-tier: most restrictive action wins across all matching policies.
  2. msg_moderation_actions — message_id UUID FK(msg_messages) NOT NULL, rule_id UUID FK(msg_moderation_rules) NOT NULL, action_taken TEXT NOT NULL 4-value CHECK (BLOCKED, FLAGGED_FOR_REVIEW, ESCALATED_TO_COUNSELLOR, AUTO_APPROVED), matched_keywords TEXT[], ai_sensitivity_score NUMERIC(3,2), review_status TEXT DEFAULT 'PENDING' 4-value CHECK (PENDING, RELEASED, CONFIRMED_BLOCK, ESCALATED), reviewed_by UUID FK, reviewed_at TIMESTAMPTZ. INDEX(message_id). RANGE partition by created_at MONTHLY.
  3. msg_moderation_appeals — action_id UUID FK(msg_moderation_actions) NOT NULL, appealed_by UUID FK NOT NULL, appeal_reason TEXT NOT NULL, status TEXT NOT NULL DEFAULT 'SUBMITTED' 3-value CHECK (SUBMITTED, UPHELD, OVERTURNED), reviewed_by UUID FK, reviewed_at TIMESTAMPTZ, reviewer_notes TEXT. UNIQUE(action_id). On OVERTURNED: message released, moderation action review_status=RELEASED.
  4. msg_ai_moderation_results — message_id UUID FK(msg_messages) NOT NULL UNIQUE, sensitivity_score NUMERIC(3,2) NOT NULL, categories_detected JSONB (e.g., {profanity: 0.9, bullying: 0.3, self_harm: 0.1}), model_version TEXT, computed_at TIMESTAMPTZ NOT NULL. Cached AI analysis — computed once per message. AI Inference service required.
  5. msg_push_campaigns — school_id UUID NOT NULL, title TEXT NOT NULL, body TEXT NOT NULL, deep_link_url TEXT, image_s3_key TEXT, audience_segment_id UUID FK(msg_broadcast_segments), scheduled_at TIMESTAMPTZ (null = send immediately), sent_at TIMESTAMPTZ, status TEXT NOT NULL DEFAULT 'DRAFT' 4-value CHECK (DRAFT, SCHEDULED, SENT, CANCELLED), created_by UUID FK NOT NULL. INDEX(school_id, status, scheduled_at). PushCampaignWorker: polls SCHEDULED WHERE scheduled_at ≤ now() → sends via push notification service.
  6. msg_push_analytics — campaign_id UUID FK(msg_push_campaigns) NOT NULL UNIQUE, total_targeted INT NOT NULL, total_delivered INT DEFAULT 0, total_opened INT DEFAULT 0, total_clicked INT DEFAULT 0, delivery_rate NUMERIC(5,4), open_rate NUMERIC(5,4), click_rate NUMERIC(5,4), last_updated_at TIMESTAMPTZ. Updated by PushAnalyticsWorker consuming push delivery callbacks.
  7. msg_push_device_tokens — user_id UUID FK(platform_users) NOT NULL, device_token TEXT NOT NULL, platform TEXT NOT NULL 3-value CHECK (IOS, ANDROID, WEB), is_active BOOLEAN DEFAULT true, registered_at TIMESTAMPTZ NOT NULL, last_used_at TIMESTAMPTZ. UNIQUE(user_id, device_token). Device token management for push delivery.
Produces → 7 tables. Migration: 139_msg_moderation_push.sql. Total P2-19 tables: 13.
04Seed + Services + UI + Tests (P2-19b)
SeedCodeUITest
Seed
  1. 3 moderation rules (1 PLATFORM non-negotiable with profanity keywords, 1 DISTRICT bullying keywords, 1 BUILDING custom). 5 moderation actions (2 BLOCKED, 1 FLAGGED_FOR_REVIEW with RELEASED outcome, 1 ESCALATED, 1 AUTO_APPROVED). 1 appeal (OVERTURNED). 3 AI moderation results. 2 push campaigns (1 SENT, 1 SCHEDULED). 2 push analytics rows. 5 device tokens (3 IOS, 2 ANDROID).
Services (~16 endpoints)
  1. ModerationService — POST /communications/moderation/rules (admin creates), GET /communications/moderation/rules. ModerationWorker: on every msg.message.posted → checks all active rules (three-tier, most restrictive wins) → keyword match + AI sensitivity score → creates msg_moderation_actions. GET /communications/moderation/queue (admin: flagged messages pending review), PATCH /communications/moderation-actions/:id (release/confirm block/escalate).
  2. AppealService — POST /communications/moderation-actions/:id/appeal (user appeals blocked message), GET /communications/moderation/appeals (admin: appeal queue), PATCH /communications/moderation-appeals/:id (uphold/overturn; on overturn: release message).
  3. AIModerationService — POST /communications/ai-moderation/analyze (compute sensitivity score via AI Inference; cache in msg_ai_moderation_results). Called by ModerationWorker when ai_sensitivity_threshold is configured on a rule.
  4. PushCampaignService — POST /communications/push-campaigns, GET /communications/push-campaigns, PATCH /communications/push-campaigns/:id (schedule/cancel). PushCampaignWorker: sends at scheduled_at via push notification service. GET /communications/push-campaigns/:id/analytics. POST /communications/push-devices (register token), DELETE /communications/push-devices/:id (deregister).
UI
  1. Moderation Dashboard /communications/moderation — admin: flagged message queue with keyword match + AI score. Release/block/escalate buttons. Rule configuration (keyword lists + AI threshold slider). Three-tier scope selector.
  2. Appeals Queue /communications/moderation/appeals — admin: appeals list with original message, moderation reason, appeal text. Uphold/overturn.
  3. Push Campaign Manager /communications/push — admin: compose push (title, body, image, deep link), select audience segment, schedule or send now. Post-send analytics (delivered/opened/clicked funnel).
Produces → P2-19b: 7 tables, ~16 endpoints, 3 workers. Create all peer review docs. Total P2-19: 13 tables, ~34 endpoints.
