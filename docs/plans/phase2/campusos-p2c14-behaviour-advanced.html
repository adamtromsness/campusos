P2-14: Behaviour Advanced

Restorative justice conferences with structured harm-repair agreements and follow-through tracking, trained peer mediators with case assignment and outcome logging, positive behaviour rewards with configurable point systems and a student rewards marketplace, advanced BIP progress monitoring with teacher feedback collection, and behaviour pattern detection alerts. Shifts the discipline model from purely punitive to restorative + preventive.
May 2026 · 8 Steps · ERD v11 · M20 Behaviour .1 (5 tables) · BEH-001 + BEH-002 · Phase 2 Cycle 14

Plan Overview

Phase 2 Cycle 14 adds 5 new tables to the Cycle 9 behaviour module. Cycle 9 built the core incident logging, consequence matrix, and discipline actions. This cycle adds the restorative and preventive layer: restorative justice conferences that bring together the offending student, the harmed party, and a trained facilitator to create a structured agreement; peer mediation for lower-level conflicts; a positive behaviour rewards system where students earn points for good conduct and spend them in a rewards marketplace; and enhanced BIP progress monitoring via structured teacher feedback collection.

Restorative justice is increasingly mandated by US school districts as an alternative to suspension. The key principle: the conference produces a written agreement with specific actions the offending student will take, and the system tracks follow-through on each action. If all actions are completed, the incident is resolved restoratively rather than punitively.

Vertical Slice Deliverable

Admin configures positive behaviour categories: "Respect" (helping a classmate, holding a door), "Responsibility" (homework streak, on-time streak), "Leadership" (peer tutoring, club leadership) — each worth configurable points → admin configures rewards marketplace: "Homework Pass" 50pts, "Extra Recess" 100pts, "Lunch with Teacher" 75pts, "Dress Down Day" 200pts (whole-class reward) → teacher awards Maya 10 Respect points for helping a struggling classmate → Maya's balance = 85pts → Maya redeems "Lunch with Teacher" for 75pts → balance = 10pts → separately, an incident occurs: Ethan pushes a classmate → logged as sis_discipline_incidents from Cycle 9 → instead of suspension, counsellor initiates restorative justice conference → conference participants: Ethan (offender), classmate (harmed party), counsellor (facilitator), both parents notified → conference produces agreement: Ethan will write a letter of apology (due in 3 days), participate in conflict resolution workshop (due in 2 weeks), and have a follow-up check-in with counsellor (due in 1 month) → Ethan writes letter (action COMPLETED), completes workshop (COMPLETED), attends check-in (COMPLETED) → all actions completed → conference status RESOLVED_SUCCESSFULLY → meanwhile, two Grade 6 students have a friendship conflict → referred to peer mediation → trained peer mediator (Grade 8 student) facilitates → both students agree to resolution → mediation RESOLVED → BIP feedback: counsellor requests feedback from 3 of Ethan's teachers on his BIP strategies → teachers submit structured observations (strategy effectiveness, recommended adjustments) → counsellor reviews at next BIP review meeting.

What's In / What's Deferred

In scope (5 tables): sis_restorative_justice_conferences, sis_rj_agreement_actions, sis_peer_mediations, sis_positive_behaviour_points, sis_behaviour_rewards. Functions BEH-001 extended (restorative justice, peer mediation, positive behaviour) + BEH-002 extended (BIP teacher feedback uses existing svc_bip_teacher_feedback from Cycle 11).

Deferred: Behaviour pattern detection AI (alert on frequency spikes — requires AI Inference service). Parent-visible positive behaviour feed. Cross-school restorative justice data sharing. Peer mediator training programme integration with P2-4 HR Training. Positive behaviour leaderboards (privacy concerns — opt-in only, deferred). Whole-class reward redemption workflow.

Step-by-Step Build Plan

01Schema (5 tables)
Schema
  1. sis_restorative_justice_conferences — school_id UUID NOT NULL, incident_id UUID FK(sis_discipline_incidents) NOT NULL, facilitator_id UUID FK NOT NULL, offender_student_id UUID FK(sis_students) NOT NULL, harmed_party_ids UUID[] NOT NULL (soft to sis_students — can be multiple), parent_notified_at TIMESTAMPTZ, conference_date TIMESTAMPTZ, conference_location TEXT, conference_notes TEXT, status TEXT NOT NULL DEFAULT 'SCHEDULED' 5-value CHECK (SCHEDULED, IN_PROGRESS, AGREEMENT_REACHED, RESOLVED_SUCCESSFULLY, FAILED), resolution_date TIMESTAMPTZ. INDEX(school_id, status). Emits beh.rj_conference.resolved on RESOLVED_SUCCESSFULLY.
  2. sis_rj_agreement_actions — conference_id UUID FK NOT NULL, action_description TEXT NOT NULL, assigned_to_student_id UUID FK NOT NULL, due_date DATE NOT NULL, status TEXT NOT NULL DEFAULT 'PENDING' 3-value CHECK (PENDING, COMPLETED, OVERDUE), completed_at TIMESTAMPTZ, verified_by UUID FK, evidence_notes TEXT. INDEX(conference_id, status). When ALL actions COMPLETED → conference auto-transitions to RESOLVED_SUCCESSFULLY. OverdueActionWorker: nightly checks for PENDING past due_date → flips to OVERDUE, notifies facilitator.
  3. sis_peer_mediations — school_id UUID NOT NULL, mediator_student_id UUID FK(sis_students) NOT NULL, party_a_student_id UUID FK(sis_students) NOT NULL, party_b_student_id UUID FK(sis_students) NOT NULL, referred_by UUID FK NOT NULL (teacher or counsellor), conflict_description TEXT NOT NULL, mediation_date TIMESTAMPTZ, outcome TEXT, status TEXT NOT NULL DEFAULT 'REFERRED' 4-value CHECK (REFERRED, SCHEDULED, RESOLVED, UNRESOLVED), is_mediator_trained BOOLEAN NOT NULL DEFAULT true. CHECK(party_a_student_id != party_b_student_id). CHECK(mediator_student_id != party_a_student_id AND mediator_student_id != party_b_student_id). INDEX(school_id, status).
  4. sis_positive_behaviour_points — school_id UUID NOT NULL, student_id UUID FK(sis_students) NOT NULL, awarded_by UUID FK NOT NULL, category TEXT NOT NULL, points INT NOT NULL CHECK(>0), reason TEXT NOT NULL, awarded_at TIMESTAMPTZ NOT NULL. INDEX(student_id, awarded_at DESC). Student balance = SUM(points) - SUM(redeemed via sis_behaviour_rewards). Emits beh.positive_points.awarded for parent notification.
  5. sis_behaviour_rewards — school_id UUID NOT NULL, reward_name TEXT NOT NULL, description TEXT, points_cost INT NOT NULL CHECK(>0), reward_type TEXT NOT NULL 4-value CHECK (INDIVIDUAL, CLASS, DIGITAL, PHYSICAL), quantity_available INT (null = unlimited), is_active BOOLEAN DEFAULT true. UNIQUE(school_id, reward_name). Student redemption: creates a negative-point transaction (or separate sis_reward_redemptions table — using point transaction with negative value for simplicity and audit trail).
Produces → 5 tables. Migration: 131_sis_behaviour_advanced.sql.

Code

06Vertical Slice Integration Test

Action 2 passes due date → OverdueWorker flips to OVERDUE + notifies. Complete remaining actions. Verify conference auto-transitions to RESOLVED_SUCCESSFULLY. Verify beh.rj_conference.resolved fires.
  2. Peer mediation: Teacher refers conflict. Counsellor assigns trained mediator. Mediation conducted. Mark RESOLVED. Verify mediator cannot be a party to the conflict (CHECK constraint).

Attempt redeem "Extra Recess" (100pts) → 400 insufficient balance. Verify quantity_available decrements on redeem (if set).
  4. BIP feedback: Counsellor requests feedback from 2 teachers on Ethan's BIP. Teacher A submits (EFFECTIVE). Teacher B submits (SOMEWHAT_EFFECTIVE with adjustments). Verify UNIQUE(plan_id, teacher_id) WHERE submitted_at IS NULL prevents duplicate pending requests.

Cannot see other students' points (unless class leaderboard enabled). Counsellor manages all. Parent notified of RJ conference + positive points.
