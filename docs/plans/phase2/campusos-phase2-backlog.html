Category A — .1 Cycle Deferrals (~210 tables)

These are the deferred tables from modules that already have their core surface built. Each .1 cycle deepens an existing module without introducing a new domain. They can be built in any order — dependencies are satisfied by the parent cycle.

Pilot Priority Recommendation

HIGH priority .1 cycles should be built before pilot if the pilot school needs that capability. MEDIUM can wait until pilot feedback confirms demand. LOW are advanced features that can wait until post-pilot scaling.

Recommended Pre-Pilot Build Order

If you want to build .1 cycles before pilot, here’s the recommended sequence based on pilot school impact. Each cycle is ~1–3 days of Claude Code build time.

Priority Sequence
  1. M90 Visitor Management (9 tables) — Every school needs visitor sign-in on day one. No dependencies beyond Platform.
  2. M91 Incident & Emergency (11 tables) — Schools must log incidents and manage emergencies. Extends Cycle 14’s alerts.
  3. Cycle 10.1 Health Advanced (3 tables) — Immunisation compliance is a state reporting requirement. Tiny scope, huge pilot impact.
  4. Cycle 4.1 HR Advanced (30 tables) — The largest .1 cycle but the most impactful. Schools need payroll, recruitment, and appraisals to operate.
  5. Cycle 16.1 Enrolment Advanced (9 tables) — Tours + withdrawals + lottery are expected by admissions teams.
  6. Cycle 6.1 Payments Advanced (17 tables) — Financial aid, fee schedules, and lunch accounts are core billing operations.
  7. Cycle 13.1 Athletics Advanced (18 tables) — Equipment + officials marketplace matter for schools with active sports programmes.
  8. Cycle 2.1 Classroom Advanced (24 tables) — AI tutoring + rubrics + hall passes are high-engagement teacher features.
  9. M82 Sub Marketplace (9 tables) — Substitute management is a daily operational need.
  10. Cycle 20.1 Food Service Advanced (15 tables) — Pre-orders + inventory for schools with cafeteria operations.

The first 3 items (Visitor + Incident + Health) are ~23 tables total and can be built in under a week. They fill the most visible operational gaps for a pilot school. The next 3 (HR + Enrolment + Payments) are ~56 tables and address the administrative backbone. Together, the top 6 add ~79 tables and take the platform from "impressive demo" to "we can actually run our school on this."
