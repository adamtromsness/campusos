P2-22: Alumni

Self-maintained alumni profiles with opt-in directory and tag-based segmentation, fundraising campaigns with multi-currency donation tracking and Stripe payment integration, campaign recipient outreach with open/respond/donate funnel tracking, alumni news feed with categorised articles, reunion group planning with RSVP management, and alumni events with optional P2-12 Events & Ticketing linkage. The school's long-term relationship engine.
May 2026 · 8 Steps · ERD v11 · M102 Alumni (8 tables) · PUB-004 · Phase 2 Cycle 22

Plan Overview

Phase 2 Cycle 22 builds the entire M102 Alumni module — 8 new tables. This is a new module (not a .1 cycle). Alumni are identified via iam_person per ADR-055 — the same identity record used when they were students. When a student graduates (P2-13 graduation audit COMPLETED), the school can invite them to create an alumni profile. Alumni self-maintain their contact data (ADR-019), and the school uses tag-based segmentation to target campaigns to specific alumni groups (STEM_MENTOR, DONOR, INTERNATIONAL, etc.).

The donation system handles multi-currency: donations store both the original amount + currency and the converted amount_in_reporting_currency at the FX rate from the payment processor at charge time. Campaign totals SUM the reporting currency column, cached in Redis with a 5-minute TTL for dashboard performance.

Vertical Slice Deliverable

School invites Class of 2020 graduates to create alumni profiles → 35 alumni register, self-populate employer + role + LinkedIn + contact info, opt in to directory → admin tags alumni: 10 as STEM_MENTOR, 5 as DONOR, 3 as INTERNATIONAL → admin creates fundraising campaign "New Science Lab" with $50K goal, USD reporting → adds 40 alumni as campaign recipients via DONOR + STEM_MENTOR tags → outreach emails sent (status: SENT) → 25 open (OPENED) → 12 respond (RESPONDED) → 8 donate: 7 donate in USD ($5K total), 1 donates in GBP (£500 at 1.27 = $635 in reporting currency) → campaign raised = $5,635 (Redis-cached) → 1 anonymous donation ($1,000 — donor_alumni_id visible to admin but hidden on public campaign page) → separately, alumni newsletter published: "Class of 2020 — Where Are They Now?" (ACHIEVEMENT category) → Class of 2020 reunion group created: organiser sets event_date + RSVP deadline, 20 alumni RSVP confirmed → alumni event "Homecoming Weekend" linked to P2-12 evt_events for ticketing (evt_event_id populated; if Events module not enabled for this school, falls back to rsvp_url).

Step-by-Step Build Plan

01Profiles + Tags + Directory Schema (2 tables)
Schema
  1. alm_alumni_profiles — school_id UUID NOT NULL, person_id UUID FK(iam_person) NOT NULL, graduation_year INT NOT NULL, degree_programme TEXT, current_employer TEXT, current_role TEXT, linkedin_url TEXT, contact_email TEXT, contact_phone TEXT, is_opted_in BOOLEAN DEFAULT true (opted into directory). INDEX(school_id, graduation_year). RLS: alumni can only read/update their own row. Self-maintained contact data (ADR-019). UNIQUE(school_id, person_id).
  2. alm_alumni_tags — alumni_id UUID FK NOT NULL, tag TEXT NOT NULL. UNIQUE(alumni_id, tag). GIN index on tag. Tags for segmentation: STEM_MENTOR, INTERNATIONAL, DONOR, BOARD_MEMBER, CAREER_SPEAKER, etc. Admin-managed + alumni can self-tag for mentorship interests.
Produces → 2 tables. Migration: 146_alm_profiles_tags.sql.
02Campaigns + Donations + Recipients Schema (3 tables)
Schema
  1. alm_campaigns — school_id UUID NOT NULL, title TEXT NOT NULL, description TEXT, goal_amount NUMERIC(10,2), reporting_currency CHAR(3) NOT NULL DEFAULT 'USD', start_date DATE, end_date DATE, status TEXT NOT NULL DEFAULT 'DRAFT' 4-value CHECK (DRAFT, ACTIVE, COMPLETED, CANCELLED), created_by UUID FK NOT NULL. INDEX(school_id, status). Emits alm.campaign.activated on DRAFT → ACTIVE.
  2. alm_donations — campaign_id UUID FK NOT NULL, donor_alumni_id UUID FK(alm_alumni_profiles) NOT NULL, amount NUMERIC(10,2) NOT NULL, currency CHAR(3) NOT NULL DEFAULT 'USD', fx_rate_at_donation NUMERIC(10,6) (from payment processor at charge time), amount_in_reporting_currency NUMERIC(10,2) NOT NULL, payment_ref TEXT, stripe_payment_intent_id TEXT, donated_at TIMESTAMPTZ NOT NULL, is_anonymous BOOLEAN DEFAULT false. INDEX(campaign_id, donated_at DESC). Campaign total: SUM(amount_in_reporting_currency) cached in Redis campaign:raised:{id} TTL=5min. Emits alm.donation.received.
  3. alm_campaign_recipients — campaign_id UUID FK NOT NULL, alumni_id UUID FK(alm_alumni_profiles) NOT NULL, outreach_status TEXT NOT NULL DEFAULT 'PENDING' 6-value CHECK (PENDING, SENT, OPENED, RESPONDED, DONATED, UNSUBSCRIBED). UNIQUE(campaign_id, alumni_id). Outreach funnel tracking per recipient.
Produces → 3 tables. Migration: 147_alm_campaigns_donations.sql.
03News + Reunions + Events Schema (3 tables)
Schema
  1. alm_alumni_news — school_id UUID NOT NULL, author_id UUID FK NOT NULL, title TEXT NOT NULL, body TEXT NOT NULL, published_at TIMESTAMPTZ, category TEXT NOT NULL 4-value CHECK (ACHIEVEMENT, EVENT, OPPORTUNITY, GENERAL). INDEX(school_id, published_at DESC).
  2. alm_reunion_groups — school_id UUID NOT NULL, graduation_year INT NOT NULL, name TEXT NOT NULL, organiser_id UUID FK(alm_alumni_profiles) NOT NULL, event_date DATE, rsvp_deadline DATE, status TEXT NOT NULL DEFAULT 'PLANNING' 4-value CHECK (PLANNING, CONFIRMED, COMPLETED, CANCELLED). INDEX(school_id, graduation_year).
  3. alm_events — school_id UUID NOT NULL, title TEXT NOT NULL, description TEXT, event_date DATE NOT NULL, venue TEXT, rsvp_url TEXT, evt_event_id UUID (DISPLAY-ONLY soft reference to evt_events — FK constraint removed per ERD; Alumni module compiles and runs regardless of Events module status; if evt_event_id IS NOT NULL: resolve from Events API, fall back to rsvp_url if Events not enabled). INDEX(school_id, event_date).
Produces → 3 tables. Migration: 148_alm_news_reunions_events.sql. Total P2-22 tables: 8.

05Alumni NestJS Module
Code
  1. AlumniProfileService — POST /alumni/profiles (create from invitation; links to iam_person), GET /alumni/profiles (alumni: directory, only is_opted_in=true visible; admin: all), PATCH /alumni/profiles/:id (alumni: own only), GET /alumni/profiles/:id. POST /alumni/tags, DELETE /alumni/tags/:id. GET /alumni/profiles/by-tag/:tag (segmentation query).
  2. CampaignService — CRUD for campaigns. POST /alumni/campaigns/:id/activate (DRAFT → ACTIVE; emits alm.campaign.activated). POST /alumni/campaigns/:id/recipients (bulk add by tag — resolves tag → alumni_ids → creates campaign_recipients with PENDING). GET /alumni/campaigns/:id/funnel (outreach funnel: PENDING → SENT → OPENED → RESPONDED → DONATED counts). GET /alumni/campaigns/:id/raised (Redis-cached SUM).
  3. DonationService — POST /alumni/campaigns/:id/donate (Stripe PaymentIntent; computes amount_in_reporting_currency from currency + fx_rate; updates campaign_recipients outreach_status=DONATED; invalidates Redis cache; emits alm.donation.received), GET /alumni/campaigns/:id/donations (admin: all; public: anonymous donations show amount but not donor).
  4. OutreachService — POST /alumni/campaigns/:id/send-outreach (sends via Communications module; flips PENDING → SENT), PATCH /alumni/campaign-recipients/:id (webhook: SENT → OPENED → RESPONDED).
Produces → 4 services, ~18 endpoints, 2 Kafka emits.
06News + Reunions + Events NestJS Module
Code
  1. AlumniNewsService — CRUD. GET /alumni/news (published articles, most recent first), POST /alumni/news (admin/staff publishes).
  2. ReunionGroupService — CRUD. GET /alumni/reunions (by graduation year), POST /alumni/reunions (alumni organiser creates), PATCH /alumni/reunions/:id (status transitions).
  3. AlumniEventService — CRUD. GET /alumni/events (upcoming alumni events). If evt_event_id IS NOT NULL: enriches response with ticket availability from P2-12 Events API (graceful fallback to rsvp_url if Events module not enabled or call fails).
Produces → 3 services, ~10 endpoints. Total P2-22 endpoints: ~28.
07Alumni UI
UI
  1. Alumni Portal /alumni — alumni: profile editor (employer, role, LinkedIn, contact). Opt-in/out toggle. Tag management. Directory (search by name, graduation year, employer, tag — opted-in only).
  2. Campaign Dashboard /alumni/campaigns — admin: campaign list with progress gauge (raised/goal). Create campaign + add recipients by tag. Outreach funnel visualization. Donation list (anonymous shows "Anonymous Donor"). Per-campaign: send outreach, track opens/responses/donations.
  3. Donation Page /alumni/campaigns/:id/donate — alumni: campaign description + progress bar. Amount input + currency selector. Anonymous toggle. Stripe checkout. Thank-you confirmation.
  4. Alumni News Feed /alumni/news — chronological article list by category. Admin: publish form.
  5. Reunion Planner /alumni/reunions — reunion list by graduation year. Organiser: plan details + RSVP tracking. Alumni: RSVP button.
  6. Alumni Events /alumni/events — upcoming events calendar. If linked to P2-12: "Buy Tickets" button. Otherwise: "RSVP" button with external URL.
Produces → Alumni portal, campaign dashboard, donation page, news, reunions, events.
