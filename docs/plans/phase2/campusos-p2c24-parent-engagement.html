P2-24: Parent Engagement

Parent-teacher conference scheduling with teacher availability slots and parent self-booking, conference outcome documentation with follow-up action tracking, composite parent engagement scoring from attendance events + communications reads + conference participation + volunteer hours + payment compliance, and parent satisfaction surveys with anonymous response aggregation. The school’s relationship health dashboard for families.
May 2026 · 8 Steps · ERD v11 · M100 Parent Engagement (5 tables) · MTG-002 + ENG-001 · Phase 2 Cycle 24

Plan Overview

Phase 2 Cycle 24 builds the entire M100 Parent Engagement module — 5 new tables. This module was extracted from Meetings (M41) by ADR-021 because parent-teacher conferences have a distinct scheduling model: teachers publish availability slots, parents self-book into them, and the booking engine prevents double-booking on both sides. The engagement scoring system is the unique value — it computes a composite score per family from data already collected across 6 other modules (attendance, communications, conferences, volunteering, payments, behaviour points), giving administrators a single number that indicates how connected a family is to the school.

Vertical Slice Deliverable

Admin creates "Fall PTC Week" conference event (Nov 10–14) → 15 teachers publish availability slots (10-min slots, 4pm–7pm each day) → booking window opens Nov 1 → parent David Chen views Mrs Rivera's available slots for Maya's class → books Tuesday 4:30pm slot → slot status BOOKED, confirmation email sent → parent Sarah Johnson tries to book the same slot → 409 (already booked) → Sarah books Tuesday 4:40pm instead → PTC week arrives → Mrs Rivera documents Maya's conference: academic progress on track, needs more practice with writing, agreed action: 20 min nightly journaling → follow-up action created (due 4 weeks) → separately, the EngagementScoreWorker runs weekly for all families → Chen family score: attendance_events=8/10 (80%), communications_read_rate=90%, conferences_attended=2/2 (100%), volunteer_hours=12, payment_on_time=true → composite score = 88 (HIGHLY_ENGAGED) → Johnson family: attendance_events=3/10 (30%), communications_read_rate=20%, conferences_attended=0/2 (0%), volunteer=0, payment=overdue → composite score = 18 (AT_RISK) → admin sees engagement dashboard: 75% of families ENGAGED or above, 10% AT_RISK → targets AT_RISK families for outreach → admin sends parent satisfaction survey (anonymous) → 80% response rate → aggregated results: "How would you rate school communication?" avg 4.2/5.

What's In / What's Deferred

In scope (5 tables): eng_conference_events, eng_conference_slots, eng_conference_bookings, eng_family_engagement_scores, eng_parent_surveys. Functions MTG-002 (PTC Conferences) + ENG-001 (Parent Engagement).

Deferred: Video conference integration (meeting_url field ready; Zoom/Teams integration deferred). Step-by-Step Build Plan

01Conference Scheduling Schema (3 tables)
Schema
  1. eng_conference_events — school_id UUID NOT NULL, title TEXT NOT NULL, start_date DATE NOT NULL, end_date DATE NOT NULL, booking_opens_at TIMESTAMPTZ NOT NULL, booking_closes_at TIMESTAMPTZ NOT NULL, default_slot_duration_minutes INT NOT NULL DEFAULT 10, default_break_minutes INT NOT NULL DEFAULT 5, status TEXT NOT NULL DEFAULT 'DRAFT' 4-value CHECK (DRAFT, BOOKING_OPEN, IN_PROGRESS, COMPLETED), created_by UUID FK NOT NULL. INDEX(school_id, status). Auto-transition: DRAFT → BOOKING_OPEN when booking_opens_at passes. Emits eng.conference.booking_open for parent notification.
  2. eng_conference_slots — conference_event_id UUID FK NOT NULL, teacher_id UUID FK(hr_employees) NOT NULL, slot_date DATE NOT NULL, start_time TIME NOT NULL, end_time TIME NOT NULL, location TEXT, meeting_url TEXT, status TEXT NOT NULL DEFAULT 'AVAILABLE' 3-value CHECK (AVAILABLE, BOOKED, BLOCKED), max_bookings INT DEFAULT 1 (1 for individual PTC; >1 for group sessions). UNIQUE(conference_event_id, teacher_id, slot_date, start_time). ATOMIC BOOKING: UPDATE SET status='BOOKED' WHERE id=$1 AND status='AVAILABLE'. 0 rows = 409 already booked.
  3. eng_conference_bookings — slot_id UUID FK NOT NULL, parent_id UUID FK NOT NULL, student_id UUID FK NOT NULL, booked_at TIMESTAMPTZ NOT NULL, cancelled_at TIMESTAMPTZ, attended BOOLEAN, conference_notes TEXT (teacher documents outcome), follow_up_actions JSONB (array of {description, due_date, status: PENDING|COMPLETED}), parent_feedback_rating INT CHECK(1..5). UNIQUE(slot_id, parent_id, student_id). INDEX(parent_id, booked_at DESC). On cancel: slot.status reverts to AVAILABLE. On attended=true: parent engagement score recalculated.
Produces → 3 tables. Migration: 151_eng_conferences.sql.
02Engagement Scores + Surveys Schema (2 tables)
Schema
  1. eng_family_engagement_scores — school_id UUID NOT NULL, family_account_id UUID FK(pay_family_accounts) NOT NULL, score_date DATE NOT NULL, composite_score INT NOT NULL CHECK(0..100), attendance_component INT (% of school events attended: open houses, sports, performances), communication_component INT (msg_read_rate from Communications), conference_component INT (conferences attended / conferences available), volunteer_component INT (volunteer hours via P2-12 evt_volunteers + P2-14 positive engagement), payment_component INT (on-time payment rate from Cycle 6), engagement_level TEXT NOT NULL 4-value CHECK (HIGHLY_ENGAGED, ENGAGED, MINIMAL, AT_RISK). UNIQUE(family_account_id, score_date). INDEX(school_id, engagement_level, score_date). Materialised weekly by EngagementScoreWorker. No individual student data — aggregated at family level.
  2. eng_parent_surveys — school_id UUID NOT NULL, title TEXT NOT NULL, description TEXT, questions JSONB NOT NULL (array of {question_text, question_type: RATING_1_5|RATING_1_10|YES_NO|FREE_TEXT|MULTIPLE_CHOICE, options: [...]}), is_anonymous BOOLEAN DEFAULT true, opens_at TIMESTAMPTZ, closes_at TIMESTAMPTZ, status TEXT NOT NULL DEFAULT 'DRAFT' 3-value CHECK (DRAFT, OPEN, CLOSED), total_responses INT DEFAULT 0, response_data_aggregated JSONB (per-question averages/counts — never individual responses when anonymous), created_by UUID FK NOT NULL. INDEX(school_id, status). Individual responses stored in a separate responses array within the survey record — when is_anonymous=true, respondent_id is NULL and cannot be reverse-engineered. Emits eng.survey.opened.
Produces → 2 tables. Migration: 152_eng_scores_surveys.sql. Total P2-24 tables: 5.
03Seed Data
Seed
  1. 1 conference event: "Fall PTC Week" COMPLETED. 10 slots across 3 teachers. 6 bookings (4 attended with notes + follow-up actions, 1 cancelled, 1 no-show).
  2. 5 engagement scores: 3 families scored: 1 HIGHLY_ENGAGED (score 88), 1 ENGAGED (score 62), 1 AT_RISK (score 18). Each with component breakdowns.
  3. 1 survey: "Fall Satisfaction Survey" CLOSED, anonymous, 3 questions (RATING_1_5 communication, RATING_1_5 safety, FREE_TEXT suggestions), 15 responses, aggregated results.
  4. Permissions: MTG-002:read to Parent (view own bookings + survey). MTG-002:write to Teacher (publish slots, document outcomes), Parent (book/cancel). ENG-001:read to Teacher (view engagement for own class families). ENG-001:admin to Admin (view all engagement, configure scoring weights, manage surveys).
Produces → Conference, engagement, survey demo data across all 5 tables.
04Conference Scheduling NestJS Module
Code
  1. ConferenceEventService — CRUD. GET /engagement/conferences (admin: all; parent: active). Auto-transition: ConferenceStatusWorker checks booking_opens_at every minute → DRAFT → BOOKING_OPEN; emits eng.conference.booking_open.
  2. ConferenceSlotService — POST /engagement/conferences/:id/slots/generate (teacher: auto-generate from availability window + duration + break config), GET /engagement/conferences/:id/slots (parent: available slots for a teacher), PATCH /engagement/slots/:id (teacher: block a slot).
  3. ConferenceBookingService — POST /engagement/slots/:id/book (ATOMIC: UPDATE eng_conference_slots SET status='BOOKED' WHERE id=$1 AND status='AVAILABLE'; 0 rows = 409; creates booking; sends confirmation), DELETE /engagement/bookings/:id (cancel: reverts slot to AVAILABLE), PATCH /engagement/bookings/:id (teacher: mark attended, write notes, add follow-up actions). GET /engagement/bookings/my (parent: own bookings).
Produces → 3 services + 1 worker, ~14 endpoints, 1 Kafka emit.
05Engagement Scoring + Survey NestJS Module
Code
  1. EngagementScoreService — GET /engagement/scores (admin: all families with scores + engagement levels; filterable by level), GET /engagement/scores/:familyId (score history + component breakdown chart), GET /engagement/scores/summary (school-wide: % per engagement level). EngagementScoreWorker: weekly for all families. Computes each component from source modules: attendance_component from att_records (school event attendance, not daily — uses cal_events attended), communication_component from msg_read_receipts, conference_component from eng_conference_bookings WHERE attended=true, volunteer_component from evt_volunteers WHERE status='CONFIRMED', payment_component from pay_invoices (on-time rate). Composite = weighted average (configurable weights via platform_tenant_configs key engagement_score_weights, default: attendance 20%, communication 25%, conference 25%, volunteer 15%, payment 15%). Level thresholds: HIGHLY_ENGAGED ≥75, ENGAGED ≥50, MINIMAL ≥25, AT_RISK <25.
  2. ParentSurveyService — POST /engagement/surveys (admin creates), GET /engagement/surveys (admin: all; parent: open surveys), POST /engagement/surveys/:id/respond (parent submits; if is_anonymous: respondent_id NOT stored; increments total_responses; aggregates into response_data_aggregated), GET /engagement/surveys/:id/results (admin: aggregated results only — never individual anonymous responses). Emits eng.survey.opened on DRAFT → OPEN.
Produces → 2 services + 1 worker, ~10 endpoints, 1 Kafka emit. Total P2-24 endpoints: ~24.
06Parent Engagement UI
UI
  1. Conference Booking Portal /engagement/conferences — parent: browse teachers with available slots. Calendar view per teacher. Book button (one click). Confirmation with details. My bookings list. Cancel button. Teacher: publish availability with auto-generate from time range. My conference list. Document outcomes form with notes + follow-up actions.
  2. Engagement Dashboard /engagement/dashboard — admin: family list sorted by engagement score. Colour-coded levels (green highly engaged → red at-risk). Per-family: component radar chart (5 axes). School-wide: engagement level distribution pie chart. AT_RISK families highlighted for outreach. Score weight configuration.
  3. Survey Manager /engagement/surveys — admin: create survey with question builder (drag-add question types). Open/close. Results dashboard with per-question charts (bar chart for ratings, word cloud for free text). Response rate. Parent: respond to open surveys.
Produces → Conference booking, engagement dashboard, survey manager.
07Vertical Slice Integration Test
Test
  1. Conference lifecycle: Create event. Teacher generates 5 slots. Parent books slot 1 (ATOMIC: AVAILABLE → BOOKED). Second parent tries slot 1 → 409. Second parent books slot 2. Cancel slot 2 → reverts to AVAILABLE. Teacher marks slot 1 attended + writes notes + adds follow-up action.
  2. Booking window enforcement: Attempt to book before booking_opens_at → 400. Attempt to book after booking_closes_at → 400. Book within window → success.
  3. Engagement scoring: Family with high activity across all 5 components → score ≥75 HIGHLY_ENGAGED. Family with zero activity → score <25 AT_RISK. Verify component breakdown sums to composite (within rounding). Verify configurable weights change the score.
  4. Anonymous survey: Create anonymous survey. Parent responds. Verify respondent_id NOT stored. Second parent responds. Verify total_responses=2. Verify aggregated results correct. Verify admin cannot see individual responses.
  5. Follow-up actions: Teacher adds 2 follow-up actions. Marks 1 COMPLETED. Verify remaining shows as PENDING.
  6. Visibility: Parent sees own bookings + open surveys. Cannot see other families' bookings. Teacher sees slots + bookings for own classes. Cannot see engagement scores. Admin sees all + engagement dashboard.
Produces → Verified parent engagement: conference booking (atomic) → outcome documentation → engagement scoring → anonymous surveys.
08Engagement Score Weight Configuration
Code
  1. Engagement score weights stored in platform_tenant_configs with key engagement_score_weights (JSONB: {attendance: 20, communication: 25, conference: 25, volunteer: 15, payment: 15}). Admin configures via GET/PATCH /engagement/score-config. Level thresholds also configurable: engagement_level_thresholds (JSONB: {highly_engaged: 75, engaged: 50, minimal: 25}). EngagementScoreWorker reads both configs at execution time. Schools can adjust weights to reflect their priorities (e.g., a school that values volunteerism heavily can weight volunteer at 30%).
Produces → Configurable scoring weights + level thresholds via tenant config. No new tables.
