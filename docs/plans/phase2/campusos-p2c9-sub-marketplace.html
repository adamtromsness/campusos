P2-9: Sub Marketplace

Platform-portable substitute teacher profiles with credential verification and configurable availability, per-school substitute pools with preferred/blocked lists, automated job posting from scheduling gaps with tiered notification (pool first, then marketplace), acceptance windows with auto-decline, substitute assignments with check-in/check-out tracking, bidirectional ratings (school rates sub, sub rates school), session handover notes for returning teachers, configurable cancellation policies with late-cancellation consequences, and per-substitute or school-default pay rates with date-range exclusion. A daily operational need for every school.
May 2026 · 10 Steps · ERD v11 · M82 Sub Marketplace (9 tenant + 4 platform = 13 tables) · ADR-029 · SCH-004 · Phase 2 Cycle 9

Plan Overview

Phase 2 Cycle 9 builds the M82 Sub Marketplace module — 9 tenant tables + 4 platform tables. This is a platform + tenant hybrid module per ADR-029: substitute profiles, credentials, availability, and school preferences live in the platform schema (portable across schools via platform entity cache), while job postings, assignments, ratings, session notes, pay rates, and cancellation policies live in the tenant schema (school-specific).

The matching engine is the keystone: when a teacher is absent (Cycle 4 leave request APPROVED), the scheduling module detects uncovered classes. The admin posts a substitute job. The JobNotificationWorker sends tiered notifications: first to the school's preferred pool, then (after configurable delay) to the wider marketplace. Substitutes respond within acceptance windows. The first to accept gets the assignment. Late cancellations trigger configurable consequences via the CancellationPolicyWorker.

Vertical Slice Deliverable

Substitute Sarah registers on the platform: creates profile (Elementary + Middle School certified, 5 years experience), uploads credentials (Teaching License verified, Safeguarding Level 2 verified), sets recurring availability (Mon–Thu 7am–3pm), blocks next Friday (BLOCKED override) → Lincoln Academy admin adds Sarah to the school's substitute pool → sets PREFERRED preference → configures pay rates: school default $180/day, Sarah specifically $200/day (experienced) → configures cancellation policy: 2-hour late window, WARNING_ONLY first, suspension after 3 offences → Monday morning: Rivera calls in sick (leave APPROVED) → admin posts substitute job for Rivera's 3 classes (5th Grade Math periods 1, 3, 5) → JobNotificationWorker tier 1: notifies school pool (Sarah + 2 others) → Sarah sees the posting, checks class details, accepts within 30-min window → assignment CONFIRMED → sub.assignment.confirmed fires → sch_cover_arrangements linked → Tuesday: Sarah checks in at 7:45am (CHECK_IN) → teaches 3 classes → writes session notes ("Covered fractions unit, Maya excelled, Ethan struggled with word problems, assigned practice worksheet") → returning teacher Rivera sees the handover notes → Sarah checks out at 3:15pm (CHECK_OUT) → admin rates Sarah: professionalism 5, punctuality 5, overall 5 → Sarah rates school: professionalism 4, overall 4 → payment processed at $200/day rate.

What's In / What's Deferred

In scope (13 tables): Platform: platform_substitute_profiles, platform_sub_credentials, platform_sub_availability, platform_sub_preferences. Tenant: sub_school_pool, sub_job_postings, sub_job_classes, sub_job_notifications, sub_assignments, sub_ratings, sub_pay_rates, sub_session_notes, sub_cancellation_policies. Function SCH-004 (Daily Coverage).

Deferred: Auto-posting from leave.approved events (manual job creation this cycle; auto-detection of uncovered classes is Phase 3). Credential verification API integration (manual verified/expired toggle this cycle). Substitute mobile app with push notifications. Multi-day assignment booking. Substitute training programme enrolment. District-wide substitute pool sharing. Automated payment processing via P2-4 payroll integration.

Step-by-Step Build Plan

01Platform Schema — Substitute Profiles + Credentials + Availability (4 tables)
Schema

PLATFORM SCHEMA — these tables are NOT in the tenant schema. Substitutes are portable across schools.

  1. platform_substitute_profiles — person_id UUID FK(iam_person) NOT NULL UNIQUE, display_name TEXT NOT NULL, bio TEXT, grade_levels TEXT[] NOT NULL, subject_areas TEXT[], years_experience INT, max_travel_miles INT, is_available BOOLEAN DEFAULT true, profile_photo_s3_key TEXT, overall_rating NUMERIC(2,1) (materialised from sub_ratings), total_assignments INT DEFAULT 0. INDEX(is_available, grade_levels) using GIN on grade_levels.
  2. platform_sub_credentials — substitute_id UUID FK(platform_substitute_profiles) NOT NULL, credential_type TEXT NOT NULL 6-value CHECK (TEACHING_LICENSE, SAFEGUARDING, FIRST_AID, BACKGROUND_CHECK, SPECIALIST_QUALIFICATION, OTHER), credential_name TEXT NOT NULL, issuing_body TEXT, issue_date DATE, expiry_date DATE, document_s3_key TEXT, verification_status TEXT NOT NULL DEFAULT 'PENDING' 3-value CHECK (PENDING, VERIFIED, EXPIRED). INDEX(substitute_id, credential_type, verification_status, expiry_date). Partial INDEX WHERE verification_status='VERIFIED' for matching. Alert: 60 + 30 days before expiry.
  3. platform_sub_availability — substitute_id UUID FK NOT NULL, availability_type TEXT NOT NULL 3-value CHECK (RECURRING, SPECIFIC, BLOCKED), day_of_week SMALLINT (0=Sun..6=Sat; for RECURRING), specific_date DATE (for SPECIFIC + BLOCKED), start_time TIME, end_time TIME. UNIQUE(substitute_id, availability_type, day_of_week, specific_date). BLOCKED overrides RECURRING via NOT EXISTS subquery in the matching engine.
  4. platform_sub_preferences — substitute_id UUID FK NOT NULL, school_id UUID NOT NULL, preference_type TEXT NOT NULL 2-value CHECK (PREFERRED, BLOCKED), reason TEXT (private — visible to substitute only, not the school). UNIQUE(substitute_id, school_id). Matching engine excludes BLOCKED schools.
Produces → 4 platform tables. Migration: 118_platform_substitute_profiles.sql (platform schema).
02Tenant Schema — Pool + Jobs + Notifications (4 tables)
Schema
  1. sub_school_pool — school_id UUID NOT NULL, substitute_id UUID NOT NULL (soft to platform_substitute_profiles), status TEXT NOT NULL DEFAULT 'ACTIVE' 3-value CHECK (ACTIVE, SUSPENDED, REMOVED), added_by UUID FK, suspended_until DATE, suspension_reason TEXT. UNIQUE(school_id, substitute_id). The school's curated list of substitutes they trust.
  2. sub_job_postings — school_id UUID NOT NULL, absent_teacher_id UUID FK(hr_employees) NOT NULL, job_date DATE NOT NULL, start_time TIME NOT NULL, end_time TIME NOT NULL, job_type TEXT NOT NULL DEFAULT 'FULL_DAY' 3-value CHECK (FULL_DAY, HALF_DAY, SPECIFIC_PERIODS), grade_level TEXT, subject TEXT, special_requirements TEXT, posted_by UUID FK NOT NULL, status TEXT NOT NULL DEFAULT 'OPEN' 5-value CHECK (OPEN, FILLED, CANCELLED, EXPIRED, UNFILLED), acceptance_window_minutes INT DEFAULT 30, notification_tier TEXT DEFAULT 'POOL' 2-value CHECK (POOL, MARKETPLACE), escalate_to_marketplace_at TIMESTAMPTZ nullable. INDEX(school_id, status, job_date). Emits sub.job.posted.
  3. sub_job_classes — job_id UUID FK NOT NULL, timetable_slot_id UUID FK(sch_timetable_slots) NOT NULL, class_name TEXT NOT NULL (snapshot), room_name TEXT (snapshot), period_label TEXT. INDEX(job_id). The specific classes/periods the substitute will cover.
  4. sub_job_notifications — job_id UUID FK NOT NULL, substitute_id UUID NOT NULL (soft to platform_substitute_profiles), notified_at TIMESTAMPTZ NOT NULL, response TEXT DEFAULT 'PENDING' 4-value CHECK (PENDING, ACCEPTED, DECLINED, EXPIRED), responded_at TIMESTAMPTZ, acceptance_window_expires_at TIMESTAMPTZ NOT NULL. INDEX(job_id, response, acceptance_window_expires_at). Partial INDEX(acceptance_window_expires_at) WHERE response='PENDING' for expiry sweep.
Produces → 4 tenant tables. Migration: 119_sub_jobs.sql.
03Tenant Schema — Assignments + Ratings + Notes + Pay + Policies (5 tables)
Schema
  1. sub_assignments — job_id UUID FK UNIQUE, substitute_id UUID FK NOT NULL (soft to platform_substitute_profiles), confirmed_at TIMESTAMPTZ, check_in_at TIMESTAMPTZ, check_out_at TIMESTAMPTZ, status TEXT NOT NULL DEFAULT 'CONFIRMED' 5-value CHECK (CONFIRMED, CHECKED_IN, CHECKED_OUT, NO_SHOW, CANCELLED), cancelled_at TIMESTAMPTZ, cancelled_by_type TEXT 2-value CHECK (SCHOOL, SUBSTITUTE), cancellation_reason TEXT, is_late_cancellation BOOLEAN DEFAULT false, late_cancellation_consequence_applied BOOLEAN DEFAULT false. INDEX(substitute_id, job_date) via JOIN to sub_job_postings. Emits sub.assignment.confirmed + sub.assignment.late_cancelled.
  2. sub_ratings — assignment_id UUID FK NOT NULL, rater_type TEXT NOT NULL 2-value CHECK (SCHOOL_RATES_SUB, SUB_RATES_SCHOOL), overall_score NUMERIC(2,1) CHECK(1.0–5.0), professionalism NUMERIC(2,1), punctuality NUMERIC(2,1), comments TEXT, rated_at TIMESTAMPTZ. UNIQUE(assignment_id, rater_type). Bidirectional: one rating each direction per assignment. On INSERT: re-materialise platform_substitute_profiles.overall_rating.
  3. sub_session_notes — assignment_id UUID FK NOT NULL UNIQUE, notes_text TEXT NOT NULL (what was covered, class behaviour, concerns), homework_set TEXT, is_visible_to_teacher BOOLEAN DEFAULT true, submitted_at TIMESTAMPTZ NOT NULL. On INSERT (if is_visible_to_teacher): Task Worker creates notification for the returning teacher.
  4. sub_pay_rates — school_id UUID, substitute_id UUID NOT NULL DEFAULT '00000000-0000-0000-0000-000000000000' (sentinel UUID = school default rate), job_type TEXT, rate NUMERIC(8,2), rate_type TEXT NOT NULL 3-value CHECK (HOURLY, DAILY, HALF_DAY), effective_from DATE, effective_to DATE. EXCLUDE USING gist (school_id WITH =, substitute_id WITH =, job_type WITH =, daterange(effective_from, COALESCE(effective_to,'infinity'),'[)') WITH &&). Per-substitute rates override school defaults.
  5. sub_cancellation_policies — school_id UUID NOT NULL UNIQUE, late_window_hours INT NOT NULL DEFAULT 2, consequence TEXT NOT NULL DEFAULT 'WARNING_ONLY' 4-value CHECK (WARNING_ONLY, TEMPORARY_POOL_SUSPENSION, PERMANENT_POOL_REMOVAL, RATING_PENALTY), suspension_duration_days INT, repeat_offence_threshold INT NOT NULL DEFAULT 3, updated_by UUID FK, updated_at TIMESTAMPTZ. CancellationPolicyWorker checks is_late_cancellation and applies configured consequence.
Produces → 5 tenant tables. Migration: 120_sub_assignments.sql. Total P2-9 tables: 13 (4 platform + 9 tenant).

05Substitute Profile NestJS Module (Platform)
Code
  1. SubstituteProfileService — POST /substitutes/profile (create/update own profile), GET /substitutes/profile/:id, GET /substitutes/search (matching engine: filters by grade_levels, subject_areas, availability for date, verified credentials, not BLOCKED for requesting school, not already assigned that day). POST /substitutes/credentials (upload credential), PATCH /substitutes/credentials/:id (admin verifies).
  2. SubstituteAvailabilityService — GET /substitutes/availability (own), POST /substitutes/availability (set recurring/specific/blocked), DELETE /substitutes/availability/:id. GET /substitutes/:id/availability/:date (is this sub available on this date? resolves RECURRING minus BLOCKED).
  3. SubstitutePreferenceService — GET /substitutes/preferences (own school preferences), POST /substitutes/preferences, DELETE /substitutes/preferences/:id.
Produces → 3 services, ~14 endpoints.
06Job Posting + Matching NestJS Module (Tenant)
Code
  1. SchoolPoolService — GET /substitutes/pool (school's curated pool), POST /substitutes/pool (add sub to pool), PATCH /substitutes/pool/:id (suspend/remove). GET /substitutes/pool/available/:date (pool members available on this date).
  2. JobPostingService — POST /substitutes/jobs (post job with classes; emits sub.job.posted), GET /substitutes/jobs (admin: all jobs; substitute: jobs I'm notified about), PATCH /substitutes/jobs/:id (cancel/expire).
  3. JobNotificationWorker — On sub.job.posted: Tier 1 (POOL): notify school pool members who match (availability + credentials + not BLOCKED). Set acceptance_window_expires_at. Tier 2 (MARKETPLACE): if escalate_to_marketplace_at passes with no acceptance, notify wider marketplace. AcceptanceExpiryWorker: polls PENDING notifications past acceptance_window_expires_at → flips to EXPIRED.
  4. JobResponseService — POST /substitutes/jobs/:jobId/accept (substitute accepts; validates window not expired; creates sub_assignments; job status → FILLED; emits sub.assignment.confirmed; links to sch_cover_arrangements), POST /substitutes/jobs/:jobId/decline.
Produces → 4 services + 2 workers, ~12 endpoints, 2 Kafka emits.
07Assignment + Ratings + Notes + Pay + Cancellation NestJS Module
Code
  1. AssignmentService — POST /substitutes/assignments/:id/check-in, POST /substitutes/assignments/:id/check-out, POST /substitutes/assignments/:id/cancel (checks cancellation policy: if within late_window_hours → is_late_cancellation=true, emits sub.assignment.late_cancelled), GET /substitutes/assignments (substitute: my assignments; admin: all).
  2. CancellationPolicyWorker — On sub.assignment.late_cancelled: counts late cancellations for this substitute at this school. If count ≥ repeat_offence_threshold: applies escalated consequence (TEMPORARY_POOL_SUSPENSION → sets sub_school_pool.status=SUSPENDED + suspended_until).
  3. RatingService — POST /substitutes/assignments/:id/rate (bidirectional: school rates sub OR sub rates school per rater_type). On INSERT: re-materialise platform_substitute_profiles.overall_rating as AVG of all SCHOOL_RATES_SUB ratings.
  4. SessionNoteService — POST /substitutes/assignments/:id/notes (substitute writes handover notes + homework set), GET /substitutes/assignments/:id/notes (teacher: sees notes if is_visible_to_teacher=true).
  5. PayRateService — GET /substitutes/pay-rates, POST /substitutes/pay-rates (EXCLUDE gist enforces no overlapping date ranges), GET /substitutes/assignments/:id/pay (compute: per-substitute rate if exists, else school default).
  6. CancellationPolicyService — GET /substitutes/cancellation-policy, PATCH /substitutes/cancellation-policy.
Produces → 6 services + 1 worker, ~16 endpoints, 1 Kafka emit. Total P2-9 endpoints: ~42.

09Vertical Slice Integration Test
Test
  1. Profile + credentials: Substitute creates profile. Uploads 2 credentials. Admin verifies 1. Verify matching engine only returns VERIFIED credentials. Verify expiry alert at 60 days.
  2. Availability: Set RECURRING Mon-Thu. Set BLOCKED next Tuesday. Verify availability check for next Tuesday returns false (BLOCKED overrides RECURRING). Verify Monday returns true.
  3. School pool + preferences: Admin adds sub to pool. Sub sets BLOCKED for another school. Verify matching excludes BLOCKED school. Verify PREFERRED school prioritised in notification order.
  4. Job posting + tiered notification: Post job. Verify POOL members notified first. Verify acceptance_window_expires_at set. Acceptance window expires → EXPIRED. Verify escalation to MARKETPLACE after delay.
  5. Accept + assignment: Sub accepts within window. Verify sub_assignments created. Verify job status=FILLED. Verify sub.assignment.confirmed fires. Verify sch_cover_arrangements linkable. Second sub tries to accept same job → 409 (already filled).
  6. Check-in/out + session notes: Sub checks in (stamps check_in_at). Checks out. Writes session notes with homework. Verify returning teacher notified (if is_visible_to_teacher=true).
  7. Late cancellation + policy: Sub cancels within 2-hour window. Verify is_late_cancellation=true. Verify sub.assignment.late_cancelled fires. CancellationPolicyWorker: first offence → WARNING. Third offence → TEMPORARY_POOL_SUSPENSION for configured days.
  8. Bidirectional ratings: School rates sub (overall 4.5). Sub rates school (overall 4.0). Verify UNIQUE(assignment_id, rater_type). Verify platform profile.overall_rating re-materialised.
  9. Pay rate resolution: School default $180/day. Per-substitute override $200/day. Verify assignment pay computes $200 (override wins). Remove override. Verify falls back to $180.
  10. Visibility: Substitute sees own profile + jobs + assignments. Cannot see other substitutes' profiles. Teacher sees session notes for their classes. Admin manages pool + jobs + ratings + pay. Substitute cannot modify pay rates or cancellation policies.
Produces → Verified sub marketplace: profile → pool → job posting → tiered notification → accept → assignment → session notes → ratings → cancellation policy → pay rates.
