Cycle 15: Meetings &
Conferences

Conference scheduling with bookable time-slot grids, structured meetings with agendas and action items, meeting notes with parent-visibility controls, recording consent tracking, IEP meeting records linking to Cycle 10's health plans, and parent-teacher conference self-service booking. Builds on Cycle 14's messaging foundation.
May 2026 · 10 Steps · ERD v11 · M41 Meetings (13 tables — 11 core in scope, 2 AI deferred)

Plan Overview

Cycle 15 builds the M41 Meetings module — 11 of the 13 ERD tables. This is the first module where parents are active schedulers rather than passive recipients: parents self-service book parent-teacher conference slots through the time-slot grid. The module bridges Cycle 10's IEP plans (via mtg_iep_meeting_records) and Cycle 14's messaging (meeting invitations and follow-ups flow through the messaging thread system).

The module spans 4 domains: (1) conference event containers + meeting types, (2) meetings with participants + bookable time slots + agenda items, (3) meeting notes with parent-visibility controls + action items with assignee tracking, and (4) recording consent + IEP meeting records. The AI-powered transcription and minutes generation tables (mtg_transcription_jobs, mtg_ai_minutes_jobs) are deferred to Cycle 15.1 because they require external service integration (AWS Transcribe / Whisper).

Privacy — Meeting Notes Parent Visibility

mtg_meeting_notes has a two-layer visibility gate. is_parent_visible is a teacher-controlled flag — when false, parents never see the notes. When true AND is_approved is true, parents see either the parent_visible_summary (a separate teacher-authored summary for parents) or the full notes_text if no summary is provided. Counselling or sensitive content should NEVER have is_parent_visible=true. The service enforces this via a warning on IEP-linked meetings.

Vertical Slice Deliverable

Admin creates a "Spring Parent-Teacher Conferences" event (PARENT_TEACHER, May 15–16) → Rivera sets availability by creating 15-minute time slots across both days → David Chen (parent) browses available slots and books a slot with Rivera to discuss Maya's progress → Rivera conducts the meeting, logs notes with is_parent_visible=true and a separate parent-facing summary → Rivera creates 2 action items (1 for himself: "Send additional reading materials", 1 for David: "Practice multiplication at home") → Rivera approves the notes → David sees the parent summary on his portal → Admin schedules an IEP review meeting for Maya, linking it to her Cycle 10 IEP plan → the IEP meeting record captures attendee roles and outcomes → Cycle 11's svc_mtss_team_meetings.meeting_id soft FK resolves to this meeting.

What's In / What's Deferred

In scope (11 tables): mtg_conference_events, mtg_meeting_types, mtg_meetings, mtg_meeting_participants, mtg_meeting_slots, mtg_agenda_items, mtg_meeting_notes, mtg_action_items, mtg_recordings, mtg_recording_consents, mtg_iep_meeting_records. Functions MTG-001 and MTG-002.

Deferred to Cycle 15.1 (2 tables): mtg_transcription_jobs (requires AWS Transcribe or Whisper integration), mtg_ai_minutes_jobs (requires AI inference service for summary + action-item extraction). Both tables' schemas are partition-ready; the service integration is the blocker.

Also deferred: Video meeting URL auto-generation (external video platform integration — manual URL entry this cycle). Calendar integration for meeting invitations (Cycle 3 calendar surface exists; the bi-directional sync is future). Conference slot auto-generation from teacher timetable gaps (manual slot creation this cycle). Recording upload to S3 (schema ready with s3_key; actual upload flow requires the video processing extracted service).

Step-by-Step Build Plan

01 Conference + Meeting Schema
Schema

Conference event containers, configurable meeting types, individual meetings with participant tracking, and bookable time slots for parent-teacher conferences.

Tables (5)
  1. mtg_conference_events — school_id UUID, title TEXT NOT NULL, conference_type TEXT NOT NULL 5-value CHECK (PARENT_TEACHER, STAFF, BOARD, IEP, TRAINING), start_date DATE NOT NULL, end_date DATE NOT NULL, status TEXT NOT NULL DEFAULT 'SCHEDULED' 4-value CHECK (SCHEDULED, ACTIVE, COMPLETED, CANCELLED). INDEX(school_id, start_date DESC). The conference is the top-level container; individual meetings and slots hang under it.
  2. mtg_meeting_types — school_id UUID, name TEXT NOT NULL, default_duration_minutes INT, is_video BOOLEAN DEFAULT false. UNIQUE(school_id, name). Seeded types: "Parent-Teacher Conference", "Staff Meeting", "IEP Review", "Department Meeting".
  3. mtg_meetings — school_id UUID, meeting_type_id UUID FK, title TEXT NOT NULL, scheduled_at TIMESTAMPTZ NOT NULL, duration_minutes INT, meeting_url TEXT nullable (manual entry for video links this cycle), status TEXT NOT NULL DEFAULT 'SCHEDULED' 4-value CHECK (SCHEDULED, IN_PROGRESS, COMPLETED, CANCELLED), organiser_id UUID FK(platform_users) NOT NULL. INDEX(school_id, scheduled_at DESC). The meeting may be standalone or linked to a conference event via the slot system.
  4. mtg_meeting_participants — meeting_id UUID FK NOT NULL, participant_id UUID NOT NULL (soft to platform_users), role TEXT NOT NULL DEFAULT 'ATTENDEE' 4-value CHECK (HOST, PRESENTER, ATTENDEE, OBSERVER), attended BOOLEAN DEFAULT false, join_at TIMESTAMPTZ, leave_at TIMESTAMPTZ. UNIQUE(meeting_id, participant_id). INDEX(participant_id, meeting_id) for "my meetings" view.
  5. mtg_meeting_slots — PTC BOOKING KEYSTONE. meeting_id UUID FK NOT NULL (the parent meeting under the conference), start_time TIMESTAMPTZ NOT NULL, end_time TIMESTAMPTZ NOT NULL, is_booked BOOLEAN DEFAULT false, booked_by UUID FK nullable (soft to platform_users — the parent who booked). INDEX(meeting_id, start_time). Partial INDEX(meeting_id) WHERE is_booked=false for the available-slots picker. The Step 4 service uses SELECT FOR UPDATE on the slot row to prevent double-booking.
Produces → 5 new tables. Migration: 051_mtg_conferences_meetings.sql.
02 Notes + Actions + Recording + IEP Schema
Schema

Meeting agendas, notes with the two-layer parent-visibility gate, action items with assignee tracking, recording metadata with consent collection, and IEP meeting records linking to the Cycle 10 health module.

Tables (6)
  1. mtg_agenda_items — meeting_id UUID FK NOT NULL, title TEXT NOT NULL, presenter_id UUID FK nullable, duration_minutes INT, sort_order INT NOT NULL, notes TEXT. INDEX(meeting_id, sort_order).
  2. mtg_meeting_notes — PARENT-VISIBILITY KEYSTONE. meeting_id UUID FK UNIQUE NOT NULL (one notes record per meeting), notes_text TEXT, is_approved BOOLEAN DEFAULT false, approved_by UUID FK nullable, is_parent_visible BOOLEAN DEFAULT false, parent_visible_summary TEXT nullable. Multi-column approved_chk: is_approved=true requires approved_by NOT NULL; is_approved=false requires approved_by IS NULL. Parent sees notes only when BOTH is_parent_visible=true AND is_approved=true; they see parent_visible_summary when provided, otherwise full notes_text.
  3. mtg_action_items — meeting_id UUID FK NOT NULL, assignee_id UUID FK NOT NULL (soft to platform_users — covers both staff and parent assignees), description TEXT NOT NULL, due_date DATE, status TEXT NOT NULL DEFAULT 'OPEN' 4-value CHECK (OPEN, IN_PROGRESS, DONE, CANCELLED). INDEX(assignee_id, status) for "my action items" dashboard.
  4. mtg_recordings — meeting_id UUID FK UNIQUE NOT NULL, s3_key TEXT nullable (populated when recording is uploaded), duration_seconds INT, file_size_bytes BIGINT, status TEXT NOT NULL DEFAULT 'PROCESSING' 3-value CHECK (PROCESSING, AVAILABLE, FAILED), consent_confirmed BOOLEAN DEFAULT false (true only when all required participants have consented). Signed S3 URLs with 15–60 min expiry at read time.
  5. mtg_recording_consents — recording_id UUID FK NOT NULL, participant_id UUID NOT NULL. UNIQUE(recording_id, participant_id). consent_given BOOLEAN NOT NULL, consented_at TIMESTAMPTZ. All participants must consent before mtg_recordings.consent_confirmed flips true and the recording becomes accessible.
  6. mtg_iep_meeting_records — CROSS-CYCLE INTEGRATION. meeting_id UUID FK NOT NULL, student_id UUID (soft to sis_students), iep_plan_id UUID (soft to hlth_iep_plans — Cycle 10), attendee_roles JSONB (structured: [{personId, role, name}]), outcomes_summary TEXT, next_review_date DATE. Resolves Cycle 11's svc_mtss_team_meetings.meeting_id soft FK.
Produces → 6 new tables. Migration: 052_mtg_notes_recording_iep.sql. Total Cycle 15 tables: 11.

04 Conference + Meeting NestJS Module
Code
Services & Endpoints
  1. ConferenceService — GET /meetings/conferences (active + upcoming for the school), GET /meetings/conferences/:id (with inlined slot availability stats), POST /meetings/conferences (admin), PATCH /meetings/conferences/:id (status transitions).
  2. 09 Recording + Consent UI
UI
Pages
  1. Recording Panel (inline on meeting detail) — when a recording exists: status pill (PROCESSING amber / AVAILABLE emerald / FAILED rose). Consent status bar showing N of M participants consented. When consent_confirmed=true: playback player with signed S3 URL. When consent_confirmed=false: "Recording available once all participants consent" message.
  2. Consent Collection Modal — opens for each participant when they first view a meeting with a PROCESSING or AVAILABLE recording. "This meeting was recorded. Do you consent to the recording being stored and accessible to meeting participants?" with Accept/Decline buttons. Decline sets consent_given=false; the recording remains inaccessible until all participants have consented.
  3. Recording Upload (staff-only) — placeholder upload form on the meeting detail page. Creates the mtg_recordings row with status=PROCESSING. Actual S3 upload integration deferred to when the video processing extracted service ships.
Produces → Recording panel with consent tracking, consent collection modal, upload placeholder.
10 Vertical Slice Integration Test
Test
Test Script
  1. Conference creation + slot grid: Admin creates PTC conference event. Rivera creates 6 time slots (3 per day). Verify available-slots query returns 6.
  2. Parent booking keystone: David Chen books slot #1 (SELECT FOR UPDATE prevents double-book). Verify is_booked=true + booked_by=David. Verify participant row auto-created. Second parent attempts same slot → 400 "Slot is already booked."
  3. Meeting lifecycle: Rivera conducts the PTC meeting. PATCH status SCHEDULED → IN_PROGRESS → COMPLETED. Verify participant attendance tracked.
  4. Notes + parent-visibility keystone: Rivera writes notes with is_parent_visible=true + parent_visible_summary. Approves. David sees the summary (not full notes_text). Student sees nothing. Staff sees full notes. Rivera toggles is_parent_visible=false → David no longer sees notes.
  5. Action items: Rivera creates 2 action items (1 self-assigned, 1 to David). David sees "Practice multiplication at home" in his action items dashboard. David marks it DONE.
  6. IEP meeting record: Admin creates IEP review meeting. Creates IEP meeting record linking to Maya's Cycle 10 IEP plan. Verify attendee_roles JSONB populated. Verify the Cycle 11 svc_mtss_team_meetings.meeting_id soft FK can now reference this meeting.
  7. Recording consent: Staff creates recording placeholder. Consent modal shows for each participant. Rivera consents (consent_given=true). Until all participants consent, recording is inaccessible. After all consent, consent_confirmed=true and playback is available.
  8. Booking cancellation: David cancels his slot. Verify is_booked=false + booked_by=null. Slot reappears in available grid.
  9. Visibility: Parent sees own bookings, parent-visible approved notes, and own action items. Cannot see other parents' bookings. Cannot create meetings or conferences. Student sees meeting schedule but not notes or action items.
  10. Kafka emit: Verify mtg.meeting.scheduled fires on meeting creation with ADR-057 envelope.
Produces → Verified meetings lifecycle: conference → slot booking → meeting → notes with parent visibility → action items → IEP record → recording consent.
