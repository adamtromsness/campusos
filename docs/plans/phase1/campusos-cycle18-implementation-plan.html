Plan Overview

Cycle 18 builds the M103 Groups & Communities module — all 7 ERD tables. This is a compact, clean greenfield with a new table prefix (grp_). Unlike every prior module which serves a specific operational domain, Groups is a horizontal fabric layer — it provides the shared social structure that other modules reference. Cycle 17's ext_activities.group_id soft FK, Cycle 13's future athletics team communities, and Cycle 14's messaging thread types all connect through grp_groups as the universal community container.

The module spans 3 domains: (1) groups with scope-aware binding (CLASS / YEAR_GROUP / SCHOOL / CUSTOM / ACTIVITY scopes) + membership with a 3-tier role hierarchy + two-party ownership transfer, (2) group-scoped announcements with read receipts + pinning, and (3) group events with RSVP and public/private visibility. The auto_dissolve_at column on groups enables temporary communities (e.g., a field trip group that auto-archives after the trip date).

Admin creates a "Grade 5 Parents" group (scope=YEAR_GROUP, membership approval required) → David Chen requests to join → admin approves → Rivera creates a "Chess Club Community" group (scope=ACTIVITY, linked to Cycle 17's Chess Club via group_id) → Maya and Ethan auto-join as members when their club membership is active → Rivera (OWNER) posts a pinned announcement "Tournament Registration Open" → Maya reads the announcement (read receipt tracked) → Rivera creates a group event "Chess Tournament" with RSVP required → David Chen (parent) sees the announcement in "Grade 5 Parents" but NOT in Chess Club (scope-gated) → Rivera initiates ownership transfer to Mitchell → Mitchell accepts → Rivera becomes ADMIN, Mitchell becomes OWNER → admin creates a temporary "Spring Concert Volunteers" group with auto_dissolve_at set to concert date + 7 days.

Step-by-Step Build Plan

01 Groups + Members + Ownership Schema
Schema

The group container with 5 scope types, membership with a 3-tier role hierarchy and 6-state lifecycle, per-member notification preferences, and the two-party ownership transfer handshake.

Tables (4)
  1. grp_groups — school_id UUID, name TEXT NOT NULL, description TEXT, scope_type TEXT NOT NULL 5-value CHECK (CLASS, YEAR_GROUP, SCHOOL, CUSTOM, ACTIVITY), scope_id UUID nullable (soft to sis_classes / sis_academic_years / ext_activities per scope_type; NULL for SCHOOL + CUSTOM), status TEXT NOT NULL DEFAULT 'ACTIVE' 3-value CHECK (ACTIVE, ARCHIVED, DISSOLVED), join_policy TEXT NOT NULL DEFAULT 'OPEN' 3-value CHECK (OPEN, APPROVAL_REQUIRED, INVITE_ONLY), auto_dissolve_at TIMESTAMPTZ nullable (for temporary groups), created_by UUID NOT NULL (soft to platform_users), avatar_url TEXT nullable. INDEX(school_id, status). INDEX(scope_type, scope_id) for scope-aware lookups. Partial INDEX WHERE auto_dissolve_at IS NOT NULL AND status='ACTIVE' for the dissolve sweep.
  2. grp_members — group_id UUID FK NOT NULL, person_id UUID NOT NULL (soft to platform_users — covers all personas: students, teachers, parents, staff), member_role TEXT NOT NULL DEFAULT 'MEMBER' 3-value CHECK (OWNER, ADMIN, MEMBER), status TEXT NOT NULL DEFAULT 'ACTIVE' 6-value CHECK (ACTIVE, INVITED, PENDING_APPROVAL, SUSPENDED, LEFT, REMOVED), joined_at TIMESTAMPTZ, invited_by UUID nullable, left_at TIMESTAMPTZ nullable, suspension_reason TEXT nullable. Partial UNIQUE(group_id, person_id) WHERE status != 'LEFT' — allows re-join after leaving. INDEX(person_id, status) WHERE status='ACTIVE' for "my groups" view. INDEX(group_id, member_role) WHERE member_role IN ('OWNER','ADMIN') for the admin roster.
  3. grp_member_notification_prefs — Per-member per-group notification settings. membership_id UUID FK UNIQUE NOT NULL, notify_announcements BOOLEAN DEFAULT true, notify_events BOOLEAN DEFAULT true, notify_membership_changes BOOLEAN DEFAULT false, notify_results BOOLEAN DEFAULT true, preferred_channel TEXT NOT NULL DEFAULT 'IN_APP' 5-value CHECK (IN_APP, EMAIL, PUSH, ALL, NONE), quiet_hours_override BOOLEAN DEFAULT false.
  4. grp_ownership_transfers — TWO-PARTY HANDSHAKE. group_id UUID FK NOT NULL, from_member_id UUID FK(grp_members) NOT NULL (current owner), to_member_id UUID FK(grp_members) NOT NULL (incoming owner — must be ACTIVE member), transfer_reason TEXT, status TEXT NOT NULL DEFAULT 'PENDING' 5-value CHECK (PENDING, ACCEPTED, DECLINED, EXPIRED, CANCELLED), initiated_at TIMESTAMPTZ NOT NULL, expires_at TIMESTAMPTZ NOT NULL (default: +7 days), responded_at TIMESTAMPTZ. Partial UNIQUE(group_id) WHERE status='PENDING' — at most one pending transfer per group. On ACCEPTED: from_member becomes ADMIN, to_member becomes OWNER (inside one tx).
Produces → 4 new tables. Migration: 059_grp_groups_members.sql.
02 Announcements + Events Schema
Schema

Group-scoped announcements with pinning and read receipt tracking, and group events with RSVP and public/private visibility.

Tables (3)
  1. grp_announcements — group_id UUID FK NOT NULL, author_id UUID NOT NULL (soft to iam_person; must be OWNER or ADMIN — app-layer validated), title TEXT NOT NULL, body TEXT NOT NULL, pinned BOOLEAN DEFAULT false, attachments JSONB nullable, publish_at TIMESTAMPTZ NOT NULL, expires_at TIMESTAMPTZ nullable. INDEX(group_id, publish_at DESC). Partial INDEX(group_id, pinned) WHERE pinned=true. On INSERT: fan out via Cycle 3 NotificationWorker per grp_member_notification_prefs.notify_announcements.
  2. grp_announcement_reads — Append-only read receipts. announcement_id UUID FK NOT NULL, reader_id UUID NOT NULL (soft to iam_person). UNIQUE(announcement_id, reader_id). read_at TIMESTAMPTZ NOT NULL.
  3. grp_events — group_id UUID FK NOT NULL, created_by UUID NOT NULL (soft to iam_person), title TEXT NOT NULL, description TEXT, location TEXT, starts_at TIMESTAMPTZ NOT NULL, ends_at TIMESTAMPTZ, event_type TEXT NOT NULL 7-value CHECK (PRACTICE, MATCH, MEETING, SOCIAL, PERFORMANCE, COMPETITION, OTHER), requires_rsvp BOOLEAN DEFAULT false, rsvp_deadline TIMESTAMPTZ nullable, max_attendees INT nullable, is_public BOOLEAN DEFAULT false (when true: visible to non-members). INDEX(group_id, starts_at DESC). On INSERT: fan out per notify_events.
Produces → 3 new tables. Migration: 060_grp_announcements_events.sql. Total Cycle 18 tables: 7.

04 Groups + Membership NestJS Module
Code
Services & Endpoints
  1. GroupService — GET /groups (browse: my groups + public groups; filters scope_type, status), GET /groups/:id (with member count + recent announcements + upcoming events inlined), POST /groups (any authenticated user creates; creator becomes OWNER; admin can set scope bindings), PATCH /groups/:id (owner/admin updates name, description, join_policy, avatar), PATCH /groups/:id/archive (owner/admin; ACTIVE → ARCHIVED).
  2. MembershipService — POST /groups/:id/join (self-service: OPEN groups → ACTIVE immediately; APPROVAL_REQUIRED → PENDING_APPROVAL; INVITE_ONLY → 403), POST /groups/:id/invite (owner/admin invites; creates INVITED member), PATCH /group-members/:id/approve (owner/admin approves PENDING_APPROVAL → ACTIVE), PATCH /group-members/:id/remove (owner/admin removes), PATCH /group-members/:id/leave (self-service; owner cannot leave — must transfer first), PATCH /group-members/:id/role (owner promotes/demotes ADMIN/MEMBER), PATCH /group-members/:id/notification-prefs (member updates own prefs). GET /groups/my (my active memberships across all groups).
  3. OwnershipTransferService — POST /groups/:id/transfer (TWO-PARTY HANDSHAKE: owner initiates; validates target is ACTIVE member; partial UNIQUE prevents concurrent transfers), PATCH /group-transfers/:id/accept (target accepts; inside one tx: from_member role → ADMIN, to_member role → OWNER), PATCH /group-transfers/:id/decline, PATCH /group-transfers/:id/cancel (initiator cancels).
Produces → GroupsModule with 3 services, ~16 endpoints.
05 Announcements + Events NestJS Module
Code
Services & Endpoints
  1. GroupAnnouncementService — GET /groups/:id/announcements (members only; pinned first, then by publish_at DESC; expired filtered out), POST /groups/:id/announcements (owner/admin posts; emits grp.announcement.posted; fan-out per notification prefs), PATCH /group-announcements/:id (author edits; toggle pinned), DELETE /group-announcements/:id (owner/admin). POST /group-announcements/:id/read (member marks read; UNIQUE prevents duplicates). GET /groups/:id/announcements/:id/reads (owner/admin sees read receipts with count + reader names).
  2. GroupEventService — GET /groups/:id/events (members see all; non-members see only is_public=true), POST /groups/:id/events (owner/admin creates; emits grp.event.created), PATCH /group-events/:id, DELETE /group-events/:id. POST /group-events/:id/rsvp (member RSVPs; validates max_attendees + rsvp_deadline). GET /group-events/:id/attendees (RSVP list).
Produces → 2 services, ~12 endpoints, 2 Kafka emits (grp.announcement.posted + grp.event.created). Total Cycle 18 endpoints: ~28.
