Cycle 21: Facilities
Management

Building and space registry with the scheduling-module cross-link, space bookings with conflict detection, proactive work orders with immutable activity timelines and vendor assignment, preventive maintenance with checklist-driven task completion, compliance inspections with violation tracking and escalation, custodial zone management, and supply inventory. The Facilities Manager (FM) is the eighth specialist operator persona.
May 2026 · 10 Steps · ERD v11 · M65 Facilities Management (37 tables — 16 core in scope, 21 deferred) · FAC-001 through FAC-005 · ADR-034

Plan Overview

Cycle 21 builds the M65 Facilities Management module — 16 of the 37 ERD tables. This is the third Campus Operations module and the first to manage the physical plant of the school: buildings, rooms, outdoor spaces, and the maintenance infrastructure that keeps them operational. Per ADR-034, Facilities owns where custodians work (zone assignments); HR (Cycle 4) owns when they work (shifts). The M60 Service Tickets module (Cycle 8) handles reactive requests from staff; M65 handles proactive operational work.

The module spans 5 domains per ADR-034: (1) building + space registry with the sch_rooms cross-link, space bookings, and temporary closures, (2) proactive work orders with immutable activity timelines, vendor assignment, and cost-approval integration, (3) preventive maintenance plans with checklist-driven tasks and immutable completion results, (4) compliance inspections with violation tracking, due-date escalation, and linked corrective work orders, and (5) custodial zone assignments + supply inventory.

Vertical Slice Deliverable

FM registers Main Building (3 floors, built 2005) → adds 12 spaces (classrooms, gym, cafeteria, corridors) with sch_room_id cross-links for the 6 classrooms → teacher books the gym for a Grade 5 assembly (conflict detection prevents double-booking) → FM creates a REPAIR work order for a leaking pipe in Room 101, assigns Custodian Martinez, priority=HIGH → Martinez logs STATUS_CHANGE to IN_PROGRESS (immutable activity row) → completes the work order with notes → FM creates a "Monthly HVAC Inspection" preventive maintenance plan with a 6-item checklist (filters, belts, thermostat, ductwork, refrigerant, drainage) → generates a task for May → technician completes 5 items PASS + 1 FAIL (belt worn) → FAIL auto-creates a follow-up work order → County Fire Marshal conducts annual fire inspection → outcome: PASSED_WITH_CONDITIONS → 1 violation logged (emergency exit signage faded, MAJOR, due in 30 days) → FM creates corrective work order linked to the violation → FM assigns Custodian Martinez to Zone A (Main Building ground floor) for the MORNING shift → supply inventory shows floor cleaner at 3 units (below reorder threshold of 5) → fac.supply.reorder_needed emits.

Step-by-Step Build Plan

01Buildings + Spaces + Bookings Schema
Schema

Building registry, space catalogue with the scheduling module cross-link, space bookings with conflict detection, and temporary closures that advisory-block scheduling.

Tables (4)
  1. fac_buildings — school_id UUID, name TEXT NOT NULL, code TEXT, year_built INT, total_floors INT, address TEXT, is_active BOOLEAN DEFAULT true. UNIQUE(school_id, name).
  2. fac_spaces — building_id UUID FK NOT NULL, name TEXT NOT NULL, floor TEXT, space_type TEXT NOT NULL 11-value CHECK (CLASSROOM, BATHROOM, CORRIDOR, STAIRWELL, MECHANICAL, STORAGE, OFFICE, GROUNDS, COMMON_AREA, GYM, CAFETERIA, OTHER), area_sqft NUMERIC(8,1), is_active BOOLEAN DEFAULT true, sch_room_id UUID nullable (DISPLAY-ONLY soft ref to sch_rooms.id — links the facilities view to the scheduling view for classrooms). INDEX(building_id, space_type, is_active).
  3. fac_space_bookings — space_id UUID FK NOT NULL, booked_by UUID NOT NULL (soft to iam_person), title TEXT NOT NULL, starts_at TIMESTAMPTZ NOT NULL, ends_at TIMESTAMPTZ NOT NULL, status TEXT NOT NULL DEFAULT 'CONFIRMED' 3-value CHECK (CONFIRMED, CANCELLED, COMPLETED), notes TEXT. EXCLUDE USING gist (space_id WITH =, tstzrange(starts_at, ends_at) WITH &&) WHERE (status = 'CONFIRMED') — prevents overlapping confirmed bookings at the schema level. INDEX(space_id, starts_at).
  4. fac_space_closures — school_id UUID, space_id UUID FK NOT NULL, closure_reason TEXT NOT NULL, starts_at TIMESTAMPTZ NOT NULL, ends_at TIMESTAMPTZ nullable (null = indefinite), affects_scheduling BOOLEAN DEFAULT true, linked_work_order_id UUID nullable (soft to fac_work_orders), created_by UUID FK NOT NULL. INDEX(space_id, starts_at).
Produces → 4 new tables. Migration: 067_fac_buildings_spaces.sql.
02Work Orders + Preventive Maintenance Schema
Schema

Proactive work orders with immutable activity timelines, vendor assignment with cost-approval gating, and preventive maintenance plans with checklist-driven tasks and immutable completion results.

Tables (6)
  1. fac_work_orders — school_id UUID, work_order_type TEXT NOT NULL 5-value CHECK (REPAIR, INSTALLATION, INSPECTION_PREP, DEEP_CLEAN, RENOVATION), priority TEXT NOT NULL 4-value CHECK (LOW, MEDIUM, HIGH, CRITICAL), space_id UUID FK nullable, building_id UUID FK nullable, assigned_to_id UUID nullable (soft to hr_employees), vendor_id UUID FK(tkt_vendors) nullable, scheduled_date DATE, completed_at TIMESTAMPTZ, status TEXT NOT NULL DEFAULT 'OPEN' 6-value CHECK (OPEN, IN_PROGRESS, VENDOR_ASSIGNED, ON_HOLD, COMPLETED, CANCELLED), tkt_ticket_id UUID nullable (DISPLAY-ONLY soft to tkt_tickets for reactive-originated jobs per ADR-033), cost NUMERIC(8,2), notes TEXT. INDEX(school_id, status, scheduled_date). Emits fac.work_order.created on creation.
  2. fac_work_order_activity — IMMUTABLE timeline. work_order_id UUID FK NOT NULL, actor_id UUID FK NOT NULL, activity_type TEXT NOT NULL 4-value CHECK (STATUS_CHANGE, REASSIGNMENT, COMMENT, ATTACHMENT), metadata JSONB, created_at TIMESTAMPTZ NOT NULL. NO UPDATE, NO DELETE. INDEX(work_order_id, created_at ASC).
  3. fac_preventive_maintenance_plans — school_id UUID, name TEXT NOT NULL, description TEXT, frequency_months INT NOT NULL, target_type TEXT NOT NULL 3-value CHECK (BUILDING, SPACE, SYSTEM), target_id UUID nullable (soft to fac_buildings or fac_spaces per target_type), is_active BOOLEAN DEFAULT true. UNIQUE(school_id, name).
  4. fac_preventive_maintenance_checklist_items — plan_id UUID FK NOT NULL, item_name TEXT NOT NULL, description TEXT, sort_order INT NOT NULL. INDEX(plan_id, sort_order).
  5. fac_preventive_maintenance_tasks — plan_id UUID FK NOT NULL, scheduled_date DATE NOT NULL, assigned_to UUID nullable (soft to hr_employees), status TEXT NOT NULL DEFAULT 'SCHEDULED' 4-value CHECK (SCHEDULED, IN_PROGRESS, COMPLETED, OVERDUE), completed_at TIMESTAMPTZ, completed_by UUID nullable, notes TEXT. INDEX(plan_id, scheduled_date DESC). Emits fac.maintenance_task.overdue when status flips to OVERDUE.
  6. fac_maintenance_checklist_results — IMMUTABLE per-item results. task_id UUID FK NOT NULL, checklist_item_id UUID FK NOT NULL, passed BOOLEAN NOT NULL, notes TEXT, photo_s3_keys TEXT[]. UNIQUE(task_id, checklist_item_id). NO UPDATE once submitted. On FAIL: auto-creates a follow-up fac_work_orders row.
Produces → 6 new tables. Migration: 068_fac_work_orders_pm.sql.
03Inspections + Zones + Supply Schema
Schema

Compliance inspection types with configurable frequency, inspections with immutable outcomes, violation tracking with due-date escalation, custodial zones with employee assignments, and building-level supply inventory.

Tables (6)
  1. fac_inspection_types — school_id UUID, name TEXT NOT NULL, authority TEXT NOT NULL (e.g., "Fire Marshal", "County Health Dept"), frequency_months INT NOT NULL, is_mandatory BOOLEAN DEFAULT true, failure_escalation_days INT. UNIQUE(school_id, name).
  2. fac_inspections — school_id UUID, inspection_type_id UUID FK NOT NULL, building_id UUID FK NOT NULL, scheduled_date DATE, conducted_date DATE, inspector_name TEXT, inspector_agency TEXT, outcome TEXT NOT NULL 4-value CHECK (PASSED, PASSED_WITH_CONDITIONS, FAILED, PENDING), certificate_s3_key TEXT, next_due_date DATE, notes TEXT. IMMUTABLE once outcome is set. INDEX(school_id, inspection_type_id, next_due_date). Emits fac.inspection.failed on FAILED or PASSED_WITH_CONDITIONS.
  3. fac_inspection_violations — inspection_id UUID FK NOT NULL, description TEXT NOT NULL, severity TEXT NOT NULL 3-value CHECK (MINOR, MAJOR, CRITICAL), due_date DATE NOT NULL, resolved_at TIMESTAMPTZ, resolved_by UUID nullable, resolution_notes TEXT, linked_work_order_id UUID nullable (soft to fac_work_orders). INDEX(inspection_id, resolved_at) WHERE resolved_at IS NULL. Emits fac.inspection_violation.overdue when past due_date and unresolved.
  4. fac_zones — school_id UUID, name TEXT NOT NULL, description TEXT, color TEXT. UNIQUE(school_id, name).
  5. fac_zone_assignments — zone_id UUID FK NOT NULL, employee_id UUID (soft to hr_employees), effective_from DATE NOT NULL, effective_to DATE nullable, shift TEXT NOT NULL 4-value CHECK (MORNING, AFTERNOON, EVENING, OVERNIGHT). UNIQUE(zone_id, employee_id, effective_from). Per ADR-034: HR owns when they work; Facilities owns where they are assigned.
  6. fac_supply_inventory — building_id UUID FK NOT NULL, item_name TEXT NOT NULL, unit TEXT NOT NULL, current_quantity NUMERIC(8,2) NOT NULL DEFAULT 0, reorder_threshold NUMERIC(8,2), preferred_supplier TEXT. UNIQUE(building_id, item_name). When current_quantity falls below reorder_threshold: emits fac.supply.reorder_needed.
Produces → 6 new tables. Migration: 069_fac_inspections_zones.sql. Total Cycle 21 tables: 16.

What Gets Seeded

10Vertical Slice Integration Test
Test
Test Script
  1. Building + spaces: FM registers building with 6 spaces. Verify sch_room_id cross-link on 3 classroom spaces.
  2. Space booking + conflict: Teacher books gym for Thursday 2pm. Second booking for same time → 409 (EXCLUDE gist). Non-overlapping booking succeeds.
  3. Space closure: FM closes Room 101 (indefinite, affects_scheduling=true). Verify closure appears in active closures. Reopen with ends_at.
  4. Work order lifecycle: FM creates REPAIR for leaking pipe (HIGH). Assigns Martinez. Activity row: STATUS_CHANGE OPEN→IN_PROGRESS. Martinez completes. Activity row: STATUS_CHANGE IN_PROGRESS→COMPLETED. Verify fac.work_order.created fires. Attempt UPDATE on activity row → rejected (immutable).
  5. PM plan + checklist: FM creates "HVAC Inspection" plan (monthly, 6 items). Generates June task. Technician submits: 5 PASS + 1 FAIL. Verify FAIL auto-creates follow-up work order. Verify checklist results are immutable.
  6. Compliance inspection: FM records fire inspection PASSED_WITH_CONDITIONS. Logs 1 MAJOR violation (due in 30 days). Verify fac.inspection.failed fires. FM creates corrective work order linked to violation. FM resolves violation with work order reference.
  7. Custodial zones: FM creates 2 zones. Assigns Martinez to Zone A MORNING. Verify UNIQUE prevents duplicate (zone, employee, effective_from).
  8. Supply reorder: FM adjusts floor cleaner to 2 units (below threshold 5). Verify fac.supply.reorder_needed fires.
  9. Visibility: Teacher can book spaces and view buildings. Cannot create work orders or manage zones. FM sees all. Staff can see inspection status. Custodian sees own zone assignments.
  10. Cross-module: Work order links to Cycle 8 tkt_ticket via DISPLAY-ONLY ref. Space closure with affects_scheduling=true is advisory for Cycle 5 scheduling.
Produces → Verified facilities lifecycle: building → booking + conflict → work order + timeline → PM + checklist → inspection + violation → zones → supply reorder.
