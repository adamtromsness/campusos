Plan Overview

Cycle 19 builds the M61 Transportation module — 16 of the 38 ERD tables. This is the first Campus Operations module and the first module that extends beyond the school building into the physical world — routes, vehicles, and GPS coordinates. The Transportation Coordinator (TC) is the sixth specialist operator persona after the nurse, counsellor, librarian, athletic director, and enrolment officer.

The module spans 4 domains: (1) route definitions with ordered stops + student-to-route assignments + parent route-change requests, (2) vehicle fleet with documents, pre-trip inspections, and maintenance schedules, (3) driver credentials with CDL/medical/background-check expiry tracking, and (4) ridership scanning with boarding/alighting records + QR-code bus passes + a no-show detection worker. The parent route-change request surface is the fourth parent-active feature (after messaging, conference booking, and application submission).

Safety — Student Safeguarding

The no-show detection worker compares expected ridership (trn_student_assignments) against actual boarding scans (trn_ridership_records) each morning. Students expected on a route but not scanned within the configurable window trigger a trn_no_show_alerts record and a parent notification via Cycle 14's messaging. The trn_route_change_log is an immutable audit trail (no UPDATE, no DELETE) of every modification to route definitions — FERPA safeguarding record with 7-year retention.

Vertical Slice Deliverable

TC creates Route 7 "Elm Street AM" with 5 stops in sequence → assigns Bus #42 (capacity 48) to the route → assigns Driver Martinez with verified CDL + medical cert → assigns Maya and Ethan to stops #2 and #4 with AM direction → generates QR-code bus passes for both students → Driver Martinez completes the pre-trip inspection (tyres, brakes, lights, mirrors — all PASS) → morning run begins → Maya scans her QR pass at stop #2 (BOARDING recorded) → Ethan does NOT board → no-show worker fires after the grace window, creates trn_no_show_alerts row, and sends parent notification → David Chen submits a route-change request for Maya (different stop for Thursday) → TC approves → one-day override created → the route change log captures every modification with before/after snapshots.

Step-by-Step Build Plan

01 Routes + Stops + Assignments Schema
Schema

Route definitions with ordered stops, student-to-stop assignments with direction and date ranges, parent route-change requests with approval workflow, and the immutable route change audit log.

Tables (5)
  1. trn_routes — school_id UUID, name TEXT NOT NULL, direction TEXT NOT NULL 2-value CHECK (AM, PM), vehicle_id UUID nullable (soft to trn_vehicles), driver_id UUID nullable (soft to hr_employees), status TEXT NOT NULL DEFAULT 'ACTIVE' 3-value CHECK (ACTIVE, INACTIVE, ARCHIVED), academic_year_id UUID FK. UNIQUE(school_id, name, direction, academic_year_id).
  2. trn_stops — route_id UUID FK NOT NULL, name TEXT NOT NULL, latitude NUMERIC(9,6), longitude NUMERIC(9,6), sequence_order INT NOT NULL, scheduled_time TIME, address TEXT. INDEX(route_id, sequence_order). The sequence defines the stop-by-stop pickup/dropoff order.
  3. trn_student_assignments — student_id UUID FK(sis_students) NOT NULL, route_id UUID FK NOT NULL, stop_id UUID FK NOT NULL, academic_year_id UUID FK, direction TEXT NOT NULL 3-value CHECK (AM, PM, BOTH), effective_from DATE NOT NULL, effective_to DATE nullable, is_override BOOLEAN DEFAULT false (true for one-day overrides from route-change requests). UNIQUE(student_id, academic_year_id) WHERE is_override=false (one permanent assignment per student per year). INDEX(route_id, stop_id) for per-stop roster.
  4. trn_route_change_requests — Parent-submitted temporary change request. school_id UUID, student_id UUID FK(sis_students) NOT NULL, submitted_by UUID FK NOT NULL, change_date DATE NOT NULL, change_type TEXT NOT NULL 3-value CHECK (DIFFERENT_STOP, NO_BUS, DIFFERENT_ROUTE), requested_stop_id UUID FK nullable, requested_route_id UUID FK nullable, reason TEXT, status TEXT NOT NULL DEFAULT 'PENDING' 3-value CHECK (PENDING, APPROVED, REJECTED), reviewed_by UUID FK nullable, reviewed_at TIMESTAMPTZ. INDEX(student_id, change_date). On APPROVED: creates one-day override assignment.
  5. trn_route_change_log — IMMUTABLE AUDIT. route_id UUID FK NOT NULL, changed_by UUID FK NOT NULL, changed_at TIMESTAMPTZ NOT NULL, change_type TEXT NOT NULL 8-value CHECK (STOP_ADDED, STOP_REMOVED, STOP_REORDERED, STOP_TIME_CHANGED, STUDENT_ADDED, STUDENT_REMOVED, ROUTE_ACTIVATED, ROUTE_DEACTIVATED), stop_id UUID FK nullable, student_id UUID nullable, old_value JSONB, new_value JSONB, reason TEXT. NO UPDATE, NO DELETE at the service layer. FERPA safeguarding record. INDEX(route_id, changed_at DESC). Partition-ready for RANGE(changed_at) monthly.
Produces → 5 new tables. Migration: 061_trn_routes_stops.sql.
02 Fleet + Inspections + Driver Schema
Schema

Vehicle fleet with registration documents and expiry tracking, daily pre-trip safety inspections with per-item pass/fail checklist, scheduled maintenance, and driver credential management with CDL/medical/background check verification.

Tables (6)
  1. trn_vehicles — school_id UUID, registration TEXT NOT NULL, make TEXT, model TEXT, year INT, capacity INT NOT NULL, vehicle_type TEXT NOT NULL 3-value CHECK (BUS, MINIBUS, VAN), status TEXT NOT NULL DEFAULT 'ACTIVE' 3-value CHECK (ACTIVE, MAINTENANCE, RETIRED). UNIQUE(school_id, registration).
  2. trn_vehicle_documents — vehicle_id UUID FK NOT NULL, document_type TEXT NOT NULL 4-value CHECK (INSURANCE, REGISTRATION, MOT, INSPECTION), s3_key TEXT NOT NULL, issued_date DATE, expiry_date DATE NOT NULL, is_current BOOLEAN DEFAULT true. INDEX(vehicle_id, document_type, is_current). Expiry alerts drive the TC dashboard.
  3. trn_pre_trip_inspections — Daily safety check header. vehicle_id UUID FK NOT NULL, driver_id UUID FK(hr_employees) NOT NULL, inspection_date DATE NOT NULL, overall_status TEXT NOT NULL 3-value CHECK (PASS, FAIL, CONDITIONAL), notes TEXT, completed_at TIMESTAMPTZ. UNIQUE(vehicle_id, inspection_date). A FAIL blocks the vehicle from service until resolved.
  4. trn_pre_trip_inspection_items — Per-checklist-item row. inspection_id UUID FK NOT NULL, item_name TEXT NOT NULL (e.g., "Tyres", "Brakes", "Lights", "Mirrors", "Emergency exit", "First aid kit"), status TEXT NOT NULL 3-value CHECK (PASS, FAIL, NOT_APPLICABLE), notes TEXT. INDEX(inspection_id).
  5. trn_maintenance_schedules — vehicle_id UUID FK NOT NULL, service_type TEXT NOT NULL, interval_miles INT, interval_months INT, last_service_date DATE, last_service_mileage INT, next_due_date DATE, next_due_mileage INT, status TEXT NOT NULL DEFAULT 'ON_SCHEDULE' 3-value CHECK (ON_SCHEDULE, DUE_SOON, OVERDUE). INDEX(vehicle_id, next_due_date).
  6. trn_driver_credentials — driver_id UUID FK(hr_employees) NOT NULL, credential_type TEXT NOT NULL 4-value CHECK (CDL, MEDICAL_CERTIFICATE, BACKGROUND_CHECK, FIRST_AID), credential_number TEXT, issued_date DATE NOT NULL, expiry_date DATE NOT NULL, s3_key TEXT, status TEXT NOT NULL DEFAULT 'VALID' 3-value CHECK (VALID, EXPIRING_SOON, EXPIRED), verified_by UUID FK nullable, verified_at TIMESTAMPTZ. UNIQUE(driver_id, credential_type). Expiry status auto-computed: EXPIRING_SOON when within 30 days, EXPIRED when past.
Produces → 6 new tables. Migration: 062_trn_fleet_inspections.sql.
03 Ridership + Passes + Operations Schema
Schema

Student boarding/alighting scan records, QR-code bus passes, route run execution logs, no-show alert records, and delay reports.

Tables (5)
  1. trn_ridership_records — student_id UUID FK(sis_students) NOT NULL, route_id UUID FK NOT NULL, stop_id UUID FK NOT NULL, scan_direction TEXT NOT NULL 2-value CHECK (BOARDING, ALIGHTING), scanned_at TIMESTAMPTZ NOT NULL, scan_method TEXT NOT NULL DEFAULT 'QR_CODE' 3-value CHECK (QR_CODE, MANUAL, RFID). INDEX(student_id, scanned_at DESC). Partition-ready for RANGE(scanned_at) monthly.
  2. trn_bus_passes — student_id UUID FK(sis_students) NOT NULL, academic_year_id UUID FK, pass_type TEXT NOT NULL 3-value CHECK (ANNUAL, TERM, DAILY), qr_code_token TEXT NOT NULL UNIQUE (the scannable token embedded in the QR code), is_active BOOLEAN DEFAULT true, valid_from DATE NOT NULL, valid_to DATE NOT NULL. INDEX(qr_code_token) for the scan-lookup hot path.
  3. trn_route_run_logs — One row per route execution. route_id UUID FK NOT NULL, vehicle_id UUID FK NOT NULL, driver_id UUID FK(hr_employees) NOT NULL, run_date DATE NOT NULL, departure_time TIMESTAMPTZ, arrival_time TIMESTAMPTZ, odometer_start INT, odometer_end INT, students_boarded INT DEFAULT 0, status TEXT NOT NULL DEFAULT 'IN_PROGRESS' 3-value CHECK (IN_PROGRESS, COMPLETED, CANCELLED). INDEX(route_id, run_date DESC).
  4. trn_no_show_alerts — SAFEGUARDING KEYSTONE. student_id UUID FK(sis_students) NOT NULL, route_id UUID FK NOT NULL, expected_date DATE NOT NULL, expected_stop_id UUID FK NOT NULL, alert_time TIMESTAMPTZ NOT NULL, resolution TEXT nullable 4-value CHECK (ABSENT_CONFIRMED, LATE_ARRIVAL, PARENT_NOTIFIED, FALSE_ALARM), resolved_by UUID nullable, resolved_at TIMESTAMPTZ nullable, parent_notified_at TIMESTAMPTZ nullable. INDEX(expected_date, resolution). Emits trn.no_show.detected on creation.
  5. trn_delay_reports — route_id UUID FK NOT NULL, run_date DATE NOT NULL, reported_by UUID FK NOT NULL, delay_minutes INT NOT NULL, reason TEXT NOT NULL, affected_stops TEXT[], parent_notification_sent BOOLEAN DEFAULT false, reported_at TIMESTAMPTZ NOT NULL. INDEX(route_id, run_date DESC). Emits trn.delay.reported for parent notification.
Produces → 5 new tables. Migration: 063_trn_ridership_operations.sql. Total Cycle 19 tables: 16.

05 Routes + Assignments NestJS Module
Code
Services & Endpoints
  1. RouteService — GET /transport/routes, GET /transport/routes/:id (with stops + assignments + vehicle + driver inlined), POST /transport/routes, PATCH /transport/routes/:id. Every mutation writes to trn_route_change_log with old_value/new_value JSONB snapshots.
  2. StopService — GET /transport/routes/:id/stops, POST /transport/routes/:id/stops, PATCH /transport/stops/:id, DELETE /transport/stops/:id. Reorder endpoint: PATCH /transport/routes/:id/stops/reorder (batch update sequence_order). All mutations logged to change log.
  3. AssignmentService — GET /transport/routes/:id/students (per-stop roster), POST /transport/routes/:id/students (assign student to stop), DELETE /transport/student-assignments/:id. GET /transport/my-route (parent/student: own assignment). All mutations logged.
  4. RouteChangeRequestService — GET /transport/route-changes (TC: pending requests), POST /transport/route-changes (parent submits), PATCH /transport/route-changes/:id/approve (TC approves; creates one-day override assignment), PATCH /transport/route-changes/:id/reject.
Produces → TransportModule with 4 services, ~14 endpoints. Immutable change log on every route mutation.

07 Ridership + Operations NestJS Module
Code
Services & Endpoints
  1. RidershipService — POST /transport/ridership/scan (QR SCAN KEYSTONE: accepts qr_code_token + stop_id + direction; resolves student from trn_bus_passes; validates pass active + valid date range; creates ridership record), GET /transport/ridership (TC: per-route per-date ridership report), GET /transport/my-ridership (parent: child's scan history).
  2. BusPassService — GET /transport/bus-passes (TC: all active passes), POST /transport/bus-passes (TC generates pass with unique QR token), PATCH /transport/bus-passes/:id (activate/deactivate). GET /transport/my-bus-pass (student/parent: own pass with QR code).
  3. RunLogService — POST /transport/runs (driver starts run), PATCH /transport/runs/:id (complete run with odometer + arrival time).
  4. NoShowWorker — Internal service triggered on a configurable schedule (default: 30 min after first stop scheduled_time). Compares trn_student_assignments (expected) against trn_ridership_records (actual) for the current date. Missing students generate trn_no_show_alerts + emit trn.no_show.detected for parent notification via Cycle 14's messaging.
  5. DelayReportService — POST /transport/delays (driver reports delay), GET /transport/delays (TC: delay history). Emits trn.delay.reported for parent notification.
Produces → 5 services, ~12 endpoints, 2 Kafka emits (trn.no_show.detected + trn.delay.reported). Total Cycle 19 endpoints: ~38.
