Cycle 16: Enrolment &
Admissions

The student lifecycle gate: enrolment periods with parallel admission streams, configurable application forms with multi-stage review pipelines, scored waitlists with automatic queue advancement, conditional and unconditional offers with deadline enforcement, and structured onboarding checklists that ensure every new student is ready before their first day. The first parent-facing application submission surface.
May 2026 · 10 Steps · ERD v11 · M81 Enrolment (25 tables — 16 core in scope, 9 deferred) · STU-003 + STU-004

Plan Overview

Cycle 16 builds the M81 Enrolment module — 16 of the 25 ERD tables. This is the first module where prospective families (people who do not yet have a student record) interact with the platform. The Enrolment Officer (EO) is the fifth specialist operator persona. The module bridges the gap between "interested family" and "enrolled student" — once an offer is accepted and onboarding completes, the enr.student.enrolled Kafka emit triggers downstream systems (Cycle 6 PaymentAccountWorker creates the family account, Cycle 1 SIS creates the student record).

The module spans 4 domains: (1) enrolment periods + admission streams + intake capacities, (2) the application pipeline with multi-stage review + scoring + documents + notes, (3) offers + waitlist with queue management, and (4) onboarding checklists with per-student progress tracking. This is the third parent-active surface (after Cycle 14 messaging and Cycle 15 conference booking) — but uniquely, the parent is a prospective applicant who may not have any existing CampusOS identity beyond the initial iam_person created at account provisioning.

Vertical Slice Deliverable

Admin creates "2026-2027 Admissions" enrolment period with "Standard Intake" + "Music Scholarship" streams → sets intake capacity (Grade 5: 30 places, 2 reserved for looked-after children) → prospective parent submits an application for their child to Grade 5 Standard Intake with supporting documents → EO reviews the application, advances it through SUBMITTED → UNDER_REVIEW → INTERVIEW stages, logs confidential interview notes and an assessment score → EO issues an unconditional offer with a 14-day response deadline → parent accepts the offer within the deadline → enr.offer.accepted fires → system generates the onboarding checklist (8 tasks: uniform ordered, bus route assigned, medical form returned, etc.) → EO and school nurse complete tasks collaboratively → when all mandatory tasks are done, enr.student.enrolled fires → downstream: SIS creates the student record, PaymentAccountWorker creates the family account → a second applicant for an oversubscribed grade enters the waitlist at position #1 → when another family declines their offer, the waitlisted family auto-advances to OFFERED.

Step-by-Step Build Plan

01 Period + Stream + Capacity Schema
Schema

The admissions infrastructure: enrolment periods defining application windows, parallel admission streams within periods (standard intake, scholarships, specialist provision), and per-grade intake capacities with reserved places.

Tables (4)
  1. enr_enrollment_periods — school_id UUID, academic_year_id UUID FK(sis_academic_years), name TEXT NOT NULL, opens_at TIMESTAMPTZ NOT NULL, closes_at TIMESTAMPTZ NOT NULL, status TEXT NOT NULL DEFAULT 'DRAFT' 5-value CHECK (DRAFT, OPEN, CLOSED, OFFERS_ISSUED, COMPLETED), decision_date DATE nullable, is_active BOOLEAN DEFAULT true. UNIQUE(school_id, name, academic_year_id). The period is the top-level container for an admissions cycle.
  2. enr_admission_streams — Parallel intake tracks. enrollment_period_id UUID FK NOT NULL, name TEXT NOT NULL (e.g., "Standard Intake", "Music Scholarship", "SEND Specialist"), description TEXT, grade_level TEXT nullable (null = all grades), opens_at TIMESTAMPTZ, closes_at TIMESTAMPTZ, is_active BOOLEAN DEFAULT true. UNIQUE(enrollment_period_id, name).
  3. enr_intake_capacities — Places per grade per period per stream. enrollment_period_id UUID FK NOT NULL, stream_id UUID FK nullable (null = general intake), grade_level TEXT NOT NULL, total_places INT NOT NULL, reserved_places INT NOT NULL DEFAULT 0 (for looked-after children, EHCP holders, etc.), notes TEXT. UNIQUE(enrollment_period_id, COALESCE(stream_id, sentinel), grade_level) — the COALESCE-sentinel pattern from Cycle 6 + Cycle 12.
  4. enr_capacity_summary — Materialised dashboard. enrollment_period_id UUID FK NOT NULL, grade_level TEXT NOT NULL, total_places INT, reserved_places INT, applications_received INT DEFAULT 0, offers_issued INT DEFAULT 0, offers_accepted INT DEFAULT 0, waitlisted INT DEFAULT 0, places_remaining INT. UNIQUE(enrollment_period_id, grade_level). Updated on every application status change via the Step 6 service.
Produces → 4 new tables. Migration: 053_enr_periods_capacity.sql.
02 Application Pipeline Schema
Schema

The application itself with multi-stage review progression, scoring criteria for ranked selection, document uploads, confidential staff notes, and structured form responses.

Tables (6)
  1. enr_applications — school_id UUID, enrollment_period_id UUID FK NOT NULL, stream_id UUID FK nullable, applicant_person_id UUID NOT NULL (soft to iam_person — the parent/guardian submitting), child_first_name TEXT NOT NULL, child_last_name TEXT NOT NULL, child_date_of_birth DATE NOT NULL, applying_for_grade TEXT NOT NULL, current_school TEXT, status TEXT NOT NULL DEFAULT 'SUBMITTED' 8-value CHECK (DRAFT, SUBMITTED, UNDER_REVIEW, INTERVIEW, ASSESSMENT, OFFERED, WAITLISTED, REJECTED, WITHDRAWN), submitted_at TIMESTAMPTZ, decision_at TIMESTAMPTZ, decision_notes TEXT. INDEX(school_id, status). INDEX(enrollment_period_id, applying_for_grade). Emits enr.application.submitted on submit.
  2. enr_application_stages — Audit trail of stage progression. application_id UUID FK NOT NULL, from_status TEXT nullable (null on initial submission), to_status TEXT NOT NULL, changed_by UUID NOT NULL, notes TEXT, changed_at TIMESTAMPTZ NOT NULL DEFAULT now(). INDEX(application_id, changed_at ASC). IMMUTABLE — no UPDATE, no DELETE.
  3. enr_application_scores — Scored criteria for ranked selection. application_id UUID FK NOT NULL, criterion_name TEXT NOT NULL, score NUMERIC(5,2) NOT NULL, max_score NUMERIC(5,2), scored_by UUID NOT NULL, notes TEXT. UNIQUE(application_id, criterion_name). The total score feeds waitlist priority_score.
  4. enr_application_documents — application_id UUID FK NOT NULL, document_type TEXT NOT NULL, s3_key TEXT NOT NULL, uploaded_at TIMESTAMPTZ. Signed S3 URLs at read time.
  5. enr_application_notes — Staff-only observations. application_id UUID FK NOT NULL, note_type TEXT NOT NULL 6-value CHECK (INTERVIEW_NOTES, ASSESSMENT_RESULT, STAFF_OBSERVATION, REFERENCE_CHECK, VISIT_NOTES, GENERAL), note_text TEXT NOT NULL, is_confidential BOOLEAN DEFAULT false (when true: EO + admin only), created_by UUID FK NOT NULL, created_at TIMESTAMPTZ. INDEX(application_id, created_at DESC).
  6. enr_application_form_responses — Structured form field responses. application_id UUID FK NOT NULL, field_name TEXT NOT NULL, response_value JSONB. UNIQUE(application_id, field_name). The dynamic form builder is deferred; the schema supports it.
Produces → 6 new tables. Migration: 054_enr_applications.sql.
03 Offers + Waitlist + Onboarding Schema
Schema

Formal offer issuance with deadline enforcement, scored waitlist with automatic queue advancement, and the onboarding checklist system that ensures every new student is operationally ready before day one.

Tables (6)
  1. enr_offers — application_id UUID FK UNIQUE NOT NULL (one offer per application), school_id UUID, offer_type TEXT NOT NULL DEFAULT 'UNCONDITIONAL' 2-value CHECK (UNCONDITIONAL, CONDITIONAL), offer_conditions TEXT[] nullable, conditions_met BOOLEAN nullable, offer_letter_s3_key TEXT nullable, issued_at TIMESTAMPTZ NOT NULL, response_deadline TIMESTAMPTZ NOT NULL, family_response TEXT nullable 3-value CHECK (ACCEPTED, DECLINED, DEFERRED), family_responded_at TIMESTAMPTZ, status TEXT NOT NULL DEFAULT 'ISSUED' 6-value CHECK (ISSUED, ACCEPTED, DECLINED, EXPIRED, WITHDRAWN, CONDITIONS_NOT_MET). INDEX(school_id, status). Partial INDEX(response_deadline) WHERE status='ISSUED' for the expiry sweep. Emits enr.offer.accepted on family acceptance.
  2. enr_waitlist_entries — application_id UUID FK UNIQUE NOT NULL, enrollment_period_id UUID FK NOT NULL, grade_level TEXT NOT NULL, queue_position INT NOT NULL, priority_score NUMERIC(8,2) nullable (from enr_application_scores), waitlisted_at TIMESTAMPTZ NOT NULL, offered_at TIMESTAMPTZ, offer_expires_at TIMESTAMPTZ, status TEXT NOT NULL DEFAULT 'WAITING' 6-value CHECK (WAITING, OFFERED, ACCEPTED, DECLINED, EXPIRED, REMOVED). Partial UNIQUE(enrollment_period_id, grade_level, queue_position) WHERE status='WAITING'. On DECLINED or EXPIRED: EnrolmentWorker advances next WAITING entry.
  3. enr_onboarding_checklists — School-level template. school_id UUID, name TEXT NOT NULL, admission_type TEXT NOT NULL DEFAULT 'STANDARD_INTAKE' 5-value CHECK (STANDARD_INTAKE, MID_YEAR_ADMISSION, TRANSFER_IN, RETURNING_STUDENT, INTERNATIONAL), is_active BOOLEAN DEFAULT true. UNIQUE(school_id, name, admission_type).
  4. enr_onboarding_tasks — Template tasks. checklist_id UUID FK NOT NULL, task_name TEXT NOT NULL, task_category TEXT NOT NULL 7-value CHECK (ADMINISTRATIVE, HEALTH, IT, FACILITIES, TRANSPORT, COMMUNICATIONS, FINANCE), is_mandatory BOOLEAN DEFAULT true, responsible_role TEXT nullable, sort_order INT NOT NULL, due_days_before_start INT NOT NULL DEFAULT 0. UNIQUE(checklist_id, task_name). INDEX(checklist_id, sort_order).
  5. enr_student_onboarding_progress — Per-student checklist tracking. application_id UUID FK NOT NULL, checklist_id UUID FK NOT NULL, student_id UUID FK(sis_students) nullable (populated when SIS record created), started_date DATE NOT NULL, target_start_date DATE NOT NULL, overall_status TEXT NOT NULL DEFAULT 'IN_PROGRESS' 3-value CHECK (IN_PROGRESS, COMPLETE, OVERDUE), tasks_total INT NOT NULL, tasks_completed INT NOT NULL DEFAULT 0. UNIQUE(application_id, checklist_id). Emits enr.student.enrolled when overall_status flips to COMPLETE and all mandatory tasks done.
  6. enr_student_onboarding_task_completions — Per-task tracking. progress_id UUID FK NOT NULL, task_id UUID FK NOT NULL, status TEXT NOT NULL DEFAULT 'PENDING' 4-value CHECK (PENDING, COMPLETED, WAIVED, OVERDUE), completed_by UUID FK nullable, completed_at TIMESTAMPTZ, notes TEXT. UNIQUE(progress_id, task_id). INDEX(progress_id, status) WHERE status != 'COMPLETED'.
Produces → 6 new tables. Migration: 055_enr_offers_onboarding.sql. Total Cycle 16 tables: 16.
04 Seed Data — Period, Applications, Offers, Onboarding
Seed
What Gets Seeded
  1. 1 enrolment period + 2 streams: "2026-2027 Admissions" (OPEN, opens Jan 15 – closes Mar 31). Streams: "Standard Intake" + "Music Scholarship".
  2. 2 intake capacities + 1 capacity summary: Grade 5: 30 places, 2 reserved. Grade 6: 25 places, 1 reserved. Summary materialised with live counts.
  3. 3 applications at different stages: (1) "Emma Wilson" Grade 5 Standard — OFFERED (interview notes + assessment score + documents). (2) "James Park" Grade 5 Standard — WAITLISTED at position #1 (scored lower). (3) "Sophia Martinez" Grade 5 Music Scholarship — SUBMITTED (fresh application).
  4. 1 offer: Unconditional offer to Emma Wilson, response_deadline in 7 days, status=ISSUED.
  5. 1 waitlist entry: James Park WAITING at position #1 with priority_score from his application scores.
  6. 1 onboarding checklist + 8 tasks: "Standard New Student Checklist" (STANDARD_INTAKE) with: Uniform ordered (ADMINISTRATIVE), Bus route assigned (TRANSPORT), Medical form returned (HEALTH), Locker allocated (FACILITIES), IT account created (IT), Library card issued (ADMINISTRATIVE), Emergency contacts confirmed (COMMUNICATIONS), Enrolment deposit paid (FINANCE).
  7. Permissions: STU-003:read to Parent (view own application status), STU-003:write to Staff (EO processes applications), STU-003:admin to Admin (configure periods, capacities, checklists). Admin gets all via everyFunction.
Produces → Rich admissions demo data across all 16 tables + STU-003 permissions.

10 Vertical Slice Integration Test
Test
Test Script
  1. Period + capacity setup: Admin creates period with 2 streams + Grade 5 capacity (30 places, 2 reserved). Verify capacity summary initialised.
  2. Parent submits application: Prospective parent submits for Grade 5 Standard Intake. Verify enr.application.submitted fires. Verify capacity_summary.applications_received++. Parent sees application in status tracker.
  3. Multi-stage review: EO advances SUBMITTED → UNDER_REVIEW → INTERVIEW. Stage audit rows created (immutable). EO logs confidential interview notes. EO scores 3 criteria.
  4. Offer issuance: EO issues unconditional offer with 14-day deadline. Application status → OFFERED. Capacity_summary.offers_issued++.
  5. Parent accepts: Parent accepts offer. enr.offer.accepted fires. Onboarding checklist auto-generated (8 tasks). Capacity_summary.offers_accepted++.
  6. Onboarding completion: EO + nurse + IT complete tasks. When all mandatory tasks done: overall_status=COMPLETE, enr.student.enrolled fires.
  7. Waitlist lifecycle: EO adds a second applicant to waitlist at position #1. First family declines their offer. advanceNext auto-offers to waitlisted family. Waitlist entry status WAITING → OFFERED.
  8. Offer expiry: Simulate deadline passing on an ISSUED offer. Verify status flips to EXPIRED.
  9. Visibility: Parent sees own application + offer + waitlist position. Cannot see other applications. EO sees all applications in the period. Teacher cannot access enrolment endpoints.
  10. Confidential notes: EO logs is_confidential=true note. Non-EO staff with STU-003:read cannot see it. Admin can.
Produces → Verified admissions lifecycle: period → application → multi-stage review → offer → accept → onboarding → enrolled → waitlist advance.

Cycle 16 delivers the student lifecycle gate — the pipeline from prospective family inquiry through accepted offer to operationally-ready enrolled student. The enr.student.enrolled Kafka emit is the cross-system trigger that downstream modules (SIS, Payments, Communications) will consume to create the student's operational identity.
