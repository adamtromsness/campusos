Cycle 20: Food Service

Menu planning with rotating cycles, POS transactions with real-time allergen safety enforcement (CRITICAL allergens block the sale and require supervisor override), NSLP free/reduced meal eligibility with USDA reimbursement claims, student dietary profiles, food safety temperature logging, cash drawer reconciliation, and parent dietary update requests. The Food Service Manager (FSM) is the seventh specialist operator persona.
May 2026 · 10 Steps · ERD v11 · M63 Food Service (31 tables — 16 core in scope, 15 deferred) · FDS-001 through FDS-004

Plan Overview

Cycle 20 builds the M63 Food Service module — 16 of the 31 ERD tables. This is the second Campus Operations module and the most safety-critical surface outside of Health (Cycle 10). The allergen safety enforcement at the POS is a life-safety feature: when a student scans their ID at the checkout, the system cross-references their fds_student_allergen_alerts (a read model populated from Cycle 10's health module via Kafka) against the allergen_codes[] on each menu item in the transaction. CRITICAL allergens (anaphylactic) BLOCK the sale and require a supervisor override with audit trail.

The module spans 4 domains: (1) menu planning with rotating cycles + daily menus + item catalogue with GIN-indexed allergen codes, (2) POS operations with device registry + meal service sessions + transactions with allergen cross-check + cash reconciliation, (3) student dietary profiles + health-module allergen read model + parent dietary update requests, and (4) NSLP eligibility determination + USDA monthly reimbursement claims + food safety temperature logging + production records. The Cycle 10 health module integration (via hlth.allergy_alert.changed Kafka event) is the cross-module keystone.

Safety — Allergen Enforcement at POS

fds_student_allergen_alerts is a read model populated by a Kafka consumer listening to hlth.allergy_alert.changed from the Cycle 10 health module (ADR-030 pattern — Food Service never reads hlth_* tables directly). Each alert has a severity: CRITICAL (anaphylactic/life-threatening) blocks the POS transaction and requires supervisor_override_id on the fds_meal_transactions row; WARNING (serious) alerts but allows with acknowledgement; INFO (intolerance/preference) displays only. The POS cross-check runs on every transaction: SELECT allergen_codes FROM fds_student_allergen_alerts WHERE student_id=$1 AND is_active=true, then intersects with each item's allergen_codes[].

Vertical Slice Deliverable

FSM creates a 5-day menu cycle → adds menu items (Chicken Nuggets with allergen_codes=[WHEAT, SOYBEANS], Grilled Cheese with [MILK, WHEAT], Fresh Fruit Salad with []) → builds Monday's lunch menu from the cycle → registers POS device "Main Cafeteria Register" → opens a LUNCH service session → Maya scans her student ID at the POS → allergen cross-check fires: Maya has a CRITICAL PEANUTS alert (from Cycle 10 health data), but today's items don't contain PEANUTS — transaction proceeds normally → Ethan scans, orders Grilled Cheese — Ethan has a CRITICAL MILK alert → POS BLOCKS the transaction → supervisor Rivera overrides with audit trail → a second student with FREE meal eligibility scans — payment_method=FREE_MEAL, $0.00 total → FSM closes the session → cash drawer reconciliation shows $0.15 variance → FSM logs food safety temperature checks (walk-in fridge at 3.2°C, compliant) → David Chen submits a dietary update request to add HALAL restriction for Maya → FSM approves → admin submits the monthly USDA reimbursement claim (42 free meals, 18 reduced, 120 paid).

Step-by-Step Build Plan

01 Menu + Item Catalogue Schema
Schema

Rotating menu cycles, food item catalogue with structured allergen codes and GIN index, daily menus, and daily menu item assignments with prepared/served/wasted tracking.

Tables (4)
  1. fds_menu_cycles — school_id UUID, name TEXT NOT NULL, cycle_length_days INT DEFAULT 5, is_active BOOLEAN DEFAULT true. UNIQUE(school_id, name). The cycle defines a rotating pattern (e.g., 5-day week, 10-day fortnight).
  2. fds_menu_items — school_id UUID, name TEXT NOT NULL, description TEXT, category TEXT NOT NULL 5-value CHECK (MAIN, SIDE, DESSERT, DRINK, SNACK), unit_cost NUMERIC(5,2), calories INT, allergens TEXT[] (free-text for display), allergen_codes TEXT[] NOT NULL DEFAULT '{}' (structured: MILK, EGG, FISH, SHELLFISH, TREE_NUTS, PEANUTS, WHEAT, SOYBEANS, SESAME — used for machine-readable POS cross-check against fds_student_allergen_alerts), is_vegetarian BOOLEAN, is_vegan BOOLEAN, is_gluten_free BOOLEAN, is_preorderable BOOLEAN DEFAULT true. INDEX(school_id, category). GIN INDEX(school_id, allergen_codes) for allergen cross-reference queries.
  3. fds_daily_menus — school_id UUID, menu_date DATE NOT NULL, cycle_id UUID FK, meal_type TEXT NOT NULL 4-value CHECK (BREAKFAST, LUNCH, DINNER, SNACK). UNIQUE(school_id, menu_date, meal_type).
  4. fds_daily_menu_items — daily_menu_id UUID FK NOT NULL, menu_item_id UUID FK NOT NULL, quantity_prepared INT, quantity_served INT nullable, quantity_wasted INT nullable, is_available BOOLEAN DEFAULT true. UNIQUE(daily_menu_id, menu_item_id).
Produces → 4 new tables. Migration: 064_fds_menus.sql.
02 POS + Transactions + Reconciliation Schema
Schema

POS device registry, meal service session lifecycle (open/close), transaction records with allergen safety override tracking, and cash drawer reconciliation.

Tables (4)
  1. fds_pos_devices — school_id UUID, device_name TEXT NOT NULL, location TEXT, device_type TEXT NOT NULL DEFAULT 'CASHIER_STAFFED' 3-value CHECK (CASHIER_STAFFED, SELF_SERVICE_KIOSK, MOBILE_CART), is_active BOOLEAN DEFAULT true. UNIQUE(school_id, device_name).
  2. fds_meal_service_sessions — school_id UUID, service_date DATE NOT NULL, meal_type TEXT NOT NULL 4-value CHECK (BREAKFAST, LUNCH, DINNER, SNACK), opened_by UUID FK NOT NULL, opened_at TIMESTAMPTZ NOT NULL, closed_at TIMESTAMPTZ nullable. UNIQUE(school_id, service_date, meal_type).
  3. fds_meal_transactions — POS TRANSACTION with ALLERGEN SAFETY. patron_id UUID NOT NULL (soft to iam_person — students + staff), patron_type TEXT NOT NULL DEFAULT 'STUDENT' 2-value CHECK (STUDENT, STAFF), session_id UUID FK NOT NULL, pos_device_id UUID FK NOT NULL, items JSONB NOT NULL, total NUMERIC(6,2) NOT NULL, payment_method TEXT NOT NULL 5-value CHECK (LUNCH_ACCOUNT, INVOICE, CASH, FREE_MEAL, STAFF_ACCOUNT), allergen_override_required BOOLEAN DEFAULT false, supervisor_override_id UUID nullable (required when allergen_override_required=true), served_at TIMESTAMPTZ NOT NULL. INDEX(patron_id, served_at DESC). INDEX(session_id, served_at). Partition-ready for RANGE(served_at) monthly.
  4. fds_cash_drawer_reconciliation — session_id UUID FK NOT NULL, pos_device_id UUID FK NOT NULL, opening_balance NUMERIC(8,2) NOT NULL, expected_closing_balance NUMERIC(8,2) NOT NULL, actual_closing_balance NUMERIC(8,2) nullable, variance NUMERIC(8,2) nullable, reconciled_by UUID nullable, reconciled_at TIMESTAMPTZ, status TEXT NOT NULL DEFAULT 'OPEN' 3-value CHECK (OPEN, RECONCILED, VARIANCE_FLAGGED). UNIQUE(session_id, pos_device_id).
Produces → 4 new tables. Migration: 065_fds_pos_transactions.sql.
03 Dietary + Allergen + Eligibility + Safety Schema
Schema

Student dietary profiles, the health-to-food allergen read model (ADR-030), parent dietary change requests, NSLP eligibility applications + determinations, USDA reimbursement claims, food safety temperature logs, and USDA production records.

Tables (8)
  1. fds_student_dietary_profiles — student_id UUID FK(sis_students) UNIQUE NOT NULL, school_id UUID, dietary_restrictions TEXT[], allergens TEXT[] (preference-based display only — NOT used for POS safety), free_meal_eligible BOOLEAN DEFAULT false, meal_plan_type TEXT NOT NULL DEFAULT 'STANDARD' 6-value CHECK (STANDARD, VEGETARIAN, VEGAN, HALAL, KOSHER, OTHER). POS safety comes from fds_student_allergen_alerts, not this table.
  2. fds_student_allergen_alerts — SAFETY KEYSTONE. Health-to-Food read model (ADR-030). student_id UUID FK(sis_students) NOT NULL, school_id UUID NOT NULL, allergen_code TEXT NOT NULL (MILK, EGG, PEANUTS, etc.), allergen_display_name TEXT NOT NULL, severity TEXT NOT NULL 3-value CHECK (INFO, WARNING, CRITICAL), source_health_alert_id UUID NOT NULL (soft to hlth_health_alerts), is_active BOOLEAN DEFAULT true, last_synced_at TIMESTAMPTZ. Partial UNIQUE(student_id, allergen_code) WHERE is_active=true. INDEX(student_id, is_active). INDEX(school_id, allergen_code) WHERE is_active=true.
  3. fds_dietary_update_requests — Parent-submitted request. school_id UUID, submitted_by UUID FK NOT NULL, student_id UUID FK(sis_students) NOT NULL, change_type TEXT NOT NULL 6-value CHECK (ADD_RESTRICTION, REMOVE_RESTRICTION, ADD_ALLERGEN, REMOVE_ALLERGEN, CHANGE_MEAL_PLAN, UPDATE_ELIGIBILITY), proposed_value TEXT NOT NULL, reason TEXT, status TEXT NOT NULL DEFAULT 'PENDING' 3-value CHECK (PENDING, APPROVED, REJECTED), reviewed_by UUID nullable, reviewed_at TIMESTAMPTZ. INDEX(school_id, status) WHERE status='PENDING'.
  4. fds_eligibility_applications — NSLP free/reduced price meal application. school_id UUID, student_id UUID FK(sis_students) NOT NULL, submitted_by UUID FK NOT NULL, academic_year_id UUID FK, household_size INT NOT NULL, annual_household_income NUMERIC(10,2) nullable (encrypted at rest), snap_benefit_case_number TEXT nullable, application_type TEXT NOT NULL 3-value CHECK (INCOME_BASED, CATEGORICAL, DIRECT_CERTIFICATION), status TEXT NOT NULL DEFAULT 'SUBMITTED' 5-value CHECK (SUBMITTED, UNDER_REVIEW, APPROVED, DENIED, WITHDRAWN). INDEX(school_id, academic_year_id, status).
  5. fds_eligibility_determinations — application_id UUID FK UNIQUE NOT NULL, determined_by UUID FK NOT NULL, determined_at DATE NOT NULL, eligibility_category TEXT NOT NULL 4-value CHECK (FREE, REDUCED, PAID, DENIED), effective_from DATE NOT NULL, effective_to DATE NOT NULL, notification_sent BOOLEAN DEFAULT false. On FREE or REDUCED: auto-update fds_student_dietary_profiles.free_meal_eligible.
  6. fds_usda_reimbursement_claims — Monthly USDA claim. school_id UUID, academic_year_id UUID FK, month_year DATE NOT NULL, free_meals_count INT NOT NULL, reduced_meals_count INT NOT NULL, paid_meals_count INT NOT NULL, reimbursement_amount NUMERIC(10,2), status TEXT NOT NULL DEFAULT 'DRAFT' 4-value CHECK (DRAFT, SUBMITTED, APPROVED, REJECTED). INDEX(school_id, month_year DESC).
  7. fds_temperature_logs — Food safety HACCP compliance. school_id UUID, check_location TEXT NOT NULL 7-value CHECK (DELIVERY, REFRIGERATOR, FREEZER, SERVING_LINE, HOT_HOLD, COLD_HOLD, COOK_TEMP), location_name TEXT NOT NULL, temperature_celsius NUMERIC(4,1) NOT NULL, safe_range_min NUMERIC(4,1) NOT NULL, safe_range_max NUMERIC(4,1) NOT NULL, is_compliant BOOLEAN NOT NULL, corrective_action TEXT (required when non-compliant), logged_by UUID FK NOT NULL, logged_at TIMESTAMPTZ NOT NULL. INDEX(school_id, is_compliant, logged_at DESC) WHERE is_compliant=false. Partition-ready RANGE(logged_at).
  8. fds_production_records — USDA compliance production documentation. school_id UUID, meal_service_date DATE NOT NULL, meal_type TEXT NOT NULL, menu_item_id UUID FK NOT NULL, quantity_prepared INT NOT NULL, quantity_served INT NOT NULL, quantity_leftover INT DEFAULT 0, quantity_wasted INT DEFAULT 0, meets_meal_pattern BOOLEAN NOT NULL. UNIQUE(school_id, meal_service_date, meal_type, menu_item_id).
Produces → 8 new tables. Migration: 066_fds_dietary_eligibility.sql. Total Cycle 20 tables: 16.
