Student Support

Counsellor caseloads, teacher-to-counsellor referral workflow, FERPA-protected session notes, MTSS/RTI tiered interventions with progress monitoring, coordinated care notes between nurse and counsellor, and mandatory reporting. The second-highest sensitivity domain after Health.

Plan Overview

Cycle 11 completes the M27 Student Services module. Cycle 9 already shipped 3 tables (behaviour plans, goals, teacher feedback); this cycle ships the remaining 16 core tables across 4 domains: (1) caseloads and referrals, (2) counselling sessions with FERPA-protected notes, (3) MTSS/RTI tier assignments with interventions and progress monitoring, and (4) coordinated care + mandatory reporting. The 6 wellbeing check-in tables (survey templates, questions, deployments, check-ins, responses, alerts) are scoped to a follow-up Cycle 11.1 since they form a self-contained sub-system with their own student-facing surface.

This module involves the second-highest sensitivity data domain after Health. Session notes (svc_session_notes) are FERPA-protected counselling records requiring a dedicated student_counseling_record:read permission. Teachers may not access session notes under any circumstance. Mandatory reports (svc_mandatory_reports) are immutable once past FILED status and retained permanently.

Data Sensitivity — FERPA Counselling Records

svc_session_notes is flagged for a separate HIPAA-equivalent encryption key in the ERD. Session notes are restricted to counsellors and administrators with the student_counseling_record:read permission. Teachers may NOT access session notes — they see only caseload assignments (which student is assigned to which counsellor) and referral status (for referrals they submitted). Parents see only that their child has an active caseload and the counsellor's name — no session content.

Vertical Slice Deliverable

Teacher submits a referral for Maya: "Struggling with peer relationships and declining grades" under type "Social/Emotional" → counsellor (Hayes) sees the referral in the triage queue, accepts it, and assigns Maya to their caseload with primary concern SOCIAL_EMOTIONAL → counsellor schedules an individual session, logs a FERPA-protected session note with goals addressed → counsellor assigns Maya to MTSS Tier 2 BEHAVIORAL domain with a targeted intervention (Social Skills Group, 2x/week) → counsellor logs an intervention progress data point showing improvement → nurse and counsellor exchange a coordinated care note about Maya's health-related anxiety → admin views the MTSS dashboard showing tier distribution → teacher sees only that Maya has an active caseload and that their referral was accepted — no session notes visible.

Step-by-Step Build Plan

01 Caseloads + Referrals Schema
Schema

The counsellor-to-student assignment system and the teacher-to-counsellor referral pipeline. svc_caseloads is the master assignment table that Cycle 9's svc_behavior_plans.caseload_id soft FK finally resolves to.

Tables (4)
  1. svc_caseloads — school_id UUID, counselor_id UUID FK(hr_employees) NOT NULL, student_id UUID FK(sis_students) NOT NULL, academic_year_id UUID FK(sis_academic_years) NOT NULL, primary_concern TEXT NOT NULL 7-value CHECK (ACADEMIC, BEHAVIORAL, SOCIAL_EMOTIONAL, ATTENDANCE, CRISIS, TRANSITION, GENERAL), is_primary_counselor BOOLEAN DEFAULT true, status TEXT NOT NULL DEFAULT 'ACTIVE' 3-value CHECK (ACTIVE, CLOSED, TRANSFERRED), opened_at DATE NOT NULL, closed_at DATE nullable, closure_reason TEXT nullable, notes TEXT. Partial UNIQUE(student_id, academic_year_id) WHERE status='ACTIVE' AND is_primary_counselor=true — one primary counsellor per student per year. Partial UNIQUE(counselor_id, student_id, academic_year_id) WHERE status='ACTIVE' — no duplicate active assignments. INDEX(counselor_id, status). INDEX(student_id, academic_year_id).
  2. svc_referral_types — School-configured referral categories. school_id UUID, name TEXT NOT NULL, description TEXT, default_priority TEXT NOT NULL 4-value CHECK (LOW, MEDIUM, HIGH, URGENT), requires_parent_notification BOOLEAN NOT NULL DEFAULT false, is_active BOOLEAN NOT NULL DEFAULT true. UNIQUE(school_id, name).
  3. svc_referrals — school_id UUID, student_id UUID FK(sis_students), referred_by UUID FK(hr_employees) NOT NULL, referral_type_id UUID FK(svc_referral_types) NOT NULL, assigned_counselor_id UUID FK(hr_employees) nullable, priority TEXT NOT NULL 4-value CHECK (LOW, MEDIUM, HIGH, URGENT), status TEXT NOT NULL DEFAULT 'SUBMITTED' 7-value CHECK (SUBMITTED, TRIAGED, ACCEPTED, IN_PROGRESS, COMPLETED, DECLINED, CANCELLED), reason TEXT NOT NULL, parent_notified BOOLEAN NOT NULL DEFAULT false, parent_notified_at TIMESTAMPTZ nullable, outcome TEXT nullable. INDEX(school_id, status). INDEX(assigned_counselor_id, status). INDEX(student_id). INDEX(referred_by, status).
  4. svc_referral_activity — IMMUTABLE per ADR-010. No UPDATE, no DELETE. referral_id UUID FK(svc_referrals) NOT NULL, actor_id UUID NOT NULL (soft to platform_users), activity_type TEXT NOT NULL 6-value CHECK (STATUS_CHANGE, ASSIGNMENT_CHANGE, NOTE_ADDED, PARENT_NOTIFIED, ESCALATED, EXTERNAL_CONTACT_MADE), notes TEXT nullable, created_at TIMESTAMPTZ NOT NULL DEFAULT now(). INDEX(referral_id, created_at ASC).
Produces → 4 new tables. Migration: 036_svc_caseloads_referrals.sql.
02 Sessions + Notes + MTSS Schema
Schema

The counselling session log with FERPA-protected notes plus the MTSS/RTI tiered intervention system with progress monitoring and team meetings. The largest schema step of Cycle 11 — 8 tables in one migration.

Tables (8)
  1. svc_sessions — counselor_id UUID FK(hr_employees) NOT NULL, school_id UUID, session_date DATE NOT NULL, duration_minutes INT with CHECK > 0, session_type TEXT NOT NULL 6-value CHECK (INDIVIDUAL, GROUP, CRISIS, CHECK_IN, PARENT_MEETING, CONSULTATION), primary_caseload_id UUID FK(svc_caseloads) nullable (identifies the student for INDIVIDUAL sessions; null for GROUP), referral_id UUID FK(svc_referrals) nullable, status TEXT NOT NULL DEFAULT 'SCHEDULED' 4-value CHECK (SCHEDULED, COMPLETED, NO_SHOW, CANCELLED). INDEX(counselor_id, session_date DESC). INDEX(primary_caseload_id) WHERE primary_caseload_id IS NOT NULL.
  2. svc_session_participants — Links students to sessions (mandatory for GROUP, optional for INDIVIDUAL). session_id UUID FK(svc_sessions) NOT NULL, student_id UUID FK(sis_students) NOT NULL, caseload_id UUID FK(svc_caseloads) nullable, attendance_status TEXT NOT NULL DEFAULT 'ATTENDED' 3-value CHECK (ATTENDED, NO_SHOW, LATE). UNIQUE(session_id, student_id). INDEX(student_id, session_id).
  3. svc_session_notes — FERPA-protected. One note per student per session (enabling group sessions to have individual notes per participant). session_id UUID FK(svc_sessions) NOT NULL, student_id UUID FK(sis_students) NOT NULL, notes_text TEXT NOT NULL, goals_addressed TEXT[] nullable, follow_up_required BOOLEAN DEFAULT false, follow_up_notes TEXT, is_locked BOOLEAN DEFAULT false, locked_at TIMESTAMPTZ nullable, locked_by UUID FK nullable. UNIQUE(session_id, student_id). Multi-column locked_chk: is_locked=true requires locked_at NOT NULL AND locked_by NOT NULL; is_locked=false requires both NULL. Access gated on student_counseling_record:read.
  4. svc_mtss_tiers — school_id UUID, student_id UUID FK(sis_students) NOT NULL, academic_year_id UUID FK NOT NULL, tier TEXT NOT NULL 3-value CHECK (TIER_1, TIER_2, TIER_3), domain TEXT NOT NULL 4-value CHECK (ACADEMIC, BEHAVIORAL, SOCIAL_EMOTIONAL, ATTENDANCE), assigned_by UUID FK(hr_employees) NOT NULL, assigned_at DATE NOT NULL, review_date DATE NOT NULL, exit_date DATE nullable, exit_reason TEXT nullable, status TEXT NOT NULL DEFAULT 'ACTIVE' 4-value CHECK (ACTIVE, EXITED, PROMOTED, DEMOTED). Partial UNIQUE(student_id, academic_year_id, domain) WHERE status='ACTIVE'. INDEX(school_id, tier, status). On tier change: emit svc.tier.changed.
  5. svc_interventions — tier_id UUID FK(svc_mtss_tiers) NOT NULL, intervention_name TEXT NOT NULL, intervention_type TEXT NOT NULL 6-value CHECK (ACADEMIC_SUPPORT, BEHAVIORAL_SUPPORT, SOCIAL_EMOTIONAL_LEARNING, ATTENDANCE_SUPPORT, COUNSELING, EXTERNAL_SERVICE), frequency TEXT, start_date DATE NOT NULL, end_date DATE nullable, provider_id UUID FK(hr_employees) nullable, status TEXT NOT NULL DEFAULT 'ACTIVE' 3-value CHECK (ACTIVE, COMPLETED, DISCONTINUED). INDEX(tier_id, status).
  6. svc_intervention_progress — Append-only progress monitoring data. intervention_id UUID FK(svc_interventions) NOT NULL, recorded_by UUID FK(hr_employees) NOT NULL, recorded_date DATE NOT NULL, measure_type TEXT NOT NULL, score NUMERIC(8,2), benchmark NUMERIC(8,2) nullable, notes TEXT. INDEX(intervention_id, recorded_date DESC).
  7. svc_mtss_team_meetings — school_id UUID, meeting_id UUID nullable (soft to future mtg_meetings), academic_year_id UUID FK NOT NULL, facilitated_by UUID FK(hr_employees) NOT NULL, meeting_date DATE NOT NULL, notes TEXT. INDEX(school_id, meeting_date DESC).
  8. svc_mtss_team_meeting_students — Students reviewed at a meeting. team_meeting_id UUID FK(svc_mtss_team_meetings) NOT NULL, student_id UUID FK(sis_students) NOT NULL, tier_id UUID FK(svc_mtss_tiers) nullable, outcome TEXT nullable 5-value CHECK (NO_CHANGE, TIER_UP, TIER_DOWN, EXIT, CONTINUE_WITH_ADJUSTMENT) or NULL, outcome_notes TEXT. UNIQUE(team_meeting_id, student_id).
Produces → 8 new tables. Migration: 037_svc_sessions_mtss.sql.
03 Coordinated Care + Mandatory Reporting Schema
Schema

The nurse-counsellor shared observation system and the mandatory reporter filing log. Both are highly restricted. This step also ships a small migration to add a DB-enforced FK from svc_behavior_plans.caseload_id to svc_caseloads(id), converting the Cycle 9 soft ref into a real FK now that the target table exists.

Tables (2) + 1 FK backfill
  1. svc_coordinated_care_notes — Shared between nurse and counsellor ONLY. student_id UUID FK(sis_students) NOT NULL, author_person_id UUID NOT NULL (soft to iam_person per ADR-001), author_role TEXT NOT NULL 2-value CHECK (NURSE, COUNSELLOR), note_text TEXT NOT NULL, created_at TIMESTAMPTZ NOT NULL DEFAULT now(). INDEX(student_id, created_at DESC). Visible only to actors who hold BOTH hlt-001:read AND cou-007:read — the intersection of the health and counselling teams.
  2. svc_mandatory_reports — student_id UUID FK(sis_students) NOT NULL, reporter_person_id UUID NOT NULL (soft to iam_person), report_type TEXT NOT NULL 4-value CHECK (SUSPECTED_ABUSE, SUSPECTED_NEGLECT, IMMINENT_DANGER, OTHER), reported_to_authority TEXT NOT NULL, report_date TIMESTAMPTZ NOT NULL, description TEXT NOT NULL, supporting_docs_s3_keys TEXT[] nullable, cps_response TEXT nullable, status TEXT NOT NULL DEFAULT 'FILED' 4-value CHECK (FILED, CPS_CONTACTED, INVESTIGATION_ACTIVE, CLOSED). INDEX(student_id, report_date DESC). INDEX(status). IMMUTABLE once past FILED — the Step 7 service enforces this: description, report_type, reported_to_authority, and report_date cannot be changed after initial filing. Only cps_response and status can be updated in subsequent transitions.
  3. FK backfill: ALTER TABLE svc_behavior_plans ADD CONSTRAINT svc_behavior_plans_caseload_id_fkey FOREIGN KEY (caseload_id) REFERENCES svc_caseloads(id) ON DELETE SET NULL. This converts the Cycle 9 soft ref into a real FK. ON DELETE SET NULL preserves the BIP when a caseload is closed and cleaned up.
Produces → 2 new tables + 1 FK backfill. Migration: 038_svc_coordinated_care_mandatory.sql. Total Cycle 11 schema: 14 new tables + 1 FK backfill. Tenant base table count: 155 → ~169.
