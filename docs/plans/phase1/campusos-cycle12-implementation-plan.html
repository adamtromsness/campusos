Cycle 12: Library

Catalogue with full-text search, physical copy tracking with barcodes, circulation (checkout, holds, renewals, overdue/lost fines), reading programmes with progress tracking and completion awards, curated reading lists, and student book reviews. The second student-input surface after wellbeing check-ins.
May 2026 · 10 Steps · ERD v11 · M24 Library (20 tables — 14 core in scope, 6 advanced deferred)

Plan Overview

Cycle 12 builds the M24 Library module — 14 of the 20 ERD tables. This is the first entirely new module prefix (lib_*) since Cycle 10's hlth_*. The library has a unique access model: patrons (both students and staff) use the same iam_person-based identity for checkouts and holds, and the catalogue is a public search surface visible to all authenticated users. The librarian is the primary operator (parallel to the nurse in Cycle 10 and the counsellor in Cycle 11).

The module spans 4 domains: (1) catalogue + locations + copies with barcode tracking, (2) circulation (checkout policies, checkouts, holds, fines with Kafka emit for payment integration), (3) reading programmes with progress tracking and completion awards, and (4) curated reading lists + student book reviews. Students submit reviews and log reading entries — the second student-input surface after Cycle 11.1's wellbeing check-ins.

Vertical Slice Deliverable

Librarian adds "The Giver" to the catalogue (ISBN, author, Dewey decimal) → adds 3 physical copies with unique barcodes to the Fiction shelf location → sets checkout policy (students: 14-day loan, 2 renewals, $0.25/day fine) → Maya checks out copy #1 by barcode scan → copy marked unavailable, due date calculated → Ethan places a hold on the same title (all copies out) → Maya returns the book after due date → overdue fine auto-calculated and lib.fine.issued emits to Kafka → Ethan's hold flips to READY (copy reassigned) → librarian creates "Summer Reading Challenge" programme (target: 10 books) → Maya logs "The Giver" as read → programme progress updates (1/10 books) → Maya writes a 4-star review → teacher creates a "Grade 5 Fiction" reading list with "The Giver" as a required item → students browse the catalogue and see the reading list + Maya's review.

What's In / What's Deferred

In scope (14 tables): lib_locations, lib_catalogue_items (with GIN full-text search), lib_catalogue_copies, lib_checkout_policies, lib_checkouts, lib_holds, lib_fines, lib_reading_programmes, lib_reading_logs, lib_programme_progress, lib_programme_completions, lib_reading_lists, lib_reading_list_items, lib_reviews. Functions LIB-001 through LIB-003.

Deferred (6 tables): lib_recommendations (requires LibraryRecommendationWorker + AI inference service), lib_class_set_checkouts (bulk teacher checkout workflow), lib_interlibrary_loans (cross-institution lending), lib_catalogue_import_jobs (bulk ISBN/MARC/CSV import worker + S3), lib_scan_sessions (AI-powered shelf scanning). LIB-004 function (Library Space) deferred entirely.

Also deferred: RANGE partitioning on lib_checkouts (simple table now; partition when volume warrants it). Redis caching of available_copies counts (computed on demand for now). Cycle 6 payment integration for fines (Kafka emit lands; no consumer wired). Programme completion certificate PDF generation (placeholder S3 key). lib.programme.completed Kafka emit for Task Worker fan-out.

Step-by-Step Build Plan

01 Catalogue Schema — Locations + Items + Copies
Schema

The library's physical and bibliographic foundation: named locations (shelves, displays, processing areas), catalogue items with full-text search, and individual physical copies tracked by barcode.

Tables (3)
  1. lib_locations — school_id UUID, name TEXT NOT NULL, location_type TEXT NOT NULL 6-value CHECK (SHELF, DISPLAY, BOOK_DROP, PROCESSING, REPAIR, STORAGE), sort_order INT DEFAULT 0, is_active BOOLEAN DEFAULT true. UNIQUE(school_id, name). INDEX(school_id, is_active). Drives the "where is this copy?" tracking on catalogue_copies.
  2. lib_catalogue_items — school_id UUID, title TEXT NOT NULL, author TEXT, isbn TEXT, publisher TEXT, publish_year INT, category TEXT, dewey_decimal TEXT, description TEXT, cover_image_url TEXT. INDEX(school_id, title). GIN index on to_tsvector('english', title || ' ' || COALESCE(author, '')) for full-text search — the catalogue search bar hits this. INDEX(isbn) for barcode-to-item resolution (barcode on copy → copy.catalogue_item_id → item).
  3. lib_catalogue_copies — catalogue_item_id UUID FK NOT NULL, location_id UUID FK nullable, barcode TEXT NOT NULL UNIQUE (the scannable identifier on the physical book), condition TEXT NOT NULL DEFAULT 'NEW' 5-value CHECK (NEW, GOOD, FAIR, POOR, LOST), is_available BOOLEAN DEFAULT true (flips false on checkout, true on return), replacement_value NUMERIC(8,2) nullable, location_status TEXT DEFAULT 'ON_SHELF' 7-value CHECK (ON_SHELF, IN_BOOK_DROP, IN_PROCESSING, CHECKED_OUT, ON_HOLD_SHELF, IN_REPAIR, LOST). INDEX(catalogue_item_id, is_available). UNIQUE(barcode).
Produces → 3 new tables. Migration: 041_lib_catalogue.sql.
02 Circulation Schema — Policies + Checkouts + Holds + Fines
Schema

The circulation engine: configurable loan policies per patron type, the checkout log with due-date enforcement, a hold queue with notification lifecycle, and fine tracking with Kafka integration to the payment system.

Tables (4)
  1. lib_checkout_policies — school_id UUID, patron_type TEXT NOT NULL 2-value CHECK (STUDENT, STAFF), max_checkouts INT NOT NULL, loan_period_days INT NOT NULL, renewals_allowed INT NOT NULL, overdue_fine_per_day NUMERIC(4,2) NOT NULL DEFAULT 0 (0 = fine-free school). UNIQUE(school_id, patron_type). One policy per (school, patron_type).
  2. lib_checkouts — copy_id UUID FK NOT NULL, patron_id UUID FK(iam_person) NOT NULL (covers both students and staff uniformly via the ADR-055 person model), checkout_date DATE NOT NULL, due_date DATE NOT NULL, returned_at TIMESTAMPTZ nullable, renewal_count INT DEFAULT 0, status TEXT NOT NULL DEFAULT 'ACTIVE' 4-value CHECK (ACTIVE, RETURNED, OVERDUE, LOST). INDEX(patron_id, checkout_date DESC). Partial INDEX WHERE returned_at IS NULL for active checkout queries. Partial INDEX WHERE status='OVERDUE' for the overdue dashboard. On return: auto-fine calculation if past due_date.
  3. lib_holds — catalogue_item_id UUID FK NOT NULL, patron_id UUID FK(iam_person) NOT NULL, placed_at TIMESTAMPTZ NOT NULL DEFAULT now(), expires_at TIMESTAMPTZ nullable, status TEXT NOT NULL DEFAULT 'PENDING' 5-value CHECK (PENDING, READY, COLLECTED, EXPIRED, CANCELLED), notified_at TIMESTAMPTZ nullable. INDEX(catalogue_item_id, status). INDEX(patron_id, status). On copy return with PENDING holds: oldest hold flips to READY + copy moved to ON_HOLD_SHELF.
  4. lib_fines — checkout_id UUID FK NOT NULL, patron_id UUID FK(iam_person) NOT NULL, fine_type TEXT NOT NULL 3-value CHECK (OVERDUE, LOST, DAMAGE), amount NUMERIC(6,2) NOT NULL, days_overdue INT nullable, status TEXT NOT NULL DEFAULT 'OUTSTANDING' 3-value CHECK (OUTSTANDING, PAID, WAIVED), invoice_id UUID nullable (soft to pay_invoices for future Cycle 6 payment integration). INDEX(patron_id, status). Emits lib.fine.issued on INSERT with status=OUTSTANDING.
Produces → 4 new tables. Migration: 042_lib_circulation.sql.
03 Reading + Reviews Schema
Schema

Reading programmes with student progress tracking and completion awards, curated reading lists from librarians and teachers, and student book reviews.

Tables (7)
  1. lib_reading_programmes — school_id UUID, name TEXT NOT NULL, academic_year_id UUID FK, target_books INT, target_pages INT, start_date DATE, end_date DATE, is_active BOOLEAN DEFAULT true, target_audience_type TEXT NOT NULL DEFAULT 'SCHOOL_WIDE' 4-value CHECK (SCHOOL_WIDE, YEAR_GROUP, CLASS, CUSTOM), target_id UUID nullable (soft to sis_classes or year group).
  2. lib_reading_logs — Student-reported reading entries. student_id UUID FK(sis_students) NOT NULL, catalogue_item_id UUID FK NOT NULL, started_date DATE, completed_date DATE, pages_read INT, rating SMALLINT CHECK(1–5), review_text TEXT. INDEX(student_id, completed_date DESC). The second student-input surface after wellbeing.
  3. lib_programme_progress — Per-(programme, student) running totals. programme_id UUID FK NOT NULL, student_id UUID FK(sis_students) NOT NULL, books_read INT DEFAULT 0, pages_read INT DEFAULT 0, last_updated_at TIMESTAMPTZ, is_complete BOOLEAN DEFAULT false. UNIQUE(programme_id, student_id). On is_complete=true: emit lib.programme.completed.
  4. lib_programme_completions — Award record. programme_id UUID FK NOT NULL, student_id UUID FK(sis_students) NOT NULL, completed_at TIMESTAMPTZ NOT NULL, books_read INT NOT NULL, pages_read INT NOT NULL, certificate_s3_key TEXT nullable, awarded_by UUID nullable, achievement_id UUID nullable (soft to future pfl_achievements). UNIQUE(programme_id, student_id).
  5. lib_reading_lists — Curated booklist. school_id UUID, name TEXT NOT NULL, description TEXT, list_type TEXT NOT NULL 5-value CHECK (CLASS, YEAR_GROUP, CURRICULUM_UNIT, GENERAL, NEW_ARRIVALS), created_by UUID FK NOT NULL, target_class_id UUID nullable (soft to sis_classes), academic_year_id UUID FK nullable, is_published BOOLEAN DEFAULT false, published_at TIMESTAMPTZ nullable. UNIQUE(school_id, name, academic_year_id).
  6. lib_reading_list_items — reading_list_id UUID FK NOT NULL, catalogue_item_id UUID FK NOT NULL, item_type TEXT NOT NULL DEFAULT 'RECOMMENDED' 4-value CHECK (REQUIRED, RECOMMENDED, EXTENSION, REFERENCE), sort_order INT NOT NULL, added_by UUID FK NOT NULL, notes TEXT. UNIQUE(reading_list_id, catalogue_item_id).
  7. lib_reviews — Student book reviews. item_id UUID FK(lib_catalogue_items) NOT NULL, student_id UUID FK(sis_students) NOT NULL, rating INT NOT NULL CHECK(1–5), review_text TEXT, is_approved BOOLEAN DEFAULT true. UNIQUE(item_id, student_id) — one review per student per item.
Produces → 7 new tables. Migration: 043_lib_reading_reviews.sql. Total Cycle 12 tables: 14.

Seed
What Gets Seeded

  2. 5 catalogue items: "The Giver" by Lois Lowry (ISBN 978-0544336261, Fiction, Dewey 813.54), "Charlotte's Web" by E.B. White, "Number the Stars" by Lois Lowry, "Holes" by Louis Sachar, "Wonder" by R.J. Palacio. Each with cover_image_url placeholder, category, Dewey decimal.

  6. 1 hold: Ethan has a PENDING hold on "The Giver" (all available copies are out or on hold).
  7. 1 fine: Maya's overdue "Holes" return: OVERDUE type, 2 days × $0.25 = $0.50, status=OUTSTANDING.
  8. 1 reading programme: "Summer Reading Challenge 2026" SCHOOL_WIDE, target_books=10, active. 1 programme_progress row for Maya (books_read=2, is_complete=false).

  10. 1 reading list: "Grade 5 Fiction Essentials" CLASS type, published, with 3 items (The Giver REQUIRED, Charlotte's Web RECOMMENDED, Number the Stars EXTENSION).
  11. 1 review: Maya reviews "Holes" with rating=4 and review text.
  12. Permissions: LIB-001:read to Teacher, Student, Parent (catalogue browsing is public). LIB-001:write to Staff (librarian adds items). LIB-002:read to Teacher, Student, Parent (view own checkouts/holds). LIB-002:write to Staff (process checkouts). LIB-003:read+write to Student (log reading, write reviews). LIB-003:write to Staff (create programmes, curate lists). Admin gets all via everyFunction.

05 Catalogue NestJS Module
Code
Services & Endpoints
  1. LocationService — GET /library/locations (all authenticated users see active locations), POST /library/locations (librarian/admin), PATCH /library/locations/:id.
  2. CatalogueItemService — GET /library/catalogue (public search with ?q= full-text via ts_rank + plainto_tsquery; filters category, author, isbn; paginated), GET /library/catalogue/:id (with inlined copies + availability count + average rating + active holds count), POST /library/catalogue (librarian/admin), PATCH /library/catalogue/:id.
  3. CopyService — GET /library/catalogue/:id/copies (per-item copy list with condition + availability + location), GET /library/copies/barcode/:barcode (barcode lookup keystone — the circulation desk scans a barcode and gets the copy + its item + current checkout status in one call), POST /library/catalogue/:id/copies (librarian adds a copy with barcode + condition + location), PATCH /library/copies/:id (update condition, location, availability).
Produces → LibraryModule with 3 services, ~12 endpoints. Full-text search + barcode lookup.
06 Circulation NestJS Module
Code
Services & Endpoints
  1. CheckoutService — POST /library/checkouts (checkout by barcode keystone: scans barcode → resolves copy → validates patron hasn't exceeded max_checkouts → validates copy is available → creates checkout row + stamps due_date from policy.loan_period_days → flips copy.is_available=false + location_status=CHECKED_OUT; all in one tx), POST /library/checkouts/:id/return (stamps returned_at; auto-calculates fine if overdue; reassigns to oldest PENDING hold if any; flips copy.is_available=true; emits lib.fine.issued when fine > 0), POST /library/checkouts/:id/renew (validates renewal_count < policy.renewals_allowed; extends due_date by loan_period_days; increments renewal_count), GET /library/checkouts (librarian: all active/overdue; patron: own), GET /library/checkouts/overdue (librarian dashboard of overdue items).
  2. HoldService — POST /library/holds (patron places hold on a catalogue item; validates at least 1 copy exists), GET /library/holds (patron: own; librarian: all), PATCH /library/holds/:id/cancel (patron or librarian cancels), PATCH /library/holds/:id/collect (librarian marks collected when patron picks up; flips to COLLECTED). Internal fulfillNextHold(catalogueItemId) called by CheckoutService on return.
  3. FineService — GET /library/fines (patron: own; librarian: all outstanding), PATCH /library/fines/:id/pay (librarian marks paid), PATCH /library/fines/:id/waive (admin waives with reason). Emits lib.fine.issued on creation for future Cycle 6 payment integration.
Produces → 3 services, ~12 endpoints, 1 Kafka emit (lib.fine.issued). Checkout by barcode is the keystone.

08 Library UI — Catalogue + Circulation
UI
Pages
  1. Library Dashboard /library — "Library" app tile. Librarian view: circulation desk (scan barcode input at top — auto-focuses; results show copy + item + current checkout with checkout/return buttons), overdue items count, active holds count, today's checkouts. Student/parent view: search bar + "My checkouts" + "My holds" + reading programme progress card.
  2. Catalogue Search /library/catalogue — full-text search bar with real-time results from the GIN index. Filter chips: category, author. Per-result card: cover image, title, author, Dewey decimal, availability count ("3 of 5 available"), average rating stars. Click to item detail.
  3. Catalogue Item Detail /library/catalogue/:id — full item metadata. Copies table (barcode, condition, location, status). Hold button (when no copies available). Reviews section (rating distribution + individual reviews). Reading lists that include this item.
  4. Circulation Desk /library/circulation — barcode scan input. Checkout history table with filters (active, overdue, returned). Per-row: patron name, item title, checkout date, due date, status pill, renewal count. Return + renew buttons per active row.
  5. Fine Management /library/fines — outstanding fines list. Per-row: patron, item, fine type, amount, days overdue, status. Pay + waive buttons.
Produces → "Library" app tile + catalogue search + item detail + circulation desk + fine management.
09 Library UI — Reading + Reviews + Student Portal
UI
Pages
  1. Reading Programmes /library/programmes — active programmes with progress bars (books_read / target_books). Leaderboard per programme. Librarian: create programme form.
  2. My Reading Log /library/reading-log — STUDENT-FACING. Log a book form (catalogue item picker, pages, started/completed date, optional rating). Reading history list. Each entry shows cover + title + pages + rating stars + completed/in-progress pill.
  3. Reading Lists /library/reading-lists — published reading lists with type pills (CLASS, GENERAL, NEW_ARRIVALS). Per-list: item cards with type pill (REQUIRED, RECOMMENDED, EXTENSION), cover, title, author. Librarian/teacher: create list + add items.
  4. Book Reviews (inline on catalogue item detail) — student submits a review (1–5 star rating + optional text). Existing reviews rendered with star display + student first name + date. Librarian can hide inappropriate reviews.
  5. Student Library Portal /library/my — student-only landing: "My checkouts" (active + due dates with overdue warnings), "My holds" (with queue position), "My fines" (outstanding amount), "My reading log" (recent entries), reading programme progress.
Produces → Reading programmes, reading log (student input), reading lists, student library portal.
10 Vertical Slice Integration Test
Test
Test Script
  1. Catalogue lifecycle: Librarian adds "Bridge to Terabithia" with ISBN. Adds 2 copies with barcodes LIB-FIC-101/102 to Fiction Shelves. Verify full-text search returns it on "Bridge" and "Terabithia" queries.
  2. Checkout by barcode: Librarian scans LIB-FIC-101. System resolves copy → item. Creates checkout for Maya. Due date = today + 14 (student policy). Copy flips unavailable + CHECKED_OUT. Verify max_checkouts enforcement (attempt checkout #6 rejected).
  3. Hold queue: Ethan places hold on "Bridge to Terabithia" (1 of 2 copies now out). Verify hold is PENDING.
  4. Return + auto-fine: Maya returns "Bridge to Terabithia" after 16 days (2 days overdue). Fine auto-created: OVERDUE, $0.50 (2 × $0.25). lib.fine.issued emits on Kafka. Ethan's hold flips to READY (returned copy reassigned to hold shelf).
  5. Renewal: Librarian renews Maya's active "The Giver" checkout. Due date extends by 14 days. Renewal count increments. Verify renewal limit enforcement.
  6. Reading programme: Maya logs "Bridge to Terabithia" as completed (288 pages). Programme progress auto-updates (books_read 2 → 3). Verify leaderboard shows Maya.
  7. Student review: Maya writes a 5-star review of "Bridge to Terabithia". Verify UNIQUE(item, student) rejects duplicate. Verify review appears on catalogue item detail.
  8. Reading list: Teacher creates "Grade 5 Adventure" reading list. Adds 2 items. Publishes. Students see the published list.
  9. Visibility: Student sees own checkouts, holds, fines, reading log. Cannot see other students' checkouts. Parent sees child's checkouts and fines. Teacher sees catalogue but cannot process checkouts.
  10. Fine management: Librarian marks Maya's fine as paid. Admin waives another fine. Verify status transitions.
Produces → Verified library lifecycle: catalogue → barcode checkout → hold → overdue return + auto-fine → hold fulfilment → reading log → review.
