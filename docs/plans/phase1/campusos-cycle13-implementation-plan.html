Plan Overview

Cycle 13 builds the M66 Athletics module — 14 of the 32 ERD tables. This is a clean greenfield with a new table prefix (ath_*). The Athletic Director (AD) is the fourth specialist operator persona alongside the nurse (Cycle 10), counsellor (Cycle 11), and librarian (Cycle 12). The module touches existing systems through sis_students (roster membership + eligibility), hr_employees (coaching assignments), and sis_academic_years (seasons). The GPA-based eligibility check is the first read-back into the Cycle 2 gradebook data.

The module spans 4 domains: (1) programme + season + roster infrastructure with eligibility tracking, (2) game scheduling with cross-school proposal workflow (ADR-069), results, player statistics, and season records, (3) coaching assignments, and (4) injury tracking with the 6-step concussion return-to-play protocol and physician clearance documents. M64 Clubs & Student Life (22 tables) moves to Wave 3 alongside Communications.

Safety — Concussion Return-to-Play Protocol

The ath_concussion_protocol_steps table enforces a mandatory 6-step graduated return-to-play process (per CDC guidelines). Each step has a minimum 24-hour duration, and step N+1 cannot start until step N is completed AND the minimum duration has elapsed. A student with return_to_play_status=CONCUSSION_PROTOCOL on their injury record is INELIGIBLE to play until they receive a physician clearance via ath_medical_clearances and the injury status flips to CLEARED.

AD creates "Basketball" programme (WINTER season, levels [VARSITY, JV], min_gpa=2.0) → opens the 2025-2026 season → creates VARSITY roster with Coach Rivera as head coach → adds Maya to the roster (eligibility check passes: GPA 3.5 ≥ 2.0, no active suspension) → AD schedules a home game vs Jefferson High (CONFIRMED, Jan 15 7pm) → after the game, enters result (Lincoln 52, Jefferson 48, WIN) and Maya's stats (12 points, 5 rebounds) → season record auto-updates to 1-0 → during practice, Maya sustains a head injury → AD logs the injury (MODERATE, CONCUSSION_PROTOCOL) → the 6-step concussion protocol begins (step 1: complete rest, 24hr minimum) → Maya's roster eligibility flips to INJURED_NOT_CLEARED → after completing all 6 steps, physician uploads clearance document → AD reviews and accepts clearance → Maya's eligibility returns to ELIGIBLE.

Step-by-Step Build Plan

01 Programme + Season + Roster Schema
Schema

The athletics foundation: sport programme definitions, per-year season instances, team rosters at different levels (Varsity/JV/Freshman/Club), and individual roster membership with eligibility tracking.

Tables (4)
  1. ath_programmes — school_id UUID, sport_name TEXT NOT NULL, season TEXT NOT NULL 4-value CHECK (FALL, WINTER, SPRING, YEAR_ROUND), levels_offered TEXT[] NOT NULL, max_roster_size_per_level JSONB nullable, min_gpa NUMERIC(3,2) nullable (the eligibility threshold the Step 5 service checks against live gradebook data), is_active BOOLEAN DEFAULT true. UNIQUE(school_id, sport_name). The programme is the sport definition; each year gets a season instance.
  2. ath_seasons — programme_id UUID FK NOT NULL, academic_year TEXT NOT NULL, first_practice_date DATE, first_game_date DATE, last_game_date DATE, playoff_cutoff_date DATE, status TEXT NOT NULL DEFAULT 'UPCOMING' 4-value CHECK (UPCOMING, ACTIVE, POSTSEASON, COMPLETED). UNIQUE(programme_id, academic_year). The season is the year-specific instance of a programme.
  3. ath_rosters — season_id UUID FK NOT NULL, level TEXT NOT NULL 4-value CHECK (VARSITY, JV, FRESHMAN, CLUB), head_coach_id UUID FK(hr_employees) nullable, is_certified BOOLEAN DEFAULT false, certified_at TIMESTAMPTZ nullable. UNIQUE(season_id, level). Certification means the AD has reviewed eligibility for all members and signed off.
  4. ath_roster_members — roster_id UUID FK NOT NULL, student_id UUID FK(sis_students) NOT NULL, jersey_number TEXT, position TEXT, eligibility_status TEXT NOT NULL 6-value CHECK (ELIGIBLE, INELIGIBLE, PENDING_PHYSICAL, PENDING_CONSENT, PENDING_TRANSFER_WAIVER, INJURED_NOT_CLEARED), joined_at DATE NOT NULL, removed_at DATE nullable, removal_reason TEXT nullable. UNIQUE(roster_id, student_id). The eligibility_status is the live state the AD tracks — the Step 5 service checks GPA against the programme's min_gpa on add and on manual re-check.
Produces → 4 new tables. Migration: 046_ath_programmes_rosters.sql.
02 Game + Results + Records Schema
Schema

The competitive surface: game scheduling with cross-school proposal workflow, results with score-by-period breakdown, per-player per-game statistics with sport-configurable categories, season W/L/D records, and school all-time records.

Tables (6)
  1. ath_games — season_id UUID FK NOT NULL, roster_id UUID FK NOT NULL, game_date DATE NOT NULL, game_time TIME NOT NULL, opponent_name TEXT NOT NULL, opponent_school_id UUID nullable (soft to platform entity cache for CampusOS opponents), location TEXT NOT NULL 3-value CHECK (HOME, AWAY, NEUTRAL), facility_booking_id UUID nullable (soft to fac_space_bookings), transport_request_id UUID nullable (soft to trn_), status TEXT NOT NULL DEFAULT 'SCHEDULED' 6-value CHECK (SCHEDULED, CONFIRMED, IN_PROGRESS, COMPLETED, POSTPONED, CANCELLED), is_conference_game BOOLEAN DEFAULT false, is_ticketed BOOLEAN DEFAULT false, event_id UUID nullable (soft to evt_events). INDEX(season_id, game_date).
  2. ath_game_proposals — Cross-school game scheduling (ADR-069). proposing_school_id UUID NOT NULL, receiving_school_id UUID NOT NULL, sport TEXT NOT NULL, proposed_date DATE NOT NULL, proposed_time TIME, proposed_location TEXT NOT NULL 3-value CHECK (HOME_PROPOSING, HOME_RECEIVING, NEUTRAL), level TEXT NOT NULL, notes TEXT, status TEXT NOT NULL DEFAULT 'PROPOSED' 5-value CHECK (PROPOSED, ACCEPTED, COUNTER_PROPOSED, DECLINED, CONFIRMED), counter_proposal_data JSONB nullable, confirmed_game_id UUID nullable. Cross-tenant via platform entity cache.
  3. ath_game_results — game_id UUID FK UNIQUE NOT NULL (one result per game), home_score INT NOT NULL, away_score INT NOT NULL, score_by_period JSONB nullable, outcome TEXT NOT NULL 4-value CHECK (WIN, LOSS, DRAW, FORFEIT), entered_by UUID FK NOT NULL, entered_at TIMESTAMPTZ. On INSERT: service updates ath_season_records. Emits ath.game.result.entered.
  4. ath_player_game_stats — Per-player per-game statistics. game_id UUID FK NOT NULL, student_id UUID FK(sis_students) NOT NULL, stat_category TEXT NOT NULL (sport-configurable: points, rebounds, assists, goals, etc.), stat_value NUMERIC(10,2) NOT NULL, entered_by UUID FK NOT NULL. INDEX(game_id, student_id). Multiple rows per (game, student) — one per stat category.
  5. ath_season_records — W/L/D rollup per roster. roster_id UUID FK UNIQUE NOT NULL, wins INT DEFAULT 0, losses INT DEFAULT 0, draws INT DEFAULT 0, conference_wins INT DEFAULT 0, conference_losses INT DEFAULT 0, conference_draws INT DEFAULT 0. Service-side update on game result entry (trigger deferred to Phase 3).
  6. ath_all_time_records — School athletic records. school_id UUID, sport TEXT NOT NULL, record_type TEXT NOT NULL 3-value CHECK (SINGLE_GAME, SEASON, CAREER), stat_category TEXT NOT NULL, record_value NUMERIC(10,2) NOT NULL, holder_student_id UUID FK(sis_students) nullable, set_date DATE, set_season_id UUID FK nullable. UNIQUE(school_id, sport, record_type, stat_category).
Produces → 6 new tables. Migration: 047_ath_games_results.sql.
03 Coaching + Injuries + Safety Schema
Schema

Coaching staff assignments per roster, injury tracking with concussion protocol, and physician clearance documents for return-to-play.

Tables (4)
  1. ath_coaching_assignments — roster_id UUID FK NOT NULL, coach_person_id UUID FK(iam_person) NOT NULL (uses the universal person identity so both staff coaches and volunteer coaches are covered), role TEXT NOT NULL 4-value CHECK (HEAD_COACH, ASSISTANT_COACH, VOLUNTEER_COACH, SPECIALIST), stipend_amount NUMERIC(8,2) nullable, is_active BOOLEAN DEFAULT true. INDEX(roster_id, is_active).
  2. ath_injuries — student_id UUID FK(sis_students) NOT NULL, game_id UUID FK(ath_games) nullable (null for practice injuries), practice_date DATE nullable, injury_date DATE NOT NULL, body_part TEXT NOT NULL, injury_description TEXT NOT NULL, initial_assessment TEXT, action_taken TEXT, severity TEXT NOT NULL 4-value CHECK (MINOR, MODERATE, SEVERE, EMERGENCY), health_record_id UUID nullable (soft to hlth_ for cross-module linking), incident_report_id UUID nullable (soft to inc_), return_to_play_status TEXT DEFAULT 'SIDELINED' 4-value CHECK (ACTIVE, SIDELINED, CONCUSSION_PROTOCOL, CLEARED), logged_by UUID FK NOT NULL. INDEX(student_id, injury_date DESC). On CONCUSSION_PROTOCOL: the roster member's eligibility_status flips to INJURED_NOT_CLEARED.
  3. ath_concussion_protocol_steps — SAFETY KEYSTONE. injury_id UUID FK NOT NULL, step_number INT NOT NULL CHECK(1–6), step_name TEXT NOT NULL, started_at TIMESTAMPTZ NOT NULL, minimum_duration_hours INT DEFAULT 24, completed_at TIMESTAMPTZ nullable, symptom_free BOOLEAN DEFAULT false, notes TEXT, cleared_by UUID FK nullable. UNIQUE(injury_id, step_number). System enforces: step N+1 cannot start until step N is completed AND minimum duration has elapsed. The 6 steps are: (1) complete rest, (2) light aerobic activity, (3) sport-specific exercise, (4) non-contact training drills, (5) full contact practice, (6) return to competition.
  4. ath_medical_clearances — injury_id UUID FK NOT NULL, document_s3_key TEXT NOT NULL, physician_name TEXT, clearance_date DATE NOT NULL, uploaded_by UUID FK NOT NULL, review_status TEXT NOT NULL DEFAULT 'PENDING' 5-value CHECK (PENDING, ACCEPTED, REJECTED, NOT_SUBMITTED, EXPIRED), reviewed_by UUID FK nullable, reviewed_at TIMESTAMPTZ nullable. Required before return_to_play_status can flip to CLEARED.
Produces → 4 new tables. Migration: 048_ath_coaching_injuries.sql. Total Cycle 13 tables: 14.
