Plan Overview

Cycle 22 builds the M62 IT Infrastructure module — 16 of the 26 ERD tables. This is the fourth and final Campus Operations module, closing Wave 4. It manages the technology fleet that supports every other module: the laptops teachers use for gradebooks, the tablets students use in classrooms, the servers running the network, and the software licences that make it all work.

The module spans 4 domains: (1) device asset management with categories, asset tags, assignments, documents, and damage/repair workflow, (2) software licence tracking with seat utilisation and per-user assignments, (3) the encrypted credential vault (ADR-065) with tiered access control and immutable audit logging, and (4) MDM integration surface with sync logs + compliance alerts, network infrastructure registry, procurement orders, and the device selection workflow (ADR-066) for onboarding.

Security — Credential Vault (ADR-065)

tech_credential_vault stores shared service credentials (vendor portals, API keys, SSL certificates, Wi-Fi passwords) encrypted with AES-256 using a separate encryption key from student data. Access is tiered: STANDARD (most staff), ELEVATED (IT team leads), CRITICAL (IT admin only). Every credential access — view, copy, modify, create, delete — writes an immutable tech_credential_access_log row. Rotation alerts fire at 60/30/14/3 days before expiry. The credential vault is the only surface in CampusOS that stores secrets beyond authentication tokens.

Vertical Slice Deliverable

IT admin creates asset categories ("Chromebook", depreciation 4 years; "iPad", 3 years) → registers 30 Chromebooks with sequential asset tags (IT-CB-001 through IT-CB-030) → assigns IT-CB-001 to Maya (condition: EXCELLENT) → uploads warranty document → Maya drops the Chromebook; teacher files a damage report (MODERATE, photo attached) → IT admin creates a repair record (WARRANTY_CLAIM, sent to vendor) → device status flips to REPAIR → IT admin registers "Google Workspace for Education" licence (SITE, unlimited seats, expires Dec 2026) + "Adobe Creative Suite" (PER_SEAT, 25 seats, 18 used) → assigns Adobe to Rivera → used_seats increments to 19 → IT admin stores the school Wi-Fi admin credential in the vault (CRITICAL tier, AES-256 encrypted) → Rivera views the credential → immutable access_log row captures the VIEW with timestamp → MDM sync shows IT-CB-015 has STALE_CHECKIN alert (hasn't checked in for 7 days) → admin registers the network infrastructure (2 switches, 4 access points, 1 server) → creates a procurement order for 10 replacement Chromebooks → new student selects a Chromebook from the device options catalogue during onboarding (ADR-066).

Step-by-Step Build Plan

01Asset + Assignment + Documents Schema
Schema

Asset category catalogue with depreciation, the device fleet registry with asset tags and warranty tracking, device-to-person assignments with condition recording, and asset documentation.

Tables (4)
  1. tech_asset_categories — school_id UUID, name TEXT NOT NULL, depreciation_years INT, maintenance_interval_months INT. UNIQUE(school_id, name).
  2. tech_assets — school_id UUID, category_id UUID FK, asset_tag TEXT NOT NULL, serial_number TEXT, make TEXT, model TEXT, purchase_date DATE, purchase_cost NUMERIC(10,2), status TEXT NOT NULL DEFAULT 'AVAILABLE' 5-value CHECK (AVAILABLE, ASSIGNED, REPAIR, RETIRED, LOST), warranty_expiry DATE, procurement_order_id UUID nullable (soft to tech_procurement_orders). UNIQUE(school_id, asset_tag). INDEX(school_id, status).
  3. tech_asset_assignments — asset_id UUID FK NOT NULL, assigned_to_id UUID FK(platform_users) NOT NULL, assigned_at TIMESTAMPTZ NOT NULL, returned_at TIMESTAMPTZ nullable, condition_at_assign TEXT 4-value CHECK (EXCELLENT, GOOD, FAIR, DAMAGED), condition_at_return TEXT same CHECK nullable, notes TEXT. INDEX(assigned_to_id) WHERE returned_at IS NULL for active assignments.
  4. tech_asset_documents — asset_id UUID FK NOT NULL, document_type TEXT NOT NULL 4-value CHECK (INVOICE, WARRANTY, INSURANCE, MANUAL), s3_key TEXT NOT NULL, uploaded_at TIMESTAMPTZ. INDEX(asset_id, document_type).
Produces → 4 new tables. Migration: 070_tech_assets.sql.
02Licences + Credential Vault Schema
Schema

Software licence tracking with seat counts and utilisation alerts, per-user licence assignments, the encrypted credential vault with tiered access (ADR-065), and the immutable credential access audit log.

Tables (4)
  1. tech_software_licences — school_id UUID, software_name TEXT NOT NULL, vendor TEXT, licence_type TEXT NOT NULL 3-value CHECK (PER_SEAT, SITE, SUBSCRIPTION), total_seats INT nullable (null for SITE), used_seats INT DEFAULT 0, expiry_date DATE, annual_cost NUMERIC(10,2). INDEX(school_id, expiry_date). Alert at 80% seat usage + 30 days before expiry.
  2. tech_software_assignments — licence_id UUID FK NOT NULL, assignee_id UUID NOT NULL (soft to platform_users), assigned_at TIMESTAMPTZ, last_used_at TIMESTAMPTZ. UNIQUE(licence_id, assignee_id). On INSERT: tech_software_licences.used_seats++. On DELETE: used_seats--.
  3. tech_credential_vault — SECURITY KEYSTONE (ADR-065). school_id UUID NOT NULL, service_name TEXT NOT NULL, credential_type TEXT NOT NULL 7-value CHECK (VENDOR_PORTAL, SERVICE_ACCOUNT, API_KEY, SSL_CERTIFICATE, WIFI_CREDENTIAL, ADMIN_SHARED, OTHER), username TEXT, encrypted_password TEXT NOT NULL (AES-256, separate key from student data), url TEXT, last_rotated_at TIMESTAMPTZ, rotation_due_at TIMESTAMPTZ, expiry_date DATE, access_tier TEXT NOT NULL DEFAULT 'STANDARD' 3-value CHECK (STANDARD, ELEVATED, CRITICAL), notes TEXT. INDEX(school_id, credential_type). INDEX(expiry_date) WHERE expiry_date IS NOT NULL for rotation alerts.
  4. tech_credential_access_log — IMMUTABLE. credential_id UUID FK NOT NULL, accessed_by UUID FK(platform_users) NOT NULL, access_type TEXT NOT NULL 5-value CHECK (VIEW, COPY, MODIFY, CREATE, DELETE), accessed_at TIMESTAMPTZ NOT NULL. NO UPDATE, NO DELETE. RANGE-partition-ready by accessed_at. INDEX(credential_id, accessed_at DESC).
Produces → 4 new tables. Migration: 071_tech_licences_vault.sql.
03MDM + Infrastructure + Procurement + Device Selection Schema
Schema

MDM device sync status with compliance alerts, network infrastructure registry, device damage reports and repair workflow, procurement orders, and the device selection catalogue + workflow for onboarding (ADR-066).

Tables (8)
  1. tech_mdm_sync_logs — asset_id UUID FK NOT NULL, mdm_provider TEXT NOT NULL 4-value CHECK (JAMF, INTUNE, MOSYLE, GOOGLE), sync_at TIMESTAMPTZ NOT NULL, device_name TEXT, os_version TEXT, last_check_in TIMESTAMPTZ, is_compliant BOOLEAN, compliance_details JSONB. INDEX(asset_id, sync_at DESC).
  2. tech_mdm_alerts — asset_id UUID FK NOT NULL, alert_type TEXT NOT NULL 6-value CHECK (STALE_CHECKIN, POLICY_VIOLATION, JAILBREAK_DETECTED, ENCRYPTION_DISABLED, UNAUTHORISED_APP, LOW_STORAGE), alert_detail TEXT, first_detected_at TIMESTAMPTZ, last_detected_at TIMESTAMPTZ, is_resolved BOOLEAN DEFAULT false, resolved_by UUID nullable, resolved_at TIMESTAMPTZ. INDEX(asset_id, is_resolved) WHERE is_resolved=false.
  3. tech_damage_reports — asset_id UUID FK NOT NULL, reported_by UUID FK NOT NULL, description TEXT NOT NULL, severity TEXT NOT NULL 4-value CHECK (MINOR, MODERATE, MAJOR, WRITE_OFF), photo_s3_keys TEXT[], reported_at TIMESTAMPTZ, repair_record_id UUID nullable. INDEX(asset_id, reported_at DESC).
  4. tech_repair_records — asset_id UUID FK NOT NULL, damage_report_id UUID FK nullable, vendor_id UUID FK(tkt_vendors) nullable, repair_type TEXT NOT NULL 3-value CHECK (INTERNAL, EXTERNAL_VENDOR, WARRANTY_CLAIM), cost NUMERIC(8,2), estimated_return_date DATE, sent_for_repair_at TIMESTAMPTZ, returned_at TIMESTAMPTZ, resolution_notes TEXT, status TEXT NOT NULL DEFAULT 'PENDING' 4-value CHECK (PENDING, IN_REPAIR, COMPLETE, WRITTEN_OFF). On INSERT with vendor: tech_assets.status → REPAIR.
  5. tech_infrastructure_items — school_id UUID, item_name TEXT NOT NULL, item_type TEXT NOT NULL 9-value CHECK (SWITCH, ACCESS_POINT, SERVER, ROUTER, FIREWALL, PRINTER, NAS, UPS, OTHER), location TEXT NOT NULL, ip_address TEXT, mac_address TEXT, make TEXT, model TEXT, serial_number TEXT, purchase_date DATE, warranty_expiry DATE, status TEXT NOT NULL DEFAULT 'ACTIVE' 3-value CHECK (ACTIVE, MAINTENANCE, DECOMMISSIONED). UNIQUE(school_id, serial_number) WHERE serial_number IS NOT NULL.
  6. tech_procurement_orders — school_id UUID, order_title TEXT NOT NULL, vendor_id UUID FK(tkt_vendors) nullable, purchase_order_number TEXT, ordered_by UUID FK(hr_employees) NOT NULL, order_date DATE NOT NULL, expected_delivery_date DATE, total_cost NUMERIC(10,2), status TEXT NOT NULL DEFAULT 'DRAFT' 6-value CHECK (DRAFT, SUBMITTED, APPROVED, ORDERED, DELIVERED, CANCELLED), linked_approval_id UUID FK(wsk_approval_requests) nullable. INDEX(school_id, status).
  7. tech_device_options — School-configurable device selection catalogue (ADR-066). school_id UUID, option_name TEXT NOT NULL, device_type TEXT NOT NULL, operating_system TEXT NOT NULL, specifications TEXT, software_available TEXT[], cost_difference NUMERIC(8,2) DEFAULT 0, is_active BOOLEAN DEFAULT true. INDEX(school_id, is_active).
  8. tech_device_selections — Per-person device selection during onboarding (ADR-066). person_id UUID FK(iam_person) NOT NULL, option_id UUID FK(tech_device_options) NOT NULL, selection_context TEXT NOT NULL 3-value CHECK (ENROLMENT, REFRESH, NEW_HIRE), selected_at TIMESTAMPTZ NOT NULL, approved_by UUID FK(platform_users) nullable, approved_at TIMESTAMPTZ, status TEXT NOT NULL DEFAULT 'SELECTED' 5-value CHECK (SELECTED, APPROVED, PROVISIONING, PROVISIONED, CANCELLED). INDEX(status) WHERE status IN ('SELECTED', 'APPROVED', 'PROVISIONING').
Produces → 8 new tables. Migration: 072_tech_mdm_procurement.sql. Total Cycle 22 tables: 16.
