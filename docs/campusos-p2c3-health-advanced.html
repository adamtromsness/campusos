May 2026 · 8 Steps · ERD v11 · M23 Health .1 (6 tables) · HLT-004 + HLT-005 · Phase 2 Cycle 3

Plan Overview

Phase 2 Cycle 3 builds the deferred tables from Cycle 10's M23 Health module — 6 new tables. This is the smallest Wave A cycle but carries the highest regulatory weight: every US state requires schools to report immunisation compliance rates, and many require vision/hearing screening documentation. Without these tables, the nurse tracks compliance in a spreadsheet — exactly the patchwork CampusOS is designed to replace.

The cycle adds 3 capabilities to the existing health module: (1) telehealth — a provider directory, session scheduling with video link, and document exchange for remote consultations, (2) immunisation compliance — state requirement definitions matched against each student's hlth_immunisations records to compute compliance status with overdue alerting, and (3) screening detail — per-test results within the existing hlth_screenings framework (left eye 20/40, right ear 25dB at 1kHz) with referral tracking for follow-up.

Vertical Slice Deliverable

Admin configures state immunisation requirements for Kansas: DTaP (5 doses by kindergarten), MMR (2 doses by kindergarten), IPV (4 doses), Varicella (2 doses), Hep B (3 doses) → ImmunisationComplianceWorker runs nightly: reads each student's hlth_immunisations records, compares against requirements by grade level, computes compliance status (COMPLIANT / NON_COMPLIANT / EXEMPT / PROVISIONAL) → school-wide compliance dashboard: 94% compliant, 12 students non-compliant, 3 exempt (religious waiver) → overdue notifications sent to parents of non-compliant students → nurse registers 2 telehealth providers (Children's Mercy Behavioral Health, Kansas Vision Clinic) → schedules a telehealth session for Maya with the behavioural health provider (parent consent via platform_signature_requests) → session completed, session notes uploaded as encrypted document → separately, nurse conducts vision screening for Grade 3: per-student results recorded (left eye 20/20, right eye 20/40 for Maya) → Maya flagged for referral (right eye below threshold) → referral letter generated, hlth_screening_referrals row created with follow-up tracking.

What's In / What's Deferred

In scope (6 tables): hlth_telehealth_providers, hlth_telehealth_sessions, hlth_telehealth_documents, hlth_immunisation_requirements, hlth_immunisation_compliance, hlth_screening_referrals. Functions HLT-004 (Screenings) + HLT-005 (Telehealth).

Deferred: Live video conferencing integration (meeting_url is a manual entry this cycle; native video integration requires Video Conferencing extracted service). Automated immunisation data import from state registries (IIS). BMI/growth chart tracking. Dental screening module. Automated referral letter PDF generation.

Step-by-Step Build Plan

01Schema — All 6 Tables
Schema
Tables (6)
  1. hlth_telehealth_providers — school_id UUID, provider_name TEXT NOT NULL, speciality TEXT, is_active BOOLEAN DEFAULT true, booking_url TEXT. INDEX(school_id, is_active).
  2. hlth_telehealth_sessions — student_id UUID FK NOT NULL, provider_id UUID FK NOT NULL, scheduled_at TIMESTAMPTZ NOT NULL, duration_minutes INT, status TEXT NOT NULL DEFAULT 'SCHEDULED' 5-value CHECK (SCHEDULED, IN_PROGRESS, COMPLETED, NO_SHOW, CANCELLED), meeting_url TEXT, session_notes_s3_key TEXT, consent_signature_id UUID (soft to platform_signature_requests). INDEX(student_id, scheduled_at DESC). HIPAA: every read logged to hlth_access_log.
  3. hlth_telehealth_documents — session_id UUID FK NOT NULL, document_type TEXT NOT NULL, s3_key TEXT NOT NULL, uploaded_at TIMESTAMPTZ NOT NULL, signature_request_id UUID (soft to platform_signature_requests). Encrypted at rest (HIPAA KMS key).
  4. hlth_immunisation_requirements — school_id UUID (null = state-level default), state_code TEXT NOT NULL, vaccine_name TEXT NOT NULL, required_doses INT NOT NULL, required_by_grade TEXT NOT NULL (e.g., "K", "7"), allows_exemption BOOLEAN DEFAULT true, exemption_types TEXT[] (MEDICAL, RELIGIOUS, PHILOSOPHICAL). UNIQUE(COALESCE(school_id, '00000000-0000-0000-0000-000000000000'), state_code, vaccine_name, required_by_grade).
  5. hlth_immunisation_compliance — Materialised by ImmunisationComplianceWorker. student_id UUID NOT NULL, school_id UUID NOT NULL, academic_year_id UUID, status TEXT NOT NULL 4-value CHECK (COMPLIANT, NON_COMPLIANT, EXEMPT, PROVISIONAL), missing_vaccines JSONB (array of {vaccine_name, doses_received, doses_required}), exemption_type TEXT, exemption_document_s3_key TEXT, last_computed_at TIMESTAMPTZ NOT NULL, parent_notified_at TIMESTAMPTZ. UNIQUE(student_id, academic_year_id). INDEX(school_id, status).
  6. hlth_screening_referrals — screening_id UUID FK(hlth_screenings) NOT NULL, student_id UUID FK NOT NULL, referral_type TEXT NOT NULL 4-value CHECK (VISION, HEARING, SCOLIOSIS, OTHER), reason TEXT NOT NULL, referred_to TEXT, referral_date DATE NOT NULL, follow_up_date DATE, follow_up_outcome TEXT 4-value CHECK (NORMAL, TREATMENT_REQUIRED, GLASSES_PRESCRIBED, HEARING_AID, OTHER) nullable, status TEXT NOT NULL DEFAULT 'REFERRED' 3-value CHECK (REFERRED, FOLLOW_UP_COMPLETE, LOST_TO_FOLLOW_UP). INDEX(student_id, status).
Produces → 6 tables. Migration: 101_hlth_advanced.sql.

03Telehealth NestJS Module

  2. 04Immunisation Compliance NestJS Module
Code
  1. ImmunisationRequirementService — GET /health/immunisation/requirements (state requirements for this school), POST /health/immunisation/requirements (admin seeds state requirements), PATCH /health/immunisation/requirements/:id.
  2. ImmunisationComplianceWorker — Nightly: for each student, reads hlth_immunisations → compares against hlth_immunisation_requirements for the student's grade → upserts hlth_immunisation_compliance with status + missing_vaccines JSONB. Newly NON_COMPLIANT students: emits hlth.immunisation.noncompliant for parent notification.
  3. Compliance endpoints: GET /health/immunisation/compliance (school-wide dashboard: % compliant + non-compliant list), GET /health/immunisation/compliance/:studentId (per-student detail with missing vaccines), POST /health/immunisation/compliance/run (admin: manual trigger), GET /health/immunisation/compliance/report (state-formatted CSV export).
Produces → 2 services + 1 worker, ~8 endpoints, 1 Kafka emit.

06Health UI — Telehealth + Immunisation + Screening
UI
