Plan Overview

Cycle 29 builds the M110 Analytics module — 16 of the 34 ERD tables. This is the operational read layer (ADR-008 CQRS-lite) that transforms the raw event stream from 28 prior cycles into actionable dashboards. No domain module serves analytics queries directly — all analytical reads go through rpt_* tables, routed to the read replica (ADR-050).

The module spans 3 domains: (1) analytics infrastructure — worker checkpoints, incremental rebuild snapshots (ADR-049), and at-risk threshold configuration, (2) core read models materialised from Kafka events — attendance, academics, class performance, staff, school, and district summaries + wellbeing trends + financial aging, and (3) the report engine — configurable report definitions, scheduled delivery, state compliance templates, and report execution tracking.

Architecture — Read Model Ownership (ADR-008)

Every rpt_* table has exactly one owning module and one writing worker. No other module writes to a rpt_* table it does not own — cross-module reads are permitted for display. The worker naming convention is {Domain}ReadModelWorker. This cycle builds the analytics-owned read models (rpt_school_summary, rpt_district_summary, rpt_district_school_comparison, rpt_wellbeing_trends, rpt_fin_aged_debtors) plus the SIS-owned and Classroom-owned read models that the Analytics module consumes for its dashboards. All rpt_* tables are read-only to the Analytics API — the workers are the sole writers.

Vertical Slice Deliverable

SISReadModelWorker consumes attendance.confirmed events and materialises rpt_daily_attendance_summary (present/absent/late counts per class per day, attendance_rate computed) → also materialises rpt_student_academic_summary (GPA + credits + attendance_rate + at_risk_flags per student per year from grade.posted events) → ClassroomReadModelWorker materialises rpt_class_performance_summary (class averages, grade distribution per class per term) → admin configures at-risk detection: "Flag students with attendance < 85% AND GPA < 2.0" via rpt_at_risk_configurations → at-risk worker evaluates against rpt_student_academic_summary and sets at_risk_flags → rpt.at_risk.flagged fires → SchoolSummaryWorker aggregates per-school totals → DistrictAnalyticsWorker (nightly 03:00 UTC) aggregates school summaries into rpt_district_summary + rpt_district_school_comparison for the superintendent → admin creates a report definition "Weekly Attendance Report" with template_config → schedules it for Monday 8am, delivery to principal via EMAIL as PDF → ScheduledReportWorker fires, generates the report, stores output in S3, creates rpt_report_runs row → principal receives the PDF.

Step-by-Step Build Plan

01Analytics Infrastructure Schema
Schema

Worker checkpoint tracking (Kafka offset-based, never timestamps), configurable at-risk threshold definitions, and incremental rebuild snapshots (ADR-049) enabling FROM_SNAPSHOT rebuilds without full Kafka replay.

Tables (3)
  1. rpt_analytics_worker_checkpoints — consumer_group TEXT NOT NULL, topic TEXT NOT NULL, partition INT NOT NULL, committed_offset BIGINT NOT NULL, log_end_offset BIGINT, lag BIGINT, recorded_at TIMESTAMPTZ. UNIQUE(consumer_group, topic, partition). Stores offsets — NEVER timestamps as Kafka checkpoints.
  2. rpt_at_risk_configurations — school_id UUID, name TEXT NOT NULL, trigger_conditions JSONB NOT NULL (attendance_threshold, grade_threshold, missed_assignments_threshold, behaviour_incident_threshold, etc.), alert_recipients UUID[], is_active BOOLEAN DEFAULT true. UNIQUE(school_id, name). The AtRiskEvaluationWorker evaluates these conditions nightly against rpt_student_academic_summary.
  3. rpt_rebuild_snapshots — read_model_name TEXT NOT NULL, school_id UUID, snapshot_date DATE NOT NULL, snapshot_data JSONB NOT NULL (frozen aggregate state at snapshot time), kafka_offsets JSONB NOT NULL (per-topic-partition offsets at snapshot). UNIQUE(read_model_name, school_id, snapshot_date). Enables FROM_SNAPSHOT rebuild: start from snapshot + replay events from offset, not from the beginning (ADR-049). SLA: <10 min for FROM_SNAPSHOT rebuild.
Produces → 3 tables. Migration: 089_rpt_infrastructure.sql.
02Core Read Models Schema
Schema

The 5 school-day read models that drive the principal's dashboard: attendance summaries, student academic snapshots, class performance analysis, staff workload summary, and school-level aggregate.

Tables (5)
  1. rpt_daily_attendance_summary — school_id UUID, class_id UUID, summary_date DATE NOT NULL, present_count INT, absent_count INT, late_count INT, total_enrolled INT, attendance_rate NUMERIC(5,4). UNIQUE(school_id, class_id, summary_date). RANGE partition by created_at monthly, 3-year retention via pg_partman. Materialised by SISReadModelWorker from attendance.confirmed.
  2. rpt_student_academic_summary — student_id UUID, academic_year_id UUID, school_id UUID, current_gpa NUMERIC(4,3), credits_earned NUMERIC(5,1), credits_attempted NUMERIC(5,1), attendance_rate NUMERIC(5,4), at_risk_flags JSONB. UNIQUE(student_id, academic_year_id). RANGE partition by created_at monthly, 3-year retention. Current-year snapshot only. Materialised by SISReadModelWorker from grade.posted + attendance.confirmed.
  3. rpt_class_performance_summary — class_id UUID, term_id UUID, school_id UUID, avg_grade NUMERIC(5,2), median_grade NUMERIC(5,2), grade_distribution JSONB (histogram: A/B/C/D/F counts), assignment_completion_rate NUMERIC(5,4), student_count INT. UNIQUE(class_id, term_id). Materialised by ClassroomReadModelWorker from grade.posted.
  4. rpt_staff_summary — employee_id UUID, academic_year_id UUID, school_id UUID, classes_taught INT, total_students INT, leave_days_taken NUMERIC(5,1), avg_class_performance NUMERIC(5,2). UNIQUE(employee_id, academic_year_id). Materialised from leave.approved + grade.posted.
  5. rpt_school_summary — school_id UUID, academic_year_id UUID, total_enrolled INT, total_staff INT, avg_attendance_rate NUMERIC(5,4), avg_gpa NUMERIC(4,3), at_risk_count INT, incident_count INT, generated_at TIMESTAMPTZ. UNIQUE(school_id, academic_year_id). Materialised nightly by SchoolSummaryWorker aggregating the above read models.
Produces → 5 tables. Migration: 090_rpt_core_read_models.sql.
03District + Cross-Domain + Report Engine Schema
Schema

District-level aggregate dashboards for superintendents, cross-domain read models (wellbeing trends, financial aging), and the configurable report engine with scheduled delivery.

Tables (8)
  1. rpt_district_summary — organisation_id UUID, academic_year_id UUID, school_count INT, total_enrolled INT, total_staff INT, avg_attendance_rate NUMERIC(5,4). UNIQUE(organisation_id, academic_year_id). Materialised by DistrictAnalyticsWorker nightly at 03:00 UTC after school-level jobs.
  2. rpt_district_school_comparison — organisation_id UUID, academic_year_id UUID, school_id UUID, rank_by_attendance INT, rank_by_performance INT, metrics JSONB, generated_at TIMESTAMPTZ. Per-school row within a district for superintendent comparison dashboard.
  3. rpt_wellbeing_trends — school_id UUID, grade_level TEXT, period_start DATE, period_end DATE, avg_wellbeing_score NUMERIC(3,1), response_count INT, wants_to_talk_count INT, flagged_count INT. No individual attribution. Aggregated by WellbeingTrendsWorker from Cycle 11.1 check-in data.
  4. rpt_fin_aged_debtors — school_id UUID, family_account_id UUID, total_outstanding NUMERIC(12,2), current_bucket NUMERIC(12,2), days_30 NUMERIC(12,2), days_60 NUMERIC(12,2), days_90_plus NUMERIC(12,2), last_payment_date DATE, generated_at TIMESTAMPTZ. Materialised by FinanceARWorker from Cycle 6 payment data.
  5. rpt_report_definitions — school_id UUID, name TEXT NOT NULL, report_type TEXT, template_config JSONB, is_state_report BOOLEAN DEFAULT false. UNIQUE(school_id, name).
  6. rpt_report_runs — report_definition_id UUID FK, run_by UUID FK, status TEXT NOT NULL 4-value CHECK (PENDING, RUNNING, COMPLETE, FAILED), output_s3_key TEXT, output_format TEXT DEFAULT 'CSV' 3-value CHECK (CSV, PDF, XLSX), generated_at TIMESTAMPTZ, row_count INT. INDEX(report_definition_id, generated_at DESC).
  7. rpt_state_report_templates — state_code TEXT, report_type TEXT, schema_version TEXT, template_config JSONB. Platform-seeded templates for state compliance reporting.
  8. rpt_scheduled_reports — school_id UUID, report_name TEXT NOT NULL, template_name TEXT NOT NULL, report_params JSONB, schedule_cron TEXT NOT NULL, timezone TEXT NOT NULL, delivery_channel TEXT NOT NULL DEFAULT 'EMAIL' 3-value CHECK (EMAIL, IN_APP, BOTH), recipient_ids UUID[], output_format TEXT NOT NULL DEFAULT 'CSV', is_active BOOLEAN DEFAULT true, last_run_at TIMESTAMPTZ, next_run_at TIMESTAMPTZ, last_run_status TEXT 2-value CHECK (SUCCESS, FAILED), created_by UUID FK. INDEX(next_run_at) WHERE is_active=true.
Produces → 8 tables. Migration: 091_rpt_district_reports.sql. Total Cycle 29 tables: 16.

05Analytics Workers NestJS Module
Code
Workers & Endpoints
  1. SISReadModelWorker — Nightly materialisation (or manual trigger): reads from sis_attendance + sis_enrolments + cls_grades, aggregates into rpt_daily_attendance_summary + rpt_student_academic_summary. Idempotent upsert on UNIQUE keys. Records checkpoint in rpt_analytics_worker_checkpoints.
  2. ClassroomReadModelWorker — Reads from cls_grades + cls_assignments, materialises rpt_class_performance_summary + rpt_staff_summary. Idempotent upsert on UNIQUE(class_id, term_id).
  3. AtRiskEvaluationWorker — Runs after SISReadModelWorker. Evaluates each active rpt_at_risk_configurations against rpt_student_academic_summary. Sets at_risk_flags JSONB on matching students. Emits rpt.at_risk.flagged for new flags (not previously flagged). GET /analytics/at-risk (at-risk student list with flags + thresholds). GET /analytics/at-risk/configurations, POST /analytics/at-risk/configurations.
  4. Manual trigger endpoints: POST /analytics/workers/run (admin: trigger all workers in sequence), GET /analytics/workers/status (checkpoint status + lag per worker).
Produces → AnalyticsModule with 3 workers, ~6 endpoints, 1 Kafka emit (rpt.at_risk.flagged).
06School + District + Cross-Domain Workers NestJS Module
Code
Workers & Endpoints
  1. SchoolSummaryWorker — Runs nightly after SIS + Classroom workers. Aggregates rpt_daily_attendance_summary + rpt_student_academic_summary + rpt_class_performance_summary + sis_behaviour_incidents into rpt_school_summary. GET /analytics/school-summary.
  2. DistrictAnalyticsWorker — Runs at 03:00 UTC after school-level jobs. Aggregates rpt_school_summary across all schools in the organisation into rpt_district_summary + rpt_district_school_comparison with rankings. GET /analytics/district-summary, GET /analytics/district-comparison.
  3. WellbeingTrendsWorker — Aggregates from Cycle 11.1 svc_checkin_responses (no individual identifiers). Groups by school + grade + period. GET /analytics/wellbeing-trends.
  4. FinanceARWorker — Reads from Cycle 6 pay_family_accounts + pay_ledger_entries. Computes aged debtor buckets (current, 30d, 60d, 90d+). GET /analytics/aged-debtors.
Produces → 4 workers, ~6 endpoints. Chained nightly execution: SIS → Classroom → AtRisk → SchoolSummary → District → Wellbeing → Finance.
07Report Engine NestJS Module
Code
Services & Endpoints
  1. ReportDefinitionService — GET /analytics/reports, POST /analytics/reports (create report definition with template_config), PATCH /analytics/reports/:id.
  2. ReportRunService — POST /analytics/reports/:id/run (on-demand: generates report from definition, queries rpt_* tables, outputs CSV/XLSX to S3, creates rpt_report_runs row), GET /analytics/reports/:id/runs (history), GET /analytics/report-runs/:id/download (S3 presigned URL).
  3. ScheduledReportWorker — Polls rpt_scheduled_reports WHERE next_run_at ≤ NOW() AND is_active=true. For each: runs the report, updates last_run_at + last_run_status, computes next_run_at from cron expression, delivers via Cycle 14 notification. GET /analytics/scheduled-reports, POST /analytics/scheduled-reports, PATCH /analytics/scheduled-reports/:id.
  4. StateReportService — GET /analytics/state-reports (available templates for the school's state), POST /analytics/state-reports/:templateId/generate (generates state compliance report from template + rpt_* data).
Produces → 4 services, ~12 endpoints. Total Cycle 29 endpoints: ~30.

10Vertical Slice Integration Test
Test
Test Script
  1. Worker materialisation: Trigger SISReadModelWorker manually. Verify rpt_daily_attendance_summary populated from sis_attendance data. Verify rpt_student_academic_summary populated from cls_grades data. Verify checkpoints recorded.
  2. At-risk detection: Configure threshold: attendance <85% AND GPA <2.0. Run AtRiskEvaluationWorker. Verify 2 students flagged. Verify rpt.at_risk.flagged fires for newly flagged students. Modify threshold to <80%. Re-run. Verify 1 student unflagged.
  3. School summary: Run SchoolSummaryWorker. Verify rpt_school_summary aggregates: total_enrolled matches enrolment count, avg_attendance_rate matches daily summaries, at_risk_count matches flagged students.
  4. District aggregation: Run DistrictAnalyticsWorker. Verify rpt_district_summary aggregates across schools. Verify rpt_district_school_comparison has correct rankings.
  5. Wellbeing trends: Run WellbeingTrendsWorker. Verify aggregation from Cycle 11.1 data. Verify NO individual student IDs appear in the output.
  6. Aged debtors: Run FinanceARWorker. Verify bucket computation matches Cycle 6 payment data.
  7. Report generation: Create "Attendance Report" definition. Run on-demand. Verify CSV output in S3. Verify rpt_report_runs row with COMPLETE status + row_count.
  8. Scheduled report: Create scheduled report (every Monday 8am). Simulate cron trigger. Verify report generated + last_run_at stamped + next_run_at computed.
  9. Rebuild from snapshot: Create snapshot of rpt_daily_attendance_summary. Truncate the table. Rebuild FROM_SNAPSHOT. Verify data restored within SLA (<10 min).
  10. Visibility: Teacher sees class-level dashboards only. Principal sees school summary + at-risk. Superintendent sees district comparison. Admin manages report engine + at-risk config. Parent cannot access analytics.
